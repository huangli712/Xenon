## 目标

Element-wise math benchmarks: add/sub/mul/div/sin/exp/abs (f32/f64/Complex<f64>, contiguous + non-contiguous)。

本任务建立 W28 benchmark 交付物的一部分，覆盖 27-benchmark §5 的 benchmark 结构、§5.5 的清单、§6 的数值与执行约束，以及 §8 的 quick smoke 验证口径。涉及的 benchmark 或检查项为：`elem_add_f64`, `elem_add_f32`, `elem_add_complex`, `elem_mul_f64`, `elem_sin_f64`, `elem_sin_f32`, `elem_sub_f64`, `elem_div_f64`, `elem_exp_f64`, `elem_abs_f64`, `elem_add_sliced`。

## 前置准备

- 确认 W28 之前的核心 API、错误语义、构造、广播、归约、矩阵、SIMD 或并行相关任务已按前置依赖完成。
- 使用仓库现有依赖，不为 benchmark 引入新的第三方测量框架。
- 仅在目标文件内添加 benchmark、辅助函数或 CI/report 逻辑，避免改变 crate 公共 API。

## 实施步骤

### Step 1: 建立目标文件骨架

按 27-benchmark §5.1 和 §5.8 的 `harness = false` 模式创建或更新目标文件，保留 `--quick` 与名称 filter 入口，确保单个 bench 可独立运行。

```rust
use std::hint::black_box;

use xenon::prelude::*;

mod utils;
use utils::{generators, run_timed, SIZES_1D};

// --- f64 contiguous benches ---

fn bench_elem_add_f64(quick: bool) {
    for &size in SIZES_1D {
        let lhs = generators::sequential_1d(size);
        let rhs = generators::sequential_1d(size);
        let median = run_timed(quick, || {
            let _result = black_box((&lhs + &rhs).expect("same-shape add must succeed"));
        });
        println!("elem_add_f64/{size}: {median} ns");
    }
}

fn bench_elem_sub_f64(quick: bool) {
    for &size in SIZES_1D {
        let lhs = generators::sequential_1d(size);
        let rhs = generators::sequential_1d(size);
        let median = run_timed(quick, || {
            let _result = black_box((&lhs - &rhs).expect("same-shape sub must succeed"));
        });
        println!("elem_sub_f64/{size}: {median} ns");
    }
}

fn bench_elem_mul_f64(quick: bool) {
    for &size in SIZES_1D {

// --- non-contiguous (sliced) bench ---
//
// 27-benchmark §5.5: elem_add_sliced uses M scale only (single Medium row).
// The fixture owner is held outside the timed loop, then `view()` is taken
// per iteration to honor the StridedFixture1D borrow contract.

fn bench_elem_add_sliced(quick: bool) {
    // §5.5 schedules this entry at Medium scale (65,536).
    const SLICED_SIZE: usize = 65_536;
    let fixture = generators::strided_view_1d(SLICED_SIZE);
    let rhs = generators::sequential_1d(SLICED_SIZE);
    let median = run_timed(quick, || {
        let lhs_sliced = fixture.view();
        let _result = black_box((&lhs_sliced + &rhs).expect("same-shape add must succeed"));
    });
    println!("elem_add_sliced/{SLICED_SIZE}: {median} ns");
}

// --- main dispatch ---

fn should_run(filter: Option<&str>, name: &str) -> bool {
    filter.map_or(true, |needle| name.contains(needle))
}

fn main() {
    let args = std::env::args().skip(1).collect::<Vec<_>>();
    let quick = args.iter().any(|arg| arg == "--quick");
    let filter = args.iter().find(|arg| !arg.starts_with("--")).map(String::as_str);

    let benches: &[(&str, fn(bool))] = &[
        ("elem_add_f64", bench_elem_add_f64),
        ("elem_sub_f64", bench_elem_sub_f64),
        ("elem_mul_f64", bench_elem_mul_f64),
        ("elem_div_f64", bench_elem_div_f64),
        ("elem_abs_f64", bench_elem_abs_f64),
        ("elem_sin_f64", bench_elem_sin_f64),
        ("elem_exp_f64", bench_elem_exp_f64),
        ("elem_add_f32", bench_elem_add_f32),
        ("elem_sin_f32", bench_elem_sin_f32),
        ("elem_add_complex", bench_elem_add_complex),
        ("elem_add_sliced", bench_elem_add_sliced),
    ];

    for &(name, func) in benches {
        if should_run(filter, name) {
            func(quick);
        }
    }
}
```

## 关键设计决策

| 决策 | 依据 |
|------|------|
| 使用仓库本地 `harness = false` runner，而非 Criterion 等第三方框架 | 27-benchmark §11 决策 1 要求不引入额外 benchmark 框架 |
| quick 模式保留 filter 与最小输入规模 | 27-benchmark §5.6 和 §8.1 要求 CI smoke 可快速验证 benchmark 入口 |
| benchmark 只记录性能趋势，不定义功能正确性合约 | 27-benchmark §1.1 将功能正确性边界交给 28-tests |
| 11 个 `elem_*` benchmark **类型轴 + 输入形态轴选择性展开**：`elem_add` 4 个变体（f64/f32/Complex\<f64\> 三档连续 + sliced 非连续输入）、`elem_sin` 跨 2 档（f64/f32）连续、其他 5 个独立 op（sub/mul/div/abs/exp）仅 f64 连续基准 | 27-benchmark §5.5 同 op 不同类型 / 输入形态性能特性差异显著但不需全面展开：`add` 跨 3 档类型 + 1 档非连续输入，测量**浮点 SIMD（f32/f64，W14T2 实现）**、**复数 deinterleave SIMD（Complex\<f64\>，W14T11 实现）**、**非连续 stride 输入**（add_sliced，dispatch fallback 到标量 path）的性能差异；`sin` 跨 2 档类型，测量**标量 sin 在 f32/f64 的精度/速度差异**（W14 范围内 sin 无专门 SIMD kernel，走标量 fallback）；**整数 add SIMD 路径在 W28 整体范围内不覆盖**（实证 W28T10 `simd_add_compare` 实际仅 f32/f64 两档，未列 simd_add_compare_i32）；W28 范围内**仅 sum 操作的整数 SIMD 路径**被 `simd_sum_compare` 覆盖（含 i32 admission / scalar-fallback path）；`sub/mul/div/abs/exp` 在 W28 范围内不做跨类型展开（设计 §5.5 elem_* 主 bench 清单仅为这些 op 列 f64 条目，未列 elem_sub_f32 / elem_mul_complex 等变体；simd_*_compare 是独立的 SIMD-on/off 对比 bench，不提供主 bench 的类型轴扩展；如需扩展需同时更新 §5.5 主 bench 清单 + W14 提供对应类型的 SIMD kernel） |

## 验证方式

1. 编译检查: `cargo check --benches`
2. Lint 检查: `cargo clippy --benches -- -D warnings`
3. 测试验证: `cargo bench --bench math -- elem_add_f64 --quick`
4. 手动验证: 运行对应 bench 的 `--quick` filter，确认输出包含本任务的 benchmark 名称和 median ns 数值。

## 注意事项

- `black_box` 必须包裹被测结果，避免编译器消除热路径。
- benchmark 输入生成应固定、可重复，避免随机噪声污染趋势判断。
- SIMD/并行对比只在对应 feature 组合下解释性能差异，不得改变默认 API 行为。
