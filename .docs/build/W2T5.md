## 目标

Public exports of XenonError, Result alias, and auxiliary enums via prelude, plus `pub use error::XenonError;` direct re-export in lib.rs.

在 `prelude.rs` 中激活 error 模块的公开导出，确保用户可以通过 `use xenon::prelude::*` 使用核心错误类型和辅助枚举；同时在 `lib.rs` 中追加 `01-architecture.md §8` 第 635 行要求的直达 re-export `pub use error::XenonError;`，让用户通过 `xenon::XenonError` 直达路径访问错误类型。

## 前置准备

- W2T4 完成：XenonError 完整实现（enum + Display + Error）
- W1T3 完成：`src/lib.rs` 已包含 `pub mod prelude;` 和 `pub use prelude::*;`；`W1T3` 中「lib.rs convenience re-export 演进协议」已明确把 `pub use error::XenonError;` 归属本 task
- W2T1 完成：`pub mod error;` 已在 lib.rs 中声明（由 W1T3 模块演进协议表分配给 W2T1）

### Step 2: 在 lib.rs 中追加 `pub use error::XenonError;` 直达 re-export

> **协议依据**：W1T3「lib.rs convenience re-export 演进协议」明确把 `01-architecture.md §8`
> 第 635 行的 `pub use error::XenonError;` 归属本 task。该 re-export 是与 `pub use prelude::*;`
> 并列的独立 convenience 通道，让用户通过 `xenon::XenonError` 直达路径访问错误类型，
> 不依赖 prelude glob 导入。

修改 `src/lib.rs`，在 W1T3 已写入的 `pub use prelude::*;` 之后追加一行：

```rust
// W1T3 already wrote:
//   pub use prelude::*;

// W2T5 appends (matches 01-architecture §8 line 635):
pub use error::XenonError;
```

修改后 lib.rs 末段应与 `01-architecture.md §8` 第 633-635 行片段完全对应：

```rust
// Convenience re-exports
pub use prelude::*;
pub use error::XenonError;
```

> **职责边界**：本 step 只追加这一行 `pub use error::XenonError;`，不得改动 W1T3 写入的
> 其他 lib.rs 内容（lint 声明、`pub mod prelude;`、`pub use prelude::*;`），亦不得提前
> 添加其他 Wave 负责的 `pub mod` 声明。

### Step 3: 单元测试

    #[test]

        // Verify XenonError is importable from prelude

        // Verify Result type alias is importable from prelude

    }

    #[test]
    fn test_error_is_debug_and_display() {
        let e = XenonError::DimensionMismatch {
            operation: std::borrow::Cow::Borrowed("test"),
            expected: 2,
            actual: 3,
        };
        // Must compile — confirms Debug + Display are in scope
        let _debug = format!("{:?}", e);
        let _display = format!("{}", e);

    #[test]
    fn test_prelude_auxiliary_enums_importable() {
        // Verify auxiliary enums are importable from prelude
        let _cat = FfiErrorCategory::NullPointer {
            argument: std::borrow::Cow::Borrowed("data"),

    /// Reference: 01-architecture.md §8 line 635.
    #[test]
    fn test_xenon_error_direct_reexport_at_crate_root() {

## 关键设计决策

| 决策 | 依据 |
|------|------|
| prelude 导出 `XenonError`、`Result` 和所有辅助枚举 | `26-error §7 T5` — 设计文档明确要求导出辅助枚举 |
| 辅助枚举按字母序排列 | 提高可读性，避免遗漏 |
| 同步在 lib.rs 追加 `pub use error::XenonError;` | `01-architecture.md §8` 第 635 行明确要求该直达 re-export；W1T3「lib.rs convenience re-export 演进协议」把该行归属本 task |
| 直达 re-export 与 prelude glob 并列存在 | 两者是不同便捷通道：`xenon::XenonError` 直达路径 vs `xenon::prelude::*` 批量导入；rustdoc 对二者的渲染入口不同，缺失任一会让用户体验偏离设计文档 §8 |

## 验证方式

> 所有验证命令在失败时必须以非零退出码返回。

1. **编译**: `cargo check`
2. **Lint 回归**: `cargo clippy --all-targets -- -D warnings`，确认 W2T5 修改未引入新警告
3. **单元测试**:
   ```bash
   cargo test --lib -- \
     test_prelude_error_imports \
     test_prelude_result_alias \
     test_error_is_debug_and_display \
     test_prelude_auxiliary_enums_importable \
     test_xenon_error_direct_reexport_at_crate_root
   ```
   五个测试必须均显示 `test result: ok. 5 passed`。
4. **Doctest**: `cargo test --doc`，验证 `XenonError` 文档块新增的两段 `# Examples`（直达 re-export + prelude glob）均可编译运行
5. **文档**: `RUSTDOCFLAGS="-D warnings" cargo doc --no-deps`——`xenon::XenonError` 应同时出现在 crate root 和 prelude 模块的 rustdoc 页面

## 注意事项

- 此任务**修改两个文件**：`src/prelude.rs`（取消注释并补全导出）+ `src/lib.rs`（追加 `pub use error::XenonError;`）；不涉及 `error.rs` 的结构变更
- 辅助枚举亦可通过 `crate::error::*` 路径按需导入（prelude 提供便利但不强制）
- `pub use error::XenonError;` **不能下放到 prelude.rs 内部**——设计文档 §8 明确要求该 re-export 出现在 lib.rs crate root，让用户通过 `xenon::XenonError` 直达，绕过 `prelude` 模块层
- W1T3 已写入的 `pub use prelude::*;` 不得删除，本 task 仅在其下方追加 `pub use error::XenonError;` 一行
- 后续 W3T12 等 task 会向 `error.rs` 追加错误变体（如 `DimensionMismatch` 的集成）；本 task 完成后 `xenon::XenonError` 直达入口稳定，新增变体自动通过该入口可见，无需后续 task 重复修改 lib.rs
