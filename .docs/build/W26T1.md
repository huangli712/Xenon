# 实施方案: W26T1

## 任务概述

| 字段 | 值 |
|------|-----|
| Wave | W26 — Output Formatting |
| Task | W26T1 — Module skeleton: crate-root declaration + format module root |
| 目标文件 | `src/format/mod.rs`, `src/lib.rs` |
| 前置依赖 | None |
| 设计文档 | 22-output.md |
| 预估工时 | 5 min |

## 目标

Module skeleton: 创建 `src/format/mod.rs` 模块根（仅含模块级文档注释，不声明子模块），并在 `src/lib.rs` 中加入 `pub mod format;` 暴露模块。

按照 `build/SUMMARY.md` 中 W26T1 的定义，建立后续 W26T2-W26T6 可以增量扩展的最小骨架，并保持与 `docs/design/22-output.md` §3（文件位置）、§4（依赖关系）一致。

## 前置准备

- 确认 `src/lib.rs` 已存在且可声明新顶层模块（参考 W1T3 的「lib.rs 模块声明演进协议」）。
- 确认 `src/format/` 目录尚未存在（如已存在则跳过 `mkdir`）。

## 实施步骤

### Step 1: Create format module root

新建 `src/format/mod.rs`，**仅写入模块级文档注释，不声明任何子模块**。子模块的 `mod config;`、`mod pretty;`、`mod display;`、`mod debug;` 声明分别由 W26T2 / W26T3 / W26T4 / W26T5 在各自实施中增量追加（参考 W1T3 协议表）。最终 `pub use` 由 W26T6 收尾添加。

```rust
//! Tensor formatting support (skeleton).
//!
//! This file is created in W26T1 as the module root. Sub-module
//! declarations (`mod config;`, `mod pretty;`, `mod display;`, `mod debug;`)
//! are appended by W26T2..W26T5; public re-exports are finalized by W26T6.
```

### Step 2: Expose format module from crate root

在 `src/lib.rs` 适当位置（按现有 wave 间模块字母/拓扑顺序）追加一行：

```rust
pub mod format;
```

### Step 3: 单元测试

> **注意**: W26T1 仅为模块骨架，本阶段 `src/format/mod.rs` 不含任何类型或函数；子模块 `config` / `pretty` / `display` / `debug` 在 W26T2-W26T5 才会陆续被声明，因此 W26T1 阶段**没有可测试的模块内行为**。本 task 的验证依据是「`cargo check` 通过 + `crate::format` 路径可解析」。
>
> 这一处理与 W4T9 / W4T12 等「纯骨架/纯文档 task」的先例一致（项目记忆 Wave 4 审计：「纯文档任务替换了代码样板为文档编写指引」）。
>
> 真实的单元测试在 W26T2 起：
> - W26T2 覆盖 `FormatConfig::default()` 与 `normalized_edge_items()`；
> - W26T3 覆盖 1D / ND pretty helper；
> - W26T4 覆盖 Display；
> - W26T5 覆盖 Debug + 布局元信息；
> - W26T6 覆盖 `pub use` 路径可达性 + Display/Debug 编译期可达 (`test_display_compile`)。

W26T1 不写入 `#[cfg(test)] mod tests`，避免引入只能 trivially 编译通过、无实质断言的占位测试（参考 Wave 9 审计：占位测试已被禁止）。

## 关键设计决策

| 决策 | 依据 |
|------|------|
| W26T1 不在 mod.rs 内声明子模块 | 遵循「lib.rs 模块声明演进协议」（项目记忆 W1T3-F1），由各子模块 task 增量声明，避免 W26T1 完成时 `cargo check` 因 unresolved module 失败 |
| W26T1 不写占位测试 | 模块根无类型/函数；trivially passing 测试在 Wave 9 审计中已被禁止；真实测试由 W26T2-T6 覆盖 |
| `pub use` 延迟到 W26T6 | 设计 §5 公共 API（`FormatConfig`, `TensorDisplay`）依赖 W26T2/T4 才完成，过早 re-export 会编译失败 |

## 验证方式

1. 编译检查: `cargo check`
2. Lint 检查: `cargo clippy --all-targets`
3. 路径可达性: `cargo check` 时 `crate::format` 必须可解析；后续 task 通过实际类型测试间接验证。
4. 手动验证: 在 lib.rs 同级临时 `use crate::format;`（或在后续 task 的测试中），确认无 unresolved module 错误。

## 注意事项

- **不要**在本 task 声明 `mod config;` / `mod pretty;` / `mod display;` / `mod debug;`，否则 W26T1 完成时立刻编译失败。
- **不要**写注释掉的 `// pub use ...` 占位代码 ── W26T6 会以完整形态写入。
- Display/Debug 不需要 `std` feature gate（设计 §5.3 line 215 显式说明）。
- 本 task 不引入任何运行时逻辑，所有格式化能力分散在 W26T2-T6。
