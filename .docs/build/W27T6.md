## 实施步骤

### Step 1: Add cross-thread storage tests

In `tests/test_parallel.rs`, cover owned transfer, mutable view scoped transfer, read-only view scoped transfer and Arc concurrent reads through public tensor APIs.

```rust
#[test]
fn test_owned_cross_thread() {
    let tensor = Tensor1::from_shape_vec([3], vec![1_i32, 2, 3]).unwrap();
    let handle = std::thread::spawn(move || tensor.iter().copied().sum::<i32>());
    assert_eq!(handle.join().unwrap(), 6);
}

#[test]
fn test_arc_concurrent_access() {
    let tensor = Tensor1::from_shape_vec([3], vec![1_i32, 2, 3]).unwrap().into_shared();
    let a = tensor.clone();
    let b = tensor.clone();
    let left = std::thread::spawn(move || a.iter().copied().sum::<i32>());
    let right = std::thread::spawn(move || b.iter().copied().sum::<i32>());
    assert_eq!(left.join().unwrap(), 6);
    assert_eq!(right.join().unwrap(), 6);
}

#[test]
fn test_view_mut_cross_thread_write() {
    let mut tensor = Tensor1::from_shape_vec([2], vec![1_i32, 2]).unwrap();
    std::thread::scope(|scope| {
        let mut view = tensor.view_mut();
        let handle = scope.spawn(move || {
            view.fill(7);
        });
        handle.join().unwrap();
    });
    assert_eq!(tensor.to_vec(), vec![7, 7]);
}
```

### Step 2: Add error-path thread-safety tests

In `tests/test_error.rs`, verify `XenonError` 满足 `Send` 约束。**权威依据**：`docs/design/26-error.md §9.3` 行 1010 明确"`XenonError` ... 错误可安全地跨线程传递和存储"，即 `XenonError: Send + Sync`；该约束在并行路径（`docs/design/09-parallel.md §6.5`）和测试模块（`docs/design/28-tests.md §5.23` 关于 `test_send_sync_contracts` 的前置依赖说明）中均被消费。W2T4 已在 error 模块内放置 `test_error_is_send_sync` 单元测试；本 step 在集成测试层补一个独立断言以验证跨 crate 边界 (integration test) 该 trait bound 依然成立，便于排查由可见性收紧或 `cause: Option<Box<XenonError>>` 装箱递归引起的退化。本 step 仅做 trait 边界检查，不耦合 `XenonError` 任何具体变体内部结构，避免因 W2 实现细节调整导致 W27 测试连锁失败。

```rust
#[test]
fn test_parallel_error_is_send() {
    fn assert_send<T: Send>() {}
    assert_send::<XenonError>();
}
```

## 关键设计决策

| 决策 | 依据 |
|------|------|
| 集成测试归入现有文件，不新建 test_thread_safety.rs | `25-safety §7 T6` 明确要求归入 `test_parallel.rs` / `test_error.rs`，避免文件碎片化 |
| 跨线程测试使用 `std::thread::scope` | 非 `'static` 的 View/ViewMut 借用无法传入 `thread::spawn`，scoped thread 保证借用生命周期有效 |
| `test_parallel_error_is_send` 在集成测试层补一个 trait 边界断言 | `26-error §9.3` 行 1010 规定 `XenonError` 可跨线程传递和存储（即 `Send + Sync`）。W2T4 已在 error 模块内部提供 `test_error_is_send_sync`，本集成测试在公开 API 边界上复查，防止跨 crate 可见性或 `cause: Option<Box<XenonError>>` 递归装箱导致退化；不匹配 Display 字符串或具体变体结构，避免耦合 W2 实现细节 |
| 追加 `test_view_scoped_cross_thread_read` 补强用例 | `25-safety §8.5` 集成测试要求覆盖 `View` 存储的跨线程传递；`test_view_mut_cross_thread_write` 已覆盖 `ViewMut`，对称地追加 `ViewRepr` 的 scoped thread 读取测试以完整覆盖只读共享路径 |
