## 目标

Create `src/set/unique.rs` and define the sealed `UniqueElement` trait together with its real scalar impls (`i32`, `i64`, `f32`, `f64`). Complex impls are deferred to W19T5. Also add a compile-time export check plus **trait-method level** unit tests for `i32` equality, f32 `-0.0 == 0.0`, and f32 `NaN != NaN` semantics. These trait-method tests are named `test_unique_eq_*` so the §8.2 names `test_unique_signed_zero_equal_f32` / `test_unique_nan_preserved_f32` remain free for the **operation-level** (`unique_impl`/`unique()`) counterparts owned by W19T4.

## 实施步骤

### Step 1: Define trait

新建 `src/set/unique.rs`。实现该步骤时只修改任务范围内的目标文件，保持与现有模块风格一致。

```rust
use crate::element::Element;

/// Sealed trait for types that support the `unique` operation.
///
/// Reuses the shared `crate::private::Sealed` infrastructure
/// (defined in `03-element.md §5.8`). Implemented only inside
/// this crate for supported element types; `bool` does not
/// implement this trait.
pub trait UniqueElement: crate::private::Sealed + Element {
    fn unique_eq(&self, other: &Self) -> bool;
}

impl UniqueElement for i32 {
    fn unique_eq(&self, other: &Self) -> bool { self == other }
}

impl UniqueElement for i64 {
    fn unique_eq(&self, other: &Self) -> bool { self == other }
}
```
### Step 2: Add float implementations

实现该步骤时只修改任务范围内的目标文件，保持与现有模块风格一致。

### Step 3: 单元测试

按设计文档测试计划添加或更新单元测试，覆盖正常路径、边界情况和错误路径。

```rust
#[cfg(test)]
mod tests {
    use super::*;
    use crate::set::UniqueElement as PubUniqueElement;

    #[test]
    fn test_set_module_exports_unique_element() {
        fn assert_unique<T: PubUniqueElement>() {}
        assert_unique::<i32>();
        assert_unique::<f64>();
    }

    #[test]
    fn test_unique_eq_basic_i32() {
        assert!(42_i32.unique_eq(&42));
        assert!(!0_i32.unique_eq(&1));
    }

    #[test]
    fn test_unique_eq_signed_zero_f32() {
        // Trait-method level check: `-0.0 == 0.0` via `UniqueElement::unique_eq`.
        // The §8.2 operation-level counterpart `test_unique_signed_zero_equal_f32`
        // is owned by W19T4.
        assert!((-0.0_f32).unique_eq(&0.0));
    }

    #[test]
    fn test_unique_eq_nan_f32() {
        // Trait-method level check: `NaN != NaN` via `UniqueElement::unique_eq`.
        // The §8.2 operation-level counterpart `test_unique_nan_preserved_f32`
        // is owned by W19T4.
        let nan = f32::NAN;
        assert!(!nan.unique_eq(&nan));
    }
}
```
## 关键设计决策

- Rust float equality already gives `NaN != NaN` and `-0.0 == 0.0`.
- The trait is sealed via `crate::private::Sealed` (reuses the shared infrastructure from `03-element.md §5.8`), which prevents downstream crates from implementing `UniqueElement` for unsupported types.
- `bool` remains excluded from the `unique` API because no `UniqueElement` impl is provided. Sealing is provided by the `crate::private::Sealed` supertrait (a crate-private trait per `03-element.md §5.8`): external crates cannot `impl crate::private::Sealed` for new types, so they cannot `impl UniqueElement` either. `bool` itself implements `Sealed` (because it implements `Element`), but the **absence of a `UniqueElement` impl for `bool` in this crate** is what excludes `bool` from the `unique` API. The two mechanisms compose: `Sealed` closes the trait against external impls; impl absence closes `bool` against the in-crate impl set.
- Complex implementations are added in W19T5 after core `unique_impl` exists.
- The export-check test (`test_set_module_exports_unique_element`) lives here rather than in W19T1 because it depends on real scalar impls that this task introduces.
- The two float trait-method tests are named `test_unique_eq_signed_zero_f32` / `test_unique_eq_nan_f32` (not `test_unique_signed_zero_equal_f32` / `test_unique_nan_preserved_f32`). The §8.2 names are reserved for the **operation-level** (`unique_impl` / `unique()`) tests added in W19T4, so f32 and f64 §8.2 entries share the same operation-level test shape and remain symmetric.
