## 目标

Audit that examples and crate docs only declare std environment; remove out-of-scope platform notes。

本任务交付可审查、可验证的文档改动：目标文件必须补齐对应层级的说明、示例或配置，并与 29-documentation 的文档层次、doctest 规范和 CI 门禁保持一致。

## 前置准备

- 确认前置依赖 `W30T1, W30T3, W30T43-W30T49` 已完成或不适用。
- 读取 `src/lib.rs, README.md, examples/` 当前内容，避免覆盖已有用户修改。
- 以 29-documentation §5.4.1 Runtime Environment (line 256-260) 为核心依据准备 std-only 检查清单；§5.4.2、§5.6 和 §5.11 仅作为通用文档验证背景。

## 实施步骤

### Step 1: 搜索越界平台声明（仅作人工定位用，未纳入门禁）

在 `src/lib.rs, README.md, examples/` 中搜索任何提及 `no_std`、`nostd`、`alloc`、`wasm`、`webassembly`、`embedded`、`bare.metal`、`freestanding` 或其他非标准平台的文档声明（仅作人工理解在哪里，不作验收门禁；验收的反向断言在 Step 5 统一执行）：

```bash
# 人工搜索：帮助定位但不作门禁
grep -rnE 'no_std|nostd|alloc(-only)?|wasm|webassembly|embedded|bare.metal|freestanding' \
    src/lib.rs README.md examples/ || true
```

### Step 2: 移除越界内容并补充 std 声明

移除搜索到的任何 out-of-scope 平台描述。如 `src/lib.rs` 已有等价 std-only 声明（grep `Xenon supports only the std environment` 命中），则不重复添加；否则添加 29-documentation §5.4.1 line 256-260 标准声明：

```rust
//! Xenon supports only the `std` environment.
//!
//! It does not need or provide a `std` feature toggle.
//! All documentation assumes a `std` environment.
```

如确认无越界内容，跳过移除步骤，并仅在缺少等价 std-only 声明时添加上述标准声明。

### Step 3: 协同审查示例代码

按 29-documentation §5.4.2 检查示例：索引用 fallible API，构造错误语义正确，运算符示例体现 `Result`，feature 描述不使用 nightly-only `doc_cfg`。

### Step 4: 检查链接与元数据

验证 README、crate docs、docs.rs metadata 或 CHANGELOG 链接可解析，且不出现 broken intra-doc links。

### Step 5: 单元测试
> **强制要求**: 本 task 为「审计型」改动，「无越界平台声明残留」本身必须以等效验证脚本以失败时非零退出码断言，无法仅靠 doctest/cargo doc 替代。

**等效验证脚本**（三个检查面 + 失败语义）：
```bash
#!/bin/bash
set -euo pipefail

# 检查面 1（核心审计门禁）：越界平台声明不得残留。有命中即失败。
# 仅扩展到具体目标范围 (src/lib.rs 顶层 + README.md + examples/，不覆盖其他 .rs)
if grep -rnE 'no_std|nostd|alloc(-only)?|wasm|webassembly|embedded|bare.metal|freestanding' \
        src/lib.rs README.md examples/ ; then
    echo '✗ Out-of-scope platform declarations remain; W30T50 audit not complete'
    exit 1
fi
echo '✓ No out-of-scope platform strings'

# 检查面 2：std-only 声明必须在 src/lib.rs 存在（由 W30T1 交付；本 task 仅核验）
grep -q 'Xenon supports only the .std. environment' src/lib.rs \
    || { echo 'Missing std-only declaration in src/lib.rs'; exit 1; }

# 检查面 3：Rust 侧文档门禁 (doctest + cargo doc + lint) 仍然通过
cargo test --doc --all-features
RUSTDOCFLAGS="-D warnings" cargo doc --all-features --no-deps
cargo clippy --all-features -- -D clippy::missing_errors_doc -D clippy::missing_panics_doc -D clippy::missing_safety_doc

echo 'OK: W30T50 audit gate passed'
```

验收点：新增或修改的 Rust doc examples 可编译运行；所有 `Result` 示例使用 `?` 并包含断言。

## 关键设计决策

- feature 文档只描述行为或执行路径差异；不使用 nightly-only `doc_cfg`，保持 MSRV 1.85 stable。
- 所有 Rust doc comment、README 和 examples 使用英文，实施方案说明保持中文以匹配现有 build 文档。
- 示例优先写成可运行 doctest 或 `main() -> xenon::Result<()>`，并使用 `?` 与断言满足 29-documentation §5.6。

## 验证方式

1. 审计门禁: 运行上述等效验证脚本，确保残留命中或缺失 std-only 声明时立即非零退出
2. 文档构建: `RUSTDOCFLAGS="-D warnings" cargo doc --all-features --no-deps`
3. Doctest 验证: `cargo test --doc --all-features`
4. 示例构建: `cargo build --examples --all-features`（保证 examples/ 移除越界声明后仍可编译）
5. 手动验证: 打开 `src/lib.rs` 顶档 + `README.md` + `examples/*.rs`，目视确认仅声明 std 环境

## 注意事项

- 不要把编译检查当作 doctest；文档示例必须由 `cargo test --doc` 覆盖。
- 以上 grep 覆盖常见显式非 std 声明；其他模糊措辞（如 `target_os = "none"`）由人工复核。
- 不要展示方括号索引语法；索引示例使用 `try_at`、`try_at_mut`、`get` 或 `get_mut`。
- 不要新增依赖、教程站点、notebook 或自定义 rustdoc 主题。
