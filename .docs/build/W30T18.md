## 目标

Index module-level docs: NdIndex trait, multi-dim access, slicing, bounds checking。

本任务交付可审查、可验证的文档改动：目标文件必须补齐对应层级的说明、示例或配置，并与 29-documentation 的文档层次、doctest 规范和 CI 门禁保持一致。

- 确认前置依赖 `W30T2` 已完成或不适用。

- 对照 29-documentation §5.4.2、§5.6 和 §5.11 准备文档质量检查清单。

## 实施步骤

### Step 1: 梳理模块职责

读取 `src/index/mod.rs` 对应模块源码和所属设计文档，列出模块职责、核心类型、公开入口和必须说明的不变量。

### Step 2: 写入模块级 `//!` 文档

在模块顶部添加英文 `//!` 文档，覆盖职责边界、核心概念、主要公开类型和与相邻模块的关系。

```rust
//! Multi-dimensional indexing and slicing.
//!
//! [`NdIndex`] maps validated coordinates into F-order offsets. Public examples
//! should use fallible accessors such as `try_at`, `try_at_mut`, `get`, and
//! `get_mut` rather than square-bracket syntax.
```

### Step 3: 补充约束与边界说明

说明错误语义、性能路径、feature 行为或 safety 约束。公开 sealed trait 所在模块必须提示后续 type-level doc 添加 `# Sealed`。

### Step 4: 校验模块公开项链接

使用 intra-doc links 指向本模块公开类型和函数，避免链接 private item；对不确定链接改用普通代码字体。

### Step 5: 文档构建验证（等效验证）

> **强制要求**: 本 task 目标为 Rust 源码（`*/mod.rs`），但内容仅含模块级 `//!` 注释，无可测函数逻辑。
> 按 TEMPLATE.md L79-99「等效验证条款」，以 `cargo doc -D warnings` 作为等效验证脚本（失败时非零退出，可入 CI）。
> 函数级 doctest 与 examples 编译由 Wave 3 (W30T29-W30T42) / Wave 4 (W30T43-W30T49) 覆盖，不在本 task 范围。

```bash
# 等效验证脚本：失败时非零退出码
RUSTDOCFLAGS="-D warnings" cargo doc --all-features --no-deps
```

验收点：`cargo doc` 无 missing_docs / broken_intra_doc_links / private_intra_doc_links 等 warning；模块 `//!` 文本可在生成的 rustdoc 中正常渲染。

## 关键设计决策

- 文档内容跟随源码签名和设计文档，不通过文档引入新 API 或新依赖。
- 所有 Rust doc comment、README 和 examples 使用英文，实施方案说明保持中文以匹配现有 build 文档。
- 示例优先写成可运行 doctest 或 `main() -> xenon::Result<()>`，并使用 `?` 与断言满足 29-documentation §5.6。

## 验证方式

1. 编译检查: `RUSTFLAGS="-D warnings" cargo check --all-features`
2. Lint 检查: `cargo clippy --all-features -- -D warnings`
3. 文档构建: `RUSTDOCFLAGS="-D warnings" cargo doc --all-features --no-deps`
4. 手动验证: 打开生成的 rustdoc，确认 `//!` 模块文本非空、链接有效、示例与任务目标一致。

## 注意事项
