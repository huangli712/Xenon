## 实施步骤

### Step 1: 定位实现边界

确认以下 trait 在 W22T1 完成后已可用（ones 与 zeros 共享构造路径）：
- `Element::one()` — 幺值填充（替代 zeros 的 `Element::zero`）
- `Dimension::checked_size()`、`layout::compute_f_strides()`、`StorageOwned::from_elem()` — 共享构造基础设施

### Step 2: 实现任务目标

在 `src/construct/init.rs` 中实现 `ones()` constructor 为 `TensorBase<Owned<A>, D>` 的关联函数（associated function），调用语法 `Tensor::<A, D>::ones(shape)`，并保持错误返回、trait 约束和 public API 与 `18-construction §5.1` 一致。

```rust
use crate::dimension::{Dimension, IntoDimension};
use crate::element::Element;
use crate::error::XenonError;
use crate::layout;
use crate::storage::{Owned, StorageOwned};
use crate::tensor::TensorBase;

impl<A, D> TensorBase<Owned<A>, D>
where
    A: Element,
    D: Dimension,
{
    /// Create a one-initialized tensor (F-order).
    pub fn ones<Sh>(shape: Sh) -> Result<Self, XenonError>
    where
        Sh: IntoDimension<Dim = D>,
    {
        let dim = shape.into_dimension();
        let len = dim.checked_size()?;
        let strides = layout::compute_f_strides(&dim)?;
        let storage = <Owned<A> as StorageOwned>::from_elem(len, A::one());
        let flags = layout::compute_layout_flags(&dim, &strides, storage.as_ptr());
        // SAFETY: shape validated by checked_size; strides from compute_f_strides;
        // flags from compute_layout_flags; storage length = len; offset 0;
        // derived_from_view_mut: false — ones is not a downgrade path.
        Ok(unsafe { Self::new_unchecked(storage, dim, strides, 0, flags, false) })
    }
}
```

### Step 3: 补齐导出与相邻调用点

`ones` 为 `TensorBase<Owned<A>, D>` 的关联函数，impl 块位于 `init.rs` 内即对整个 crate 可见，无需在 `mod.rs` 中添加 `pub use`。只需确认 `src/lib.rs` 已注册 `pub mod construct;`。

**同文件协调（与 W22T2 批次 2 并行落地）**：W22T2 与 W22T3 都向 `src/construct/init.rs` 写入。落地时按如下规则合并，避免 Rust 同一模块文件中出现两个同泛型签名的 `impl` 块或两个同名内联 `mod tests`（后者会直接编译失败）：

1. 若 `src/construct/init.rs` 中**已存在** `impl<A, D> TensorBase<Owned<A>, D> where A: Element, D: Dimension { ... }` 块，则把本任务的 `fn ones` 体**追加**到该现有 impl 块内；否则新建该 impl 块。
2. 若 `src/construct/init.rs` 中**已存在** `#[cfg(test)] mod tests { ... }` 块，则把本任务新增的 `#[test] fn` 与所需 `use` 语句**追加**到该现有 mod 内；否则新建 `mod tests`。
3. 顶层 `use` 若已被 W22T2 导入则不重复追加，保持文件内 `use` 去重。

### Step 4: 单元测试

> **强制要求**:
> - 本步骤必须包含一个或者多个单元测试。
> - 测试函数名称和测试内容必须参考对应设计文档的 **「测试计划」** 一节。
> - 编译检查与Lint检查不等同于单元测试。
> - 如果测试没有通过需要修复直至测试通过。
> - **无测试 = 任务未完成。**

```rust
#[cfg(test)]
mod tests {
    use super::*;
    use crate::tensor::Tensor;

    #[test]
    fn test_ones_values() {
        let tensor = Tensor::<bool, _>::ones([2, 2]).unwrap();
        assert_eq!(tensor.len(), 4);
        assert!(tensor.iter().all(|value| *value));
    }

    #[test]
    fn test_ones_zero_dim() {
        // Zero-dimensional tensor: shape = [], product = 1, len() == 1.
        // (Per 18-construction §8.3: `from_scalar(42)` / `ones([])` both yield
        // ndim=0 tensors of length 1; this is distinct from `ones([0])`.)
        let tensor = Tensor::<i32, _>::ones([]).unwrap();
        assert_eq!(tensor.shape(), &[]);
        assert_eq!(tensor.ndim(), 0);
        assert_eq!(tensor.len(), 1);
        assert_eq!(*tensor.get(()).unwrap(), 1);
    }

    #[test]
    fn test_ones_empty() {
        // Zero-length axis produces a valid empty tensor with len() == 0.
        // This is the canonical "empty tensor" case from 18-construction §8.3.
        let tensor = Tensor::<i32, _>::ones([0, 5]).unwrap();
        assert_eq!(tensor.shape(), &[0, 5]);
        assert_eq!(tensor.len(), 0);
    }
}
```

## 关键设计决策

1. 依据 `18-construction §5.1`，`ones` 定义为 `TensorBase<Owned<A>, D>` 的关联函数（`Tensor::<A, D>::ones(shape)`），与 `zeros` 共享 `impl` 块。
2. 依据 `18-construction §8.2` / §8.3，单元测试同时覆盖**两种**容易混淆的边界场景：
   - `test_ones_zero_dim`（shape = `[]`，零维张量，len = 1）—— 对应设计 §8.3 `from_scalar` 行的"ndim() == 0"。
   - `test_ones_empty`（shape = `[0, 5]`，至少一个零长度轴，len = 0）—— 对应设计 §8.3 `zeros([0, 3])` 行的"空张量"。
   这是显式拒绝把"零维"与"空张量"混淆的语义防御。
3. 依据 Wave 22 的依赖层级，本 task 不新增第三方依赖，也不改变前置模块的 public contract。

## 注意事项

- 零长度轴是合法空张量（如 `[0, 5]`，len=0），零维张量长度为 1（shape=`[]`，len=1）。这两个是不同的边界场景，测试必须分别覆盖。
- from_shape_vec 长度不匹配必须返回可恢复错误。
- eye 仅支持 `EyeElement`（i32/i64/f32/f64/Complex<f32>/Complex<f64> 封闭集合），不把 bool 或其它 Numeric 元素纳入单位矩阵 API。
