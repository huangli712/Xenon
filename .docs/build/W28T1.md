## 目标

Add 9 [[bench]] entries, no new benchmark-specific third-party deps。

本任务建立 W28 benchmark 交付物的一部分，覆盖 27-benchmark §5 的 benchmark 结构、§5.5 的清单、§6 的数值与执行约束，以及 §8 的 quick smoke 验证口径。涉及的 benchmark 或检查项为：`math`, `reduction`, `dot`, `set`, `broadcast`, `shape`, `simd_comparison`, `parallel_comparison`, `construction`。

## 前置准备

- 确认 W28 之前的核心 API、错误语义、构造、广播、归约、矩阵、SIMD 或并行相关任务已按前置依赖完成。
- 使用仓库现有依赖，不为 benchmark 引入新的第三方测量框架。
- 仅在目标文件内添加 benchmark、辅助函数或 CI/report 逻辑，避免改变 crate 公共 API。

#### 等效验证条款（仅适用于非 Rust 源码类目标文件）

目标文件 `Cargo.toml` 为非 Rust 源码，按 TEMPLATE.md §82-138 要求以「等效验证脚本」满足验收门禁：脚本任何检查失败必须以非零退出码返回。涵盖三类检查面：（1）语法可解析（Python 3.11+ stdlib `tomllib`，无外部依赖）；（2）与设计文档 27-benchmark §5.5 / §7 的 9 个 bench 入口字段一一对照；（3）工具链可消费配置（`cargo metadata`）。

> 注：原 `cargo verify-project` 已被 cargo 上游标记 DEPRECATED（见 rust-lang/cargo#14679），改用 Python 3.11+ stdlib `tomllib` 做 TOML 语法可解析检查。**本等效验证脚本仅在 task 实施者本地或定向调用时运行**，不接入 W28T12 的 bench.yml CI workflow；因此运行环境的 Python 版本由实施者自行保证。参考环境需 Python ≥ 3.11：**GitHub Actions `ubuntu-latest` 自 2024 年 12 月起 = ubuntu-24.04 = 默认 Python 3.12（够用，无需升级）**；仅当显式指定 `runs-on: ubuntu-22.04`（默认 Python 3.10）时才需升级。升级途径：`pyenv install 3.11` / `actions/setup-python with: python-version: '3.11'` / `apt install python3.11`，或改用其他 TOML 解析器（如 `pip install tomli; python -c "import tomli; tomli.loads(...)"`）。`tomllib` 与 cargo 一样不接受含 UTF-8 BOM 的 `Cargo.toml`（实证：BOM 输入会让 tomllib 抛 `TOMLDecodeError`），与「与工具链可消费配置一致」要求吻合。

```bash
set -euo pipefail

# Test 0: TOML 语法可解析（TEMPLATE.md §82-103 要求的「语法/格式可解析」检查面）
# 使用 Python 3.11+ stdlib tomllib（无外部依赖，替代已 DEPRECATED 的 cargo verify-project）
python3 -c "import tomllib; tomllib.loads(open('Cargo.toml','rb').read().decode())"

# 27-benchmark §8 测试计划要求 benchmark 入口可枚举且数量正确。
# Test 1: 9 个 [[bench]] 条目存在于 Cargo.toml（无 jq 依赖，只用 grep）
test "$(grep -c '^\[\[bench\]\]' Cargo.toml)" = "9"

# Test 2: 九个 bench name 必须全部出现
for name in math reduction dot set broadcast shape simd_comparison parallel_comparison construction; do
    grep -q "name = \"$name\"" Cargo.toml || { echo "missing bench: $name"; exit 1; }
done

# Test 3: 每个 [[bench]] 都用 harness = false（自定义 runner，不引入 Criterion）
test "$(grep -c '^harness = false' Cargo.toml)" = "9"

# Test 4: cargo 视图也确认 9 个 bench target（不依赖 jq，避免 CI 主机假设）
test "$(cargo metadata --format-version=1 --no-deps \
    | grep -o '"kind":\["bench"\]' | wc -l)" = "9"
```

## 关键设计决策

| 决策 | 依据 |
|------|------|
| 使用仓库本地 `harness = false` runner，而非 Criterion 等第三方框架 | 27-benchmark §11 决策 1 要求不引入额外 benchmark 框架 |
| quick 模式保留 filter 与最小输入规模 | 27-benchmark §5.6 和 §8.1 要求 CI smoke 可快速验证 benchmark 入口 |
| benchmark 只记录性能趋势，不定义功能正确性合约 | 27-benchmark §1.1 将功能正确性边界交给 28-tests |
| `Cargo.toml` 中 9 个 `[[bench]]` 入口的列表顺序为：math / reduction / dot / set / broadcast / shape / simd_comparison / parallel_comparison / **construction**（6 个核心模块 / 操作在前 → 2 个对比 bench 居中 → construction 在末尾） | `[[bench]]` 列表顺序在 cargo 编译时无强语义约束，本顺序属于维护方便的列表组织选择；与 27-benchmark §7 task 编号顺序（T3-T11）不严格对齐（按 §7 task 编号顺序 construction（T9）应排在第 7 位、在 simd_comparison/parallel_comparison 之前，但实际 Cargo.toml 中被放在最末第 9 位与对比 bench 相邻）。CI smoke 名单（math/reduction/construction）通过 W28T12 显式列出，不依赖此 [[bench]] 顺序 |

## 验证方式

1. 编译检查: `cargo check --benches`
2. Lint 检查: `cargo clippy --benches -- -D warnings`
3. 测试验证: `cargo metadata --no-deps`
4. 手动验证: 运行对应 bench 的 `--quick` filter，确认输出包含本任务的 benchmark 名称和 median ns 数值。

## 注意事项

- `black_box` 必须包裹被测结果，避免编译器消除热路径。
- benchmark 输入生成应固定、可重复，避免随机噪声污染趋势判断。
- SIMD/并行对比只在对应 feature 组合下解释性能差异，不得改变默认 API 行为。
