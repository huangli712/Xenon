## 目标

实现真正的标量内积，将 W17T2 的 `Ok(A::zero())` 占位替换为 `Ok(scalar_dot(a, b))`。设计 §6.3 / §6.4 要求按元素类型分派：
- **浮点/复数路径**：`acc + x.conjugate() * y`（实数 conjugate 为恒等，复数为共轭线性）
- **整数路径**：`x.checked_mul(y).unwrap_or_else(panic!) + acc.checked_add(...)`

由于 03-element §5.10 的 `CheckedAdd` / `CheckedMul` 仅对 `i32` / `i64` 实现，无法用 `A: Numeric + CheckedMul + CheckedAdd` 统一约束（浮点/复数会编译失败）。本 task 在 `matrix/dot.rs` 内引入 **sealed `DotAccumulate` trait**（`pub` 但通过 `Numeric → Element → Sealed` 链结构化封闭，避免 `private_bounds` lint；详见 Step 1 visibility note），为每个 Numeric 具体类型（`i32` / `i64` / `f32` / `f64` / `Complex<f32>` / `Complex<f64>`）显式实现 `dot_step`，让 `scalar_dot<A: DotAccumulate>` 在单态化后自然走对应分支。

同时落地 `TensorBase::dot` method（12-matrix §5.1 line 164-175）。

## 实施步骤

### Step 1: 引入 `DotAccumulate` sealed trait

在 `src/matrix/dot.rs` 顶部 use 列表之后定义 trait。trait 设为 `pub` 但通过 `Numeric → Element → Sealed` 链结构化封闭（避免 Rust 1.79+ `private_bounds` warn-by-default lint触发；详见下方 visibility note）——下游无法添加新 impl（被 Sealed 链拦截），所有 `Numeric` sealed 类型都将实现它，对用户透明。

```rust
use crate::complex::Complex;
use crate::element::{CheckedAdd, CheckedMul, Numeric};

/// Per-type accumulation step for the scalar dot product.
///
/// Design reference: 12-matrix §6.3 / §6.4. The public `dot()` is
/// generic over `A: Numeric`, but the integer (`CheckedMul + CheckedAdd`)
/// and floating-point / complex (`Add + Mul + conjugate`) accumulation
/// rules are mutually exclusive in trait coverage (03-element §5.10:
/// `CheckedMul` / `CheckedAdd` are sealed to `i32` / `i64`).
///
/// `DotAccumulate` is a `pub` sealed trait implemented for every concrete
/// `Numeric` type. Sealing is inherited transitively: `DotAccumulate:
/// Numeric` and `Numeric: Element` (03-element §5.1.1) and `Element:
/// Sealed` (03-element §5.8). Therefore downstream crates cannot add
/// new `DotAccumulate` impls — even though the trait is `pub`, its
/// implementer set is closed at the `Element` boundary. Each impl encodes
/// the per-type accumulation rule:
///   * integers use checked arithmetic and panic on overflow with the
///     diagnostic format mandated by 12-matrix §6.4;
///   * floats and complex use `acc + x.conjugate() * y` — `conjugate()`
///     is identity for reals (zero overhead) and the conjugate-linear
///     factor for complex (§5.2).
///
/// The bound `A: DotAccumulate` is additive over `Numeric`. Since every
/// concrete `Numeric` type also implements `DotAccumulate`, end users
/// cannot hit an unfulfillable bound.
pub trait DotAccumulate: Numeric + 'static {
    /// Accumulate one element pair `(x, y)` into the running result `acc`.
    ///
    /// `index` is the logical 1-D position of the element pair within
    /// the input vectors; integer impls embed it into panic messages so
    /// failures pinpoint the offending element.
    ///
    /// `len` is the total length of the input vectors (validated equal
    /// for `a` and `b` by `validate_dot_inputs`); integer impls embed
    /// it into panic messages as `shape [{len}]` per 12-matrix §6.4
    /// line 386 (panic must include applicable shape).
    fn dot_step(acc: Self, x: Self, y: Self, index: usize, len: usize) -> Self;
}

// `'static` supertrait: every concrete `Numeric` type (i32 / i64 / f32 /
// f64 / Complex<f32> / Complex<f64>) is already `'static`, so this is
// transparent to users. It is required for W17T5's `TypeId`-based SIMD
// dispatch to compile (`TypeId::of::<A>()` needs `A: 'static`).
//
// Visibility note: `pub` (not `pub(crate)`) because `pub fn dot` carries
// `where A: ... + DotAccumulate`; the `private_bounds` lint (Rust 1.79+,
// warn-by-default) rejects `pub` items whose bounds reference items with
// strictly tighter visibility. Sealing is provided structurally via the
// `Numeric → Element → Sealed` chain, matching the existing pattern used
// by `OrderedCompareElement` (03-element §5.5 line 391).
```

### Step 2: 实现 4 个浮点 / 复数 impl

按设计 §6.3 line 297-311 与 §5.2 line 180-193，浮点 / 复数路径用 `acc + x.conjugate() * y`。复数 `conjugate()` 翻转虚部符号，实现 `conj(a) * b` 共轭线性内积。

```rust
impl DotAccumulate for f32 {
    #[inline]
    fn dot_step(acc: Self, x: Self, y: Self, _index: usize, _len: usize) -> Self {
        // conjugate is identity for reals; the compiler inlines it away.
        // _len/_index unused: float dot never panics on overflow.
        acc + x.conjugate() * y
    }
}

impl DotAccumulate for f64 {
    #[inline]
    fn dot_step(acc: Self, x: Self, y: Self, _index: usize, _len: usize) -> Self {
        acc + x.conjugate() * y
    }
}

impl DotAccumulate for Complex<f32> {
    #[inline]
    fn dot_step(acc: Self, x: Self, y: Self, _index: usize, _len: usize) -> Self {
        // dot(x, y) = sum(conj(x_i) * y_i)  — 12-matrix §5.2.
        acc + x.conjugate() * y
    }
}

impl DotAccumulate for Complex<f64> {
    #[inline]
    fn dot_step(acc: Self, x: Self, y: Self, _index: usize, _len: usize) -> Self {
        acc + x.conjugate() * y
    }
}
```

### Step 3: 实现 2 个整数 impl（checked + panic 字段完整）

按 12-matrix §6.4 line 386 panic 字段必须包含 `operation` / **元素类型** / **阶段（multiply / accumulate）** / **逻辑位置** / **适用 shape**。本 task panic 字符串：
- multiply 阶段：`"dot: integer overflow during multiplication at element {index} of shape [{len}] (type {type})"`
- accumulate 阶段：`"dot: integer overflow during accumulation at element {index} of shape [{len}] (type {type})"`

其中 `{len}` 通过闭包捕获 `a.len()` 或 `b.len()`（两者相等，已由 `validate_dot_inputs` 保证）。

整数路径不使用 `conjugate()`——对 `i32` / `i64` 它是恒等，写出来会绕过 checked 边界。

```rust
impl DotAccumulate for i32 {
    #[inline]
    fn dot_step(acc: Self, x: Self, y: Self, index: usize, len: usize) -> Self {
        // 12-matrix §6.4 mandates checked arithmetic on BOTH multiply
        // and accumulate; conjugate is identity for i32 and is omitted
        // here to keep checked semantics explicit.
        // Panic message includes `shape [{len}]` per §6.4 line 386.
        let product = CheckedMul::checked_mul(x, y).unwrap_or_else(|| {
            panic!(
                "dot: integer overflow during multiplication at element {index} of shape [{len}] (type i32)"
            )
        });
        CheckedAdd::checked_add(acc, product).unwrap_or_else(|| {
            panic!(
                "dot: integer overflow during accumulation at element {index} of shape [{len}] (type i32)"
            )
        })
    }
}

impl DotAccumulate for i64 {
    #[inline]
    fn dot_step(acc: Self, x: Self, y: Self, index: usize, len: usize) -> Self {
        let product = CheckedMul::checked_mul(x, y).unwrap_or_else(|| {
            panic!(
                "dot: integer overflow during multiplication at element {index} of shape [{len}] (type i64)"
            )
        });
        CheckedAdd::checked_add(acc, product).unwrap_or_else(|| {
            panic!(
                "dot: integer overflow during accumulation at element {index} of shape [{len}] (type i64)"
            )
        })
    }
}
```

### Step 4: 引入 `scalar_dot` 标量内积函数

`scalar_dot` 是 dot 内部的标量基线实现，约束在 `A: Numeric + DotAccumulate`。Iter 元素迭代器消费两个输入（与 §6.3 line 287-294 一致），不要求 `D1 == D2`。

```rust
/// Scalar inner product baseline used by every dispatch path.
///
/// Design reference: 12-matrix §6.3 (per-type variants) and §6.4
/// (unified dispatch). Caller guarantees rank-1 / length-equal
/// invariants via `validate_dot_inputs` (W17T2); this function does
/// NOT re-validate.
///
/// `len = a.len()` is computed once and threaded into every
/// `DotAccumulate::dot_step` invocation so integer overflow panics can
/// embed `shape [{len}]` per 12-matrix §6.4 line 386 (panic must
/// include applicable shape).
pub(crate) fn scalar_dot<S1, S2, A, D1, D2>(
    a: &TensorBase<S1, D1>,
    b: &TensorBase<S2, D2>,
) -> A
where
    S1: Storage<Elem = A>,
    S2: Storage<Elem = A>,
    A: Numeric + DotAccumulate,
    D1: Dimension,
    D2: Dimension,
{
    let len = a.len();
    a.iter()
        .copied()
        .zip(b.iter().copied())
        .enumerate()
        .fold(A::zero(), |acc, (index, (x, y))| {
            <A as DotAccumulate>::dot_step(acc, x, y, index, len)
        })
}
```

> `.copied()` 因为 `Numeric: Copy`（03-element §5.2）；`.iter()` 返回 `Iter<&A>`，`.copied()` 转为 `Iter<A>`。

### Step 5: 替换 `dot()` 函数体，并增加 `DotAccumulate` 边界

`pub fn dot` 签名增加 sealed trait 边界 `+ DotAccumulate`。由于 `DotAccumulate` 为 `pub` 但通过 Sealed 链封闭（仅 6 个 Numeric 具体类型可实现），对外效果等同 W17T1 / W17T2 的 `where A: Numeric` 签名。

```rust
pub fn dot<S1, S2, A, D1, D2>(
    a: &TensorBase<S1, D1>,
    b: &TensorBase<S2, D2>,
) -> Result<A, XenonError>
where
    S1: Storage<Elem = A>,
    S2: Storage<Elem = A>,
    A: Numeric + DotAccumulate,
    D1: Dimension,
    D2: Dimension,
{
    validate_dot_inputs(a, b)?;
    Ok(scalar_dot(a, b))
}
```

### Step 6: 添加 `TensorBase::dot` method

按 12-matrix §5.1 line 164-175。方法委托给自由函数，保持单一权威实现。

```rust
impl<S, D, A> TensorBase<S, D>
where
    S: Storage<Elem = A>,
    D: Dimension,
    A: Numeric + DotAccumulate,
{
    /// Stable method-style API; semantically equivalent to
    /// `matrix::dot(self, other)`. See 12-matrix §5.1.
    pub fn dot<S2, D2>(&self, other: &TensorBase<S2, D2>) -> Result<A, XenonError>
    where
        S2: Storage<Elem = A>,
        D2: Dimension,
    {
        crate::matrix::dot(self, other)
    }
}
```

## 关键设计决策

- **`DotAccumulate` 而非 trait specialization**：Rust stable 不支持 specialization，所以无法对 `A: Numeric` 做按类型重载。在 matrix 模块内引入 sealed `DotAccumulate` trait 是 stable-Rust 唯一可行路径，且不需要修改 element 模块（03-element §5.2 / §5.10 保持只读）。
- **`DotAccumulate` 需 `pub` 而非 `pub(crate)`**：`pub fn dot` 携带 `+ DotAccumulate` 边界，Rust 1.79+ 的 `private_bounds` lint（warn-by-default）拒绝 `pub` 项引用严格更窄可见性的 trait。sealing 通过 `DotAccumulate: Numeric` 、`Numeric: Element` (03-element §5.1.1 line 128)、`Element: Sealed` (03-element §5.8) 的传递结构完成——与 `OrderedCompareElement` (03-element §5.5 line 391：`pub trait OrderedCompareElement: Element + PartialOrd + Sealed`) 同模式。
- **`+ DotAccumulate` 边界对用户透明**：由于 `Numeric` 是 sealed trait（仅 6 个具体类型），且 6 个类型在本 task 中都已实现 `DotAccumulate`，外部用户既无法添加新的 `DotAccumulate` impl（被 Sealed 链拦截）也无法构造满足 `Numeric` 但不满足 `DotAccumulate` 的类型。从公开 API 视角看，签名等同于 §5.1 line 151-160 的 `where A: Numeric`。
- **整数 panic 消息格式严格遵守 §6.4 line 386**：包含 `operation="dot"`、元素类型（`i32` / `i64`）、阶段（`multiplication` / `accumulation`）、逻辑位置（`element {index}`）、适用 shape（`of shape [{len}]`）。`len` 通过扩展 `DotAccumulate::dot_step` 签名（追加 `len: usize` 参数）从 `scalar_dot` 闭包捕获，对外不可见。
- **整数路径不使用 `conjugate()`**：对 `i32` / `i64` 它是恒等，写出来反而模糊"两阶段都必须 checked" 的契约（§6.4 line 386 "文档不得只对累加做 checked 处理而把乘法留给 release wrapping 语义"）。
- **`scalar_dot` 设为 `pub(crate)`**：W17T4-T6 的各 ExecPath 分支需要把它作为 fallback baseline 直接调用。

## 注意事项

- `DotAccumulate` 为 `pub` 但通过 `Sealed` 链封闭；该选择是为了避免 Rust 1.79+ 的 `private_bounds` warn-by-default lint。外部 crate 看到 trait 名但不能添加新 impl（被 `Numeric → Element → Sealed` 链拦截），与 `OrderedCompareElement` 模式一致。
- 不要在本 task 引入 `scalar_dot_int` / `scalar_dot_float_or_complex` 两个独立函数——设计 §6.3 把它们作为 pseudo-code 示意，等价的最终实现是通过 `DotAccumulate::dot_step` 的单态化让编译器自动选择路径。这两条路径在生成代码里依然是两套分离的指令序列。
- W17T1 / W17T2 暴露的 `pub fn dot` 签名只允许增加 sealed trait 边界 `+ DotAccumulate`（trait 为 `pub` 但通过 Sealed 链封闭），不允许变更参数列表或返回类型。
- `TensorBase::dot` method 必须委托给自由函数 `crate::matrix::dot`，避免双实现导致语义漂移。
- 不要在本 task 接入 `select_exec_path` 或 SIMD / parallel 分支——这些属于 W17T4-T6 的边界。
