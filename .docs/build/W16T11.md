## 实施步骤

### Step 1: Wire `dispatch::select_exec_path` into the unary math entry

`dispatch::select_exec_path` 的精确签名（30-dispatch.md §5.5 line 436-440）：

```rust
pub(crate) fn select_exec_path(
    len: usize,
    is_contiguous: bool,
    alignment_ok: bool,
) -> (ExecPath, Option<ParallelGuard>);
```

**必须传 3 个参数**。`len` 来自张量元素数（`tensor.len()`，07-tensor §5 line
300）；`is_contiguous` 来自 `tensor.is_f_contiguous()`（07-tensor §5 line
325、09-parallel §6.x line 670）；`alignment_ok` 来自 `tensor.is_aligned()`
（07-tensor §5 line 331、08-simd §5 line 442-446）。**注意**：公开方法名为
`is_f_contiguous` 与 `is_aligned`，**不是** `is_contiguous` 或
`is_aligned_for::<A>()`——后者在 TensorBase 上不存在（早期草稿错误，已更正）。

W14 的 SIMD facade 使用 slice 接口与 `UnaryOp` / `BinaryOp` 枚举（W14T1
line 122-133 + line 141-163、W14T7 line 50-62），调用方必须传入 F-order
连续的 `&[A]` / `&mut [A]` 切片。因此 SIMD 路径仅对**已 F-contiguous** 的
输入启用；非连续输入直接走 `ExecPath::Serial` 或 `ExecPath::Parallel`
（由 `select_exec_path` 根据 `is_contiguous` 标志裁决）。

```rust
use crate::dispatch::{select_exec_path, ExecPath, ParallelGuard};
use crate::dimension::Dimension;
use crate::element::{Element, Numeric};
use crate::math::helpers::apply_unary;   // W16T1 pub(in crate::math)
use crate::storage::Storage;
use crate::tensor::{Tensor, TensorBase};

// W14 / W15 facade modules:
// - `simd::dispatch_vector_unary_op(UnaryOp, src: &[A], dst: &mut [A]) -> bool`
//   (per W14T1 Step 5 line 156-163 / W14T7 line 50)
// - `simd::dispatch_vector_binary_op(BinaryOp, lhs, rhs, dst: &mut [A]) -> bool`
//   (per W14T1 Step 5 line 141-154 / W14T7 line 50)
// - `parallel::par_map` / `parallel::par_zip_map`
//   (per 09-parallel.md §5 line 157 / line 525)
use crate::simd;
use crate::parallel;

/// Dispatch-aware variant of `apply_unary` — routes between Serial,
/// SIMD, and Parallel paths per 11-math §5.2 / §6.3. The scalar
/// baseline `apply_unary` (W16T1 helpers) is the SIMD-fallback target.
///
/// `op_tag: Option<simd::UnaryOp>` encodes which SIMD kernel to attempt:
/// - `Some(UnaryOp::Neg)` → `dispatch_vector_unary_op(Neg, ...)` (only
///   unary op currently in the W14 coverage matrix, per W14T1 Step 4
///   line 129-133).
/// - `None` → SIMD path is unavailable for this op (e.g. `abs` / `sin` /
///   `sqrt` / `exp` / `ln` / `floor` / `ceil` / `signum` / `square` /
///   `conjugate` / `modulus` / `not`; W14T1 line 132 explicitly reserves
///   these for future SIMD coverage). Fall back to `Serial` / `Parallel`
///   without trying SIMD.
fn apply_unary_with_dispatch<A, S, D, F>(
    input: &TensorBase<S, D>,
    op: F,
    op_tag: Option<simd::UnaryOp>,
) -> Tensor<A, D>
where
    A: Element + crate::simd::SimdElement,
    S: Storage<Elem = A>,
    D: Dimension,
    F: Fn(A) -> A + Copy + Send + Sync,
{
    let len = input.len();
    let is_contiguous = input.is_f_contiguous();
    let alignment_ok = input.is_aligned();

    let (path, guard) = select_exec_path(len, is_contiguous, alignment_ok);
    match path {
        ExecPath::Serial => apply_unary(input, op),
        ExecPath::Simd => {
            // W14 facade uses slice-based kernels. SIMD only runs when
            // op_tag is set AND input is F-contiguous (required to view
            // storage as `&[A]`). When admission fails inside W14
            // (return false) OR op_tag is None, fall back to scalar.
            try_simd_unary_via_slice(input, op_tag)
                .unwrap_or_else(|| apply_unary(input, op))
        }
        ExecPath::Parallel => {
            // `guard` is `Some(ParallelGuard)`; pass it by value so RAII
            // clears the IN_PARALLEL TLS flag once when the parallel
            // region exits. Each worker chunk may independently call
            // SIMD via worker-local admission (09-parallel.md §6.3).
            let g = guard.expect("ExecPath::Parallel must carry a ParallelGuard");
            parallel::par_map(input, op, g)
        }
    }
}

/// Helper: attempt a slice-based SIMD unary kernel. Returns `None` if
/// op_tag is None, the kernel returned false, or the input cannot be
/// viewed as `&[A]` (non-contiguous — though the caller already gated
/// on `is_f_contiguous`, kept as defense-in-depth).
fn try_simd_unary_via_slice<A, S, D>(
    input: &TensorBase<S, D>,
    op_tag: Option<simd::UnaryOp>,
) -> Option<Tensor<A, D>>
where
    A: Element + crate::simd::SimdElement,
    S: Storage<Elem = A>,
    D: Dimension,
{
    let tag = op_tag?;
    let src: &[A] = input.as_slice()?; // None if non-contiguous
    let mut result = Tensor::<A, _>::zeros(input.shape().clone());
    let dst: &mut [A] = result.as_slice_mut()?;
    if simd::dispatch_vector_unary_op(tag, src, dst) {
        Some(result)
    } else {
        None
    }
}
```

> **API 名校对（W14 落地版）**：
> - `simd::dispatch_vector_unary_op` / `simd::dispatch_vector_binary_op` 是
>   W14T1 Step 5（line 141、line 156）与 W14T7 line 50 显式列出的 `pub(crate)`
>   facade 名；原草稿里的 `try_unary_kernel` / `try_binary_kernel` 在 W14
>   不存在，本 task 已修正到 W14 真实 facade。
> - `parallel::par_map` / `par_zip_map` 是 W15 / 09-parallel.md §5 line 157 /
>   §6 line 525 的公认入口名。
> - `UnaryOp::Neg` 是 W14 当前唯一覆盖的一元 SIMD 操作（W14T1 Step 4 line
>   129-133 注释 "// Future: Abs, Square"）——其余一元数学方法（abs /
>   signum / square / sin / sqrt / exp / ln / floor / ceil / conjugate /
>   modulus / not）在当前 W14 覆盖矩阵**外**，本 task 对应方法的 `op_tag`
>   传 `None`，直接走 Serial / Parallel 路径。该限制与 11-math §6.3 line
>   579-586 一致——SIMD 覆盖"仅在 08-simd 定义的正式支持子集内尝试"。

### Step 3: Slice-based binary & comparison dispatch (拆分为两条独立路径以消除 unsafe)

W16T11 不止覆盖 unary——还需同时为 W16T6（add/sub/mul/div）、W16T8/T9/T10
（equal/not_equal/less/greater）接入 dispatch。binary 与 comparison 的输出类型
不同：arithmetic 是 homogeneous `A → A`，comparison 是 heterogeneous `A → bool`。
W14 SIMD facade 只提供 homogeneous kernel（`dispatch_vector_binary_op(..., &[A],
&[A], &mut [A]) -> bool`），comparison 永远无法走 SIMD。

**关键设计决策（消除 unsafe）**：将 binary dispatch 拆分为两个独立的 helper，
**arithmetic 专用 helper 不携带输出泛型 `O`**，从根本上消除"`Tensor<A, D>` →
`Tensor<O, D>` 需要 transmute"的类型系统缺口。comparison 专用 helper 的 SIMD
分支直接走标量回退（无 W14 kernel 可用）。原草案的泛型 `apply_binary_with_
dispatch<A, O, ...>` + `unsafe transmute` 路线被废弃。

### Step 4: Shared non-broadcasting traversal helper (apply_binary_scalar)

Step 5 / Step 6 下面两个 dispatch helper 在 `ExecPath::Serial` 与 `ExecPath::Simd` 回退路径都调用 `apply_binary_scalar`。本 step 提供该质 helper 的定义 —— 与 W16T2 的 `apply_binary` 区别：`apply_binary` 含广播解析 (`broadcast_shape` + `broadcast_to`)，而 `apply_binary_scalar` 假定两个输入已同形（在 dispatch helper 中所有输入都在调用前已被 `broadcast_to` 到 `out_shape`），跳过广播重复工作：

```rust
/// Non-broadcasting binary traversal helper. Assumes `a` and `b` have
/// identical shapes (caller is responsible for `broadcast_to` upstream).
/// Used by `apply_arith_with_dispatch` / `apply_compare_with_dispatch`
/// in their Serial and SIMD-fallback paths.
pub(in crate::math) fn apply_binary_scalar<A, O, S1, S2, D, F>(
    a: &TensorBase<S1, D>,
    b: &TensorBase<S2, D>,
    mut op: F,
) -> Tensor<O, D>
where
    A: Element,
    O: Element,
    S1: Storage<Elem = A>,
    S2: Storage<Elem = A>,
    D: Dimension,  // Dimension supertrait 已含 Clone（见 02-dimension L123），无需重复
    F: FnMut(A, A) -> O,
{
    // Both inputs already share `a.shape()` per caller contract.
    let mut result = Tensor::<O, D>::zeros(a.shape().clone());
    for ((dst, &a_val), &b_val) in result.iter_mut().zip(a.iter()).zip(b.iter()) {
        *dst = op(a_val, b_val);
    }
    result
}
```

**为何需要单独定义**：W16T2 `apply_binary` 重复进行广播检查（即使输入已同形也会走一遍 `broadcast_shape` 并设置 BroadcastView flag），在 dispatch helper 的 hot path 上是不必要的费用。`apply_binary_scalar` 采用与 W16T6 `apply_binary_indexed` 同样的全遍历骨架 —— 不传递 idx/shape，专为浮点 / 复数路径服务（该路径不 panic，不需要 element_index）。

### Step 5: Arithmetic dispatch helper (apply_arith_with_dispatch)

```rust
/// Dispatch-aware broadcast arithmetic helper for W16T6 (add/sub/mul/div).
/// Output type equals input type — no `O` generic, no `TypeId` check, no
/// `unsafe transmute`. SIMD path is available when W14 facade covers the op.
pub(in crate::math) fn apply_arith_with_dispatch<A, S1, S2, D1, D2, F>(
    a: &TensorBase<S1, D1>,
    b: &TensorBase<S2, D2>,
    op: F,
    op_tag: Option<simd::BinaryOp>,
) -> Result<Tensor<A, <D1 as BroadcastDim<D2>>::Output>, XenonError>
where
    A: Element + crate::simd::SimdElement + 'static,  // 'static 供函数体内 TypeId 检查
    S1: Storage<Elem = A>,
    S2: Storage<Elem = A>,
    D1: Dimension + BroadcastDim<D2>,
    D2: Dimension,
    F: Fn(A, A) -> A + Copy + Send + Sync,
{
    use core::any::TypeId;

    let out_shape = crate::broadcast::broadcast_shape(a.shape(), b.shape())?;
    let a_view = a.broadcast_to(out_shape.clone())?;
    let b_view = b.broadcast_to(out_shape.clone())?;

    // ⚡ §10 element_index carve-out: 整数类型路径不走本 helper，
    // 而是调用点直接使用 apply_binary_indexed，以保留 (idx, shape) panic 诊断。
    // 本 helper 专为浮点 / 复数路径服务（该路径不 panic，不需 element_index）。
    // 详见 Step 7 retrofit 检查表。
    debug_assert!(
        TypeId::of::<A>() != TypeId::of::<i32>()
        && TypeId::of::<A>() != TypeId::of::<i64>(),
        "apply_arith_with_dispatch must not be called with integer types; \
         use apply_binary_indexed instead per 11-math §10 element_index requirement"
    );

    let len = out_shape.size();
    let both_contiguous = a_view.is_f_contiguous() && b_view.is_f_contiguous();
    let both_aligned = a_view.is_aligned() && b_view.is_aligned();
    let (path, guard) = select_exec_path(len, both_contiguous, both_aligned);

    let result = match path {
        ExecPath::Serial => apply_binary_scalar(&a_view, &b_view, op),
        ExecPath::Simd => {
            try_simd_arith(&a_view, &b_view, op_tag)
                .unwrap_or_else(|| apply_binary_scalar(&a_view, &b_view, op))
        }
        ExecPath::Parallel => {
            let g = guard.expect("ExecPath::Parallel must carry a ParallelGuard");
            parallel::par_zip_map(&a_view, &b_view, op, g)
        }
    };
    Ok(result)
}

/// Homogeneous arithmetic SIMD helper. Output type `A` matches input type,
/// so result construction does NOT require `transmute`. Returns `None` if
/// op_tag is None, W14 kernel returned false, or views are non-contiguous.
fn try_simd_arith<A, S1, S2, D>(
    a: &TensorBase<S1, D>,
    b: &TensorBase<S2, D>,
    op_tag: Option<simd::BinaryOp>,
) -> Option<Tensor<A, D>>
where
    A: Element + crate::simd::SimdElement,
    S1: Storage<Elem = A>,
    S2: Storage<Elem = A>,
    D: Dimension,
{
    let tag = op_tag?;
    let lhs_slice: &[A] = a.as_slice()?;
    let rhs_slice: &[A] = b.as_slice()?;
    let mut result = Tensor::<A, _>::zeros(a.shape().clone());
    let dst: &mut [A] = result.as_slice_mut()?;
    if simd::dispatch_vector_binary_op(tag, lhs_slice, rhs_slice, dst) {
        Some(result)
    } else {
        None
    }
}
```

### Step 6: Comparison dispatch helper (apply_compare_with_dispatch)

```rust
/// Dispatch-aware broadcast comparison helper for W16T8/T9/T10
/// (equal/not_equal/less/greater/…). Output is always `bool`. W14 does not
/// expose comparison SIMD kernels yet (W14T1 Step 4 only lists Add/Sub/Mul/
/// Div in `BinaryOp`), so `ExecPath::Simd` falls through to the scalar
/// loop unconditionally. Parallel path is available via `par_zip_map`.
pub(in crate::math) fn apply_compare_with_dispatch<A, S1, S2, D1, D2, F>(
    a: &TensorBase<S1, D1>,
    b: &TensorBase<S2, D2>,
    op: F,
) -> Result<Tensor<bool, <D1 as BroadcastDim<D2>>::Output>, XenonError>
where
    A: Element,
    S1: Storage<Elem = A>,
    S2: Storage<Elem = A>,
    D1: Dimension + BroadcastDim<D2>,
    D2: Dimension,
    F: Fn(A, A) -> bool + Copy + Send + Sync,
{
    let out_shape = crate::broadcast::broadcast_shape(a.shape(), b.shape())?;
    let a_view = a.broadcast_to(out_shape.clone())?;
    let b_view = b.broadcast_to(out_shape.clone())?;

    let len = out_shape.size();
    let both_contiguous = a_view.is_f_contiguous() && b_view.is_f_contiguous();
    let both_aligned = a_view.is_aligned() && b_view.is_aligned();
    let (path, guard) = select_exec_path(len, both_contiguous, both_aligned);

    let result = match path {
        // SIMD path has no comparison kernel in W14; scalar fallback covers it.
        ExecPath::Serial | ExecPath::Simd => apply_binary_scalar(&a_view, &b_view, op),
        ExecPath::Parallel => {
            let g = guard.expect("ExecPath::Parallel must carry a ParallelGuard");
            parallel::par_zip_map(&a_view, &b_view, op, g)
        }
    };
    Ok(result)
}
```

`apply_binary_scalar` 是 `apply_binary`（W16T2）去掉广播解析后的纯遍历
（视图已经在上文构造）。两条 helper 在 `src/math/binary.rs` 内并列定义；
arithmetic 签名保留 `A: SimdElement` 约束，comparison 签名移除该约束以支持
`bool` / `Complex` 等非 SIMD 元素类型的比较。

> **彻底消除 unsafe**：原草案的 `apply_binary_with_dispatch<A, O, ...>` +
> `try_simd_binary_homogeneous<A, O, ...>` + `unsafe { transmute::<Tensor<A,
> D>, Tensor<O, D>>(result) }` 路径被**本 Step 废弃**。拆分为两条类型单一的
> helper 后，arithmetic 的 `O` 永远等于 `A`（类型系统自动成立），comparison
> 的 `O` 永远等于 `bool`（类型系统固定）；两条路径都无需跨类型断言。W16T11
> 实施方案**不再包含任何 `unsafe` 代码**。

### Step 7: Binary entry retrofit checklist (W16T6 / W16T8-T10 方法体迁移)

Step 5 / Step 6 定义了 `apply_arith_with_dispatch` 与 `apply_compare_with_dispatch` 两个 helper。本节明确列出 **哪些 W16T6 / W16T8-T10 方法体应在 W16T11 中被 retrofit**，以与 11-math §5.9 line 504 契约对齐。

**重要架构处理**：11-math §10 line 785 明文要求 panic 信息 “至少包含 `operation`、`type`、`trigger`、`element_index`，并在适用时附带 `shape`” —— `element_index` 是**必需字段**，只有 `shape` 是适用时附带。而 SIMD/Parallel 路径上 `element_index` 概念不明确（并行 worker 内），与 dispatch 架构存在本质冲突。**解决方案**：整数路径（i32 / i64）**保留** `apply_binary_indexed`（不走 dispatch）以保留 `element_index` 诊断；浮点 / 复数路径走 `apply_arith_with_dispatch`（获得 SIMD + parallel 加速）。类型分类在 `apply_arith_with_dispatch` helper 内部通过 `TypeId` 运行期检查实现 —— 调用点上不需区分类型。

**法理依据**：08-simd §5.7 已明确 “整数 sum / dot 无 widening 验证路径时调用方在 dispatch 之前自行选 Serial”，本架构是该原则在 `apply_arith_with_dispatch` 中的一般化：i32 / i64 的整数算术必须保持标量，以同时满足 §10 诊断要求与 §5.7 SIMD admission 要求。

**与 Step 5 `apply_arith_with_dispatch` 定义的关系**：Step 5 中的定义已直接包含为本 carve-out 服务的两项设计要素，**本处仅作事后索引**、不需重复修订：

1. **trait bound 含 `'static`**（Step 5 代码定义处）：`A: Element + crate::simd::SimdElement + 'static`。`'static` 用于函数体内 `TypeId::of::<A>()` 类型检查（防止调用点误将整数类型传入本 helper）。

2. **函数体顶部含 `debug_assert!`**（Step 5 代码定义处，位于 broadcast_to 之后、select_exec_path 之前）：

   ```rust
   debug_assert!(
       TypeId::of::<A>() != TypeId::of::<i32>()
       && TypeId::of::<A>() != TypeId::of::<i64>(),
       "apply_arith_with_dispatch must not be called with integer types; \
        use apply_binary_indexed instead per 11-math §10 element_index requirement"
   );
   ```

**为何在 Step 5 而非 Step 7 落地**：`'static` 与 `debug_assert!` 是 `apply_arith_with_dispatch` 函数本身内部的防护，逻辑上属于 helper 定义本身（Step 5）而非调用点迁移 checklist（本 Step 7）。代码定义集中于单一位置避免裂变。

**Arithmetic 调用点（`src/math/binary.rs`）**— 按类型类别分两套表：

**浮点 / 复数类型（f32 / f64 / Complex<f32> / Complex<f64>）— 走 dispatch**：

| W16T6 source | 方法名 | 原始主体（所有类型同一实现）| retrofit 后主体（float / complex 专用分支）| `op_tag` |
|---|---|---|---|---|
| W16T6 Step 3 | `add` (tensor-tensor) | `apply_binary_indexed(self, other, |x, y, idx, shape| <A as BinaryArith>::add_step(x, y, idx, shape))` | `apply_arith_with_dispatch(self, other, |x, y| x + y, Some(simd::BinaryOp::Add))` ⚡仅在 A 为浮点/复数时调用 | `Some(Add)` |
| W16T6 Step 3 | `sub` (tensor-tensor) | 同上，`sub_step` | `apply_arith_with_dispatch(self, other, |x, y| x - y, Some(simd::BinaryOp::Sub))` ⚡同上 | `Some(Sub)` |
| W16T6 Step 3 | `mul` (tensor-tensor) | 同上，`mul_step` | `apply_arith_with_dispatch(self, other, |x, y| x * y, Some(simd::BinaryOp::Mul))` ⚡同上 | `Some(Mul)` |
| W16T6 Step 3 | `div` (tensor-tensor) | 同上，`div_step` | `apply_arith_with_dispatch(self, other, |x, y| x / y, Some(simd::BinaryOp::Div))` ⚡同上 | `Some(Div)` |
| W16T6 Step 4 | `add_scalar` / `sub_scalar` / `mul_scalar` / `div_scalar` | `self.{add,sub,mul,div}(&other).unwrap()`（委托给 tensor-tensor）| **保持不变** —— 自动继承 tensor-tensor 已 retrofit 后的 dispatch 能力 | 继承 |
| **W16T6 Step 5** | **`sub_from_scalar`** (左标量) | `apply_binary_indexed(&other, self, |x, y, idx, shape| <A as BinaryArith>::sub_step(x, y, idx, shape))` | **必须 retrofit**：`apply_arith_with_dispatch(&other, self, |x, y| x - y, Some(simd::BinaryOp::Sub))` ⚡仅在 A 为浮点/复数时调用 | `Some(Sub)` |
| **W16T6 Step 5** | **`div_from_scalar`** (左标量) | 同上，`div_step` | `apply_arith_with_dispatch(&other, self, |x, y| x / y, Some(simd::BinaryOp::Div))` ⚡同上 | `Some(Div)` |

**整数类型（i32 / i64）— 保留原始标量路径**：

| W16T6 source | 方法名 | 修订后主体（与原一致保留）| 说明 |
|---|---|---|---|
| W16T6 Step 3 | `add` / `sub` / `mul` / `div` (i32/i64) | `apply_binary_indexed(self, other, |x, y, idx, shape| <A as BinaryArith>::add_step(x, y, idx, shape))` 等 | **保持 W16T6 原实现不变** —— 保留 (idx, shape) 以满足 §10 line 785 `element_index` 必须字段 |
| W16T6 Step 4 | `add_scalar` / `sub_scalar` / `mul_scalar` / `div_scalar` (i32/i64) | `self.{add,sub,mul,div}(&other).unwrap()` | **保持不变** —— 委托给整数 tensor-tensor 路径同样保留诊断 |
| W16T6 Step 5 | `sub_from_scalar` / `div_from_scalar` (i32/i64) | `apply_binary_indexed(&other, self, |x, y, idx, shape| <A as BinaryArith>::sub_step(x, y, idx, shape))` | **保持不变** —— 与同类型的 sub_scalar 使用同一骨架（都不走 dispatch），满足 §5.9 line 504 “完全相同的执行骨架”契约 |

**方法体中的类型分发模式**：每个 tensor-tensor 方法体（如 `add`）需要在调用两个 helper 之前做一次类型检查。

> ⚡ **可见性注意**：`BinaryArith` 是 `src/math/binary.rs` 内部的 **private trait**（W16T6.md L73 `trait BinaryArith: Numeric + 'static`无 `pub`）。Rust `private_in_public` lint 拒绝 `pub fn` 在其**自己的 where clause**引用 private trait。本 task 下面的示例采用 W16T6 已有的布局——`A: BinaryArith` 保留在 **impl block** 的 where clause（W16T6.md L242 `impl<S, D, A> TensorBase<S, D> where ... A: BinaryArith`），**方法自身的 where clause 仅补上 `A: crate::simd::SimdElement`**。以下示例在 `where` 同一行同时列出 `BinaryArith + SimdElement` 仅为读者集中阅读便利，**实际实现时 `A: BinaryArith` 不能从 impl block 移动到 method-level where**。

```rust
// impl block (W16T6 L240-243 原状保留):
//   impl<S, D, A> TensorBase<S, D>
//   where
//       S: Storage<Elem = A>,
//       D: Dimension,
//       A: BinaryArith,  // ⚠ 保留在 impl block，不要下移到 method
//   {

pub fn add<S2, DB>(
    &self,
    other: &TensorBase<S2, DB>,
) -> Result<Tensor<A, <D as BroadcastDim<DB>>::Output>, XenonError>
where
    // ⚡ 仅在 method-level where 补上 SimdElement；BinaryArith 保留在 impl block
    A: crate::simd::SimdElement,
    /* ... 其他 W16T6 原有的 method bounds: S2/D/DB ... */
{
    use core::any::TypeId;
    // §10 element_index carve-out：整数类型保持标量以保留诊断
    if TypeId::of::<A>() == TypeId::of::<i32>() || TypeId::of::<A>() == TypeId::of::<i64>() {
        apply_binary_indexed(self, other, |x, y, idx, shape|
            <A as BinaryArith>::add_step(x, y, idx, shape))
    } else {
        // 浮点/复数路径：SIMD + parallel 加速
        apply_arith_with_dispatch(self, other, |x, y| x + y, Some(simd::BinaryOp::Add))
    }
}
```

**关于 `sub_from_scalar` / `div_from_scalar` 的补充说明**：

11-math §5.9 line 504-507 明确要求这两个方法 “**必须**复用与 `sub_scalar` / `div_scalar` 完全相同的执行骨架”。本修订下：
- 浮点 / 复数类型下，`sub_scalar` 与 `sub_from_scalar` 都走 `apply_arith_with_dispatch` ✅
- 整数类型下，`sub_scalar` 与 `sub_from_scalar` 都走 `apply_binary_indexed` ✅
- 两个方法在同类型下使用同一路径 → 满足 §5.9 契约

**Comparison 调用点（`src/math/comparison.rs`）**：

Comparison 输出类型是 bool，bool 不补与 SIMD admission 冲突，不需要§10 element_index carve-out。所有类型走同一路径：

| W16T8/T9/T10 source | 方法名 | 原始主体 | retrofit 后主体 | 备注 |
|---|---|---|---|---|
| W16T8 | `equal` / `not_equal` (tensor-tensor) | `apply_compare(self, other, |a, b| a == b)` | `apply_compare_with_dispatch(self, other, |a, b| a == b)` | SIMD 总是回退（W14 无 comparison kernel）|
| W16T9 | `less` / `less_equal` | 同上 | 同上 | 同上 |
| W16T10 | `greater` / `greater_equal` | 同上 | 同上 | 同上 |
| W16T8/T9/T10 | `*_scalar` | `self.equal(&other).unwrap()` 等（委托给 tensor-tensor）| **保持不变** —— 自动继承 dispatch 能力 | 继承 |

**为何需要本节**：Step 5 / Step 6 只描述了 helper 的定义，如果缺少本调用点清单 与 §10 carve-out 安排，实施者会误用 `apply_arith_with_dispatch` 于整数类型 → 丢失 `element_index` 诊断 → 违反 §10 line 785 必须字段要求。`apply_arith_with_dispatch` 内部的 `debug_assert!` 提供开发期可见性，本清单提供设计期契约。

### Step 8: Pass `ParallelGuard` by value to the parallel backend

`ParallelGuard` 是 `!Send + !Sync`，其 `Drop` 清理调用线程的 `IN_PARALLEL`
TLS flag（09-parallel.md line 238、§5.2 line 235）。本 task 必须遵守：

1. `guard: ParallelGuard` 由 `select_exec_path` 返回，**仅当**
   `path == ExecPath::Parallel` 时为 `Some`；否则为 `None`。
2. `guard` 按值（move）传递给 `parallel::par_map` / `par_zip_map`；这两个
   入口持有 guard 至并行区段结束，不允许将 guard 移入 rayon 闭包。
3. RAII 自动释放，无需手动 `drop(guard)`。

### Step 9: Fall back to scalar loops on SIMD admission failure or coverage miss

W14 SIMD facade (`simd::dispatch_vector_unary_op` / `simd::dispatch_vector_
binary_op`) 的返回类型是 `bool`（W14T1 Step 5 line 141-163 / W14T7 line 50）：

- `true`：SIMD admission 通过且 (op, type) 在覆盖矩阵内 → `dst` 已被原地
  填充；调用方取结果返回。
- `false`：admission 失败（连续 / 对齐 / 长度阈值）或 (op, type) 未覆盖 →
  `dst` 内容未定义，**必须**回退到 `apply_unary` / `apply_binary_scalar`
  的标量循环（在标量 baseline 中重新分配并填充 `result`）。

本 task 的 `try_simd_unary_via_slice` / `try_simd_arith` helper 将 `bool`
facade 返回值封装为 `Option<Tensor<...>>`：`true` → `Some(result)`，
`false` → `None`——调用方通过 `.unwrap_or_else(|| 标量回退)` 统一处理。
Comparison 路径（`apply_compare_with_dispatch`）**没有** SIMD helper：W14 的
`BinaryOp` 不含比较变体，该路径的 `ExecPath::Simd` 直接落到标量分支。

并行路径中，每个 worker chunk 独立做 SIMD admission（11-math §6.3 line
574-577）。chunk 内 admission 失败时该 chunk 走标量；chunk 间合并顺序由
`par_map` / `par_zip_map` 的固定 chunking 控制，与单线程 SIMD admission
**同源**。

### Step 10: `not` bool tensor 的 dispatch wiring 说明

11-math §6.3 line 586 把 "逻辑 (`not`)" 列入 SIMD / 并行覆盖矩阵，但 W14
当前的 `UnaryOp` 只包含 `Neg`（W14T1 Step 4 line 129-133 注释 "// Future:
Abs, Square" 同样暗示 bool `not` 未落地）；同时 `bool` 是否 impl
`SimdElement` 取决于 W14——若未 impl，bool 路径在编译期就无法进入
`apply_unary_with_dispatch`（该 helper 的 where 子句含 `A: SimdElement`）。

因此本 task 中 `Tensor<bool, D>::not()` 的 dispatch wiring **不复用**
`apply_unary_with_dispatch`，而是直接内联一个与 `apply_compare_with_dispatch`
同构的精简模板——`ExecPath::Simd` 分支直接落到标量、Parallel 分支走
`par_map`：

```rust
impl<S, D> TensorBase<S, D>
where
    S: Storage<Elem = bool>,
    D: Dimension,
{
    pub fn not(&self) -> Tensor<bool, D> {
        let len = self.len();
        let is_contiguous = self.is_f_contiguous();
        let alignment_ok = self.is_aligned();
        let (path, guard) = select_exec_path(len, is_contiguous, alignment_ok);
        match path {
            // No bool SIMD kernel in W14; Serial and Simd both fall through
            // to the scalar helper from `math::helpers::apply_unary`.
            ExecPath::Serial | ExecPath::Simd => apply_unary(self, |x| !x),
            ExecPath::Parallel => {
                let g = guard.expect("ExecPath::Parallel must carry a ParallelGuard");
                parallel::par_map(self, |x| !x, g)
            }
        }
    }
}
```

未来 W14 扩展 `UnaryOp` 覆盖 `BoolNot`（或等价 token）并让 `bool` impl
`SimdElement` 后，本 task 的 `not()` 方法可切回 `apply_unary_with_dispatch`
路线，签名与行为保持不变。

### Step 11: 单元测试

添加覆盖设计文档测试计划的单元测试，至少包含正常路径和一个边界或回退场景。

```rust
#[cfg(test)]
mod tests {
    use super::*;
    use crate::Tensor;
    use crate::dimension::Ix1;

    /// Validates that the SIMD-on path produces results identical
    /// (within tolerance) to the SIMD-off baseline. Runs only when
    /// the `simd` feature is enabled; on default builds the feature
    /// is off and this test is excluded from the test set.
    ///
    /// The test does not call SIMD kernels directly. Instead it
    /// compares the public `add` method (which goes through
    /// `apply_binary_with_dispatch`) against a precomputed scalar
    /// reference vector, ensuring the dispatch wiring routes through
    /// the SIMD path without breaking semantics.
    #[cfg(feature = "simd")]
    #[test]
    fn test_add_simd_vs_scalar() {
        let a = Tensor::<f64, Ix1>::from_shape_vec(
            [256], (0..256).map(|x| x as f64).collect(),
        ).unwrap();
        let b = Tensor::<f64, Ix1>::from_shape_vec(
            [256], (0..256).map(|x| (x * 2) as f64).collect(),
        ).unwrap();
        let expected: Vec<f64> = (0..256).map(|x| 3.0 * x as f64).collect();
        let result = a.add(&b).unwrap();
        for i in 0..256 {
            assert!(
                (result[[i]] - expected[i]).abs() < 1e-10,
                "SIMD path mismatch at index {}: got {} expected {}",
                i, result[[i]], expected[i]
            );
        }
    }

    /// Cross-path consistency: SIMD-off (default) and SIMD-on builds
    /// must produce the same byte-level result for integer ops, per
    /// 11-math §10 line 787 ("路径一致性").
    #[test]
    fn test_add_path_consistency_i32() {
        // i32 add is exact (no float tolerance), so byte-level equality
        // is required across Serial / SIMD / Parallel paths.
        let a = Tensor::<i32, Ix1>::from_shape_vec(
            [64], (0..64).collect(),
        ).unwrap();
        let b = Tensor::<i32, Ix1>::from_shape_vec(
            [64], (0..64).map(|x| x * 3).collect(),
        ).unwrap();
        let r = a.add(&b).unwrap();
        for i in 0..64 {
            assert_eq!(r[[i]], i as i32 + i as i32 * 3);
        }
    }
}
```

## 注意事项

- Math methods define user-visible semantics; acceleration backends cannot change shape, errors, NaN behavior, or panic boundaries.
- Broadcast incompatibility is recoverable, while integer overflow and division by zero are panic paths.
- Do not expose generic map helpers as public API in this wave.
- 所有代码注释和 Rust 标识符使用英文，文档说明保持当前实施方案风格。
- 不添加新的第三方依赖，除非设计文档已在 Cargo feature 中声明。
