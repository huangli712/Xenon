## 实施步骤

### Step 1: 提取设计约束

从 29-documentation §5.8、§5.4.2 和 §5.6 提取本任务必须体现的 README 结构、示例协同审查和示例验证规则。

### Step 2: 写入 README 六段 Markdown 骨架

按 29-documentation §5.8 (line 555-585) 的 README 模板，在 `README.md` 写入以下六段结构（H1 项目名 + 引言句 + 5 个 H2 小节）。所有 Markdown 内容使用英文，不引入未实现功能或平台承诺。

```markdown
# Xenon

Rust N-dimensional tensor library for scientific computing.

## Features

- N-dimensional arrays with static (0-6D) and dynamic dimensions (`IxDyn` for runtime-rank tensors)
- Column-major (F-order) default, with helper APIs and compatibility checks for upstream BLAS/LAPACK integration when the layout preconditions are satisfied
- Custom FFI-friendly complex number type
- Optional SIMD (pulp) and parallel (rayon) acceleration

## Quick Start

```rust
use xenon::prelude::*;

fn main() -> xenon::Result<()> {
    let a = Tensor::<f64, _>::ones([2, 3])?;
    let b = Tensor::<f64, _>::ones([2, 3])?;
    let c = (&a + &b)?;
    assert_eq!(c.shape(), &[2, 3]);
    assert_eq!(c.sum(), 12.0);
    Ok(())
}
```

## Installation

```toml
[dependencies]
xenon = "x.y.z"
```

## Documentation

Full API documentation is published on [docs.rs](https://docs.rs/xenon).

## License

MIT
```

Quick Start 代码片段必须与 crate lib.rs doctest 同源（同形状、同算子、同断言），保持 README ↔ crate doc 的一致性。

### Step 3: 协同审查示例代码

按 29-documentation §5.4.2 检查示例：索引用 fallible API，构造错误语义正确，运算符示例体现 `Result`，feature 描述不使用 nightly-only `doc_cfg`。

### Step 4: 检查链接与 Markdown 格式

验证 README 内部链接（`docs.rs` URL）可达；Markdown 可被标准解析器读取。不在 README 引入未实现的本地 doc 链接。

### Step 5: 单元测试

> **强制要求**: README.md 是非 Rust 文件，按 TEMPLATE.md L79-99 等效验证条款，必须提供可执行、失败时非零退出的验证脚本。

**Markdown 等效验证脚本**：
```bash
#!/bin/bash
set -euo pipefail

# 检查面 1: 语法可解析（Markdown 作为 UTF-8 文本可被 Python markdown 解析器读取）
python3 - <<'PY'
from pathlib import Path
import sys
text = Path('README.md').read_text(encoding='utf-8')
assert text.strip(), 'README.md is empty'
try:
    import markdown  # type: ignore
    markdown.markdown(text)
except ImportError:
    pass  # markdown 未安装时跳过该检查
print('OK: markdown parses')
PY

# 检查面 2: 与 §5.8 设计文档字段一一对照
grep -q '^# Xenon$' README.md || { echo 'Missing H1 # Xenon'; exit 1; }
grep -q '^## Features$' README.md || { echo 'Missing ## Features'; exit 1; }
grep -q '^## Quick Start$' README.md || { echo 'Missing ## Quick Start'; exit 1; }
grep -q '^## Installation$' README.md || { echo 'Missing ## Installation'; exit 1; }
grep -q '^## Documentation$' README.md || { echo 'Missing ## Documentation'; exit 1; }
grep -q '^## License$' README.md || { echo 'Missing ## License'; exit 1; }

# 检查面 3: Quick Start 代码片段必须带 ? 传播与 assert_eq!（与 crate doctest 同源）
awk '/^## Quick Start$/,/^## Installation$/' README.md | grep -q '?;' \
    || { echo 'Quick Start missing ? propagation'; exit 1; }
awk '/^## Quick Start$/,/^## Installation$/' README.md | grep -q 'assert_eq!' \
    || { echo 'Quick Start missing assert_eq!'; exit 1; }

# 检查面 3 (续): docs.rs 链接可解析
grep -q 'docs\.rs/xenon' README.md || { echo 'Missing docs.rs link'; exit 1; }

echo 'OK: README.md verified'
```

验收点：README 包含 Features/Quick Start/Installation/Documentation/License 章节；Quick Start 示例包含 `assert_eq!`；代码片段与 crate doctest 同源。

## 关键设计决策

- 文档内容跟随源码签名和设计文档，不通过文档引入新 API 或新依赖。
- 所有 Rust doc comment、README 和 examples 使用英文，实施方案说明保持中文以匹配现有 build 文档。
- 示例优先写成可运行 doctest 或 `main() -> xenon::Result<()>`，并使用 `?` 与断言满足 29-documentation §5.6。

## 验证方式

1. 结构检查: 运行上述等效验证脚本，锁定六段 H1/H2 骨架与 Quick Start 内容
2. 代码同源: 脸贴或脚本比对 README Quick Start 与 `src/lib.rs` 顶层 doctest 的形状、算子、断言是否一致
3. 手动验证: 打开 README.md 预览，确认章节非空、`docs.rs` 链接可点击、安装示例与 Cargo.toml `package.name` 一致

## 注意事项

- README 为 Markdown 产物，验证不依赖 `cargo check`/`cargo doc`/`cargo test`；doctest 覆盖由 W30T1 (`src/lib.rs`) 负责。
- 不要展示方括号索引语法 `t[[i, j]]`；如需展示索引必须用 `try_at` / `get(&[...])`。
- 不要在 README 引入未实现的依赖、教程站点、notebook 或自定义 rustdoc 主题。
- Quick Start 示例必须与 crate 顶层 doctest 同源，避免两者漂移。
