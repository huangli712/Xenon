## 实施步骤

### Step 1: Strengthen ArcRepr Send/Sync safety comments

Keep both impls gated by `A: Send + Sync`, matching `Arc<T>` sharing requirements and `25-safety §5.1`.

```rust
// SAFETY: `ArcRepr<A>` shares storage through atomic reference counting.
// Moving the handle across threads is sound when `A` can be sent and shared
// across threads, matching `Arc<[A]>` requirements.
unsafe impl<A: Send + Sync> Send for ArcRepr<A> {}

// SAFETY: `&ArcRepr<A>` may be accessed concurrently and exposes shared reads
// of `A`. Concurrent shared reads are sound when `A: Sync`, and cloned handles
// may move between threads when `A: Send`.
unsafe impl<A: Send + Sync> Sync for ArcRepr<A> {}
```

### Step 2: Add concurrent read tests

Assert Send + Sync and spawn multiple readers over cloned shared tensors to verify concurrent read semantics.

```rust
#[test]
fn test_arc_send_sync() {
    fn assert_send_sync<T: Send + Sync>() {}
    assert_send_sync::<ArcRepr<f64>>();
}

#[test]
fn test_arc_concurrent_read() {
    let tensor = Tensor1::from_shape_vec([3], vec![1_i32, 2, 3]).unwrap().into_shared();
    let left = tensor.clone();
    let right = tensor.clone();
    let a = std::thread::spawn(move || left.iter().copied().sum::<i32>());
    let b = std::thread::spawn(move || right.iter().copied().sum::<i32>());
    assert_eq!(a.join().unwrap(), 6);
    assert_eq!(b.join().unwrap(), 6);
}
```

## 关键设计决策

| 决策 | 依据 |
|------|------|
| Send/Sync 均要求 `A: Send + Sync` | `25-safety §5.1` 与 §11 决策 3 要求 ArcRepr 继承 `Arc<[A]>` 的线程安全约束。多个线程可同时持有 `&A`，因此 A 必须可安全共享 |
| 并发测试仅验证只读访问 | `25-safety §5.8` 明确共享可写路径仅在内部唯一化后恢复，不构成公开的共享可写存储模式。测试不应新增共享可写 API |
| Arc 原子计数的生命周期保证 | 克隆 ArcRepr 句柄通过原子计数确保底层分配在最后一个句柄丢弃前保持有效，与 `std::sync::Arc` 语义一致 |

## 验证方式

1. 编译检查: `cargo check`
2. Lint 检查: `cargo clippy --all-targets`
3. 测试验证: `cargo test test_arc_send_sync test_arc_concurrent_read`
4. 手动验证: 检查 ArcRepr 写路径仍只在唯一化或复制后恢复可写性。

## 注意事项

- 不要把 ArcRepr 的 bound 降为仅 `A: Send`。
- 并发测试只验证读取；不要新增共享可写 API。
- Arc 原子计数保证句柄生命周期，不保证非 Sync 元素可共享。
