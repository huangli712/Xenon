## 目标

将 W5T1 写入的最小 `ComplexFloat` sealed bound 扩展为 `docs/design/04-complex.md §5.2` 描述的完整 supertrait 集合：

```
Sealed + Copy + Default + Debug + PartialEq + PartialOrd
       + Add + Sub + Mul + Div + Neg
```

W5T5、W5T6、W5T7、W5T8、W5T10、W5T12 都隐式依赖本 task —— 它们的算术、相等、Display 等 impl 都直接使用上述 supertrait。本 task 同时通过 `compile_fail` doctest 在编译期验证 sealed 边界（`Complex<i32>` 必须编译失败）。

按照 `build/SUMMARY.md` 中 W5T2 的定义，在 `src/complex/mod.rs` 中完成此 task 的最小实现，并保持与 `docs/design/04-complex.md` §5（公共 API）、§6（实现细节）、§7（任务拆分）和 §8（测试计划）一致。

## 实施步骤

### Step 1: Extend ComplexFloat supertraits

替换 W5T1 写入的最小 `ComplexFloat` 声明为 `04-complex §5.2` 中的完整声明。trait body 仍然为空 —— 它是纯 sealing 机制，不携带任何方法。

```rust
use core::fmt::Debug;

/// Public bound for `Complex<T>` — sealed to `f32` and `f64`.
///
/// The supertrait set captures every algebraic / ordering capability used by
/// the complex arithmetic and Display impls (W5T5+/W5T7+). `f32` and `f64`
/// from the standard library naturally satisfy every supertrait listed below.
///
/// # Sealed boundary
///
/// Downstream crates cannot implement `ComplexFloat` because of the
/// `Sealed` supertrait. The following doctest verifies that non-supported
/// types are rejected at compile time:
///
/// ```compile_fail
/// use xenon::complex::Complex;
/// // i32 does not implement ComplexFloat (Sealed); this declaration must
/// // fail at compile time.
/// let _: Complex<i32>;
/// ```
pub trait ComplexFloat:
    crate::private::Sealed
    + Copy
    + Default
    + Debug
    + PartialEq
    + PartialOrd
    + core::ops::Add<Output = Self>
    + core::ops::Sub<Output = Self>
    + core::ops::Mul<Output = Self>
    + core::ops::Div<Output = Self>
    + core::ops::Neg<Output = Self>
{}

// `impl ComplexFloat for f32 {}` and `impl ComplexFloat for f64 {}` were
// written by W5T1; both continue to satisfy the extended supertrait set.
// Do NOT add or duplicate the impls here.
```

> 注意：本 task 仅修改 `pub trait ComplexFloat: ... {}` 这一行的 supertrait 列表，**不要**重复写入 `impl ComplexFloat for {f32, f64} {}`（W5T1 已写入）；也**不要**修改或删除 W5T1 的 `Complex<T>` 结构体定义。

### Step 2: 单元测试

> **强制要求**:
> - 本步骤必须包含一个或者多个单元测试。
> - 测试函数名称和测试内容必须参考对应设计文档的 **「测试计划」** 一节。
> - 编译检查与Lint检查不等同于单元测试。
> - 如果测试没有通过需要修复直至测试通过。
> - **无测试 = 任务未完成。**

参考 `docs/design/04-complex.md` §8.7 类型边界 / 编译期测试。Positive case 写为常规单元测试；sealed 边界由 Step 1 中嵌入的 `compile_fail` doctest 覆盖（无需引入 `trybuild` 等额外 dev-dependency）。

```rust
#[cfg(test)]
mod tests {
    use super::*;

    #[test]
    fn test_complex_float_accepts_f32_f64() {
        fn accepts_complex_float<T: ComplexFloat>(_value: Complex<T>) {}
        accepts_complex_float(Complex::new(1.0_f32, 2.0));
        accepts_complex_float(Complex::new(1.0_f64, 2.0));
    }
}
```

补充编译期验证：执行 `cargo test --doc complex` 时，Step 1 文档注释中的 `compile_fail` 块会被 doc-test 框架强制要求"编译失败"，否则该 doc-test 整体失败。这就是设计 §8.7「sealed 边界 / compile-fail」要求的最小落地。

## 关键设计决策

| 决策 | 依据 |
|------|------|
| 只支持 `Complex<f32>` 与 `Complex<f64>` | `04-complex §5.2` 使用 sealed `ComplexFloat` 封闭实现范围 |
| `ComplexFloat` 不携带方法 | `04-complex §5.2` 明确"trait 不携带任何方法，仅作类型封闭之用" |
| sealed 边界由 `compile_fail` doctest 验证 | 避免引入 `trybuild` dev-dependency；`04-complex §8.7` 接受该路径 |
| 不在本 task 重复写入 f32/f64 impl | W5T1 已写入；重复 impl 会导致 E0119 冲突错误 |

## 验证方式

1. 编译检查: `cargo check`
2. Lint 检查: `cargo clippy --all-targets`
3. 单元测试: `cargo test --lib complex::tests::test_complex_float_accepts_f32_f64`
4. 编译期 sealed 测试: `cargo test --doc complex` — 验证 `compile_fail` doctest 报告通过（即代码块如期未能编译）
5. 手动验证: 在 scratch 文件中写入 `let _: xenon::complex::Complex<i32>;`，确认编译失败、错误信息包含 "the trait bound `i32: Sealed` is not satisfied" 或等价语义

## 注意事项

- 不实现跨精度运算，也不实现 `Complex<T> op T` 便捷运算符。
- `NaN != NaN` 由底层浮点 `PartialEq` 自然保证，不要实现 `Eq`。
- `ComplexFloat: PartialOrd` 是为了让 **`T` 自身**可比较（被 Display 的零比较与 `Complex<f32>` / `Complex<f64>` Div 算法的 `abs()` 比较使用）；**`Complex<T>` 自身不实现 `PartialOrd`**，因为复数无自然全序，详见 `04-complex §5.8`。该决策是设计的稳定承诺，不要在 W5T2 或后续 task 中放宽。
- 不修改 W5T1 已写入的 `Complex<T>` 结构体定义或 `f32`/`f64` 的 `impl ComplexFloat` 行。
- FFI 布局测试由 W5T3 覆盖 size、align 和字段偏移。
