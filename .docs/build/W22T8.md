## 实施步骤

### Step 1: 定位实现边界

确认以下类型和函数已可用：
- `crate::dimension::Ix0` — 零维返回类型（W3）
- `crate::element::Element` — 标量元素类型（W4，比 Numeric 宽松，允许 bool）
- `crate::storage::Owned::from_vec_aligned(Vec<A>)`（W7，签名见 `05-storage.md` line 825）— 返回 `Result<Self, XenonError>`，必须 `?` 传播
- `crate::layout::{compute_f_strides, compute_layout_flags}`（W6）
- `crate::tensor::TensorBase::new_unchecked`（W8，参见 `07-tensor.md §5.6`）— 安全前提下的快速构造

### Step 2: 实现 `from_scalar()` 为关联函数

在 `src/construct/scalar.rs` 中实现 `from_scalar` 为 `TensorBase<Owned<A>, Ix0>` 的关联函数，调用语法 `Tensor::<A, Ix0>::from_scalar(value)`。

```rust
use crate::dimension::Ix0;
use crate::element::Element;
use crate::error::XenonError;
use crate::layout;
use crate::storage::Owned;
use crate::tensor::TensorBase;

impl<A> TensorBase<Owned<A>, Ix0>
where
    A: Element,
{
    /// Construct a zero-dimensional tensor from a scalar.
    ///
    /// # Errors
    ///
    /// In practice this single-element path does not produce
    /// `InvalidShapeKind::ElementCountMismatch` (the `vec![scalar]` length is
    /// always 1, matching `Ix0::checked_size() == 1`). The `Result` return
    /// type is preserved for signature uniformity with the rest of the
    /// construction family and to leave room for future allocator-side
    /// failure paths surfaced by `Owned::from_vec_aligned`.
    pub fn from_scalar(scalar: A) -> Result<Self, XenonError> {
        let storage = Owned::from_vec_aligned(vec![scalar])?;
        let shape = Ix0;
        let strides = layout::compute_f_strides(&shape)?;
        let flags = layout::compute_layout_flags(&shape, &strides, storage.as_ptr());
        // SAFETY: 0-D scalar; `shape = Ix0` (product = 1); `strides = []`;
        // `flags` from `compute_layout_flags`; storage length = 1; offset 0;
        // logical access trivially within storage.
        // `derived_from_view_mut: false` — `from_scalar` is not a downgrade path.
        Ok(unsafe { TensorBase::new_unchecked(storage, shape, strides, 0, flags, false) })
    }
}
```

### Step 3: 补齐导出与相邻调用点

`from_scalar` 为 `TensorBase<Owned<A>, Ix0>` 的关联函数，impl 块位于 `scalar.rs` 内即对整个 crate 自动可见，**不需要** 在 `mod.rs` 中添加 `pub use scalar::from_scalar;`。

只需确认 `src/lib.rs` 已注册 `pub mod construct;`（由 W22T1 完成）。

```rust
#[cfg(test)]
mod tests {
    use super::*;
    use crate::tensor::Tensor;

    #[test]
    fn test_from_scalar() {
        let tensor = Tensor::<i32, Ix0>::from_scalar(42i32).unwrap();
        assert_eq!(tensor.ndim(), 0);
        assert_eq!(tensor.len(), 1);
        assert_eq!(*tensor.get(()).unwrap(), 42);
    }

    #[test]
    fn test_from_scalar_bool() {
        // from_scalar allows `Element`-bound types including `bool` (more
        // permissive than `eye`'s `EyeElement` constraint).
        let tensor = Tensor::<bool, Ix0>::from_scalar(true).unwrap();
        assert_eq!(tensor.len(), 1);
        assert!(*tensor.get(()).unwrap());
    }
}
```

## 关键设计决策

1. 依据 `18-construction §5.4` line 486-519，`from_scalar` 是 `impl<A: Element> TensorBase<Owned<A>, Ix0>` 的**关联函数**，调用语法 `Tensor::<A, Ix0>::from_scalar(value)`，不是自由函数。
2. 依据设计 §5.4 line 506-518，实现走 `Owned::from_vec_aligned + compute_f_strides + compute_layout_flags + new_unchecked` 直接路径，**不**委托给 W22T5 的 `from_shape_vec`。这避免单元素路径走运行时 shape-len 校验、与设计 §5.4 错误注释（"In practice this single-element path does not produce ElementCountMismatch"）保持一致。因此前置依赖只需 W22T1，不需 W22T5。
3. 依据 `18-construction §8.2` 与 §8.7，`test_from_scalar` 覆盖正常路径，`test_from_scalar_bool` 覆盖 `Element` 比 `EyeElement` 宽松的差异点。
4. 依据 Wave 22 的依赖层级，本 task 不新增第三方依赖，也不改变前置模块的 public contract。

## 注意事项

- 零长度轴是合法空张量，零维张量长度为 1。
- from_shape_vec 长度不匹配必须返回可恢复错误。
- eye 仅支持 `EyeElement`（i32/i64/f32/f64/Complex<f32>/Complex<f64> 封闭集合），不把 bool 或其它 Numeric 元素（如 usize/isize/u8）纳入单位矩阵 API。
- `from_scalar` 仅约束 `A: Element`（比 `EyeElement` 宽松），允许 bool。
