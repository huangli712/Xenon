## 目标

`tests/test_complex.rs` 作为 black-box 集成测试文件，从外部 `use xenon::complex::Complex;` 出发，覆盖 `04-complex §8.2`（单元测试清单跨模块复检）+ §8.3（边界场景）+ §8.4（属性不变量，固定值版本）+ §8.5（complex 模块自身的端到端路径）：

| 测试组 | 内容 |
|---|---|
| arithmetic | Add / Sub / Mul / Div / Neg 端到端 |
| constructors + accessors | `new` / `from` / `from_imag` / `conj` / `re` / `im` |
| predicates | `is_real` / `is_imaginary` / `is_nan` / `is_finite` |
| math | `norm` / `norm_sqr` |
| display | §5.9 表中六行 + NaN + precision |
| layout | size / align |
| boundary | div by zero / NaN 传播 / 大值 norm / 负零 Display |
| invariants (§8.4) | `(z * z.conj()).re == z.norm_sqr()` 且 `(z * z.conj()).im == 0`；`(z / w) * w ≈ z` |

跨模块协同测试（complex × element / math / matrix / ffi）按 `04-complex §8.5` 描述，但因 element / math / matrix / ffi 由 W4 / W16 / W17 / W13 提供，在 W5 阶段不可见 —— **这部分集成测试由 W29 Integration Tests Wave 在所有依赖 Wave 完成后补全**，W5T16 不强行实现。

按照 `build/SUMMARY.md` 中 W5T16 的定义，在 `tests/test_complex.rs` 中完成此 task 的最小实现，并保持与 `docs/design/04-complex.md` §5（公共 API）、§6（实现细节）、§7（任务拆分）和 §8（测试计划）一致。

## 实施步骤

### Step 1: 集成测试

> **强制要求**:
> - 本步骤必须包含一个或者多个集成测试。
> - 测试函数名称和测试内容必须参考对应设计文档的 **「测试计划」** 一节。
> - 编译检查与Lint检查不等同于单元测试。
> - 如果测试没有通过需要修复直至测试通过。
> - **无测试 = 任务未完成。**

Create `tests/test_complex.rs` as a black-box integration test file. Integration tests are **not** wrapped in `#[cfg(test)] mod tests` — the file itself is the test context. Import only the public API (`use xenon::complex::Complex;`).

```rust
use xenon::complex::Complex;

// ── Arithmetic integration ──

#[test]
fn integration_add_sub_mul_div_neg() {
    let a = Complex::new(1.0_f64, 2.0);
    let b = Complex::new(3.0_f64, 4.0);
    assert_eq!(a + b, Complex::new(4.0, 6.0));
    assert_eq!(a - b, Complex::new(-2.0, -2.0));
    assert_eq!(a * b, Complex::new(-5.0, 10.0));
    let q = Complex::new(6.0_f64, 8.0) / Complex::new(3.0, 4.0);
    assert!((q.re - 2.0).abs() < 1e-12);
    assert!(q.im.abs() < 1e-12);
    assert_eq!(-a, Complex::new(-1.0, -2.0));
}

// ── Constructors and accessors ──

#[test]
fn integration_constructors_and_accessors() {
    let z = Complex::new(3.0_f64, 4.0);
    assert_eq!(z.re(), 3.0);
    assert_eq!(z.im(), 4.0);
    assert_eq!(Complex::from(5.0_f64), Complex::new(5.0, 0.0));
    assert_eq!(Complex::from_imag(6.0_f64), Complex::new(0.0, 6.0));
    assert_eq!(z.conj(), Complex::new(3.0, -4.0));
}

// ── Predicates ──

#[test]
fn integration_predicates() {
    assert!(Complex::new(3.0_f64, 0.0).is_real());
    assert!(Complex::new(0.0, 3.0_f64).is_imaginary());
    assert!(!Complex::new(3.0_f64, 4.0).is_real());
    assert!(!Complex::new(3.0_f64, 4.0).is_imaginary());

    // is_nan / is_finite — provided by W5T14
    assert!(Complex::new(f64::NAN, 0.0).is_nan());
    assert!(!Complex::new(1.0_f64, 2.0).is_nan());
    assert!(Complex::new(1.0_f64, 2.0).is_finite());
    assert!(!Complex::new(f64::INFINITY, 0.0).is_finite());
}

// ── Math methods ──

#[test]
fn integration_norm() {
    let z = Complex::new(3.0_f64, 4.0);
    assert_eq!(z.norm(), 5.0);
    assert_eq!(z.norm_sqr(), 25.0);
}

// ── Display formatting ── (mirrors design §5.9 stability table)

#[test]
fn integration_display() {
    assert_eq!(Complex::new(3.0_f64, 4.0).to_string(), "3+4j");
    assert_eq!(Complex::new(3.0_f64, -4.0).to_string(), "3-4j");
    assert_eq!(Complex::new(0.0_f64, 5.0).to_string(), "5j");
    assert_eq!(Complex::new(5.0_f64, 0.0).to_string(), "5");
    assert_eq!(Complex::new(0.0_f64, 0.0).to_string(), "0");
}

#[test]
fn integration_display_neg_zero_preserved() {
    // Design §5.9 stability rule: -0.0 imaginary must be preserved
    assert_eq!(Complex::new(3.0_f64, -0.0).to_string(), "3-0j");
}

#[test]
fn integration_display_nan_imag() {
    assert_eq!(format!("{}", Complex::new(1.0_f64, f64::NAN)), "1+NaNj");
}

// ── Layout guarantees ──

#[test]
fn integration_layout() {
    assert_eq!(core::mem::size_of::<Complex<f32>>(), 8);
    assert_eq!(core::mem::size_of::<Complex<f64>>(), 16);
    assert_eq!(core::mem::align_of::<Complex<f32>>(), core::mem::align_of::<f32>());
    assert_eq!(core::mem::align_of::<Complex<f64>>(), core::mem::align_of::<f64>());
}

// ── Boundary: zero division (design §8.3) ──

#[test]
fn integration_div_by_zero() {
    let z = Complex::new(1.0_f64, 2.0);
    let zero = Complex::new(0.0_f64, 0.0);
    let result = z / zero;
    assert!(result.re.is_nan() || result.re.is_infinite());
    assert!(result.im.is_nan() || result.im.is_infinite());
}

// ── Boundary: NaN propagation through operators ──

#[test]
fn integration_nan_propagation() {
    let nan = Complex::new(f64::NAN, f64::NAN);
    // NaN + anything has at least one NaN component
    let sum = nan + Complex::new(1.0_f64, 2.0);
    assert!(sum.is_nan());
    // NaN * anything has at least one NaN component
    let prod = nan * Complex::new(1.0_f64, 2.0);
    assert!(prod.is_nan());
    // NaN != NaN
    assert_ne!(nan, nan);
}

// ── Boundary: large magnitude norm avoids overflow (§8.3) ──

#[test]
fn integration_large_norm_no_overflow() {
    let big = 1.0e200_f64;
    let z = Complex::new(big, big);
    // norm() MUST stay finite via hypot; norm_sqr() has no such guarantee
    // (it can overflow on huge inputs, but design does not constrain it).
    assert!(z.norm().is_finite());
}

// ── Boundary: subnormal magnitudes still produce finite, non-zero norm ──

#[test]
fn integration_subnormal_norm() {
    let tiny = Complex::new(f64::MIN_POSITIVE, f64::MIN_POSITIVE);
    assert!(tiny.norm().is_finite() && tiny.norm() > 0.0);
}

// ── Property (§8.4): (z * z.conj()).re == norm_sqr  &&  .im == 0  ──

#[test]
fn integration_conjugate_norm_invariant() {
    // Fixed-value coverage of §8.4 invariant; property-based tests are deferred to W30.
    let cases = [
        Complex::new(1.0_f64, 2.0),
        Complex::new(-3.0_f64, 4.0),
        Complex::new(0.5_f64, -0.25),
        Complex::new(1.0e6_f64, 1.0e-6),
    ];
    for z in cases {
        let product = z * z.conj();
        assert!((product.re - z.norm_sqr()).abs() < 1e-9 * z.norm_sqr().abs().max(1.0));
        assert!(product.im.abs() < 1e-9 * z.norm_sqr().abs().max(1.0));
    }
}

// ── Property (§8.4): (z / w) * w ≈ z  ──

#[test]
fn integration_div_then_mul_roundtrip() {
    let cases = [
        (Complex::new(1.0_f64, 2.0), Complex::new(3.0_f64, 4.0)),
        (Complex::new(-1.0_f64, 0.5), Complex::new(2.0_f64, -1.0)),
        (Complex::new(7.0_f64, 11.0), Complex::new(-0.5_f64, 0.25)),
    ];
    for (z, w) in cases {
        let recovered = (z / w) * w;
        let tol = 1e-9 * z.norm().max(1.0);
        assert!((recovered.re - z.re).abs() < tol, "z={z}, recovered={recovered}");
        assert!((recovered.im - z.im).abs() < tol, "z={z}, recovered={recovered}");
    }
}
```

## 关键设计决策

| 决策 | 依据 |
|------|------|
| 只支持 `Complex<f32>` 与 `Complex<f64>` | `04-complex §5.2` 使用 sealed `ComplexFloat` 封闭实现范围 |
| 运算符仅实现 `Complex<T> op Complex<T>` | `04-complex §1.1` 和 §5.6 明确混合实复运算需显式构造 |
| `norm()` 使用 `hypot()` | `04-complex §1.2` 和 §5.5 要求避免中间溢出 |
| §8.4 属性不变量用固定值版本覆盖 | 不引入 `quickcheck` / `proptest` 依赖；随机化属性测试由 W30 Documentation / W29 Integration Tests Wave 决定是否补全 |
| 大值 `norm_sqr` 不强行断言溢出 | 设计 §8.3 只规定 `norm()` 不溢出，没有规定 `norm_sqr` 必须溢出；脆弱断言会被未来浮点优化破坏 |
| `-0.0` Display 期望 `"3-0j"` 而非 `"3"` | `04-complex §5.9` 稳定性规则：`-0.0` 必须保留符号 |
| 跨模块协同测试 (element/math/matrix/ffi) 延迟到 W29 | W5 阶段这些依赖 Wave 尚未交付；`04-complex §8.5` 的跨模块路径需要等待 |

## 验证方式

1. 编译检查: `cargo check --tests`
2. Lint 检查: `cargo clippy --all-targets`
3. 集成测试: `cargo test --test test_complex` — 确认所有测试通过
4. 手动验证: 运行 `cargo test --test test_complex -- --nocapture` 观察每个测试名称与输出

## 注意事项

- 不实现跨精度运算，也不实现 `Complex<T> op T` 便捷运算符。
- `NaN != NaN` 由底层浮点 `PartialEq` 自然保证，不要实现 `Eq`。
- FFI 布局测试必须覆盖 size、align 和字段偏移意图（W5T3 已实现，本 task 在集成层再次复检 size/align）。
- `integration_display_neg_zero_preserved` 是 `-0.0` 稳定性的核心断言，**不要**为了让简化版 Display 通过而把期望写成 `"3"`。
- §8.5 中跨模块协同路径（与 `element` / `math` / `matrix` / `ffi`）由 W29 Integration Tests Wave 补全，本 task 内不实现 —— 防止 W5 阶段对未交付 Wave 形成隐式依赖。
- §8.4 属性不变量在本 task 仅以固定值版本覆盖；若后续引入 `proptest`，应在 W30 Wave 中以新增 task 形式补强。
