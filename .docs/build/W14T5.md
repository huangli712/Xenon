## 目标

Complex sum SIMD: Complex<f32>/Complex<f64> AoS split real/imag accumulation。

本任务在 `src/simd/vector.rs` 中完成 complex sum 的 SIMD admission 与 kernel 切片，严格遵守 08-simd §5, §6, §7, §8 的范围边界：输入仍保持 `Complex<T>` AoS 存储，SIMD kernel 内部临时 reinterpret 并 deinterleave 成实部/虚部向量，再分别累加并重建 `Complex<T>`。

Complex sum 阈值 = 1024。该阈值来源为 `build/PLAN.md` W14 章节"docs_fix 补充决策 — Complex sum/dot 阈值"，由 §5.8 "f32/f64 sum=1024" + §5.2 Complex AoS split 策略推导而来；若 W14T0 spike 显示 deinterleave 开销过高，可经 PLAN.md 修订后整体上调。

## 实施步骤

### Step 1: Add Complex<f32> sum kernel with AoS reinterpret and deinterleave

Add `try_sum_complex_f32(data: &[Complex<f32>]) -> Option<Complex<f32>>` for Complex<f32> sum admission.

Apply the Complex sum threshold (per PLAN.md W14 补充决策) before any unsafe reinterpret: inputs shorter than 1024 return `None`. Inputs with 1024 or more elements may enter SIMD only when W14T0 confirms a usable pulp shuffle/interleave API or an explicitly audited ISA-specific deinterleave path.

The AoS-to-SoA flow is:

1. Prove the unsafe reinterpret preconditions for `&[Complex<f32>] -> &[f32]`: `Complex<f32>` must be the crate's two-field real/imag layout, element alignment must be compatible with `f32`, and the resulting scalar slice length must be exactly `data.len() * 2` without overflow.
2. Reinterpret the complex input as a scalar float slice representing `[re, im, re, im, ...]`.
3. Use `simd.f32s_as_simd` on that scalar slice. After split, the SIMD body is `&[S::f32s]`; each vector still contains interleaved lanes `[re, im, re, im, ...]`.
4. Use the pulp shuffle/interleave API confirmed by W14T0 to deinterleave each body vector into real-only and imaginary-only vectors.
5. Accumulate real and imaginary lanes independently.
6. Process prefix and suffix elements using the same scalar Complex sum semantics as the caller.
7. Merge real and imaginary accumulators separately, then rebuild `Complex<f32>`.

The deinterleave implementation must cite the W14T0 spike report. Concrete references may include pulp shuffle/interleave methods if available, or ISA-specific patterns such as x86 `_mm_shuffle_ps`, x86 `_mm256_permute_ps`, and ARM NEON `vtrn` when W14T0 approves those paths.

Do not introduce an external SoA layout or a public layout conversion API. The split remains kernel-local, matching 08-simd §5.2.

### Step 2: Add Complex<f64> sum kernel with the same AoS split contract

Add `try_sum_complex_f64(data: &[Complex<f64>]) -> Option<Complex<f64>>` with the same admission shape as the f32 helper.

The f64 path uses the same Complex sum threshold of 1024 elements. Its unsafe reinterpret preconditions are analogous: `&[Complex<f64>] -> &[f64]`, compatible alignment, exact `data.len() * 2` scalar length, and no public layout conversion.

The body split after `simd.f64s_as_simd` still contains interleaved `[re, im, re, im, ...]` lanes. It must use W14T0-confirmed shuffle/interleave support to deinterleave into real-only and imaginary-only vectors before accumulation.

### Step 3: Merge real and imaginary accumulators with W14T3 pairwise policy

Merge using pairwise summation (与 W14T3 一致；不用 Kahan)；tolerance 引用 13-reduction.md §6.3。

The merge operation is performed independently for the real accumulator and the imaginary accumulator. Each component follows the same reduction order policy as W14T3 float sum: vector lane accumulation, horizontal pairwise merge, scalar tail merge, and tolerance documented through the reduction tolerance formula.

Do not hard-code `1e-5` or `1e-10` in the implementation tests. The test helper should obtain or mirror the tolerance formula documented in `13-reduction.md §6.3`, so the Complex sum tolerance source chain is:

1. W14T5 Complex component merge uses W14T3 float sum merge policy.
2. W14T3 float sum tolerance references `13-reduction.md §6.3`.
3. Complex result comparison applies that tolerance separately to `re` and `im`.

FMA must not be used for element-wise complex arithmetic in this task. For sum, FMA is not needed in the main loop. Any future use in horizontal reduction merge must follow the FMA capability-bit rule from W14T0 and the unified FMA rule in the notes below.

### Step 4: Rebuild Complex result and preserve fallback ownership

After vector body, prefix, and suffix accumulation, rebuild the result as `Complex::new(real_total, imag_total)` using the crate's existing `Complex<T>` constructor or equivalent internal fields.

The facade contract remains:

- `Some(value)` means SIMD admission succeeded and the Complex sum value is already computed.
- `None` means SIMD refused admission and the caller must run its existing scalar Complex sum implementation.
- `simd` module does not implement the caller's scalar fallback loop.
- `simd` module does not expose SoA storage or change Tensor/Complex memory layout.

Both f32 and f64 helpers must be `pub(crate)` and `#[cfg(feature = "simd")]`, matching the W14 internal API boundary.

### Step 5: 单元测试

添加覆盖设计文档测试计划的单元测试，至少包含 Complex<f32>、Complex<f64>、低于阈值拒绝、达到阈值后的 SIMD admission 分支，以及 deinterleave 不可用时返回 `None`。

测试数据长度必须使用 1024 或 2048 元素，避免短于 Complex sum 阈值导致静默空测试。

```rust
#[cfg(all(test, feature = "simd"))]
mod tests {
    use super::*;
    use crate::complex::Complex;

    #[test]
    fn test_sum_dispatch_simd_complex_f32() {
        // Temporary W14T5 decision: Complex sum threshold = 1024.
        let short: Vec<Complex<f32>> = (0..1023)
            .map(|i| Complex::new(i as f32, -(i as f32) * 0.5))
            .collect();
        assert!(try_sum_complex_f32(&short).is_none());

        let data: Vec<Complex<f32>> = (0..1024)
            .map(|i| Complex::new(i as f32, -(i as f32) * 0.5))
            .collect();
        let simd_result = try_sum_complex_f32(&data);

        if complex_deinterleave_supported_by_spike_report() {
            let scalar: Complex<f32> = data.iter().copied().sum();
            let simd = simd_result.expect("SIMD should be admitted when deinterleave is supported");
            // tolerance per 13-reduction.md §6.3 (sum): max(4·ε·n·max_abs_input, 4·MIN_POSITIVE)
            // 分量级断言（W14 修复决策 12 + 08-simd §6.6）：real/imag 独立比较，禁用 .norm()
            let max_abs_re = data.iter().map(|c| c.re.abs()).fold(0.0_f32, f32::max);
            let max_abs_im = data.iter().map(|c| c.im.abs()).fold(0.0_f32, f32::max);
            let tol_re = (4.0 * f32::EPSILON * (data.len() as f32) * max_abs_re)
                .max(4.0 * f32::MIN_POSITIVE);
            let tol_im = (4.0 * f32::EPSILON * (data.len() as f32) * max_abs_im)
                .max(4.0 * f32::MIN_POSITIVE);
            assert!((simd.re - scalar.re).abs() <= tol_re,
                "Complex<f32> sum real: simd={}, scalar={}, tol={tol_re}", simd.re, scalar.re);
            assert!((simd.im - scalar.im).abs() <= tol_im,
                "Complex<f32> sum imag: simd={}, scalar={}, tol={tol_im}", simd.im, scalar.im);
        } else {
            assert!(simd_result.is_none());
    }

    #[test]
    fn test_sum_dispatch_simd_complex_f64() {
        // Temporary W14T5 decision: Complex sum threshold = 1024.
        let short: Vec<Complex<f64>> = (0..1023)
            .map(|i| Complex::new(i as f64 * 0.25, -(i as f64) * 0.125))
            .collect();
        assert!(try_sum_complex_f64(&short).is_none());

        let data: Vec<Complex<f64>> = (0..2048)
            .map(|i| Complex::new(i as f64 * 0.25, -(i as f64) * 0.125))
            .collect();
        let simd_result = try_sum_complex_f64(&data);

        if complex_deinterleave_supported_by_spike_report() {
            let scalar: Complex<f64> = data.iter().copied().sum();
            let simd = simd_result.expect("SIMD should be admitted when deinterleave is supported");
            // tolerance per 13-reduction.md §6.3 (sum): max(4·ε·n·max_abs_input, 4·MIN_POSITIVE)
            let max_abs_re = data.iter().map(|c| c.re.abs()).fold(0.0_f64, f64::max);
            let max_abs_im = data.iter().map(|c| c.im.abs()).fold(0.0_f64, f64::max);
            let tol_re = (4.0 * f64::EPSILON * (data.len() as f64) * max_abs_re)
                .max(4.0 * f64::MIN_POSITIVE);
            let tol_im = (4.0 * f64::EPSILON * (data.len() as f64) * max_abs_im)
                .max(4.0 * f64::MIN_POSITIVE);
            assert!((simd.re - scalar.re).abs() <= tol_re,
                "Complex<f64> sum real: simd={}, scalar={}, tol={tol_re}", simd.re, scalar.re);
            assert!((simd.im - scalar.im).abs() <= tol_im,
                "Complex<f64> sum imag: simd={}, scalar={}, tol={tol_im}", simd.im, scalar.im);
        } else {
            assert!(simd_result.is_none());
    }
}
```

The helper assertions must derive tolerance from `13-reduction.md §6.3` instead of using fixed magic numbers. Compare `re` and `im` independently so a deinterleave bug cannot hide by cancelling components.

## 注意事项

- SIMD module does not own scalar fallback loops; callers keep the serial baseline.
- All SIMD entries are internal `pub(crate)` APIs and must stay feature-gated.
- Unsafe code requires explicit length, tail, and alignment proof before vector load/store.
- The unsafe AoS reinterpret must remain private to the complex SIMD kernel.
- deinterleave must be implemented only through W14T0-confirmed pulp shuffle/interleave API or W14T0-approved ISA-specific intrinsic patterns.
- Complex sum 阈值 = 1024 来源于 `build/PLAN.md` W14 补充决策（design/08-simd.md §5.8 不直接列出 Complex 阈值）。
- **FMA 使用规则**（08-simd §1.2/§6.6）：element-wise 与 dot per-element 主循环禁用 FMA（保持与标量逐位一致）；仅 horizontal reduction merge 阶段可在记录容差且 FMA capability bit 独立检测确认后使用。pulp 0.18 的 FMA capability 通过 spike（W14T0）确认。
- 所有代码注释和 Rust 标识符使用英文，文档说明保持当前实施方案风格。
- 不添加新的第三方依赖，除非设计文档已在 Cargo feature 中声明。
