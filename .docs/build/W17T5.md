## 目标

在 W17T4 落地的 `ExecPath::Simd` match arm 中接入 SIMD kernel：
- 通过 `TypeId` 分派调用 W14 已提供的 slice 级 `simd::try_dot_*` facade（仅对 08-simd §5.6 "已实现" 集合：`f32` / `f64` / `Complex<f32>` / `Complex<f64>` / `i32`）；
- kernel 返回 `Option<A>`：`Some(v)` 表示 SIMD 成功完成，`None` 表示 SIMD 后端拒绝准入（例如 ISA 不可用、未达 SIMD 阈值、整数无 widening 实现），调用方**静默回退** `dot_serial`；
- 元素类型不在 "已实现" 集合内（`i64`）时走 scalar fallback，与 08-simd §5.7 "调用方 L2 type gate" 契约一致。

本 task **不**修改 `src/simd/mod.rs`——`try_dot_*` 由 W14T6 / W14T4 的 slice 级 pub(crate) API 提供，已在 W14 wave 中落地。

## 实施步骤

### Step 1: 引入 SIMD admission helper `can_use_simd_dot`

SIMD dot 只支持 §5.6 "已实现" 子集 + F-contig 前提（12-matrix §6.1 line 254 "SIMD 路径要求 `a` 和 `b` 均为 F-contiguous 且满足对齐前提"）。本 task 把 type gate 通过 `TypeId::of::<A>()` 检查（08-simd §5.7 L2 契约），避免在泛型层引入额外 trait。

```rust
#[cfg(feature = "simd")]
use std::any::TypeId;

/// Cheap L2 type gate for the SIMD dot path (08-simd §5.7 line 401-408).
///
/// SIMD dot is only viable for element types that W14 provides a
/// `try_dot_*` facade for: f32, f64, Complex<f32>, Complex<f64>.
/// Integer dot is intentionally excluded from the type gate because
/// W14T4 returns `Option<i32>` (not `Option<i64>`) — the i64 widening
/// is an internal accumulator only, and the final narrowing back to i32
/// can fail, causing the facade to return `None`. Since `dot<i32>` must
/// return `i32` (not `i64`), and the SIMD path's narrowing failure would
/// force scalar fallback anyway, we exclude i32 from the type gate
/// entirely (08-simd §5.6 line 385 "conditional implementation, scalar
/// fallback by default").
///
/// Per 30-dispatch §5.5, alignment is only a capability hint; this
/// function therefore does NOT re-check alignment — `simd::try_dot_*`
/// owns the final admission decision (is_aligned, len threshold, ISA).
#[cfg(feature = "simd")]
#[inline]
fn can_use_simd_dot<A: 'static, S1, S2, D1, D2>(
    a: &TensorBase<S1, D1>,
    b: &TensorBase<S2, D2>,
) -> bool
where
    S1: Storage<Elem = A>,
    S2: Storage<Elem = A>,
    D1: Dimension,
    D2: Dimension,
{
    // F-contiguous on both sides is a hard prerequisite: simd::try_dot_*
    // consumes &[A] slices produced via `as_slice()` (07-tensor §5.5
    // line 544) which requires contiguous element layout.
    if !(a.is_f_contiguous() && b.is_f_contiguous()) {
        return false;
    }
    // L2 type gate — 08-simd §5.7 line 401-408.
    let t = TypeId::of::<A>();
    t == TypeId::of::<f32>()
        || t == TypeId::of::<f64>()
        || t == TypeId::of::<Complex<f32>>()
        || t == TypeId::of::<Complex<f64>>()
}
```

> `A: 'static` 已由 W17T3 的 `DotAccumulate: Numeric + 'static` supertrait 提供，无需在本函数显式引入。

### Step 2: 引入 `try_simd_dot_dispatch` per-type 分派

按 `TypeId` 静态分派到具体的 `try_dot_*`。`Option::None` 表示后端拒绝，调用方走 scalar fallback。

```rust
/// Runtime-to-compile-time bridge for SIMD dot.
///
/// Returns `Some(result)` if the SIMD backend accepted the input and
/// completed the computation; `None` if the backend refused admission
/// (ISA unavailable, sub-threshold length, unsupported type, or
/// pointer misalignment caught inside the kernel). Callers treat
/// `None` as transparent scalar fallback per 12-matrix §6.1 line 253.
///
/// The `TypeId` branches are monomorphized per instantiation; in any
/// given specialization exactly one branch compiles down to a real
/// call and the rest collapse to unreachable code.
#[cfg(feature = "simd")]
fn try_simd_dot_dispatch<A: 'static + Copy, S1, S2, D1, D2>(
    a: &TensorBase<S1, D1>,
    b: &TensorBase<S2, D2>,
) -> Option<A>
where
    S1: Storage<Elem = A>,
    S2: Storage<Elem = A>,
    D1: Dimension,
    D2: Dimension,
{
    // Both inputs are F-contiguous (enforced by can_use_simd_dot) so
    // as_slice() succeeds on both sides (07-tensor §5.5 line 544).
    let lhs = a.as_slice()?;
    let rhs = b.as_slice()?;

    let t = TypeId::of::<A>();
    // SAFETY of each transmute-free cast below: TypeId equality proves
    // A == concrete type; we use the `downcast` helper via
    // `std::mem::transmute_copy` encapsulated in a tiny `reinterpret`
    // function to avoid spreading `unsafe` across match arms. The
    // pattern mirrors 13-reduction.rs's sum TypeId dispatch (see
    // W18T2 §6.4) to keep the whole crate consistent.
    if t == TypeId::of::<f32>() {
        let lhs = reinterpret_slice::<A, f32>(lhs);
        let rhs = reinterpret_slice::<A, f32>(rhs);
        return crate::simd::try_dot_f32(lhs, rhs)
            .map(|v| reinterpret_value::<f32, A>(v));
    }
    if t == TypeId::of::<f64>() {
        let lhs = reinterpret_slice::<A, f64>(lhs);
        let rhs = reinterpret_slice::<A, f64>(rhs);
        return crate::simd::try_dot_f64(lhs, rhs)
            .map(|v| reinterpret_value::<f64, A>(v));
    }
    if t == TypeId::of::<Complex<f32>>() {
        let lhs = reinterpret_slice::<A, Complex<f32>>(lhs);
        let rhs = reinterpret_slice::<A, Complex<f32>>(rhs);
        return crate::simd::try_dot_complex_f32(lhs, rhs)
            .map(|v| reinterpret_value::<Complex<f32>, A>(v));
    }
    if t == TypeId::of::<Complex<f64>>() {
        let lhs = reinterpret_slice::<A, Complex<f64>>(lhs);
        let rhs = reinterpret_slice::<A, Complex<f64>>(rhs);
        return crate::simd::try_dot_complex_f64(lhs, rhs)
            .map(|v| reinterpret_value::<Complex<f64>, A>(v));
    }
    None
}

/// `TypeId`-guarded reinterpret of `&[A]` as `&[B]`.
///
/// Must be called only after `TypeId::of::<A>() == TypeId::of::<B>()`
/// is proven, which guarantees layout, alignment and niche identity.
#[cfg(feature = "simd")]
#[inline]
fn reinterpret_slice<A: 'static, B: 'static>(s: &[A]) -> &[B] {
    debug_assert_eq!(TypeId::of::<A>(), TypeId::of::<B>());
    // SAFETY: TypeId equality implies full type identity; ref-to-slice
    // cast preserves length and lifetime. Zero runtime cost after
    // monomorphization.
    unsafe { &*(s as *const [A] as *const [B]) }
}

#[cfg(feature = "simd")]
#[inline]
fn reinterpret_value<A: 'static + Copy, B: 'static + Copy>(v: A) -> B {
    debug_assert_eq!(TypeId::of::<A>(), TypeId::of::<B>());
    // SAFETY: TypeId equality implies same size / alignment / niche;
    // `Copy` guarantees no drop glue conflict.
    unsafe { std::mem::transmute_copy::<A, B>(&v) }
}
```

> 两个 `reinterpret_*` helper 的 `unsafe` 被 `TypeId` 等价前置条件隔离，符合 25-safety 对 unsafe 使用面的要求（每处 unsafe 都有显式前置断言注释）。

### Step 3: 重写 `dot()` 的 `ExecPath::Simd` match arm

将 W17T4 留下的回退 arm 替换为 admission + fallback 组合。`Serial` / `Parallel` arm 保持 W17T4 原状。

```rust
match path {
    ExecPath::Serial => Ok(dot_serial(a, b)),
    ExecPath::Simd => {
        let _ = guard; // Simd path carries guard=None by dispatch §5.5.
        #[cfg(feature = "simd")]
        {
            if can_use_simd_dot::<A, _, _, _, _>(a, b) {
                if let Some(v) = try_simd_dot_dispatch(a, b) {
                    return Ok(v);
                }
            }
        }
        Ok(dot_serial(a, b))
    }
    ExecPath::Parallel => {
        let _guard = match guard {
            Some(g) => g,
            None => unreachable!(
                "dispatch returned (ExecPath::Parallel, None) — \
                 invariant violated, see 30-dispatch §5.5 line 166"
            ),
        };
        Ok(dot_serial(a, b))
    }
}
```

> `#[cfg(feature = "simd")]` 块内的 SIMD 分派在默认特性下整体消失，`dot()` 在 `Simd` arm 上回退到 `dot_serial`——与 30-dispatch §5.1 "`feature = "simd"` 关闭时 `select_exec_path` 永不返回 `ExecPath::Simd`" 的契约结合后，该 arm 在默认特性下实际为 dead code，但保留 arm 让 W17T6 接入 parallel 时无需触碰 W17T5 代码。

### Step 4: 单元测试

按 12-matrix §10.1 容差表 + §10.3 上线条件，测试必须用**容差比较**而非 `assert_eq!`（严格相等在 SIMD 合并顺序变化后会 flaky）。提供 §10.1 容差计算 helper，与 W17T7 集成测试共享同一公式。

**实施提示**：本 task 不创建新的 `mod tests_w17tN` 声明。原设计采用 `#[cfg(all(test, feature = "simd"))] mod tests_w17t5` 的 mod-level 门控改为 `#[cfg(feature = "simd")]` 逐项门控（语义等价：`mod tests` 本身已由 W17T1 加上 `#[cfg(test)]`，本 task 追加项只在 `feature = "simd"` 下启用）。以下 helper + 测试追加到 W17T1-W17T4 共享的 `mod tests` 块内：

```rust
// 追加到 mod tests 块末尾（在 W17T4 追加块之后）：

/// 12-matrix §10.1 line 574-575 tolerance for f64 dot, adapted for
/// equal-vector self-dot reference checks.
///
/// Helper 门控为 `any(feature = "simd", feature = "parallel")`——设计上被
/// W17T5 (simd) 与 W17T6 (parallel) 共用；W17T6 不重复定义。两个 feature
/// 都关闭时 helper 不被编译，避免 unused-fn warning。
#[cfg(any(feature = "simd", feature = "parallel"))]
fn f64_dot_tolerance(n: usize, max_abs_a: f64, max_abs_b: f64) -> f64 {
    let ulp_term =
        8.0 * f64::EPSILON * (n as f64) * max_abs_a * max_abs_b;
    let floor = 4.0 * f64::MIN_POSITIVE;
    ulp_term.max(floor)
}

#[cfg(feature = "simd")]
#[test]
fn test_dot_simd_path_with_feature() {
    // §8.2 line 468: SIMD path activated via feature, result
    // matches scalar baseline within §10.1 tolerance.
    let values: Vec<f64> = (0..1024).map(|i| (i as f64) * 0.5).collect();
    let a = Tensor1::from_shape_vec(Ix1(values.len()), values.clone()).unwrap();
    let b = Tensor1::from_shape_vec(Ix1(values.len()), values.clone()).unwrap();

    let actual = dot(&a, &b).unwrap();
    let expected = dot_serial(&a, &b);

    let max_abs = values
        .iter()
        .fold(0.0_f64, |acc, &v| acc.max(v.abs()));
    let tol = f64_dot_tolerance(values.len(), max_abs, max_abs);
    assert!(
        (actual - expected).abs() <= tol,
        "SIMD result {actual} drifts beyond §10.1 tol {tol} from scalar {expected}"
    );
}

#[cfg(feature = "simd")]
#[test]
fn test_dot_simd_path_unsupported_type_falls_back() {
    // i64 is not in the §5.6 "implemented" SIMD dot set; dispatch
    // may still return Simd (when feature=simd AND len>=threshold)
    // but `can_use_simd_dot::<i64>` gates it off and the arm
    // returns dot_serial deterministically.
    let values: Vec<i64> = (0..2048).collect();
    let a = Tensor1::from_shape_vec(Ix1(values.len()), values.clone()).unwrap();
    let b = Tensor1::from_shape_vec(Ix1(values.len()), values).unwrap();
    assert_eq!(dot(&a, &b).unwrap(), dot_serial(&a, &b));
}

// Note: `test_dot_simd_non_contig_falls_back` is deferred to W21T6
// integration tests where `slice()` API is available to construct
// non-contiguous 1-D views. W17 executes before W21 (see PLAN.md
// wave ordering), so W17T5 cannot construct a non-contiguous Tensor1
// without `slice_axis_step` / `slice()` / `step_by` view APIs that
// are not part of W3-W8 contract. The non-contig fallback behavior
// is still verified at the level of `can_use_simd_dot` returning
// false when `is_f_contiguous() == false` — but exercising this in
// a test requires W21's slicing primitives. The two tests above
// (`test_dot_simd_path_with_feature` for the SIMD-engaged path and
// `test_dot_simd_path_unsupported_type_falls_back` for the type-gate
// fallback path) already cover the two primary admission outcomes.
```

> **W21 依赖说明**：原设计列表中的 `test_dot_simd_non_contig_falls_back` 需要 W21 (indexing/slicing wave) 提供的 `slice()` / `slice_axis_step` API 来构造非连续 1-D 视图。由于 W17 在 W21 之前执行（PLAN.md wave 排序），W17T5 无法构造非连续 `Tensor1` 输入。该测试推迟到 **W21T6 集成测试层**（届时 `slice()` 可用），此处仅保留两个 W17T5 边界内可达的测试（SIMD-engaged path 与 type-gate fallback），覆盖 admission 的两个主要分支。非连续场景的"SIMD admission → false → scalar fallback" 行为本身已由 `can_use_simd_dot` 中的 `is_f_contiguous()` 检查在代码层面保证。

## 关键设计决策

- **`TypeId`-based 分派 vs trait 分派**：08-simd 已把 `try_dot_*` 定为 slice 级 pub(crate) facade，只接 `&[concrete]`，不暴露泛型。matrix 层必须桥接 `&TensorBase<S, D>` → `&[A]` + 类型解包；引入新的 `SimdDot` trait 会绕过 W14 已确立的 facade 边界。用 `TypeId` 分派是最小侵入路径，与 08-simd §5.7 "调用方 L2 type gate" 契约一致。
- **`reinterpret_slice` / `reinterpret_value` 隔离 unsafe**：两个 helper 集中承担 `TypeId` 等价 → 内存布局等价的推理，`unsafe` 只在这两个函数内出现，match arm 本体保持 safe 代码。
- **`None` 静默回退 `dot_serial`**：与 12-matrix §6.1 line 253 "不进入 SIMD 时回退到该路径上的标量循环"、08-simd §5.7 line 408 "admission 返回 None 时调用方负责走标量回退" 一致。
- **跨路径容差采用 §10.1 公式**：测试 helper `f64_dot_tolerance` 严格按 line 574-575 `max(8.0 * EPSILON * n * max_abs_a * max_abs_b, 4.0 * MIN_POSITIVE)`；cfg 门控为 `any(simd, parallel)`，被 W17T6 复用；W17T7 集成测试独立复制一份用于跨 crate scope 隔离。
- **不修改 `src/simd/mod.rs`**：W14 已确立 `simd::try_dot_*` 自由函数形式；matrix 层直接通过 `crate::simd::try_dot_*` 访问，无需新增 `simd/dot.rs` 或重新导出。

## 注意事项

- **严禁修改 `src/simd/mod.rs` 或新建 `src/simd/dot.rs`**——W14 设计已锁定 `try_dot_*` facade 由 `src/simd/reduce.rs` 或等价文件导出；matrix 层只消费。
- 跨路径浮点测试必须用 §10.1 容差而非 `assert_eq!`；否则 CI 可能因 ISA 差异出现 flaky。
- `can_use_simd_dot` 不在 gate 内检查 len 阈值——`select_exec_path` 已做过长度阈值裁决；再次 gate 属于重复逻辑且与 30-dispatch §5.5 "单一裁决点" 冲突。
- W17T4 的 `alignment_ok(a, b)` helper 已传给 dispatch；SIMD 后端内部用 `layout::is_aligned()` 二次检查，matrix 层不再做第三次对齐裁决（08-simd §9.3 双层加速模型）。
- W17T5 边界之后，`pub fn dot` 签名仍为 `where A: Numeric + DotAccumulate`——`'static` 由 `DotAccumulate` supertrait 提供，对外不可见。
