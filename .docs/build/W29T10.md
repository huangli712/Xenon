## 实施步骤

### Step 1: 创建测试文件与导入

创建或更新目标文件，使用 `xenon::prelude::*` 和 `tests/common` helper。每个测试名称必须描述可观察行为，并保持单文件可独立运行。

```rust
use xenon::prelude::*;

#[test]
fn test_dot_product() {
    let a = Tensor1::from_shape_vec([3], vec![1.0_f64, 2.0, 3.0]).unwrap();
    let b = Tensor1::from_shape_vec([3], vec![4.0_f64, 5.0, 6.0]).unwrap();
    let r = a.dot(&b).unwrap();
    assert_eq!(r.shape(), &[] as &[usize]);
    assert_eq!(*r.iter().next().unwrap(), 1.0 * 4.0 + 2.0 * 5.0 + 3.0 * 6.0);
}

#[test]
fn test_dot_shape_mismatch() {
    let a = Tensor1::from_shape_vec([3], vec![1.0_f64; 3]).unwrap();
    let b = Tensor1::from_shape_vec([2], vec![2.0_f64; 2]).unwrap();
    assert!(a.dot(&b).is_err());
}

#[test]
fn test_dot_empty() {
    // Empty vector dot returns the additive identity (zero) per 12-matrix.md.
    let a = Tensor1::<f64>::zeros([0]);
    let b = Tensor1::<f64>::zeros([0]);
    let r = a.dot(&b).unwrap();
    assert_eq!(r.shape(), &[] as &[usize]);
    assert_eq!(*r.iter().next().unwrap(), 0.0);
}
```

### Step 2: 实现正常路径、边界路径和错误路径

按 28-tests §5.11 清单补齐 i32 / i64 溢出 panic 路径，以及 dot 自由函数入口与双入口等价性。整数溢出按 12-matrix.md 的契约触发 panic（不可恢复）。

```rust
#[test]
#[should_panic]
fn test_i32_dot_overflow_panics() {
    // i32 dot accumulator overflow is unrecoverable. Two elements of i32::MAX
    // multiplied / accumulated must overflow.
    let a = Tensor1::<i32>::from_shape_vec([2], vec![i32::MAX, i32::MAX]).unwrap();
    let b = Tensor1::<i32>::from_shape_vec([2], vec![1, 1]).unwrap();
    let _ = a.dot(&b);
}

#[test]
#[should_panic]
fn test_i64_dot_overflow_panics() {
    let a = Tensor1::<i64>::from_shape_vec([2], vec![i64::MAX, i64::MAX]).unwrap();
    let b = Tensor1::<i64>::from_shape_vec([2], vec![1, 1]).unwrap();
    let _ = a.dot(&b);
}

#[test]
fn test_dot_free_function() {
    // Exercise the free-function entry point `crate::matrix::dot(&a, &b)`
    // explicitly (§4.2 / 12-matrix.md §5).
    let a = Tensor1::from_shape_vec([3], vec![1.0_f64, 2.0, 3.0]).unwrap();
    let b = Tensor1::from_shape_vec([3], vec![4.0_f64, 5.0, 6.0]).unwrap();
    let r = xenon::matrix::dot(&a, &b).unwrap();
    assert_eq!(*r.iter().next().unwrap(), 32.0);
}

#[test]
fn test_dot_dual_entry_equivalence() {
    // The inherent method `a.dot(&b)` and the free function
    // `crate::matrix::dot(&a, &b)` must return identical results.
    let a = Tensor1::from_shape_vec([4], vec![1.0_f64, -2.0, 3.5, 0.25]).unwrap();
    let b = Tensor1::from_shape_vec([4], vec![2.0_f64, 0.5, -1.0, 8.0]).unwrap();
    let via_method = a.dot(&b).unwrap();
    let via_free = xenon::matrix::dot(&a, &b).unwrap();
    assert_eq!(
        *via_method.iter().next().unwrap(),
        *via_free.iter().next().unwrap(),
    );
}
```

### Step 3: 单元测试

> **强制要求**:
> - 本步骤必须包含一个或者多个单元测试。
> - 测试函数名称和测试内容必须参考对应设计文档的 **「测试计划」** 一节。
> - 编译检查与Lint检查不等同于单元测试。
> - 如果测试没有通过需要修复直至测试通过。
> - **无测试 = 任务未完成。**

```rust
// §5.11 covers vector inner-product semantics only (1D · 1D → scalar).
// Matrix/vector multiplication belongs to a separate matmul path and is
// intentionally NOT tested here.
//
// §5.11 high-priority coverage delivered by #[test] functions above:
//   - test_dot_product
//   - test_dot_complex
//   - test_dot_shape_mismatch
//   - test_dot_empty
//   - test_i32_dot_overflow_panics
//   - test_i64_dot_overflow_panics
//   - test_dot_free_function
//   - test_dot_dual_entry_equivalence

#[test]
fn test_dot_complex() {
    // Complex inner product follows the conjugate-linearity contract specified
    // in 12-matrix.md; the conjugate side (lhs vs rhs) is determined by that
    // contract and must not be hard-coded as an implementation detail here.
    // Tier 1 comparison: assert real and imaginary parts separately (§6.2).
    let a = Tensor1::from_shape_vec(
        [2],
        vec![Complex::new(1.0, 2.0), Complex::new(3.0, 4.0)],
    ).unwrap();
    let b = Tensor1::from_shape_vec(
        [2],
        vec![Complex::new(1.0, 0.0), Complex::new(1.0, 0.0)],
    ).unwrap();
    let r = a.dot(&b).unwrap();
    let v = r.iter().next().unwrap();
    // Whichever side carries the conjugate, summing (1±2i) + (3±4i) yields
    // real part = 4. We only constrain what the contract uniquely fixes.
    assert_eq!(v.re(), 4.0);
    assert_eq!(v.im().abs(), 6.0);
}
```

## 关键设计决策

| 决策 | 依据 |
|------|------|
| 集成测试通过公开 API 验证跨模块协作 | 28-tests §1.1 和 §5 将跨模块行为定义为本 wave 职责 |
| dot 双入口（固有方法 + 自由函数）必须显式覆盖等价性 | 28-tests §5.11 L517–518 + §4.2 + 12-matrix.md §5 |
| i32 / i64 dot 溢出视为不可恢复错误（`#[should_panic]`） | 12-matrix.md overflow 契约 + 28-tests §5.11 |
| Complex dot 测试不锁死共轭方向，只断言契约保证的不变量 | 12-matrix.md 复数内积契约 |
| Tier 1 浮点路径默认使用 bitwise/ULP==0 精确比较；复数按分量比较 | 28-tests §6.2 |

## 验证方式

1. 编译检查: `cargo check --tests`
2. Lint 检查: `cargo clippy --tests -- -D warnings`

4. 手动验证: 人工审阅失败断言信息，确认 shape、索引、feature 或错误类型上下文足以定位失败原因。
