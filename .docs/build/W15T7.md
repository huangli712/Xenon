## 目标

实现 `par_map_checked`：闭包返回 `Result<B, XenonError>` 的并行单输入映射入口。按 09-parallel §6.6 line 450-498 的**两遍模式**——第一遍 `try_for_each` 错误探测，第二遍 indexed collect 写入最终结果。错误透传（不包装为新类别），panic 通过 rayon 默认 unwind 传播（不被吞掉）。

## 实施步骤

### Step 1: 创建 `src/parallel/checked.rs` 并定义 `par_map_checked` 签名

签名按 09-parallel §6.6 line 450-462。`F: Fn(&A) -> Result<B, XenonError> + Sync + Send`。

```rust
// src/parallel/checked.rs
use crate::dispatch::{ParallelExecStrategy, ParallelGuard, with_parallel_worker_context};
use crate::dimension::Dimension;
use crate::element::Element;
use crate::error::XenonError;
use crate::storage::Storage;
use crate::tensor::{Tensor, TensorBase};
use crate::parallel::compute_safe_chunks;

#[cfg(feature = "parallel")]
pub(crate) fn par_map_checked<S, A, B, D, F>(
    tensor: &TensorBase<S, D>,
    strategy: &ParallelExecStrategy,
    _guard: ParallelGuard,
    f: F,
) -> Result<Tensor<B, D>, XenonError>
where
    S: Storage<Elem = A>,
    D: Dimension + Clone,
    A: Element + Send + Sync,
    B: Element + Send,
    F: Fn(&A) -> Result<B, XenonError> + Send + Sync,
{
    // continuation in Step 2-3
    unimplemented!()
}
```

> **签名不要求 `F: Clone`**: 09-parallel §6.6 line 462 的签名仅要求 `F: Fn(&A) -> Result<B, XenonError> + Sync + Send`。两遍模式通过**克隆 `ParIter`**（而非克隆闭包）来复用迭代状态：第一遍 `try_for_each` 与第二遍 `map` 都**按引用共享** `&f`（两个外层闭包均非 `move`，Rust 自动推断为借用捕获）。由于 `F: Sync + Send`，`&F` 同样满足 rayon worker 对闭包的 `Send + Sync` 约束。因此调用方传入的闭包无需是 `Clone`，可以是纯 `FnMut` 的函数指针、`Arc`-包装闭包或任意捕获型 `Fn`。

### Step 2: 第一遍 — `try_for_each` 错误探测

09-parallel §6.6 line 481-486：第一遍并行运行 `f` 仅为探测错误；遇到 `Err` 立即停止 rayon 调度。**不要求**返回"第一个发生"的 `Err`（rayon 不保证完成顺序）；只承诺"至少传播一个 `Err`"（§10 line 700）。

```rust
    let total = tensor.len();
    let num_threads = strategy
        .max_workers()
        .unwrap_or_else(rayon::current_num_threads);
    let chunk_size = strategy
        .chunk_size()
        .unwrap_or_else(|| compute_safe_chunks(total, num_threads));

    use rayon::iter::{IndexedParallelIterator, ParallelIterator};

    // Build the parallel iterator once and clone it for phase 1 (since
    // `try_for_each` consumes `self`). `ParIter: Clone` per W15T1; clone
    // is metadata-only (TensorView + 4 small fields). Both phases capture
    // `f` by shared reference (`&F` is `Send + Sync` because `F: Sync`),
    // so `f` is owned by the outer fn through both phases without
    // requiring `F: Clone` (09-parallel §6.6 line 481-486).
    let par_iter = tensor.par_iter().with_strategy(strategy);

    // Phase 1: error probe via try_for_each. If any element returns Err,
    // bail without scheduling the second collect pass. Rayon does NOT
    // guarantee returning the lowest-index Err; design (§10 line 700)
    // only requires that at least one Err is propagated.
    let probe: Result<(), XenonError> = par_iter
        .clone()
        .with_min_len(chunk_size)
        .try_for_each(|item| {
            with_parallel_worker_context(|| {
                f(item).map(|_| ())
            })
        });
    probe?;
```

> **内部前置条件**: 09-parallel §6.6 line 472-474 要求 `f` 在 Ok 路径上"side-effect free and deterministic"，因为成功路径会在两遍中各调用一次 `f`。这是文档化的内部契约（call site 责任），不在签名层强制；违反时行为未定义但不破坏内存安全。

### Step 3: 第二遍 — indexed collect 写入最终结果

09-parallel §6.6 line 485-491：所有 chunk 都成功后，第二遍 `map(...).collect_into_vec(&mut out)` 按 F-order 索引位置写入。第二遍 `f(item).expect(...)`：理论上探测已通过，此处不应再失败；但若由于内部前置条件违反（非确定性 / 副作用）出现 Err，使用 `unwrap()` panic 暴露内部 bug（设计 line 485 line 488 显示 `expect(...)`）。

```rust
    // Phase 2: success path — indexed collect into pre-sized Vec<B>.
    // IndexedParallelIterator + collect_into_vec writes results by F-order
    // logical index, regardless of worker completion order (§6.7 line 504-505).
    // `par_iter` was cloned (not moved) for Phase 1, so the original value
    // remains available here for the second pass.
    let mut out: Vec<B> = Vec::with_capacity(total);
    par_iter
        .with_min_len(chunk_size)
        .map(|item| {
            with_parallel_worker_context(|| {
                f(item).expect(
                    "internal precondition violation: f returned Err on \
                     phase 2 after phase 1 probe passed; f must be \
                     deterministic + side-effect free (09-parallel §6.6 line 472-474)"
                )
            })
        })
        .collect_into_vec(&mut out);

    // SAFETY (07-tensor §5 from_raw_vec_unchecked precondition):
    //   - out.len() == total == checked_size(tensor.raw_dim())
    //     (IndexedParallelIterator len + collect_into_vec)
    //   - F-order alignment (§6.7 line 504-505)
    Ok(unsafe { Tensor::from_raw_vec_unchecked(out, tensor.raw_dim()) })
```

### Step 4: panic 透传（不转换为错误）

09-parallel §10 line 691："Panic 与 `Err(XenonError)` 都不得被吞掉"。本函数**不使用** `std::panic::catch_unwind` 或类似机制；Rayon 默认在 `for_each` / `collect_into_vec` 期间捕获 worker panic 并在汇合点 `resume_unwind`，将 panic 传播到调用线程。本 task 仅需确保不引入 catch 即可（Step 2 / Step 3 的代码已经天然满足）。

测试依据：09-parallel §8.2 的三个高优先级测试——`test_par_map_checked_matches_serial`（line 602）、`test_parallel_error_propagation`（line 603）、`test_parallel_panic_propagation`（line 604）。`ParallelGuard` 通过真路径获取。

```rust
#[cfg(all(test, feature = "parallel"))]
mod tests {
    // Cross-wave test convention (PLAN.md §W13 line 423-429 pattern):
    // W15 and W22 share PLAN.md group D; W22T5 `Tensor::from_shape_vec`
    // is unavailable. Tests construct via W8T7 `TensorView::from_raw_parts`.
    use super::*;
    use crate::dispatch::{
        select_exec_path, ExecPath, ParallelExecStrategy,
        set_parallel_threshold, reset_parallel_threshold,
    };
    use crate::dimension::Ix1;
    use crate::layout::Strides;
    use crate::tensor::TensorView;
    use std::borrow::Cow;
    use crate::error::InvalidArgumentKind;

    fn acquire_parallel_guard<S, D, A>(t: &TensorBase<S, D>) -> ParallelGuard
    where
        S: Storage<Elem = A>,
        D: Dimension,
        A: Element,
    {
        let (path, g) = select_exec_path(t.len(), t.is_f_contiguous(), t.is_aligned());
        assert_eq!(path, ExecPath::Parallel);
        g.expect("Parallel implies Some(guard)")
    }

    unsafe fn view_1d_f64<'a>(data: &'a [f64]) -> TensorView<'a, f64, Ix1> {
        TensorView::<f64, Ix1>::from_raw_parts(
            data.as_ptr(),
            data.len(),
            Ix1(data.len()),
            Strides::from_slice(&[1_usize]).unwrap(),
            0,
        )
        .expect("valid F-order 1-D f64 view")
    }

    #[test]
    fn test_par_map_checked_matches_serial() {
        // 09-parallel §8.2 line 602: Ok path produces same result as serial.
        set_parallel_threshold(1);
        let data = vec![1.0f64, 2.0, 3.0, 4.0];
        let tensor = unsafe { view_1d_f64(&data) };
        let strategy = ParallelExecStrategy::auto();
        let guard = acquire_parallel_guard(&tensor);
        let result = par_map_checked(&tensor, &strategy, guard, |v| Ok(v * 2.0)).unwrap();
        assert_eq!(result.as_slice().unwrap(), &[2.0, 4.0, 6.0, 8.0]);
        reset_parallel_threshold();
    }

    #[test]
    fn test_parallel_error_propagation() {
        // 09-parallel §8.2 line 603 + §10 line 700: at least one Err propagated.
        // Use NumericOutOfRange (26-error §5.1 line 479-484): existing variant
        // for "numeric parameter outside its required domain".
        set_parallel_threshold(1);
        let data = vec![1.0f64, 2.0, 3.0, 4.0];
        let tensor = unsafe { view_1d_f64(&data) };
        let strategy = ParallelExecStrategy::auto();
        let guard = acquire_parallel_guard(&tensor);
        let result = par_map_checked(&tensor, &strategy, guard, |v| {
            if *v == 3.0 {
                Err(XenonError::InvalidArgument {
                    operation: Cow::Borrowed("test"),
                    kind: InvalidArgumentKind::NumericOutOfRange {
                        argument: Cow::Borrowed("v"),
                        domain: Cow::Borrowed("[0, 2]"),
                        actual: Cow::Borrowed("3"),
                    },
                })
            } else {
                Ok(v * 2.0)
            }
        });
        assert!(result.is_err());
        reset_parallel_threshold();
    }

    #[test]
    #[should_panic]
    fn test_parallel_panic_propagation() {
        // 09-parallel §8.2 line 604 + §10 line 691: panic not swallowed.
        // rayon propagates worker panic via resume_unwind at the join point.
        set_parallel_threshold(1);
        let data = vec![1.0f64, 2.0, 3.0, 4.0];
        let tensor = unsafe { view_1d_f64(&data) };
        let strategy = ParallelExecStrategy::auto();
        let guard = acquire_parallel_guard(&tensor);
        let _ = par_map_checked(&tensor, &strategy, guard, |v| {
            if *v == 3.0 {
                panic!("panic in worker");
            }
            Ok(v * 2.0)
        });
        // unreachable; rayon resume_unwind will propagate before this point.
        reset_parallel_threshold();
    }
}
```

> **`#[should_panic]` 而非 `#[should_panic(expected = "...")]`**: rayon worker panic 经 `resume_unwind` 传播时，外层 panic message 可能被 rayon 包装（取决于 rayon 版本），匹配字面字符串脆弱。仅断言 panic 发生即可满足 §10 line 691"panic 不被吞掉"契约。

## 关键设计决策

| 决策 | 依据 |
|------|------|
| 只实现本 task 对应切片 | SUMMARY.md 将 W14-W16 拆成单文件粒度任务 |
| 两遍模式（probe + collect）而非单遍带 Result 的 collect | 09-parallel §6.6 line 481-491：rayon 不保证 indexed collect 在 Err 时短路至最低索引；两遍模式独立解决"错误探测"与"F-order 收集" |
| 不引入 `F: Clone` bound，改为克隆 `ParIter` + `&f` 共享 | 09-parallel §6.6 line 462 签名为 `F: Fn(&A) -> Result<B, XenonError> + Sync + Send`；设计 line 481-485 伪码显式 `iter.clone()` + `f` 按引用复用，ParIter clone 是元数据级成本；`F: Sync` 保证 `&F` 可在 rayon worker 间共享 |
| panic 通过 rayon 默认 `resume_unwind` 传播，不引入 `catch_unwind` | 09-parallel §10 line 691 显式契约 |
| `#[should_panic]` 不带 `expected` | rayon 跨版本 panic 包装格式不稳定，仅断言 panic 发生足够 |

## 注意事项

- 并行函数假定 dispatch 已选中并行路径。
- Outer `ParallelGuard` 留在调用线程栈帧，**绝不**被 Rayon worker 闭包捕获。
- Worker 闭包必须包裹 `dispatch::with_parallel_worker_context`。
- 闭包 `f` 必须 side-effect free 且 deterministic（§6.6 line 472-474）——这是内部前置条件，违反时第二遍 collect 可能 panic 而非返回 `Err`。
- 签名严格对齐 09-parallel §6.6 line 462：`F: Fn(&A) -> Result<B, XenonError> + Send + Sync`；**不引入** `F: Clone`。两遍扫描通过 `par_iter.clone()`（`ParIter` 是元数据 cheap clone，由 W15T1 提供 `Clone` impl）+ `&f` 共享借用实现。
- Feature gate 测试必须证明默认构建无 rayon。
- 所有代码注释和 Rust 标识符使用英文。
- 不添加新的第三方依赖。
