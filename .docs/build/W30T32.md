## 实施步骤

### Step 1: 定位公开 API

读取 `src/storage/mod.rs` 中与任务目标对应的 pub 类型、trait、函数和方法签名，确认每个文档注释需要包含的参数、返回值、错误、panic 或 safety 章节。

- 读取 `05-storage.md` §5 公共 API 设计与 §8「测试计划」节，将其中针对 Owned/ViewRepr/StorageMut 的核心测试用例映射为 doctest（参考 29-documentation §8.2 doctest 覆盖要求）。

### Step 2: 编写类型/函数级 doc comment

为目标 API 写入英文 `///` 文档，按 29-documentation §5.4.2 添加必要章节，并为 sealed public trait 添加 `# Sealed`。

```rust
/// ```rust
/// # use xenon::storage::*;
/// let storage = <Owned<f64> as StorageOwned>::from_elem(4, 0.0);
/// assert_eq!(storage.len(), 4);
/// ```
```

### Step 3: 添加真实 doctest

每个关键 API 至少包含一个可编译 doctest。示例使用隐藏样板、`?`、`assert_eq!` 或 `assert!`，并避免 `unwrap()`。

### Step 4: 审查错误与 feature 语义

按 29-documentation §5.4.2 协同审查清单检查错误构造、索引 API、转换层次、workspace borrow 和 feature-gated 描述。

- Sealed 检查必须覆盖 `RawStorage` / `RawStorageMut` / `Storage` / `StorageMut` / `StorageOwned` / `StorageShared`（6 个）+ `IsOwned` / `IsView` / `IsViewMut` / `IsShared`（4 个），每个公开 sealed trait 的 doc comment 都必须包含 `# Sealed`。

### Step 5: 单元测试

> **强制要求**: 本 task 目标为 Rust 源码，按 TEMPLATE.md L79-99「等效验证条款」，doctest 与 `cargo doc -D warnings` 作为等效验证脚本（失败时非零退出，可入 CI）。所有 Rust doc examples 必须通过 `cargo test --doc` 验证；编译/lint 检查不替代 doctest 验证。

```bash
cargo test --doc --all-features
RUSTDOCFLAGS="-D warnings" cargo doc --all-features --no-deps
cargo clippy --all-features -- -D clippy::missing_errors_doc -D clippy::missing_panics_doc -D clippy::missing_safety_doc
```

验收点：新增或修改的 Rust doc examples 可编译运行；所有 `Result` 示例使用 `?` 并包含断言。

## 关键设计决策

- 公开 sealed trait 必须在自身 doc comment 中包含 `# Sealed`，但不暴露 `crate::private::Sealed` 实现细节。
- 所有 Rust doc comment、README 和 examples 使用英文，实施方案说明保持中文以匹配现有 build 文档。
- 示例优先写成可运行 doctest 或 `main() -> xenon::Result<()>`，并使用 `?` 与断言满足 29-documentation §5.6。

## 验证方式

1. 编译检查: `RUSTFLAGS="-D warnings" cargo check --all-features`
2. Lint 检查: `cargo clippy --all-features -- -D warnings`
3. 文档构建: `RUSTDOCFLAGS="-D warnings" cargo doc --all-features --no-deps`
4. Doctest 验证: `cargo test --doc --all-features`
5. 示例验证: `cargo build --examples --all-features`
6. 手动验证: 打开生成的 rustdoc 或目标 Markdown，确认章节非空、链接有效、示例与任务目标一致。

- 不要展示方括号索引语法；索引示例使用 `try_at`、`try_at_mut`、`get` 或 `get_mut`。
