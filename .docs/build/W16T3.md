### Step 2: Introduce private per-type dispatch traits for unary ops

**Pattern reference**：本 task 采用 W17T3 的 `DotAccumulate` 私有 trait 分派
模式。公开 API trait bound 固定为 `A: Numeric` / `A: Numeric +
OrderedCompareElement`；per-type 细节（整数 checked、浮点 IEEE 754）由私有
sealed trait 在单态化时选择——避免尝试把 `CheckedNeg` / `CheckedMul` 加到
公开 bound 导致浮点 / 复数 trait bound 无解。

```rust
/// Per-type unary step for abs / neg / square.
///
/// - Integer types (`i32`, `i64`): checked arithmetic; overflow / `i{32,64}::MIN`
///   等不可表示情形 panic，符合 11-math §5.4 line 257-259 的整数规约。
/// - Floating types (`f32`, `f64`): delegate to `RealScalar` intrinsics.
/// - Complex types (`Complex<f32>`, `Complex<f64>`): use `Neg` /
///   `Mul` 标准运算符（IEEE 754 传播 NaN / Inf）；`abs` / `signum` 不覆盖
///   复数（trait bound `OrderedCompareElement` 编译期排除）。
///
/// Sealed via `Numeric: Sealed` (03-element §5.2). Consumers cannot add
/// new impls; all six concrete `Numeric` types provide their own impl in
/// this file.
///
/// `*_step_with_ctx` variants propagate `element_index` + `shape` into
/// integer panic text per 11-math §10 line 785-790. Default implementations
/// forward to context-free `*_step` (zero cost on non-integer paths after
/// `#[inline]`); integer impls override these to embed the full diagnostic
/// fields. See Step 5 for the panic-text contract.
trait UnaryArith: Numeric + 'static {
    /// Element-wise negation; integer path panics on `MIN`.
    fn neg_step(x: Self) -> Self;
    /// Element-wise square `x * x`; integer path panics on overflow.
    fn square_step(x: Self) -> Self;

    /// Context-aware variant used by integer monomorphizations to embed
    /// `element_index` + `shape` into panic text per 11-math §10. Default
    /// impl forwards to the context-free `*_step` (non-integer types have
    /// no panic path, so the index / shape are simply dropped).
    #[inline]
    fn neg_step_with_ctx(x: Self, _idx: usize, _shape: &[usize]) -> Self {
        Self::neg_step(x)
    }
    #[inline]
    fn square_step_with_ctx(x: Self, _idx: usize, _shape: &[usize]) -> Self {
        Self::square_step(x)
    }
}

/// Per-type unary step for abs / signum, restricted to ordered types.
///
/// Trait bound `Numeric + OrderedCompareElement` 在 03-element §5.5 sealed
/// 到 `i32` / `i64` / `f32` / `f64`；复数编译时被排除。
///
/// `*_step_with_ctx` variants follow the same contract as `UnaryArith`:
/// default implementations forward to `*_step`; integer impls override to
/// embed `element_index` + `shape` into panic text per 11-math §10.
trait OrderedUnaryArith: Numeric + OrderedCompareElement + 'static {
    /// Element-wise absolute value; integer path panics on `MIN`.
    fn abs_step(x: Self) -> Self;
    /// Element-wise signum. Integers: `-1` / `0` / `1`.
    /// Floats: delegates to `RealScalar::signum` (IEEE 754).
    fn signum_step(x: Self) -> Self;

    #[inline]
    fn abs_step_with_ctx(x: Self, _idx: usize, _shape: &[usize]) -> Self {
        Self::abs_step(x)
    }
    #[inline]
    fn signum_step_with_ctx(x: Self, _idx: usize, _shape: &[usize]) -> Self {
        Self::signum_step(x)
    }
}

// ========== Integer impls (checked arithmetic) ==========

impl UnaryArith for i32 {
    #[inline]
    fn neg_step(x: Self) -> Self {
        x.checked_neg().unwrap_or_else(|| panic!(
            "integer overflow: operation=neg, type=i32, trigger={}", x
        ))
    }
    #[inline]
    fn square_step(x: Self) -> Self {
        x.checked_mul(x).unwrap_or_else(|| panic!(
            "integer overflow: operation=square, type=i32, trigger={}", x
        ))
    }
}

impl UnaryArith for i64 {
    #[inline]
    fn neg_step(x: Self) -> Self {
        x.checked_neg().unwrap_or_else(|| panic!(
            "integer overflow: operation=neg, type=i64, trigger={}", x
        ))
    }
    #[inline]
    fn square_step(x: Self) -> Self {
        x.checked_mul(x).unwrap_or_else(|| panic!(
            "integer overflow: operation=square, type=i64, trigger={}", x
        ))
    }
}

impl OrderedUnaryArith for i32 {
    #[inline]
    fn abs_step(x: Self) -> Self {
        if x >= 0 { x } else {
            x.checked_neg().unwrap_or_else(|| panic!(
                "integer overflow: operation=abs, type=i32, trigger={}", x
            ))
        }
    }
    #[inline]
    fn signum_step(x: Self) -> Self { x.signum() }
}

impl OrderedUnaryArith for i64 {
    #[inline]
    fn abs_step(x: Self) -> Self {
        if x >= 0 { x } else {
            x.checked_neg().unwrap_or_else(|| panic!(
                "integer overflow: operation=abs, type=i64, trigger={}", x
            ))
        }
    }
    #[inline]
    fn signum_step(x: Self) -> Self { x.signum() }
}

// ========== Float impls (IEEE 754) ==========

impl UnaryArith for f32 {
    #[inline] fn neg_step(x: Self) -> Self { -x }
    #[inline] fn square_step(x: Self) -> Self { x * x }
}
impl UnaryArith for f64 {
    #[inline] fn neg_step(x: Self) -> Self { -x }
    #[inline] fn square_step(x: Self) -> Self { x * x }
}

impl OrderedUnaryArith for f32 {
    // `RealScalar::abs` / `RealScalar::signum` already follow IEEE 754 /
    // 03-element §5.3 line 338-339.
    #[inline] fn abs_step(x: Self) -> Self { <Self as RealScalar>::abs(x) }
    #[inline] fn signum_step(x: Self) -> Self { <Self as RealScalar>::signum(x) }
}
impl OrderedUnaryArith for f64 {
    #[inline] fn abs_step(x: Self) -> Self { <Self as RealScalar>::abs(x) }
    #[inline] fn signum_step(x: Self) -> Self { <Self as RealScalar>::signum(x) }
}

// ========== Complex impls (only neg / square; abs / signum are excluded
// at compile time via `OrderedCompareElement` — Complex does NOT implement
// it per 03-element §5.5 line 391-396). ==========

impl UnaryArith for crate::complex::Complex<f32> {
    #[inline] fn neg_step(x: Self) -> Self { -x }
    #[inline] fn square_step(x: Self) -> Self { x * x }
}
impl UnaryArith for crate::complex::Complex<f64> {
    #[inline] fn neg_step(x: Self) -> Self { -x }
    #[inline] fn square_step(x: Self) -> Self { x * x }
}
```

> **Why this shape (vs. attempting `A: Numeric + CheckedNeg + CheckedMul`)**:
> `CheckedNeg` / `CheckedMul` 在 03-element §5.10 line 594、line 627-640 明文
> **仅** `i32` / `i64` impl；把它们加到 trait bound 会让浮点 / 复数路径在
> 单态化时找不到 impl，公开 API 直接编译失败。私有 `UnaryArith` /
> `OrderedUnaryArith` 是 "`Numeric` sealed + 本文件手工覆盖所有六个具体类型"
> 的组合，绕开该 trait bound 冲突并保持 03-element 只读。

### Step 3: Add `abs`, `neg`, `signum`, and `square` methods with correct trait bounds

按设计 §5.4 分层（line 211-251）：`abs` / `signum` 要求
`Numeric + OrderedCompareElement`（限 i32/i64/f32/f64）；`neg` / `square` 仅
要求 `Numeric`（覆盖含 Complex 的全部数值类型）。所有方法委托到 Step 2 的
私有 trait dispatch，编译后每个单态化实例直接内联对应 `*_step` 分支。

```rust
// abs / signum: 顺序约束类型（i32/i64/f32/f64）。
impl<S, D, A> TensorBase<S, D>
where
    S: Storage<Elem = A>,
    D: Dimension,
    A: OrderedUnaryArith,
{
    /// Element-wise absolute value. Integer path panics on `MIN`;
    /// float path follows IEEE 754 (`abs(NaN) = NaN`).
    ///
    /// 整数路径使用 `apply_unary_indexed` + `abs_step_with_ctx`，
    /// panic 文本携带 `element_index` + `shape`（11-math §10 line 785-790）；
    /// 浮点路径通过 `abs_step_with_ctx` 的默认实现零成本转发到 `abs_step`。
    pub fn abs(&self) -> Tensor<A, D> {
        apply_unary_indexed(self, |x, idx, shape|
            <A as OrderedUnaryArith>::abs_step_with_ctx(x, idx, shape))
    }

    /// Element-wise signum. Integers: sign-based `-1` / `0` / `1`.
    /// Floats: IEEE 754 semantics via `RealScalar::signum` (handles
    /// ±0.0 and NaN per 11-math §5.4 line 240-247).
    pub fn signum(&self) -> Tensor<A, D> {
        apply_unary_indexed(self, |x, idx, shape|
            <A as OrderedUnaryArith>::signum_step_with_ctx(x, idx, shape))
    }
}

// neg / square: 全部 Numeric（含 Complex）。
impl<S, D, A> TensorBase<S, D>
where
    S: Storage<Elem = A>,
    D: Dimension,
    A: UnaryArith,
{
    /// Element-wise negation. Integer path panics on `MIN`; float path
    /// uses `-x` (IEEE 754); complex path uses `Neg` operator.
    pub fn neg(&self) -> Tensor<A, D> {
        apply_unary_indexed(self, |x, idx, shape|
            <A as UnaryArith>::neg_step_with_ctx(x, idx, shape))
    }

    /// Element-wise square: `x * x`. Integer path panics on overflow;
    /// float / complex path uses `*` (IEEE 754 propagation).
    pub fn square(&self) -> Tensor<A, D> {
        apply_unary_indexed(self, |x, idx, shape|
            <A as UnaryArith>::square_step_with_ctx(x, idx, shape))
    }
}
```

> **Trait bound 等价性**：`A: UnaryArith` 要求 `A: Numeric + 'static`；
> 03-element §5.7 matrix line 421-428 列出的 6 个 `Numeric` 类型都已在
> Step 2 提供 impl，所以用户侧 trait bound 等价于设计文档的 `A: Numeric`。
> 同理 `A: OrderedUnaryArith` ≡ `A: Numeric + OrderedCompareElement`。

### Step 5: Diagnostic panic text format

按 11-math §10 「panic 信息至少包含 `operation`、`type`、`trigger`、
`element_index`，并在适用时附带 `shape`」，整数路径 panic 文本采用统一模板：

```text
"integer overflow: operation={op}, type={type_name}, trigger={value}, element_index={idx}, shape={shape:?}"
```

Step 2 的整数 `*_step` 方法只携带 `operation` / `type` / `trigger`。为在
panic 文本中补全 `element_index` 与 `shape`，本 task 的整数路径改走
`apply_unary_indexed`——该 helper 已由 **W16T1 Step 2 在 `src/math/helpers.rs`
单点落地**（`pub(in crate::math) fn apply_unary_indexed`，签名参见 W16T1），
本 task **不**在 `helpers.rs` 追加任何定义，仅通过 Step 1 的 `use` 语句导入。

为让整数 `*_step` 获取 `element_index` / `shape`，在 Step 2 的
`trait UnaryArith` / `trait OrderedUnaryArith` 中**追加** `*_step_with_ctx`
默认方法（非整数类型走默认转发、零成本；整数类型覆盖默认实现以注入完整
诊断字段）。为避免重复声明，这些默认方法**直接写入 Step 2 的 trait 声明
主体**，不再另起 trait 块。Step 2 的最终 trait 形态如下（替换 Step 2 已列
出的最小版 trait 声明——**同一文件中 `trait UnaryArith` 只保留这一份**）：

```rust
/// Per-type unary step for abs / neg / square.
///
/// - `*_step`: 精简接口（早期整数 panic 只带 `operation` / `type` /
///   `trigger`）——保留以便浮点 / 复数路径零成本直通。
/// - `*_step_with_ctx`: 带 `element_index` + `shape` 上下文的变体，供整数
///   路径通过 `apply_unary_indexed` 透传。默认实现转发到 `*_step`；i32 / i64
///   覆盖实现以包含完整诊断字段（11-math §10 line 785-790）。
trait UnaryArith: Numeric + 'static {
    fn neg_step(x: Self) -> Self;
    fn square_step(x: Self) -> Self;

    #[inline]
    fn neg_step_with_ctx(x: Self, _idx: usize, _shape: &[usize]) -> Self {
        Self::neg_step(x)
    }
    #[inline]
    fn square_step_with_ctx(x: Self, _idx: usize, _shape: &[usize]) -> Self {
        Self::square_step(x)
    }
}

trait OrderedUnaryArith: Numeric + OrderedCompareElement + 'static {
    fn abs_step(x: Self) -> Self;
    fn signum_step(x: Self) -> Self;

    #[inline]
    fn abs_step_with_ctx(x: Self, _idx: usize, _shape: &[usize]) -> Self {
        Self::abs_step(x)
    }
    #[inline]
    fn signum_step_with_ctx(x: Self, _idx: usize, _shape: &[usize]) -> Self {
        Self::signum_step(x)
    }
}
```

> **强制合并规则**：Step 2 已声明的 `trait UnaryArith` / `trait
> OrderedUnaryArith` 必须**直接替换**为上方的扩展形态；**不得**在文件中
> 再出现第二份 `trait UnaryArith { ... }` 声明。落地者应把 Step 2 的 trait
> 声明与本 Step 的 `*_step_with_ctx` 默认方法合并为单一 trait 块。

i32 / i64 覆盖 `*_step_with_ctx` 以嵌入完整诊断字段：

### Step 5: 单元测试

添加覆盖设计文档测试计划的单元测试，至少包含正常路径和一个边界或回退场景。

```rust
#[cfg(test)]
mod tests {
    use super::*;
    use crate::Tensor;
    use crate::dimension::Ix1;

    #[test]
    fn test_abs() {
        // abs(-3) = 3 for i32; abs(-2.5) = 2.5 for f64.
        let t = Tensor::<i32, Ix1>::from_shape_vec([3], vec![-3, 0, 5]).unwrap();
        let r = t.abs();
        assert_eq!(r[[0]], 3);
        assert_eq!(r[[1]], 0);
        assert_eq!(r[[2]], 5);
    }

    #[test]
    fn test_neg() {
        let t = Tensor::<f64, Ix1>::from_shape_vec([3], vec![1.0, -2.0, 0.0]).unwrap();
        let r = t.neg();
        assert_eq!(r[[0]], -1.0);
        assert_eq!(r[[1]], 2.0);
        // -0.0 in IEEE 754 is distinct from +0.0 but compares equal.
        assert_eq!(r[[2]], 0.0);
    }

    #[test]
    fn test_signum() {
        // i32: -1 / 0 / 1; f64: follows IEEE 754 signum (NaN→NaN, ±0.0→±1.0).
        let t = Tensor::<i32, Ix1>::from_shape_vec([3], vec![-7, 0, 4]).unwrap();
        let r = t.signum();
        assert_eq!(r[[0]], -1);
        assert_eq!(r[[1]], 0);
        assert_eq!(r[[2]], 1);
    }

    #[test]
    fn test_square_checked_overflow() {
        // i32::MAX squared overflows i32 — square() must panic via
        // UnaryArith::square_step for i32 (Step 2 per-type impl).
        let t = Tensor::<i32, Ix1>::from_shape_vec([1], vec![i32::MAX]).unwrap();
        let result = std::panic::catch_unwind(|| t.square());
        assert!(result.is_err(), "i32::MAX squared must panic on overflow");
    }
}
```
