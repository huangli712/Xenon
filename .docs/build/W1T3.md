# 实施方案: W1T3

## 任务概述

| 字段 | 值 |
|------|-----|
| Wave | W1 — Coding Standards & Project Setup |
| Task | W1T3 — src/lib.rs crate root skeleton |
| 目标文件 | `src/lib.rs` |
| 前置依赖 | W1T1（Cargo.toml 存在） |
| 设计文档 | 00-coding.md §12, 01-architecture.md §3, §8 |
| 预估工时 | 10 min |

## 目标

Crate root skeleton with lint declarations (missing_docs, unsafe_op_in_unsafe_fn, clippy::unwrap_used) and minimal declarations that compile immediately.

创建 `src/lib.rs`，配置：
- Crate 级 lint 属性
- W1 阶段唯一需要激活的 `prelude` 模块入口
- 不提前声明或创建后续 Wave 负责的模块文件，避免与 `01-architecture.md §3` 的目录结构冲突

## 前置准备

- W1T1 完成：Cargo.toml 存在，crate 名为 `xenon`
- W1T2 完成：rustfmt.toml 配置完成（非强依赖）
- 确保 `src/` 目录存在

## 实施步骤

### Step 1: 创建 src/ 目录

```bash
mkdir -p src
```

### Step 2: 编写 lint 声明

按 `00-coding.md §7.1` 的权威 lint 基线添加 crate 级 lint 属性。不得将
`missing_docs` 降级为 `allow`。

```rust
//! # Xenon — N-dimensional array library
//!
//! Xenon is a pure Rust N-dimensional array library for scientific computing.
//!
//! Public API examples are added by later documentation tasks after the
//! corresponding types and functions exist.

#![warn(missing_docs)]
#![warn(missing_debug_implementations)]
#![warn(rust_2024_compatibility)]
#![warn(unsafe_op_in_unsafe_fn)]
#![warn(clippy::unwrap_used)]
```

### Step 3: 声明 W1 阶段最小模块结构

W1T3 只激活 `prelude` 入口，保持 crate root 可编译。`01-architecture.md §8`
中的其他模块由各自 Wave 的负责 task 创建并接入（参见本文末「lib.rs 模块声明
演进协议」表），W1T3 不创建 `src/dimension.rs`、`src/element.rs` 等会与后续
目录模块冲突的平铺 stub 文件。

```rust
/// Common exports for convenient use.
pub mod prelude;

pub use prelude::*;
```

### Step 4: 创建 src/prelude.rs 编译占位

> **职责边界声明**：本步骤只负责让 Step 3 中的 `pub mod prelude;` 不导致编译失败。
> 文件内容仅一行模块级文档注释，**不包含任何 re-export 占位符**。
> W1T4（前置依赖本 task）会完整覆盖写入 prelude 文档与 re-export 注释占位符，
> 这一覆盖是 W1T4 实施方案的明示行为，不算"破坏 W1T3 产物"。

```bash
echo "//! Xenon prelude module." > src/prelude.rs
```

### Step 5: 单元测试

```rust
#[cfg(test)]
mod tests {
    //! Crate-level integrity verification tests.

    /// Verifies that Cargo.toml metadata matches the expected crate identity.
    /// `env!` reads these values from Cargo.toml at compile time.
    #[test]
    fn test_crate_metadata() {
        assert_eq!(env!("CARGO_PKG_NAME"), "xenon",
            "Cargo.toml [package] name must be 'xenon'");
        assert_eq!(env!("CARGO_PKG_VERSION"), "0.1.0",
            "Cargo.toml [package] version must be '0.1.0'");
    }

    /// Verifies that src/prelude.rs exists on disk.
    /// Created in Step 4 of this task and required by the `pub mod prelude;`
    /// declaration in Step 3. W1T4 will later overwrite this placeholder
    /// file with the full prelude module skeleton.
    #[test]
    fn test_prelude_module_file_exists() {
        let path = concat!(env!("CARGO_MANIFEST_DIR"), "/src/prelude.rs");
        assert!(
            std::path::Path::new(path).exists(),
            "src/prelude.rs must exist (created in Step 4)"
        );
    }

}
```

## 关键设计决策

| 决策 | 依据 |
|------|------|
| `#![warn(missing_docs)]` | `00-coding.md §7.1` 的权威 lint 基线要求，不得弱化 |
| `#![warn(unsafe_op_in_unsafe_fn)]` | 强制 unsafe 块包装（warn 级别，CI 中 `-D warnings` 升级为 deny） |
| W1T3 仅激活 `prelude` 模块 | 避免提前创建平铺 stub 文件并阻塞后续目录模块 |
| prelude.rs 先创建空文件（Step 4） | 避免 Step 3 中的 `pub mod prelude;` 编译失败。W1T4 将完整覆盖该占位文件——此覆盖在 W1T3 Step 4 与 W1T4 Step 1 双向明示 |
| 协议表新增 W3T15 / 修正 W16T1 / 修正 W23T1 / 对齐 dispatch 私有性 | 与 `01-architecture.md §3` 目录结构、§8 lib.rs 模块清单逐项对照，消除原协议表对 `private`/`overload`/`ffi`-W23 的错位与遗漏 |
| 验证方式明示 `cargo test` 执行门禁 | Step 5 包含真实 Rust 单元测试，符合 TEMPLATE.md「单元测试」强制要求；验证方式必须运行测试方可视为完成 |

## 验证方式

> 所有验证命令在失败时必须以非零退出码返回（由 `cargo` 子命令天然提供）。
> Step 5 定义的两个单元测试 **必须经过 `cargo test` 实际执行通过**，仅有
> 编译通过不构成验收依据。

1. **编译**: `cargo check`
2. **Lint**: `cargo clippy --all-targets -- -W clippy::unwrap_used -D warnings`（应无警告，且作为门禁失败）
3. **文档**: `RUSTDOCFLAGS="-D warnings" cargo doc --no-deps` 确认 rustdoc 零警告
4. **单元测试**（强制，验收门禁）:
   ```bash
   cargo test --lib -- test_crate_metadata test_prelude_module_file_exists
   ```
   两个测试必须均显示 `test result: ok. 2 passed`。
5. **特征组合**:
   ```bash
   set -euo pipefail
   cargo check
   cargo check --features "simd"
   cargo check --features "parallel"
   cargo check --features "simd,parallel"
   ```

>

每个负责的 task 必须在其实施方案中明确：

3. 在 `cargo check` 中验证 lib.rs + 模块文件可以联合编译

**警告**：下游 task（如 W2T5）不得假设"W1T3 已配置好所有 `pub mod` 声明"。下游 task 应引用本协议表确认其上游负责 task 已将相应模块声明加入 lib.rs。

### lib.rs convenience re-export 演进协议

`01-architecture.md §8` 第 633-635 行除模块声明之外，还规定了两条 lib.rs 顶层 convenience re-export：

```rust,ignore
// Convenience re-exports
pub use prelude::*;
pub use error::XenonError;
```

这两条 re-export 不属于上表"`pub mod` 声明"范畴，但同样是 lib.rs 的权威组成部分。其归属如下：

| 来源 | 负责 task | lib.rs 新增 re-export |
|------|-----------|----------------------|
| `01-architecture.md §8` 第 634 行 | W1T3（本 task）Step 3 已写入 | `pub use prelude::*;` |
| `01-architecture.md §8` 第 635 行 | W2T5 同步修改 lib.rs | `pub use error::XenonError;` |

> **W2T5 直达 re-export 职责声明**：`pub use error::XenonError;` 必须等到 `error` 模块声明（W2T1 添加 `pub mod error;`）和 `XenonError` 类型（W2T2）就绪之后才能写入。W2T5 是 W2 收尾 task（前置 W2T4），同时承担 prelude 导出激活与 lib.rs 直达 re-export 写入两项工作。下游 task 不得擅自抢占该职责，亦不得删除 W1T3 已写入的 `pub use prelude::*;`。
