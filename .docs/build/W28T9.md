本任务建立 W28 benchmark 交付物的一部分，覆盖 27-benchmark §5 的 benchmark 结构、§5.5 的清单、§6 的数值与执行约束，以及 §8 的 quick smoke 验证口径。涉及的 benchmark 或检查项为：`zeros_1d`, `from_shape_vec_1d`, `eye_2d`。

## 实施步骤

### Step 1: 建立目标文件骨架

按 27-benchmark §5.1 和 §5.8 的 `harness = false` 模式创建或更新目标文件，保留 `--quick` 与名称 filter 入口，确保单个 bench 可独立运行。

```rust
use std::hint::black_box;

use xenon::prelude::*;

mod utils;
use utils::{run_timed, SIZES_1D, SIZES_2D};

fn bench_zeros_1d(quick: bool) {
    for &size in SIZES_1D {
        let median = run_timed(quick, || {
            // 18-construction.md §5: zeros(shape) -> Result<Self, XenonError>
            let _result = black_box(Tensor1::<f64>::zeros([size]).expect("valid shape"));
        });
        println!("zeros_1d/{size}: {median} ns");
    }
}

fn bench_from_shape_vec_1d(quick: bool) {
    // CAVEAT (27-benchmark §5.9 "Good / Bad 示例" Bad pattern 妥协):
    //   from_shape_vec 按 18-construction.md §5 / W22T5 设计消耗 Vec (move 语义),
    //   timing loop 多次测量必须 data.clone() 否则首次迭代后 data 已被 move。
    //   故测量值 ≈ 1× Vec<f64>::clone() (O(n) memcpy) + 1× from_shape_vec
    //   (O(n) memcpy + 元数据初始化), 大致是纯 from_shape_vec 的 ~2 倍。
    //   该 bench 输出应解读为 "from_shape_vec + 1x Vec clone 合并基线", 仅可与
    //   同样含 clone 开销的历史 baseline 对比, 不可跨 bench 比较绝对值。
    //   stderr 警告下游 baseline 消费者保持口径一致 (stdout 仍按 BENCH_LINE_RE 格式)。
    eprintln!(
        "[bench_from_shape_vec_1d] NOTE: measurements include 1x Vec<f64>::clone() per iteration; \
         see source comment for rationale (27-benchmark §5.9 \"Good / Bad 示例\")."
    );
    for &size in SIZES_1D {
        let data: Vec<f64> = (0..size).map(|idx| idx as f64).collect();
        let median = run_timed(quick, || {
            // 18-construction.md §5: from_shape_vec(shape, vec) -> Result<Self, XenonError>
            let _result = black_box(
                Tensor1::<f64>::from_shape_vec([size], data.clone()).expect("valid shape-vec"),
            );
        });
        println!("from_shape_vec_1d/{size}: {median} ns");
    }
}

fn bench_eye_2d(quick: bool) {
    for &(rows, cols) in SIZES_2D {
        let n = rows.min(cols);
        let median = run_timed(quick, || {
            // 18-construction.md §5: eye(n) -> Result<Self, XenonError>
            let _result = black_box(Tensor2::<f64>::eye(n).expect("valid eye size"));
        });
        println!("eye_2d/{n}x{n}: {median} ns");
    }
}

fn should_run(filter: Option<&str>, name: &str) -> bool {
    filter.map_or(true, |needle| name.contains(needle))
}

fn main() {
    let args = std::env::args().skip(1).collect::<Vec<_>>();
    let quick = args.iter().any(|arg| arg == "--quick");
    let filter = args.iter().find(|arg| !arg.starts_with("--")).map(String::as_str);

    if should_run(filter, "zeros_1d") { bench_zeros_1d(quick); }
    if should_run(filter, "from_shape_vec_1d") { bench_from_shape_vec_1d(quick); }
    if should_run(filter, "eye_2d") { bench_eye_2d(quick); }
}
```

### Step 2: 覆盖 benchmark 参数矩阵

## 关键设计决策

| 决策 | 依据 |
|------|------|
| 使用仓库本地 `harness = false` runner，而非 Criterion 等第三方框架 | 27-benchmark §11 决策 1 要求不引入额外 benchmark 框架 |
| quick 模式保留 filter 与最小输入规模 | 27-benchmark §5.6 和 §8.1 要求 CI smoke 可快速验证 benchmark 入口 |
| benchmark 只记录性能趋势，不定义功能正确性合约 | 27-benchmark §1.1 将功能正确性边界交给 28-tests |
| `bench_from_shape_vec_1d` 在 timing loop 内保留 `data.clone()`（违 27-benchmark §5.9 "Good / Bad 示例" 中的 Bad pattern），并以 stderr `eprintln!` 警告 + 函数体 CAVEAT 注释明示妥协 | 18-construction.md §5.3 / W22T5 设计 `from_shape_vec` 为 move 语义（消耗 Vec），多次迭代必须 clone；27-benchmark §6.2 「数据生成策略」自身假定「预先构造 Vec 后用 from_shape_vec 导入」——设计矛盾由 W28T9 承担披露义务，不上升为代码修改 |

## 验证方式

1. 编译检查: `cargo check --benches`
2. Lint 检查: `cargo clippy --benches -- -D warnings`
3. 测试验证: `cargo bench --bench construction -- zeros_1d --quick`
4. 手动验证: 运行对应 bench 的 `--quick` filter，确认输出包含本任务的 benchmark 名称和 median ns 数值。

## 注意事项

- `black_box` 必须包裹被测结果，避免编译器消除热路径。
- benchmark 输入生成应固定、可重复，避免随机噪声污染趋势判断。
- SIMD/并行对比只在对应 feature 组合下解释性能差异，不得改变默认 API 行为。
