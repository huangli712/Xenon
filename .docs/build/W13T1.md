## 目标

在 `src/ffi/mod.rs` 中创建 FFI 子模块骨架：仅声明 5 个子模块 (`types` / `private` / `ptr` / `blas` / `offset`) 并把 `ffi` 加入 crate root；**不写任何 `pub use`**。所有 `pub use` 由后续 task 在各自子模块就位后按"模块声明演进协议"分批写入 mod.rs。

> **设计来源**: `23-ffi.md` §3 file layout + §4.1 mod.rs 依赖图。设计 §7 Wave 1 T1 把 mod.rs + types.rs + BlasInfo 合并为单一 task；项目实施粒度将其拆为 W13T1（mod 骨架）+ W13T2（types.rs 内容）+ W13T3（private.rs 内容），与 PLAN.md 批次顺序对应。

```bash
touch src/ffi/types.rs \
      src/ffi/private.rs \
      src/ffi/ptr.rs \
      src/ffi/blas.rs \
      src/ffi/offset.rs
```

每个占位文件的初始内容：

```rust
//! Placeholder; populated by subsequent W13 tasks.
```

> **注意**：占位文件内容会被对应子任务整体覆盖。W13T1 阶段不应在占位文件中放置任何 stub 类型 / 方法，避免与下游 task 产生重写冲突。

### Step 2: 创建 FFI 模块入口

`src/ffi/mod.rs` 仅声明子模块，**不写任何 `pub use`**：

```rust
//! FFI helper APIs.
//!
//! See `docs/design/23-ffi.md` for the public API surface, lifetime
//! contracts, BLAS compatibility rules, and Safety considerations.
//!
//! # Pointer / Offset Semantic Boundary
//!
//! The `offset` field appears across several FFI paths with subtly
//! different conventions; this section is the single source of truth:
//!
//! - `TensorBase::as_ptr()` (W8T6, defined in `07-tensor.md` §5.2)
//!   returns the **logical first element** pointer. It has already
//!   absorbed `self.offset()` (i.e. `storage_base.add(self.offset())`).
//! - `TensorBase::as_storage_ptr()` returns the **storage base pointer**.
//! - `export().data` (W13T4 / `§5.4 line 542-543`) carries the storage
//!   base pointer, NOT the logical first. The logical first address is
//!   `data.add(offset)` for non-empty tensors. This is the historical
//!   regression point.
//! - `try_offset_of(idx)` (W13T6 / `§5.13 line 1085`) returns an offset
//!   relative to `as_ptr()` (logical first), NOT relative to the storage
//!   base. `try_ptr_at(idx)` therefore forwards via `as_ptr().add(offset)`
//!   and does NOT add `self.offset()` again.
//!
//! Invariant: `export().data + export().offset == as_ptr()`, and
//! `try_ptr_at(idx) == as_ptr() + try_offset_of(idx)`. Any path diverging
//! from these invariants is a regression and must be caught by
//! W13T4/W13T6 unit tests.
//!
//! # FFI Panic Boundary (Doc Example)
//!
//! Xenon does NOT define any `pub extern "C"` exported functions. The
//! example below shows how downstream consumers should wrap Xenon API
//! calls in their own `extern "C"` boundary using
//! `std::panic::catch_unwind` to prevent Rust panics from crossing the C
//! ABI (`23-ffi.md` §5.4 line 642-675, §8.2 line 1364).
//!
//! ```ignore
//! // Upstream library defines an extern "C" wrapper that calls into
//! // Xenon and catches any panic at the FFI boundary.
//! #[repr(C)]
//! pub enum XenonFfiStatus { Ok = 0, Error = 1, Panic = 2 }
//!
//! #[no_mangle]
//! pub extern "C" fn upstream_call_xenon() -> XenonFfiStatus {
//!     match std::panic::catch_unwind(|| {
//!         // Build or borrow Xenon tensors; use xenon::ffi::* APIs:
//!         //   tensor.export()         -> TensorExportRaw
//!         //   tensor.blas_info()      -> Result<BlasInfo<A>, XenonError>
//!         //   tensor.try_offset_of(.) -> Result<usize, XenonError>
//!         // Do not let C store the borrowed pointers after this fn returns.
//!     }) {
//!         Ok(()) => XenonFfiStatus::Ok,
//!         Err(_panic) => XenonFfiStatus::Panic,
//!     }
//! }
//! ```
//!
//! Without `catch_unwind`, a Rust panic crossing `extern "C"` is
//! undefined behavior. Wrappers must capture the panic and convert it to
//! an upstream ABI error code (or use `panic = "abort"`).

mod blas;
mod offset;
mod private;
mod ptr;
mod types;

// Public re-exports are intentionally absent at W13T1.
// Each downstream task (W13T2 / W13T4) adds the `pub use` lines for the
// items it introduces, following the module-declaration-evolution
// protocol defined by W1T3.
```

### Step 3: 接入 crate root

```

> - W13T4 完成时，在 `src/ffi/mod.rs` 末尾追加：

> - 本 task **不**修改 `src/prelude.rs`；FFI 类型仅通过 `crate::ffi::*` 路径访问，与 W2T5 prelude 极简策略一致。

### Step 4: 单元测试

> **强制要求**:
> - 本步骤必须包含一个或多个单元测试。
> - 测试函数名称和测试内容必须参考对应设计文档的 **「测试计划」** 一节。
> - 编译检查与 Lint 检查不等同于单元测试。
> - 如果测试没有通过需要修复直至测试通过。
> - **无测试 = 任务未完成。**

W13T1 阶段尚无任何 `pub` API 可达（`pub use` 都在下游 task），因此本 task 的"单元测试"为骨架可编译性测试，验证 5 个子模块都被声明：

```rust
#[cfg(test)]
mod tests {
    // Module-level compile probe: each `use` resolves only if the
    // corresponding `mod xxx;` declaration in mod.rs is in place.
    // The five sub-modules are private at W13T1, so we reference them
    // from this in-crate test module where the privacy boundary allows
    // it. Empty `pub use` blocks would not compile because the
    // sub-modules contain no items yet at this stage; importing the
    // modules themselves is sufficient and stable.

    #[test]
    fn test_ffi_submodules_declared() {
        use crate::ffi::blas as _;
        use crate::ffi::offset as _;
        use crate::ffi::private as _;
        use crate::ffi::ptr as _;
        use crate::ffi::types as _;
    }
}
```

> `use ... as _;` 仅强制路径解析（compile-time gate），不引入符号，避免 unused-import 警告。该测试通过即证明 5 个子模块声明已就位。

## 关键设计决策

| 决策 | 依据 |
|------|------|
| sub-module 按功能域拆分（blas / offset / private / ptr / types） | `23-ffi.md` §3 文件位置：每个子模块职责单一，`private.rs` 隔离泛型描述符、`types.rs` 包含 C-visible 类型、`ptr.rs` / `blas.rs` / `offset.rs` 各司其职 |
| mod.rs 在 W13T1 阶段不写 `pub use` | 占位文件为空，任何 `pub use sub::Symbol` 都会引用未定义符号；遵循 W1T3 「模块声明演进协议」，由下游 task 在符号就位时追加 |
| `pub use` 仅覆盖类型，不重导出 inherent methods | `export`/`is_blas_layout_compatible`/`blas_info`/`lda`/`try_offset_of`/`try_ptr_at` 是 `TensorBase` 的固有方法（`23-ffi.md` §5.4/§5.10-§5.13），inherent methods 没有自由路径符号可被 `pub use`；调用方通过 `TensorBase` 类型直接调用 |
| 不修改 prelude | W2T5 的 prelude 策略极简，仅暴露 `XenonError` / `Result` / 错误辅助枚举；FFI 类型按 `23-ffi.md` 设计预期由用户显式从 `crate::ffi::*` 路径访问，避免 prelude 膨胀 |
| 子模块声明使用私有 `mod xxx;` 而非 `pub mod xxx;` | `crate::ffi::types::*` 等子路径设计上只在 crate 内部可达；crate 外调用方通过下游 task 补充的 `pub use sub::Item` 平铺路径访问（对齐 23-ffi.md §3 file layout 表中「mod.rs Module root, re-exports」的注释）。这强制了调用方 API 表面仅由 mod.rs 的 `pub use` 列表锁定，避免下游误入子模块内部项 |
| mod.rs 顶部集中说明 `offset` / `as_ptr` 语义边界 | `23-ffi.md` §5.4 / §5.13 重复陈述 `data = storage base`、`try_offset_of 返回相对 as_ptr()` 等语义；在 ffi/mod.rs 顶部集中一份，作为 W13T4 / W13T6 实现与 PR 评审的 anchor，防止重复出现 "`data = as_ptr()`" 这种回归 |
| mod.rs doc 中嵌入 `catch_unwind` wrapper 示例（`ignore` doctest）以覆盖 `test_ffi_wrapper_catches_panic_doc_example` | `23-ffi.md` §8.2 line 1364 明确该测试为高优先级 "doc 示例级验证"；嵌在 ffi/mod.rs 顶部 doc comment，`cargo doc` 走访时可验证示例使用的是实际 API；Xenon 本身不定义 `pub extern "C"` (§1.2 / §9.1)，对上游集成代码是设计意图上的责任边界 |

## 验证方式

1. 编译检查: `cargo check`
2. Lint 检查: `cargo clippy --all-targets`
3. 测试验证: `cargo test ffi::tests::test_ffi_submodules_declared`
4. 手动验证: `cargo doc --no-deps -p xenon --open` 查看 `crate::ffi` 模块页面存在但暂无公开项（W13T1 阶段预期为空）。

## 注意事项

- 本 task 不引入任何 `pub` 项；用户可见的 FFI API 由 W13T2–W13T6 提供。
- 不得在占位 `.rs` 文件中放置任何会被下游 task 推翻的 stub。
- 不得在本 task 修改 `src/prelude.rs` 或其它 crate-level 文件，除了 `src/lib.rs` 中 `pub mod ffi;` 一行。
- `mod.rs` 中嵌入的 `catch_unwind` 示例为 `ignore` doctest（避免 `cargo test --doc` 试图编译 `extern "C" + #[no_mangle]`，这些需要 wrapper crate 上下文）。`cargo doc` 会将该示例渲染到文档中，作为 `23-ffi.md` §8.2 line 1364 要求的「文档示例级验证」。需要反面验证「不用 catch_unwind 会 panic 穿越 C ABI」的动态集成测试推迟到 **W29T18 (`tests/test_ffi.rs`)**，在有 wrapper crate 环境下实现。
