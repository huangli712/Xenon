### Step 2: 修改目标文件

**Prelude `//!` 文档模板**（附加到 src/prelude.rs 顶部）：

```rust
//! The Xenon prelude.
//!
//! Re-exports the most commonly used types so downstream code can
//! write `use xenon::prelude::*;` instead of importing each item.

//!
//! # Example
//!
//! ```rust
//! use xenon::prelude::*;

必须保留 `00-coding §7.1` 完整项目级基线（含 `missing_debug_implementations`、`rust_2024_compatibility`、`unsafe_op_in_unsafe_fn`、`clippy::unwrap_used` 等），在其上追加本 task 的文档专项 lint，不得弱化或移除基线项。**禁止**写入 `#![cfg_attr(docsrs, feature(doc_cfg))]` 或任何 `doc(cfg(...))` 属性。原因：MSRV 1.95 stable，doc_cfg 是 nightly-only。引用 29-documentation §5.5.1 line 370-371 + 00-coding §10.3。

```rust

#![warn(missing_debug_implementations)]
#![warn(rust_2024_compatibility)]
#![warn(unsafe_op_in_unsafe_fn)]
#![warn(clippy::unwrap_used)]

#![warn(clippy::missing_errors_doc)]
#![warn(clippy::missing_panics_doc)]

上述三条 clippy 文档 lint 开发期写入源码为 `warn`，CI 中升级为 deny。

## 关键设计决策

- 文档内容跟随源码签名和设计文档，不通过文档引入新 API 或新依赖。
- 所有 Rust doc comment、README 和 examples 使用英文，实施方案说明保持中文以匹配现有 build 文档。
- 示例优先写成可运行 doctest 或 `main() -> xenon::Result<()>`，并使用 `?` 与断言满足 29-documentation §5.6。
- PLAN.md 中 `doxcs.rs` 为表格勘误（应为 docs.rs），不属本 task 范围；保留观察。

## 验证方式

1. 编译检查: `RUSTFLAGS="-D warnings" cargo check --all-features`
2. Lint 检查: `cargo clippy --all-features -- -D warnings`
3. 文档构建: `RUSTDOCFLAGS="-D warnings" cargo doc --all-features --no-deps`
4. Doctest 验证: `cargo test --doc --all-features`
5. 示例验证: `cargo build --examples --all-features`
6. 手动验证: 打开生成的 rustdoc 或目标 Markdown，确认章节非空、链接有效、示例与任务目标一致。

## 注意事项

- 不要把编译检查当作 doctest；文档示例必须由 `cargo test --doc` 覆盖。
- 不要展示方括号索引语法；索引示例使用 `try_at`、`try_at_mut`、`get` 或 `get_mut`。
- 不要新增依赖、教程站点、notebook 或自定义 rustdoc 主题。
