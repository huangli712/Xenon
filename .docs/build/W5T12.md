## 实施步骤

### Step 1: Implement Neg

Append unary negation to `src/complex/ops.rs`. It stays generic because `ComplexFloat` includes `Neg<Output = Self>`.

```rust
impl<T: ComplexFloat> core::ops::Neg for Complex<T> {
    type Output = Self;

    #[inline]
    fn neg(self) -> Self {
        Self::new(-self.re, -self.im)
    }
}
```

## 关键设计决策

| 决策 | 依据 |
|------|------|
| 只支持 `Complex<f32>` 与 `Complex<f64>` | `04-complex §5.2` 使用 sealed `ComplexFloat` 封闭实现范围 |
| 运算符仅实现 `Complex<T> op Complex<T>` | `04-complex §1.1` 和 §5.6 明确混合实复运算需显式构造 |

## 验证方式

1. 编译检查: `cargo check`
2. Lint 检查: `cargo clippy --all-targets`
3. 测试验证: `cargo test --lib complex::ops::tests::test_neg_complex`
4. 手动验证: 验证 `-Complex::new(1.0, 2.0)` 等于 `Complex::new(-1.0, -2.0)`，且 `--z == z` 成立。

## 注意事项

- 不实现跨精度运算，也不实现 `Complex<T> op T` 便捷运算符。
- `NaN != NaN` 由底层浮点 `PartialEq` 自然保证，不要实现 `Eq`。
- FFI 布局测试必须覆盖 size、align 和字段偏移意图。
