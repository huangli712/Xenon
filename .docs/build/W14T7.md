## 实施步骤

### Step 1: Verify W1T1 Cargo feature configuration

确认 W1T1 已配置 `simd = ["dep:pulp"]` 及 `pulp = { version = "0.18", optional = true }`。

本 task 不重新添加或改写 `Cargo.toml` 中的 feature/dependency 片段，只验证现有配置满足 08-simd §5.1 与 W1T1 的基线约束：

- `[features] default = []`，`simd` 不属于 default feature。
- `[features] simd = ["dep:pulp"]`。
- `[dependencies] pulp = { version = "0.18", optional = true }`。
- 默认构建不得因为其它 feature 或依赖路径无意引入 `pulp`。

### Step 2: Apply cfg guard and pub(crate) facade boundaries in `src/simd/mod.rs`

在 `mod.rs` 中：所有 items 加 `#[cfg(feature = "simd")]`；需要外露的入口标记 `pub(crate)`；feature off 时模块编译为空（无符号泄漏）。

所有 items（trait 定义、enum 定义、struct 定义、impl 块、函数、static）均需 `#[cfg(feature = "simd")]`；trait 定义本身也必须 gated——feature off 时整个 trait 不可见。

Required `pub(crate)` facade surface:

- `pub(crate) fn get_arch() -> &'static Arch`
- `pub(crate) fn dispatch_vector_binary_op<A>(op: BinaryOp, lhs: &[A], rhs: &[A], dst: &mut [A]) -> bool`
- `pub(crate) fn dispatch_vector_unary_op<A>(op: UnaryOp, src: &[A], dst: &mut [A]) -> bool`
- `pub(crate) fn try_sum_f32(data: &[f32]) -> Option<f32>`
- `pub(crate) fn try_sum_f64(data: &[f64]) -> Option<f64>`
- `pub(crate) fn try_sum_complex_f32(data: &[Complex<f32>]) -> Option<Complex<f32>>`
- `pub(crate) fn try_sum_complex_f64(data: &[Complex<f64>]) -> Option<Complex<f64>>`
- `pub(crate) fn try_dot_f32(lhs: &[f32], rhs: &[f32]) -> Option<f32>`
- `pub(crate) fn try_dot_f64(lhs: &[f64], rhs: &[f64]) -> Option<f64>`
- `pub(crate) fn try_dot_complex_f32(lhs: &[Complex<f32>], rhs: &[Complex<f32>]) -> Option<Complex<f32>>`
- `pub(crate) fn try_dot_complex_f64(lhs: &[Complex<f64>], rhs: &[Complex<f64>]) -> Option<Complex<f64>>`
- `pub(crate) fn try_sum_i32(data: &[i32]) -> Option<i32>`
- `pub(crate) fn try_dot_i32(lhs: &[i32], rhs: &[i32]) -> Option<i32>`
- `pub(crate) fn simd_vector_width<T: SimdElement>() -> Option<usize>`

Do not expose i64 SIMD reduction/dot facades beyond the current default fallback policy. `i64` remains scalar unless a later task explicitly adds a verified widening path.

### Step 3: Verify W14T1 crate-level module registration ownership

验证 W14T1 已完成 crate-level SIMD module registration；W14T7 不重新添加或修改该注册。

Ownership rule:

- W14T1 owns crate-level registration of the `simd` module.
- W14T7 owns conditional compilation and facade hygiene inside `src/simd/mod.rs`, plus Cargo feature verification.
- If W14T1 registration is absent during implementation, report it as a W14T1 blocker rather than adding it in W14T7.

### Step 4: W10 dispatch → W14 simd 集成面

Document and verify the W10 dispatch → W14 simd integration contract.

When `select_exec_path()` returns `ExecPath::Simd`, the semantic caller's match branch calls the W14T1/W14T7 facade that corresponds to the operation shape:

- 二元 element-wise：`dispatch_vector_binary_op(op, lhs, rhs, dst)` returns `bool`; `true` means SIMD wrote `dst`, `false` means scalar fallback must run.
- 一元 element-wise：`dispatch_vector_unary_op(op, src, dst)` returns `bool`; `true` means SIMD wrote `dst`, `false` means scalar fallback must run.
- sum/dot：the corresponding `try_*` facade returns `Option<A>`; `Some(value)` means SIMD produced the result, `None` means scalar fallback must run.
- `alignment_ok` is hints-only and must not participate in hard gating, matching W10T4 L116-L119.

本 step 仅文档化 dispatch 集成契约；具体实施在 W16/W17/W18 等语义模块中。

Non-contiguous or broadcast views must not directly enter SIMD. The semantic module must first obtain contiguous slices or fall back to scalar execution.

## 验证方式

1. 编译检查: `cargo check`
2. Default-off 编译检查: `cargo check --no-default-features`
3. Feature 编译: `cargo check --features simd`
4. Feature tree 验证: `cargo tree -e features -f simd`
5. 静态审查: 确认 `src/simd/mod.rs` 中所有 items（trait 定义、enum 定义、struct 定义、impl 块、函数、static）均受 `#[cfg(feature = "simd")]` 守护
6. 手动验证: 阅读 rustdoc 或编译错误输出，确认 feature off 时无 SIMD symbol leakage，feature on 时 crate 内语义模块可访问 `pub(crate)` facades

## 注意事项

- SIMD module does not own scalar fallback loops; callers keep the serial baseline.
- All SIMD entries are internal `pub(crate)` APIs and must stay feature-gated.
- Unsafe code requires explicit length, tail, and alignment proof before vector load/store.
- Non-contiguous and broadcast views must not directly enter SIMD; semantic modules must first obtain contiguous slices or fall back.
- `alignment_ok` remains a hints-only input for the SIMD backend and never replaces per-kernel admission checks.
- W14T7 documents the dispatch integration contract only; semantic integration lands in W16/W17/W18 according to each semantic module's task scope.
- 所有代码注释和 Rust 标识符使用英文，文档说明保持当前实施方案风格。
- 不添加新的第三方依赖，除非设计文档已在 Cargo feature 中声明。
- **集成测试分拆**：设计 §8.5 的 `tests/test_simd.rs` 拆为两部分。SIMD 与 math 模块的 dispatch 集成在 **W16T11** 实现。独立集成测试文件 `tests/test_simd.rs` 本身在 **W29T20** 创建（见 PLAN.md L788-789）。原描述「推迟至 W16」漏判了 W29 集成测试阶段的实际承担人。
