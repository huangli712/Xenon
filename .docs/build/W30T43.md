## 实施步骤

### Step 1: 核对示例覆盖范围

从 29-documentation §5.3 和 §5.7 提取此示例必须展示的 API：Usage example: create, operate, reduce, print。确认示例只依赖已公开 API，并且 `main` 返回 `xenon::Result<()>`。

### Step 2: 编写独立可运行示例

在 `examples/basic.rs` 写入自包含示例。示例必须包含导入、构造数据、执行核心操作、输出结果，不使用 `unwrap()`。

```rust
use xenon::prelude::*;

fn main() -> xenon::Result<()> {
    let a = Tensor::<f64, _>::ones([2, 3])?;
    let b = Tensor::<f64, _>::ones([2, 3])?;
    let c = (&a + &b)?;
    assert_eq!(c.shape(), &[2, 3]);
    assert_eq!(c.sum(), 12.0);
    println!("shape={:?}, sum={}", c.shape(), c.sum());
    // Tensor Display uses the default NumPy-style truncation rules.
    println!("{}", c);
    Ok(())
}
```

### Step 3: 添加输出与错误路径说明

保留 `println!` 输出形状、结果或路径选择；对 fallible API 使用 `?` 传播 `XenonError`，不在示例中制造 panic。

### Step 4: 审查 feature 与平台描述

若示例涉及 feature，仅使用 `#[cfg(feature = "...")]` 描述路径差异；不要声称 API 只在 feature 下存在，除非源码确实 feature-gated。

### Step 5: 单元测试

> **强制要求**: 示例文件通过编译，并按 29-documentation §5.11.1 Gate 4 对关键示例执行运行验证。

```bash

cargo run --example basic
```

验收点：示例使用 `main() -> xenon::Result<()>`、不使用 `unwrap()`，并通过 `println!` 展示结果。
