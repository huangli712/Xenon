# 实施方案: W17T1

## 任务概述

| 字段 | 值 |
|------|-----|
| Wave | W17 — Matrix Operations |
| Task | W17T1 — Module skeleton with compilable dot() stub |
| 目标文件 | `src/matrix/mod.rs`, `src/matrix/dot.rs`, `src/lib.rs` |
| 前置依赖 | None |
| 设计文档 | 12-matrix §3（文件位置）, §5.1（公开 API 签名）, §7（实现拆分） |
| 预估工时 | 10 min |

## 目标

创建 `src/matrix/` 模块骨架并暴露 `dot()` 自由函数。`src/matrix/dot.rs` 提供一个**可编译的最小桩**——签名与设计 §5.1 严格一致，函数体返回 `Ok(A::zero())` 作为占位实现。该桩保证 W17T1 完成时 crate 完整可编译、可通过测试。真正的输入校验（W17T2）、标量内积（W17T3）、dispatch 接入（W17T4-T6）由后续 task 增量替换函数体，**不再变更签名**。

## 前置准备

- 确认基础 tensor / dimension / storage / element / error 模块已由前序 wave（W1–W8）提供：`TensorBase`、`Storage`、`Dimension`、`Numeric`、`Tensor1`、`Ix1`、`XenonError`。
- 阅读 12-matrix §3、§5.1 与 §7 Wave 1（T1）。
- 在修改前运行 `cargo check` 获取基线，避免把既有失败误认为本任务引入。

## 实施步骤

### Step 1: 创建 `src/matrix/mod.rs`

仅声明子模块并 re-export `dot` 自由函数；不暴露 prelude 别名，外部入口在 Step 3 的 `src/lib.rs` 处一次性闭环。

```rust
//! Matrix operations.
//!
//! Currently this module exposes the vector dot product. The
//! method-style `TensorBase::dot()` mirror is added by W17T3 once the
//! scalar inner product is implemented.
//!
//! Design reference: 12-matrix §3, §5.1.

mod dot;

pub use dot::dot;
```

### Step 2: 创建 `src/matrix/dot.rs` 编译桩

签名严格按 12-matrix §5.1 line 151-160 的自由函数原型：两侧允许不同的 `S` 与 `D` 泛型，约束 `A: Numeric`。函数体返回 `Ok(A::zero())`，仅用于保证本 task 完成时 crate 整体可编译；W17T2 增加校验，W17T3 替换为真实计算。

```rust
//! Vector dot product entry point.
//!
//! Layered implementation across W17 tasks:
//!   * W17T1 (this task): public signature with `Ok(A::zero())` stub.
//!   * W17T2: rank + length validation returning recoverable errors.
//!   * W17T3: scalar inner product via private `DotAccumulate` trait.
//!   * W17T4: dispatch wiring (`select_exec_path`).
//!   * W17T5: SIMD path integration via `simd::try_dot_*`.
//!   * W17T6: parallel path integration via `parallel::par_dot`.
//!
//! Design reference: 12-matrix §5.1, §6.

use crate::dimension::Dimension;
use crate::element::Numeric;
use crate::error::XenonError;
use crate::storage::Storage;
use crate::tensor::TensorBase;

/// Vector dot product entry point (W17T1 skeleton).
///
/// At the W17T1 task boundary this function returns `Ok(A::zero())` for
/// every well-typed input. Validation and computation are layered in by
/// W17T2-W17T6; this stub exists only so the crate compiles and downstream
/// tasks have a stable symbol to wire against.
///
/// See 12-matrix §5.1 for the final user-visible contract.
pub fn dot<S1, S2, A, D1, D2>(
    _a: &TensorBase<S1, D1>,
    _b: &TensorBase<S2, D2>,
) -> Result<A, XenonError>
where
    S1: Storage<Elem = A>,
    S2: Storage<Elem = A>,
    A: Numeric,
    D1: Dimension,
    D2: Dimension,
{
    Ok(A::zero())
}
```

### Step 3: Wire `src/lib.rs`

将 `matrix` 注册为顶级模块并在 crate root 直接 re-export `dot`，让 W17T7 的集成测试可以使用 `use xenon::dot;`（与 §8.5 “tests/test_matrix.rs 端到端协同验证” 的导出路径一致）。

```rust
// src/lib.rs — incremental addition by W17T1
pub mod matrix;

pub use matrix::dot;
```

> 仅追加上述两行；不修改 `src/lib.rs` 中既有的其它 `pub mod` 与 `pub use` 项。

### Step 4: 单元测试

按 12-matrix §8 测试计划添加最小的"模块导出 + 桩可调用" smoke test。本测试仅验证 W17T1 范围内的可观察行为——`dot` 符号可见且对空向量返回加法单位元；shape mismatch / rank 校验属于 W17T2 的测试边界。

```rust
#[cfg(test)]
mod tests {
    use super::*;
    use crate::{Ix1, Tensor1};

    #[test]
    fn test_matrix_module_dot_skeleton_returns_zero() {
        // W17T1 stub returns Ok(A::zero()) for every input. Validation
        // (W17T2) and real computation (W17T3) are added in later tasks.
        let a = Tensor1::<f64>::from_shape_vec(Ix1(0), vec![]).unwrap();
        let b = Tensor1::<f64>::from_shape_vec(Ix1(0), vec![]).unwrap();
        assert_eq!(dot(&a, &b).unwrap(), 0.0_f64);
    }

    #[test]
    fn test_matrix_module_dot_skeleton_returns_zero_for_int() {
        // Same stub semantics for integer Numeric types. Real integer
        // checked arithmetic is added in W17T3.
        let a = Tensor1::<i32>::from_shape_vec(Ix1(0), vec![]).unwrap();
        let b = Tensor1::<i32>::from_shape_vec(Ix1(0), vec![]).unwrap();
        assert_eq!(dot(&a, &b).unwrap(), 0_i32);
    }
}
```

## 关键设计决策

- `pub use dot::dot;` 保证 `dot` 实现细节私有，对外只暴露稳定的自由函数名。
- `src/lib.rs` 同时声明 `pub mod matrix;` 与 crate root re-export `pub use matrix::dot;`，使外部访问路径同时支持 `xenon::dot` 与 `xenon::matrix::dot`，对齐 12-matrix §8.5 集成测试用例的 `use xenon::dot;`。
- 桩返回 `Ok(A::zero())` 而非 `unimplemented!()`/`todo!()`——保证 `cargo test` 在 W17T1 边界处 100% pass，不留任何 panic 路径。
- 不引入 `prelude` 入口，避免与 SUMMARY 之外的导出契约扩散；如需 prelude 收纳，由独立 wave 统一处理。
- 不在本 task 添加 `TensorBase::dot` 方法——该方法依赖 W17T3 的 `DotAccumulate` 私有 trait，强行提前会导致 W17T2/T3 重复编辑。

## 验证方式

1. 执行 ``cargo check``——必须通过且 `src/matrix/mod.rs`、`src/matrix/dot.rs`、`src/lib.rs` 无 warning。
2. 执行 ``cargo test matrix::dot::tests::test_matrix_module_dot_skeleton_returns_zero matrix::dot::tests::test_matrix_module_dot_skeleton_returns_zero_for_int``——两个 smoke test 必须通过。
3. 执行 ``cargo test --doc``——确认 W17T1 的 doc comment 不破坏 doc test 构建。
4. 手动验证：打开 `src/matrix/mod.rs`、`src/matrix/dot.rs`、`src/lib.rs`，确认实现只覆盖 W17T1 范围，且与 12-matrix §3、§5.1、§7 的"Wave 1: 基础"完全对齐。

## 注意事项

- `src/lib.rs` 仅追加 `pub mod matrix;` 与 `pub use matrix::dot;` 两行；严禁在本 task 内顺手改动其它无关导出。
- 公共 `dot()` 签名一旦在 W17T1 落地，后续 W17T2-T6 只允许替换函数体，不得变更签名或泛型边界（W17T3 会增加 `+ DotAccumulate` 私有 trait 边界，这是本 wave 内允许的唯一边界扩张，且对外完全不可见）。
- 不为桩添加 `#[deprecated]` 或 `#[doc(hidden)]`——桩的存在期只跨越单个 wave，无需向下游传播。
