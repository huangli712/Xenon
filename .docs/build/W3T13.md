## 目标

校验 W2T1 已添加的 `XenonError::DimensionMismatch` variant 是否与 `26-error.md` §5.1 设计完全一致；若有字段缺失或类型不符，补齐到设计契约要求。**本 task 不重新定义 variant、不重复添加；只做一致性校验与必要的字段补丁。**

依据：
- `26-error.md` §5.1 (lines 164-168) 定义 `DimensionMismatch { operation: Cow<'static, str>, expected: usize, actual: usize }`
- `02-dimension.md` §5 / §6（lines 360-364）使用该 variant 构造错误，并要求 `operation` 字段存在
- `W2T1.md` 已在 W2 阶段添加该 variant
- `W3T12.md` 在本 task 之前实际使用 variant 构造错误（见 W3T11 Step 2-9 中的 `Cow::Borrowed("<Type>::try_from_dyn")`）

## 前置准备

1. 确认 W2T1 已完成并通过 `cargo check`：`src/error.rs` 已含 `XenonError::DimensionMismatch` variant。
2. 确认 W3T12 已完成：所有 Ix0-Ix6 与 IxDyn 的 inherent `try_from_dyn` 已用此 variant 构造错误。
3. 阅读 `26-error.md` §5.1 与 `02-dimension §5, §6, §7, §8`，掌握 `DimensionMismatch` 的字段契约。

## 实施步骤

### Step 1: 读取 `src/error.rs`，定位 `DimensionMismatch` 当前定义

打开 `src/error.rs`，在 `XenonError` enum 中找到 `DimensionMismatch` variant，记录其当前字段集合。

### Step 2: 对照 `26-error.md` §5.1 与 W3T12 实际使用，核对字段集合

字段契约（必须）：

| 字段 | 类型 | 出处 |
|------|------|------|
| `operation` | `Cow<'static, str>` | 26-error.md §5.1 line 164；W3T12 构造点使用 `Cow::Borrowed("Ix3::try_from_dyn")` 等 |
| `expected` | `usize` | 26-error.md §5.1 line 166 |
| `actual` | `usize` | 26-error.md §5.1 line 168 |

判断当前 `src/error.rs` 中的 `DimensionMismatch` 是否同时具备这三个字段且类型正确：

- **若三字段都存在且类型正确** → 本 task 不修改代码，进入 Step 4 写校验测试。
- **若 `operation` 缺失** → 进入 Step 3 补齐。
- **若 `expected` / `actual` 类型不对** → 进入 Step 3 修正。

### Step 3: 必要时补齐 `operation` 字段（仅当 Step 2 检测到字段缺失时执行）

仅做最小修补——添加缺失字段，**不**重排现有字段顺序，**不**修改其他 variant。

```rust
// Before (if missing operation):
DimensionMismatch {
    expected: usize,
    actual: usize,
},

// After:
DimensionMismatch {
    operation: std::borrow::Cow<'static, str>,
    expected: usize,
    actual: usize,
},
```

同步检查并修补 `impl fmt::Display for XenonError`（由 W2T3 添加）的 `DimensionMismatch` 分支：

```rust
XenonError::DimensionMismatch { operation, expected, actual } => {
    write!(
        f,
        "dimension mismatch in {operation}: expected {expected} dimensions, got {actual}"
    )
}
```

同步检查并修补 `impl std::error::Error for XenonError`（由 W2T4 添加）的 `source()` 实现：`DimensionMismatch` 没有底层 source，继续返回 `None`（通常 W2T4 已为 fallthrough arm 处理）。

### Step 4: 单元测试

> **强制要求**:
> - 本步骤必须包含一个或者多个单元测试。
> - 测试函数名称和测试内容必须参考对应设计文档的 **「测试计划」** 一节。
> - 编译检查与Lint检查不等同于单元测试。
> - 如果测试没有通过需要修复直至测试通过。
> - **无测试 = 任务未完成。**

测试用于**校验** `DimensionMismatch` variant 的字段集合与 Display 格式符合设计契约。测试可放在 `src/error.rs` 的 `#[cfg(test)] mod tests` 中（与 W2T1 的测试共存）。

```rust
#[cfg(test)]
mod tests {
    use super::*;
    use std::borrow::Cow;

    /// §8.2-style verification: DimensionMismatch must carry operation/expected/actual.
    #[test]
    fn test_dimension_mismatch_variant_fields() {
        let err = XenonError::DimensionMismatch {
            operation: Cow::Borrowed("Ix3::try_from_dyn"),
            expected: 3,
            actual: 4,
        };
        match err {
            XenonError::DimensionMismatch { operation, expected, actual } => {
                assert_eq!(operation, "Ix3::try_from_dyn");
                assert_eq!(expected, 3);
                assert_eq!(actual, 4);
            }
            _ => panic!("not DimensionMismatch"),
        }
    }

    /// W2T3 Display format includes operation, expected, actual.
    #[test]
    fn test_dimension_mismatch_display_includes_operation() {
        let err = XenonError::DimensionMismatch {
            operation: Cow::Borrowed("Ix2::try_from_dyn"),
            expected: 2,
            actual: 3,
        };
        let msg = format!("{err}");
        assert!(msg.contains("Ix2::try_from_dyn"), "msg: {msg}");
        assert!(msg.contains("expected 2"), "msg: {msg}");
        assert!(msg.contains("3"), "msg: {msg}");
    }
}
```

## 关键设计决策

1. 按 PLAN.md 注 3 与决定 D-1，`DimensionMismatch` variant **已**由 W2T1 添加；本 task 不重复添加，只做一致性校验与必要补丁。这消除了"W2T1 与 W3T13 都声明添加 variant"的潜在冲突。
2. 依据 `26-error.md` §5.1，`DimensionMismatch` 必含三字段（`operation`, `expected`, `actual`），其中 `operation` 为 `Cow<'static, str>` 以避免分配（错误路径中字符串常为 `'static`）。
3. 本 task 是轮 W3T12 之后执行（PLAN.md 批次 12），原因：W3T12 是实际使用 variant 的最大消费者，若 variant 字段不符 W3T11 会编译失败；W3T12 在 W3T11 通过编译后做最终一致性校验。
4. 本 task 修改范围**仅限** `src/error.rs`，**不**修改 `src/dimension/` 任何文件。

## 验证方式

1. 编译检查: `cargo check`（验证 variant 字段定义可被 W3T12 构造点使用）
2. Lint 检查: `cargo clippy`
3. 测试验证: `cargo test test_dimension_mismatch_variant_fields test_dimension_mismatch_display_includes_operation`
4. 手动验证: 对照 `26-error.md` §5.1 字段定义；运行 `grep "DimensionMismatch" src/error.rs src/dimension/` 确认所有构造点都填入了三个字段。
