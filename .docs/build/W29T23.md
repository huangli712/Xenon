## 实施步骤

### Step 1: 扩展 CI 工作流文件

基于 W29T21 已创建的 `.github/workflows/test.yml` 扩展：保留 workflow 身份（`name: Test`）与 matrix/step 主体；`test` job 的显示名按 full-matrix 含义重命名，并通过 `needs: lint` 串接；在 `test` job 中追加 property tests 步骤，并新增 `lint`（含 §8.2 全部 4 条 hard gate）和 `compile-fail` job。

```yaml
# Extended CI matrix (extends W29T21 — keep workflow name "Test")
name: Test

on:
  push:
    branches: [main]
  pull_request:
    branches: [main]

env:
  CARGO_TERM_COLOR: always

jobs:
  lint:
    name: lint-and-hard-gates
    runs-on: ubuntu-latest
    steps:
      - uses: actions/checkout@v4
      - uses: dtolnay/rust-toolchain@stable
      # §8.2 hard gate 1: clippy
      - name: Clippy (all features)
        run: cargo clippy --all-features -- -D warnings
      # §8.2 hard gate 2: compile warnings
      - name: RUSTFLAGS warnings check (all features)
        run: RUSTFLAGS="-D warnings" cargo check --all-features
      # §8.2 hard gate 3: rustdoc warnings
      - name: Rustdoc warnings (all features)
        run: RUSTDOCFLAGS="-D warnings" cargo doc --all-features --no-deps
      # §8.2 hard gate 4: cooperative-baseline pin drift
      # 注：tools/check_baseline_pins.py 独立交付于 cooperative-baseline pin tooling task
      # （不在本 PLAN 任务范围）；本 CI gate 在该脚本存在后才能运行。
      - name: Cooperative-baseline pin drift
        run: python3 tools/check_baseline_pins.py docs/design/

  test:
    name: test-full-matrix (${{ matrix.features }})
    needs: lint
    runs-on: ubuntu-latest
    strategy:
      matrix:
        features: ["", "--features parallel", "--features simd", "--all-features"]
    steps:
      - uses: actions/checkout@v4
      - uses: dtolnay/rust-toolchain@stable
      - name: Run lib + integration tests
        run: cargo test --lib --tests ${{ matrix.features }}
      - name: Run doc tests
        run: cargo test --doc ${{ matrix.features }}
      - name: Run property tests
        run: cargo test --test property_tests ${{ matrix.features }}

  compile-fail:
    name: compile-fail-harness
    runs-on: ubuntu-latest
    steps:
      - uses: actions/checkout@v4
      - uses: dtolnay/rust-toolchain@stable
      - name: Run compile-fail harness
        run: cargo test --test compile_fail_tests
```

### Step 2: 等效验证（bash 字段断言，失败必非零退出）

```bash
#!/usr/bin/env bash
set -euo pipefail

WF=.github/workflows/test.yml

# (1) YAML must parse.
python3 -c "import yaml; yaml.safe_load(open('${WF}'))"

# (2) workflow name preserved (T21 identity).
grep -qE '^name:\s*Test\s*$' "${WF}" || { echo "workflow name must stay 'Test'"; exit 1; }

# (3) Steps presence.
grep -q 'cargo test --lib --tests'              "${WF}" || { echo "missing lib+tests step";    exit 1; }
grep -q 'cargo test --doc'                      "${WF}" || { echo "missing doctest step";      exit 1; }
grep -q 'cargo test --test property_tests'      "${WF}" || { echo "missing property step";     exit 1; }
grep -q 'cargo test --test compile_fail_tests'  "${WF}" || { echo "missing compile-fail step"; exit 1; }

# (4) §8.2 hard gates — all four must appear.
grep -q 'cargo clippy --all-features -- -D warnings'                              "${WF}" || { echo "hard gate clippy missing";       exit 1; }
grep -q 'RUSTFLAGS="-D warnings" cargo check --all-features'                      "${WF}" || { echo "hard gate compile warn missing"; exit 1; }
grep -q 'RUSTDOCFLAGS="-D warnings" cargo doc --all-features --no-deps'           "${WF}" || { echo "hard gate rustdoc missing";      exit 1; }
grep -q 'tools/check_baseline_pins.py docs/design/'                               "${WF}" || { echo "hard gate baseline-pins missing"; exit 1; }
```

### Step 3: 单元测试（Python + PyYAML 结构化断言，失败必非零退出）

> **强制要求**:
> - 本步骤必须包含一个或者多个单元测试。
> - 测试函数名称和测试内容必须参考对应设计文档的 **「测试计划」** 一节。
> - 编译检查与Lint检查不等同于单元测试。
> - 如果测试没有通过需要修复直至测试通过。
> - **无测试 = 任务未完成。**

落实 `test_ci_matrix_has_all_feature_combinations` 与 `test_ci_invokes_property_tests`，并对 §8.2 的 4 条 hard gate 逐字段断言。`assert` 失败让 Python 非零退出。

```python
# Equivalent test: assertions raise on failure -> non-zero exit.
import yaml

with open(".github/workflows/test.yml", "r") as f:
    wf = yaml.safe_load(f)

assert wf.get("name") == "Test", "workflow name must remain 'Test' (T21 identity preserved)"

jobs = wf["jobs"]
assert {"lint", "test", "compile-fail"}.issubset(jobs.keys()), \
    f"jobs lint/test/compile-fail required, got {list(jobs.keys())}"

# test_ci_matrix_has_all_feature_combinations
features = jobs["test"]["strategy"]["matrix"]["features"]
required_features = {"", "--features parallel", "--features simd", "--all-features"}
assert required_features.issubset(set(features)), \
    f"feature matrix incomplete: got {features}, need {required_features}"

# test_ci_invokes_property_tests
test_runs = [s.get("run", "") for s in jobs["test"]["steps"]]
assert any("cargo test --lib --tests"          in r for r in test_runs), "missing lib+tests"
assert any("cargo test --doc"                  in r for r in test_runs), "missing doctest"
assert any("cargo test --test property_tests"  in r for r in test_runs), "missing property_tests step"

# compile-fail job invokes harness
cf_runs = [s.get("run", "") for s in jobs["compile-fail"]["steps"]]
assert any("cargo test --test compile_fail_tests" in r for r in cf_runs), "missing compile_fail_tests"

# §8.2 four hard gates — all required in lint job.
lint_runs = [s.get("run", "") for s in jobs["lint"]["steps"]]
def has(token): return any(token in r for r in lint_runs)
assert has("cargo clippy --all-features -- -D warnings"),                    "hard gate clippy missing"
assert has('RUSTFLAGS="-D warnings" cargo check --all-features'),            "hard gate compile-warnings missing"
assert has('RUSTDOCFLAGS="-D warnings" cargo doc --all-features --no-deps'), "hard gate rustdoc-warnings missing"
assert has("tools/check_baseline_pins.py docs/design/"),                     "hard gate baseline-pins missing"

print("OK: W29T23 full matrix + 4 hard gates verified")
```

## 关键设计决策

| 决策 | 依据 |
|------|------|
| workflow `name: Test` 保持不变；区分由 job name 承担 | TEMPLATE 边界承诺「保留 workflow 身份（`name: Test`）与 matrix/step 主体；`test` job 的显示名按 full-matrix 含义重命名，并通过 `needs: lint` 串接」，避免替换 T21 workflow 身份 |
| 4 条 hard gate 全部置于 `lint` job | 28-tests §8.2 line 1354-1386 权威清单 |
| **Hard gate 抽出到独立 `lint` job** | 与 design §8.2（28-tests.md:1352-1386）字面置于 `test` job 内的布局不同。原因：避免在 4 个 matrix 副本上重复执行，且 lint 失败可阻断 matrix 启动，节省 CI 资源。 |
| compile-fail 通过 `cargo test --test compile_fail_tests` 驱动 | 28-tests §8.4 line 1405-1432 仓库本地 harness |
| 等效验证脚本失败必返回非零退出 | TEMPLATE 等效验证条款；bash `\|\| exit 1` 与 Python `assert` |
| 集成测试通过公开 API 验证跨模块协作 | 28-tests §1.1 和 §5 |

## 验证方式

1. 编译检查: `cargo check --tests`
2. Lint 检查: `cargo clippy --tests -- -D warnings`
3. 测试验证: `cargo test --lib --tests && cargo test --doc && cargo test --test property_tests && cargo test --test compile_fail_tests`
4. 等效验证脚本（TEMPLATE.md L96 强制要求显式列出执行命令）：
   - 将 Step 2 的 bash 块保存到 `/tmp/verify_w29t23.sh`，执行：`bash /tmp/verify_w29t23.sh`
   - 将 Step 3 的 Python 块保存到 `/tmp/verify_w29t23.py`，执行：`python3 /tmp/verify_w29t23.py`
   - 任一脚本以非零退出码结束 → 视为该 task 验收失败。
5. 手动验证: 人工审阅失败断言信息，确认 shape、索引、feature 或错误类型上下文足以定位失败原因。
