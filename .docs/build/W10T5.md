## 目标

Threshold config: 对称提供 `set_parallel_threshold` / `reset_parallel_threshold` / `set_simd_threshold` / `reset_simd_threshold`，使用 `Relaxed` ordering（`30-dispatch.md §5.6, §6.3`）。

本任务基于 W10T4 已定义的 `PARALLEL_THRESHOLD` / `SIMD_THRESHOLD` 原子，仅追加**对称的运行时覆写与重置接口**（parallel 和 simd 两侧均支持），与 `30-dispatch §5.6, §7, §8` 保持一致。

## 实施步骤

### Step 1: 实现核心代码

在 `src/dispatch.rs` 中添加本任务要求的最小实现。注意：`DEFAULT_*` 常量、`PARALLEL_THRESHOLD`/`SIMD_THRESHOLD` 原子、`get_parallel_threshold()`/`get_simd_threshold()` 已在 **W10T4** 中定义；本任务仅添加运行时覆写接口。

```rust
pub(crate) fn set_parallel_threshold(threshold: usize) {
    PARALLEL_THRESHOLD.store(threshold, std::sync::atomic::Ordering::Relaxed);
}
pub(crate) fn reset_parallel_threshold() { set_parallel_threshold(DEFAULT_PARALLEL_THRESHOLD); }

pub(crate) fn set_simd_threshold(threshold: usize) {
    SIMD_THRESHOLD.store(threshold, std::sync::atomic::Ordering::Relaxed);
}
pub(crate) fn reset_simd_threshold() { set_simd_threshold(DEFAULT_SIMD_THRESHOLD); }
```

### Step 2: 单元测试

> - 编译检查与Lint检查不等同于单元测试。
> - 如果测试没有通过需要修复直至测试通过。

测试依据: `test_threshold_override_respected`、`test_threshold_zero_disables_parallel`、`test_threshold_saturating_mul_no_overflow`、`test_reset_threshold_restores_default` 验证阈值配置（`30-dispatch.md §8.2`）。

> **注意**: `test_threshold_saturating_mul_no_overflow` 原在 W10T6 中，现已移至本任务以便与阈值设置/重置测试逻辑归组。所有调用 `should_parallelize()` 的测试均**不**再传入 `ParallelExecStrategy`——该函数签名为 `should_parallelize(len, is_contiguous)`（`30-dispatch.md §5.5` line 471）。

```rust
#[cfg(test)]
mod tests {
    use super::*;

    #[test]
    fn test_threshold_override_respected() {
        set_parallel_threshold(42);
        assert_eq!(get_parallel_threshold(), 42);
        reset_parallel_threshold();
    }

    #[cfg(feature = "parallel")]
    #[test]
    fn test_threshold_zero_disables_parallel() {
        // 30-dispatch §5.6 line 494-499: threshold=0 is the parallel-disable sentinel.
        set_parallel_threshold(0);
        assert!(!should_parallelize(usize::MAX, true));
        reset_parallel_threshold();
    }

    #[cfg(feature = "parallel")]
    #[test]
    fn test_threshold_saturating_mul_no_overflow() {
        // 30-dispatch §8.2 / §8.3: threshold near usize::MAX must saturate, never wrap.
        set_parallel_threshold(usize::MAX / 2 + 1);
        assert!(!should_parallelize(usize::MAX - 1, false));
        reset_parallel_threshold();
    }

    #[test]
    fn test_reset_threshold_restores_default() {
        set_parallel_threshold(1);
        reset_parallel_threshold();
        assert_eq!(get_parallel_threshold(), DEFAULT_PARALLEL_THRESHOLD);
    }

    #[test]
    fn test_reset_simd_threshold_restores_default() {
        set_simd_threshold(1);
        reset_simd_threshold();
        assert_eq!(get_simd_threshold(), DEFAULT_SIMD_THRESHOLD);
    }
}
```

## 关键设计决策

| 决策 | 依据 |
|------|------|
| Parallel 优先于 SIMD | `30-dispatch.md §6.1` 规定大输入先尝试并行 |
| ParallelGuard 与 Parallel 返回值绑定 | `30-dispatch.md §5.7` 消除选择后进入失败的中间状态 |
| 阈值使用 Relaxed 原子 | `30-dispatch.md §6.3` 只需运行时配置可见性 |
| 对称提供 simd 阈值 set/reset | `30-dispatch.md §5.6` line 504-532、§6.3 line 751-757 |
| `set_parallel_threshold(0)` = 显式禁用 parallel sentinel | `30-dispatch.md §5.6` line 494-499 |

## 验证方式

1. 编译检查: `cargo check --all-features`
2. Lint 检查: `cargo clippy --all-targets --all-features`
3. 测试验证: `cargo test dispatch --all-features` 和不同 feature 组合下的 `cargo test dispatch`
4. 手动验证: 使用 `-- --nocapture` 检查阈值重置测试不会互相污染。

## 注意事项

- `ParallelGuard` 不提供公开构造函数。
- 阈值测试必须 reset，避免影响同模块其他测试。
- feature 关闭时模块仍编译，并回落到 Serial 或可用路径。
- `set_parallel_threshold` 与 `set_simd_threshold` 的 "disable" sentinel **不对称**：parallel 用 `0`（admission 检查 `threshold != 0`），simd 用 `usize::MAX`（admission 是 `len >= threshold`）。详见 `30-dispatch.md §5.6` line 511-528。
