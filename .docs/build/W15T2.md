## 目标

实现 `par_map`：`pub(crate)` 单输入并行逐元素映射入口，假定 `dispatch::select_exec_path()` 已选中并行路径，接收已校验的 `ParallelExecStrategy` 和按值移交的 `ParallelGuard`，返回 `Tensor<B, D>`，与串行 `map` 语义一致。

## 实施步骤

### Step 1: 创建 `src/parallel/map.rs` 并定义 `par_map` 签名

签名严格按 09-parallel §5.5 line 157-169。`A: Element + Send + Sync`、`B: Element + Send`、`F: Fn(&A) -> B + Send + Sync`。

```rust
// src/parallel/map.rs
use crate::dispatch::{ParallelExecStrategy, ParallelGuard, with_parallel_worker_context};
use crate::dimension::Dimension;
use crate::element::Element;
use crate::storage::Storage;
use crate::tensor::{Tensor, TensorBase};
use crate::parallel::compute_safe_chunks;

#[cfg(feature = "parallel")]
pub(crate) fn par_map<S, A, B, D, F>(
    tensor: &TensorBase<S, D>,
    strategy: &ParallelExecStrategy,
    _guard: ParallelGuard,
    f: F,
) -> Tensor<B, D>
where
    S: Storage<Elem = A>,
    D: Dimension + Clone,
    A: Element + Send + Sync,
    B: Element + Send,
    F: Fn(&A) -> B + Send + Sync,
{
    // continuation in Step 2-4
    unimplemented!()
}
```

### Step 2: 选定 chunk_size

按 09-parallel §6.3 line 366 决策点：`strategy.chunk_size()` 为 `Some(n)` 时直接覆盖；为 `None` 时调用 `compute_safe_chunks(total, num_threads)`，其中 `num_threads = strategy.max_workers().unwrap_or_else(rayon::current_num_threads)`。策略字段访问通过 W10T3 提供的 `chunk_size()`/`max_workers()` accessor。

```rust
    let total = tensor.len();
    let num_threads = strategy
        .max_workers()
        .unwrap_or_else(rayon::current_num_threads);
    let chunk_size = strategy
        .chunk_size()
        .unwrap_or_else(|| compute_safe_chunks(total, num_threads));
```

### Step 3: 在 Rayon worker 闭包内包裹 `with_parallel_worker_context`

按 09-parallel §6.2 line 318-324 和 30-dispatch §5.4：每个 worker 必须在其 chunk 执行处包裹 `dispatch::with_parallel_worker_context(|| ...)`，使该 worker 自身 TLS 在 chunk 执行期间观测到 `IN_PARALLEL == true`。outer `ParallelGuard` 留在调用线程栈帧，**不被 worker 闭包捕获**（`!Send`，09-parallel line 238、30-dispatch §5.4 line 282）。

### Step 4: 用 indexed collect 写入预分配输出，避免 set_len UB

按 09-parallel §6.7 line 504-505：`IndexedParallelIterator::collect_into_vec` 按索引位置写入，与 worker 完成顺序无关，保证 F-order 输出。**不使用 `Vec::set_len` 后再写入的模式**——否则若闭包 panic，未初始化的 `B` 会被 Drop，违反 §6.7 "Send/Sync/借用边界" 与 Rust 内存安全。Rayon 的 `collect_into_vec` 内部使用 uninit slot + commit 协议，panic-safe（07-tensor §5 `from_raw_vec_unchecked` 的安全前提同时也要求 `Vec` 已初始化且长度一致）。

```rust
    use rayon::iter::IndexedParallelIterator;
    use rayon::iter::ParallelIterator;

    let par_iter = tensor.par_iter().with_strategy(strategy);

    let mut output_data: Vec<B> = Vec::with_capacity(total);
    par_iter
        .with_min_len(chunk_size)
        .map(|src| {
            // Worker TLS: IN_PARALLEL = true for the duration of this map call.
            // Nested select_exec_path() inside f() will fall back to Serial.
            with_parallel_worker_context(|| f(src))
        })
        .collect_into_vec(&mut output_data);

    // SAFETY (07-tensor §5 from_raw_vec_unchecked precondition):
    //   - output_data.len() == total == checked_size(tensor.raw_dim())
    //     (collect_into_vec on an IndexedParallelIterator with len() = total)
    //   - F-order index alignment guaranteed by IndexedParallelIterator
    //     (09-parallel §6.7 line 504-505)
    unsafe { Tensor::from_raw_vec_unchecked(output_data, tensor.raw_dim()) }
```

### Step 5: 单元测试

> **强制要求**:
> - 本步骤必须包含一个或者多个单元测试。
> - 测试函数名称和测试内容必须参考对应设计文档的 **「测试计划」** 一节。
> - 编译检查与Lint检查不等同于单元测试。
> - 如果测试没有通过需要修复直至测试通过。
> - **无测试 = 任务未完成。**

测试依据：09-parallel §8.2 line 597 的 `test_par_map_parallel_path`（高优先级）。`ParallelGuard` 必须通过 `dispatch::select_exec_path()` 获取（30-dispatch §5.7 line 553、W10T1 line 129）——本测试通过 `set_parallel_threshold(1)` 将并行阈值下探至最小正值（30-dispatch §5.6 line 492-499：`threshold == 0` 是"禁用并行"的 sentinel，要强制并行须使用 `>= 1` 的阈值；`len >= 1` 对任何非空张量恒成立），然后从 `select_exec_path` 拿真实 guard。

```rust
#[cfg(all(test, feature = "parallel"))]
mod tests {
    // Cross-wave test convention (PLAN.md §W13 line 423-429 pattern):
    // W15 and W22 share PLAN.md group D. W22T5 `Tensor::from_shape_vec`
    // is NOT available here; use W8T7 `TensorView::from_raw_parts`
    // with a `Vec` backing buffer. Full integration coverage with
    // public APIs is deferred to W29T19 (`tests/test_parallel.rs`).
    use super::*;
    use crate::dispatch::{
        select_exec_path, ExecPath, ParallelExecStrategy,
        set_parallel_threshold, reset_parallel_threshold,
    };
    use crate::dimension::Ix1;
    use crate::layout::Strides;
    use crate::tensor::TensorView;

    #[test]
    fn test_par_map_parallel_path() {
        // Force parallel by lowering the threshold to 1 (the smallest value
        // that still admits the parallel path). 30-dispatch §5.6 line 492-499
        // explicitly defines `threshold == 0` as the "disable parallel"
        // sentinel, so 0 would NOT force parallel — the smallest enabling
        // value is 1, after which any non-empty `len >= 1` qualifies.
        set_parallel_threshold(1);

        let data = vec![1.0f64, 2.0, 3.0, 4.0];
        // SAFETY: F-order [4] view over data; offset = 0; stride 1.
        let tensor = unsafe {
            TensorView::<f64, Ix1>::from_raw_parts(
                data.as_ptr(),
                data.len(),
                Ix1(4),
                Strides::from_slice(&[1_usize]).unwrap(),
                0,
            )
        }
        .expect("valid F-order [4] view");
        // Acquire guard via the only sanctioned path: select_exec_path.
        let (path, guard_opt) = select_exec_path(
            tensor.len(),
            tensor.is_f_contiguous(),
            tensor.is_aligned(),
        );
        assert_eq!(path, ExecPath::Parallel);
        let guard = guard_opt.expect("Parallel implies Some(guard) by 30-dispatch §5.5");

        let strategy = ParallelExecStrategy::auto();
        let result = par_map(&tensor, &strategy, guard, |v| v * 2.0);
        assert_eq!(result.as_slice().unwrap(), &[2.0, 4.0, 6.0, 8.0]);

        reset_parallel_threshold();
    }
}
```

## 关键设计决策

| 决策 | 依据 |
|------|------|
| 只实现本 task 对应切片 | SUMMARY.md 将 W14-W16 拆成单文件粒度任务，避免跨 task 重构 |
| `par_map` 假定 dispatch 已选中并行路径，不重复阈值/嵌套裁决 | 09-parallel §1.1 / §5.2 / §6.1 显式职责边界 |
| 用 `collect_into_vec` 而非 `Vec::set_len + 索引写入` | 09-parallel §6.7 line 504-505 indexed collect 语义 + Rust panic-safety；避免 M1 类 UB |
| 单元测试通过 `set_parallel_threshold(1)` + `select_exec_path` 获取真 guard | 30-dispatch §5.6 line 492-499：`threshold == 0` 是禁用并行的 sentinel，最小启用值是 `1`；§5.7 line 553：`select_exec_path` 是唯一 guard 入口 |
| `ParallelExecStrategy::auto()` 而非 `default()` | 30-dispatch §5.3 line 229 ：`auto()` 是 infallible 默认 |

## 注意事项

- 并行函数假定 dispatch 已选中并行路径。
- Outer `ParallelGuard` 留在调用线程栈帧，**绝不**被 Rayon worker 闭包捕获（`!Send`）。
- 每个 worker 闭包必须包裹 `dispatch::with_parallel_worker_context` 以使 worker TLS 正确（09-parallel §6.2 line 333）。
- `Tensor::from_raw_vec_unchecked` 的 unsafe 前提（07-tensor §5 line 653）由 `collect_into_vec` + `IndexedParallelIterator::len() == total` 共同保证。
- Feature gate 测试必须证明默认构建无 rayon。
- 所有代码注释和 Rust 标识符使用英文。
- 不添加新的第三方依赖。
- 本文件 `src/parallel/map.rs` 由 W15T2 (par_map) 和 W15T3 (par_zip_map) 共享。W15T2 创建文件骨架与 par_map，W15T3 增量添加 par_zip_map。
- **Cross-wave test convention**：W15 与 W22 同处 PLAN.md 可并行组 D，互不可见；W22T5 `Tensor::from_shape_vec` 在本 task 实施期不可用。本 task 单元测试改用 W8T7 `TensorView::from_raw_parts`，对齐 W13T4 先例（PLAN.md §W13 line 423-429）。依赖公开构造 API 的集成测试推迟到 W29T19。
