## 实施步骤

### Step 1: Add doc comments to all pub complex items

为下面清单中**每一项**补齐 `///` doc comment。每项 doc 必须包含「内容」列中的所有要点。完成本步骤前不要标记 task 为已完成。

#### `src/complex/mod.rs` — mandatory doc items

| Pub item | Required content |
|----------|-----------------|
| `Complex<T>` struct | Memory layout (`#[repr(C)]`)、字段含义、支持类型 (`f32`, `f64`)、构造示例。W5T13 已附加 8 个 `compile_fail` 块（type-safety section），不要删除。 |
| `Complex::new(re, im)` | 参数说明 + 最小示例；`const fn` 说明 |
| `Complex::re(self)` | 返回实部 |
| `Complex::im(self)` | 返回虚部 |
| `Complex::from_imag(im)` | `re=0` 的复数构造 + 示例 |
| `Complex::conj(self)` | 共轭 `a - bj` + 示例 |
| `Complex::is_real(self)` | `im == 0`，注：`0` 既是 real 也是 imaginary |
| `Complex::is_imaginary(self)` | `re == 0` |
| `Complex<f32>::norm(self)` | 欧氏模，使用 `hypot()` 避免溢出 |
| `Complex<f32>::norm_sqr(self)` | 平方模 `re² + im²`，不开方 |
| `Complex<f32>::is_nan(self)` | 任一分量为 NaN 即返回 true |
| `Complex<f32>::is_finite(self)` | 两个分量都 finite 才返回 true |
| `Complex<f64>::norm(self)` | 同 `Complex<f32>::norm` |
| `Complex<f64>::norm_sqr(self)` | 同 `Complex<f32>::norm_sqr` |
| `Complex<f64>::is_nan(self)` | 同 `Complex<f32>::is_nan` |
| `Complex<f64>::is_finite(self)` | 同 `Complex<f32>::is_finite` |
| `ComplexFloat` trait | Sealed marker trait，仅供 `f32` / `f64` 使用；W5T2 已写入的 sealed `compile_fail` doctest 必须保留 |
| `From<T> for Complex<T>` | 实数提升为复数 (`im = 0`)，是唯一允许的标量→复数显式构造路径 |
| `PartialEq for Complex<T>` | IEEE 754 component-wise 比较；保留 `NaN != NaN` |
| `Display for Complex<T>` | 按 `04-complex §5.9` 表格描述 6 种基础输出 + NaN + precision；说明 `-0.0` 保留符号；注明 `PositiveZero` 是 `pub(crate)` helper |

> `PositiveZero` trait 是 `pub(crate)`，仍然需要简单 doc comment（说明它是 implementation detail，不暴露为公开扩展点），但不会出现在 `cargo doc` 公开 HTML 中。

#### `src/complex/ops.rs` — mandatory doc items

| Pub item | Required content |
|----------|-----------------|
| `Add for Complex<T>` | Component-wise: `(a+bj) + (c+dj) = (a+c)+(b+d)j` |
| `Sub for Complex<T>` | Component-wise subtraction |
| `Mul for Complex<T>` | `(ac-bd)+(ad+bc)j` (参见 §5.6) |
| `Div for Complex<f32>` | Smith 算法独立在 f32 上完成，避免中间溢出；**不**委托到 f64 |
| `Div for Complex<f64>` | Smith 算法独立在 f64 上完成；分支根据 `|re| >= |im|` 选择 |
| `Neg for Complex<T>` | Component-wise negation: `-(a+bj) = -a-bj` |

#### Struct doc example skeleton

```rust
/// Complex number represented as `re + im*j`.
///
/// # Supported types
///
/// Only `Complex<f32>` and `Complex<f64>` are supported, enforced by
/// the sealed [`ComplexFloat`] trait.
///
/// # Memory layout
///
/// `#[repr(C)]` keeps this type layout-compatible with a two-field C struct
/// `{ T re; T im; }`. Size is `2 * size_of::<T>()`; alignment matches `T`.
///
/// # Examples
///
/// ```
/// use xenon::complex::Complex;
/// let z = Complex::new(3.0_f64, 4.0);
/// assert_eq!(z.norm(), 5.0);
/// ```
///
/// # Type safety: real-complex mixed arithmetic is rejected at compile time
///
/// [Existing 8 `compile_fail` blocks from W5T13 stay here unchanged.]
#[repr(C)]
pub struct Complex<T: ComplexFloat> {
    pub re: T,
    pub im: T,
}
```

## 关键设计决策

| 决策 | 依据 |
|------|------|
| 只支持 `Complex<f32>` 与 `Complex<f64>` | `04-complex §5.2` 使用 sealed `ComplexFloat` 封闭实现范围 |
| 运算符仅实现 `Complex<T> op Complex<T>` | `04-complex §1.1` 和 §5.6 明确混合实复运算需显式构造 |
| `norm()` 使用 `hypot()` | `04-complex §1.2` 和 §5.5 要求避免中间溢出 |
| `Div for Complex<f32>` 的描述使用"independent Smith algorithm" | W5T11 实现独立 f32 Smith 算法；**不**沿用旧的"delegates to f64"措辞 |
| 文档清单同时覆盖 `is_nan` / `is_finite` | W5T14 新增的 concrete 方法属于 `04-complex §5.4` 公共 API |
| 保留 W5T2 与 W5T13 已写入的 `compile_fail` 块 | 它们是设计 §8.7 sealed/boundary 编译期测试的载体 |

## 验证方式

1. 文档生成: `cargo doc --no-deps -p xenon` — 确认无 broken intra-doc link 或 missing-docs warning
2. 编译检查: `cargo check`
3. Lint 检查: `cargo clippy --all-targets`
4. 文档测试: `cargo test --doc complex` — 正向 doctest 通过；`compile_fail` 块"成功未能编译"
5. 单元测试: `cargo test --lib complex::tests::test_complex_docs_compile_example`
6. 手动验证: 打开 `target/doc/xenon/complex/index.html`，逐项对照本 task 文档清单确认每个公开项的文档页面存在且无空白

## 注意事项

- 不实现跨精度运算，也不实现 `Complex<T> op T` 便捷运算符。
- `NaN != NaN` 由底层浮点 `PartialEq` 自然保证，不要实现 `Eq`。
- FFI 布局测试由 W5T3 覆盖 size、align 和字段偏移。
- **不要**删除或简化 W5T2 (sealed) 与 W5T13 (boundary) 已经写入的 `compile_fail` doctest 块。
- **不要**保留旧的 "delegates to f64" 措辞描述 `Div for Complex<f32>` —— W5T11 已修正为独立算法。
- 若 `cargo doc` 报出 "missing docs" warning，必须修复直至 warning 清零（项目 `missing_docs = warn` 由 W1T3 设定）。
