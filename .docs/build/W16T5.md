## 实施步骤

### Step 1: Import the type-changing traversal skeleton from `math::helpers`

W16T1 在 `src/math/helpers.rs` 中提供 `apply_complex_to_real`
（`pub(in crate::math)`）——`modulus` 的 `Complex<T> → T` 遍历骨架。本 task
**不**重复定义。

```rust
use crate::complex::Complex;
use crate::dimension::Dimension;
use crate::element::{ComplexScalar, Numeric, RealScalar};
use crate::math::helpers::{apply_complex_to_real, apply_unary};
use crate::storage::Storage;
use crate::tensor::{Tensor, TensorBase};
```

> `ComplexScalar` 的关联类型名为 **`Real`**（03-element.md §5.4 line 376）——
> 本 task 直接使用 `<A as ComplexScalar>::Real` 或通过 `T: RealScalar` 锚定。

### Step 2: Implement `modulus` for `TensorBase<S, D>` where `Elem = Complex<T>`

设计 §5.6 line 287-296 定义 `modulus` 的精确签名：泛型于 `T: RealScalar`，
返回 `Tensor<T, D>`。

```rust
impl<S, D, T> TensorBase<S, D>
where
    S: Storage<Elem = Complex<T>>,
    D: Dimension,
    T: RealScalar,
    Complex<T>: ComplexScalar<Real = T>,
{
    /// Element-wise modulus: `|a + bi| = sqrt(a*a + b*b)`.
    /// Returns a real tensor of the same dimension.
    pub fn modulus(&self) -> Tensor<T, D> {
        apply_complex_to_real(self, |c| c.norm())
    }
}
```

> `ComplexScalar::norm` 是 scalar 级方法（03-element.md §5.4 line 380），
> 张量级公开 API 命名为 `modulus`（11-math §5.6 line 319）—— 两者命名差异
> 是有意的：`modulus` 对应需求说明书 §12 的"模"，`norm` 是 scalar 一致接口。
> 等式 `Complex<T>: ComplexScalar<Real = T>` 在 where 子句中显式锚定 Real
> 关联类型，单态化时 Tensor 输出元素类型直接收敛到 `T`，避免冗余推导。

### Step 3: Implement `conjugate` for `Complex<f32>` and `Complex<f64>` tensors (two independent impls)

设计 §5.6 line 298-314 显式列出**两个独立**的 `impl` 块（按 W5T11 模式：
`Complex<f32>` 与 `Complex<f64>` 各自独立 impl，避免委托）。函数体调用
`<Complex<T> as Numeric>::conjugate` 统一共轭入口（03-element §5.2 line
310 / §5.5 line 773），**不**在 math 层重新实现 `(re, -im)` 构造，保持
DRY 与"统一共轭入口"设计意图（03-element §5.2 line 319-321）。

```rust
impl<S, D> TensorBase<S, D>
where
    S: Storage<Elem = Complex<f32>>,
    D: Dimension,
{
    /// Element-wise complex conjugate: `(a + bi) → (a - bi)`.
    /// Delegates to `Numeric::conjugate` per 03-element §5.2.
    pub fn conjugate(&self) -> Tensor<Complex<f32>, D> {
        apply_unary(self, |c| <Complex<f32> as Numeric>::conjugate(c))
    }
}

impl<S, D> TensorBase<S, D>
where
    S: Storage<Elem = Complex<f64>>,
    D: Dimension,
{
    /// Element-wise complex conjugate.
    pub fn conjugate(&self) -> Tensor<Complex<f64>, D> {
        apply_unary(self, |c| <Complex<f64> as Numeric>::conjugate(c))
    }
}
```

> 这两份 impl 函数体相同但**不可合并**为单一泛型 impl，因为公开 API 命名
> 承诺只针对 `Complex<f32>` / `Complex<f64>` 这两个具体类型（设计 §5.6
> line 317）。

### Step 4: Do NOT expose a public real-number `conjugate` tensor method

设计 §5.6 line 318 明确：实数（i32/i64/f32/f64）类型的共轭等于自身，Xenon
**不**为实数张量提供 `conjugate()` 入口；要求显式调用，避免冗余 API。需要
跨类型统一处理时由调用方通过 `Numeric::conjugate()`（scalar 级，03-element
§5.3）在泛型代码中调用。本 task 不实现 `TensorBase<S, D> where ... A: RealScalar`
的 `conjugate` 方法。

### Step 5: 单元测试

添加覆盖设计文档测试计划的单元测试，至少包含正常路径和一个边界或回退场景。

```rust
#[cfg(test)]
mod tests {
    use super::*;
    use crate::Tensor;
    use crate::complex::Complex;
    use crate::dimension::Ix1;

    #[test]
    fn test_modulus() {
        // |3 + 4i| = 5.0 — tensor-level API.
        let t = Tensor::<Complex<f64>, Ix1>::from_shape_vec(
            [1], vec![Complex::new(3.0_f64, 4.0)],
        ).unwrap();
        let r = t.modulus();
        assert!((r[[0]] - 5.0).abs() < 1e-10,
            "modulus(3+4i) should be 5.0, got {}", r[[0]]);
    }

    #[test]
    fn test_conjugate() {
        // Complex{1, 2}.conjugate() = Complex{1, -2}.
        let t = Tensor::<Complex<f64>, Ix1>::from_shape_vec(
            [1], vec![Complex::new(1.0_f64, 2.0)],
        ).unwrap();
        let r = t.conjugate();
        assert_eq!(r[[0]].re(), 1.0);
        assert_eq!(r[[0]].im(), -2.0);
    }
}
```
