## 实施步骤

### Step 1: 定位实现边界

在 `src/element/mod.rs` 中集中建立 `element` 模块骨架，导入共享 `Sealed`，并定义以下 §5 公开 API 的 **trait 签名与枚举类型**（不含具体类型 impl）：
- §5.1 `Element` trait + §5.1.2 `ElementType` 枚举 + `element_type_of` / `element_type_name_of` 自由函数
- §5.5 `OrderedCompareElement` trait（仅 trait 定义；4 个具体类型 impl 由 W4T11 在 calibrate 阶段集中落地，详见 W4T11.md Step 3）
- §5.9 `CastTo<T>` trait（仅 trait 定义，具体 impl 由 `21-type.md` Wave 负责，**不**在本 Wave 实现）

本任务不提前实现 `Numeric`、`RealScalar`、`ComplexScalar`；这些 trait 由 W4T2/W4T3/W4T4 在独立子模块文件中落地。

`ElementType` 枚举必须保持 `#[repr(u8)]`、`#[non_exhaustive]`，并包含 §5.1.2 指定的 7 个判别值：`Bool = 0`、`I32 = 1`、`I64 = 2`、`F32 = 3`、`F64 = 4`、`Complex32 = 5`、`Complex64 = 6`。

### Step 2: 实现 Element trait 与 ElementType 枚举（§5.1）

按 `03-element.md` §5.1 定义基础 trait 与类型判别枚举。`Element` 必须继承 `Sealed`，让元素类型集合保持 crate 内封闭；`Copy + Clone + PartialEq + Debug + Display + Send + Sync` 是所有后续数值 trait 的共同基础约束。

```rust,ignore
use crate::private::Sealed;

/// Base trait for all tensor element types.
pub trait Element:
    Copy
    + Clone
    + PartialEq
    + core::fmt::Debug
    + core::fmt::Display
    + Send
    + Sync
    + Sealed
{
    fn zero() -> Self;
    fn one() -> Self;
    const ELEMENT_TYPE: ElementType;
    const ELEMENT_TYPE_NAME: &'static str;
}

#[derive(Clone, Copy, Debug, PartialEq, Eq, Hash)]
#[repr(u8)]
#[non_exhaustive]
pub enum ElementType {
    Bool = 0,
    I32 = 1,
    I64 = 2,
    F32 = 3,
    F64 = 4,
    Complex32 = 5,
    Complex64 = 6,
}

impl ElementType {
    /// Canonical name of the variant.
    pub const fn name(self) -> &'static str {
        match self {
            ElementType::Bool       => "bool",
            ElementType::I32        => "i32",
            ElementType::I64        => "i64",
            ElementType::F32        => "f32",
            ElementType::F64        => "f64",
            ElementType::Complex32  => "Complex<f32>",
            ElementType::Complex64  => "Complex<f64>",
        }
    }

    /// Discriminant for element type `A`.
    pub const fn of<A: Element>() -> Self {
        A::ELEMENT_TYPE
    }
}

impl core::fmt::Display for ElementType {
    fn fmt(&self, f: &mut core::fmt::Formatter<'_>) -> core::fmt::Result {
        f.write_str(self.name())
    }
}

/// Free function returning the `ElementType` discriminant for `A`.
pub const fn element_type_of<A: Element>() -> ElementType {
    A::ELEMENT_TYPE
}

/// Free function returning the canonical name for `A`.
pub const fn element_type_name_of<A: Element>() -> &'static str {
    A::ELEMENT_TYPE_NAME
}
```

`zero()` / `one()` 只声明元素 identity，不在本任务内扩展具体类型实现；`ELEMENT_TYPE` 面向编译期类型判别与 FFI 映射；`ELEMENT_TYPE_NAME` 是错误诊断使用的 canonical name，后续 primitive impl 必须与 `ElementType::name()` 保持一致。

### Step 3: 添加 OrderedCompareElement trait（§5.5）

按 `03-element.md` §5.5 定义 `OrderedCompareElement` 公开 sealed trait，用于把有序比较能力显式收敛到 `i32`、`i64`、`f32`、`f64`。本任务只定义 trait 签名，4 个具体类型的 impl 由 W4T11 在 calibrate 阶段与 `CastElement`、`BoolElement` 一起集中落地（见 W4T11.md Step 3）。

```rust,ignore
/// Marker trait for element types that support ordered comparison.
///
/// Only `i32`, `i64`, `f32`, `f64` implement this trait.
/// Used by `11-math.md` `less()` / `greater()` comparison APIs.
pub trait OrderedCompareElement: Element + PartialOrd + Sealed {}
```

**注意**：本任务不写 `impl OrderedCompareElement for i32 {}` 等 4 个 impl 块；这些 impl 由 W4T11 在 `src/element/primitives.rs` 中与 `CastElement`、`BoolElement` 的 marker trait impl 一起集中落地（见 W4T11.md Step 3）。

### Step 4: 添加 CastTo<T> trait（§5.9）

按 `03-element.md` §5.9 定义 `CastTo<T>` trait 签名。本任务只定义 trait 骨架，所有具体 impl（36 个转换对）由 `21-type.md` Wave 负责实现。

```rust,ignore
use crate::error::XenonError;

/// Type conversion trait for element types.
///
/// Defines fallible conversion between element types. Lossy conversions
/// (e.g., f64 → i32 truncation, overflow) return `Err(XenonError::TypeConversion)`.
///
/// Sealed: only Xenon's closed element set may implement this trait.
/// Concrete impls are provided by `21-type.md` (Type Conversion Wave).
pub trait CastTo<T: Element>: Element {
    /// Attempts to convert `self` to type `T`.
    ///
    /// # Errors
    /// Returns `XenonError::TypeConversion` if the conversion is lossy or
    /// the value cannot be represented in the target type.
    fn cast_to(self) -> Result<T, XenonError>;
}
```

**注意**：
- `CastTo<T>` 的具体 impl 不在本 Wave 实现，由 `21-type.md` 负责
- `CastElement` marker trait（§5.9.1）由 W4T11 在 calibrate 阶段添加（因为需要 Complex 类型已知）

### Step 5: 补齐导出与相邻调用点

`src/element/mod.rs` 是本任务的权威定义文件：在同一文件内集中声明 `Element`、`ElementType`、`OrderedCompareElement`、`CastTo<T>`，并引入共享 sealed trait 与错误类型。不要在本任务中声明 `numeric`、`real`、`complex` 子模块；这些模块由后续任务分别补齐。

## 关键设计决策

1. **trait 签名集中定义**：依据 §5.1/§5.5/§5.9，`Element`、`OrderedCompareElement`、`CastTo<T>` 三个公开 trait 的签名集中在 `mod.rs`，具体类型 impl 分散到 `primitives.rs`（W4T5+）和 `convert/cast.rs`（W21）。
2. **CastTo 延迟实现**：`CastTo<T>` trait 定义在 W4，但 36 个转换对的 impl 由 `21-type.md` Wave 负责，避免 W4 范围膨胀。
3. **OrderedCompareElement 无 impl**：本任务只定义 trait，4 个 impl（i32/i64/f32/f64）由 W4T11 在 calibrate 阶段集中落地（与 CastElement、BoolElement 一起），避免分散到多个任务导致遗漏。
