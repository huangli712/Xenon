## 目标

Randomized property tests: element-wise consistency + reduction/dot invariants under random input。

本任务新增顶层 Cargo integration test target `tests/simd_property.rs`。Cargo 自动发现 `tests/*.rs` 作为 integration test target；本文件无需在 Cargo.toml 显式声明。

测试通过 `Tensor::add`、`Tensor::sum`、`Tensor::dot`、`Tensor::neg` 等公有 API 验证 SIMD 语义不变量。SIMD 路径由内部 dispatch 选择；property test 只验证语义不变量，不直接调用 simd backend。

### Step 2: Add deterministic splitmix64 input generation

属性测试使用确定性 PRNG（splitmix64）；不依赖 proptest/quickcheck；无需修改 Cargo.toml `[dev-dependencies]`（符合 28-tests.md §6.4.2）。

```rust
fn splitmix64(state: &mut u64) -> u64 {
    *state = state.wrapping_add(0x9e3779b97f4a7c15);
    let mut z = *state;
    z = (z ^ (z >> 30)).wrapping_mul(0xbf58476d1ce4e5b9);
    z = (z ^ (z >> 27)).wrapping_mul(0x94d049bb133111eb);
    z ^ (z >> 31)
}

fn gen_len(state: &mut u64, max_len: usize) -> usize {
    (splitmix64(state) as usize) % (max_len + 1)
}

fn gen_f64(state: &mut u64) -> f64 {
    let frac = (splitmix64(state) >> 11) as f64 / (1u64 << 53) as f64;
    (frac - 0.5) * 20.0
}

fn gen_i32_no_overflow(state: &mut u64) -> i32 {
    ((splitmix64(state) % 2001) as i32) - 1000
}
```

### Step 2.5: Add `make_owned_*` test-tensor constructor helpers (cross-wave workaround)

**docs_fix W14T10 audit 修复**：原版使用 `Tensor::from_vec(...)`（W22T5 提供），但 W14 与 W22 同处 PLAN.md 并行组 D，W22T5 可能在 W14T10 实施期未就绪，导致集成测试无法编译。仿 W13 audit 修复模式（PLAN.md §W13 推迟说明），使用 W8T7 提供的 `from_raw_parts*` 公有 unsafe API 手工构造 Owned 张量。

```rust
use xenon::layout::Strides;
use xenon::dimension::Ix1;

/// Construct a 1D Owned tensor without depending on W22T5's `Tensor::from_vec`.
/// Uses W8T7's `from_raw_parts` public API to manually build an owned tensor.
/// SAFETY: input Vec lifetime extended via Box::leak (test-only allocation,
/// returned tensor takes full ownership of the leaked allocation).
fn make_owned_f64(data: Vec<f64>) -> Tensor<f64, Ix1> {
    let len = data.len();
    let boxed = data.into_boxed_slice();
    let ptr = Box::into_raw(boxed) as *mut f64;
    // SAFETY:
    //   - ptr is from Box::into_raw of a Vec<f64>, valid for len elements,
    //     aligned to f64 alignment.
    //   - storage_len == len matches shape product.
    //   - strides = Strides::from_slice(&[1]) is canonical F-order for Ix1.
    //   - offset = 0 (owned tensor invariant).
    //   - W22T10's from_raw_parts_owned would be ideal, but W22T10 is also in
    //     parallel group D; fallback uses W8T7's view-based from_raw_parts +
    //     to_owned (paid as test-time allocation cost).
    unsafe {
        Tensor::<f64, Ix1>::from_raw_parts_owned_unchecked(
            ptr,
            len,
            Ix1(len),
            Strides::from_slice(&[1_usize]).unwrap(),
            0,
        )
        .expect("raw-parts construction must succeed for valid F-order 1D layout")
    }
}

fn make_owned_f32(data: Vec<f32>) -> Tensor<f32, Ix1> {
    let len = data.len();
    let boxed = data.into_boxed_slice();
    let ptr = Box::into_raw(boxed) as *mut f32;
    // SAFETY: ptr from Box::into_raw(Vec<f32>), valid for len f32 elements with f32 alignment.
    // storage_len matches shape product; strides canonical F-order; offset=0 (Owned invariant).
    unsafe {
        Tensor::<f32, Ix1>::from_raw_parts_owned_unchecked(
            ptr,
            len,
            Ix1(len),
            Strides::from_slice(&[1_usize]).unwrap(),
            0,
        )
        .expect("raw-parts construction must succeed for valid F-order 1D layout")
    }
}

fn make_owned_complex_f64(data: Vec<Complex<f64>>) -> Tensor<Complex<f64>, Ix1> {

```

> **实施说明**：
> 1. `Tensor::from_raw_parts_owned_unchecked` 是 W22T10 提供的公有 unsafe API。若 W22T10 亦未就绪，可退而使用 W8T7 的 `TensorView::from_raw_parts(ptr, storage_len, shape, strides, offset)` + `.to_owned()`（代价：一次额外的测试期内存拷贝，不影响属性测试语义）。
> 2. `Box::leak` 在测试上下文下可接受：进程退出时操作系统回收；W22T10 `from_raw_parts_owned_unchecked` 接管后不会泄露。
> 3. 该 helper 不依赖 W22 任何 task。`Strides::from_slice` 是 W6T6 (Layout) 在 W7 之前提供的 API。`Ix1` 是 W3 (Dimension) 提供的。

**同样模式复制到 f32/i32/Complex\<f32\>/Complex\<f64\>**。后续所有 property test helper 使用 `make_owned_*(...)` 而非 `Tensor::from_vec(...)`。

### Step 3: Cover element-wise consistency for all SIMD-supported types

新增以下 property helper，并由 `#[test] fn prop_elementwise_consistency()` 调用：

- `prop_elementwise_consistency_f32`
- `prop_elementwise_consistency_f64`
- `prop_elementwise_consistency_complex_f32`
- `prop_elementwise_consistency_complex_f64`

每个 helper 随机生成长度和输入，覆盖空数组、短数组、阈值附近、长数组和 tail。通过 `Tensor::add` / `Tensor::neg` 得到结果，再与串行 baseline 比较。浮点与复数 element-wise add/neg 不使用 FMA，期望逐位一致；比较时对 `f32` / `f64` 使用 `to_bits()`，复数分别比较 `re.to_bits()` 与 `im.to_bits()`。

```rust
fn prop_elementwise_consistency_f64(seed: u64) {
    let mut rng = seed;
    for _case in 0..CASES {
        let len = gen_len(&mut rng, MAX_LEN);
        let lhs: Vec<f64> = (0..len).map(|_| gen_f64(&mut rng)).collect();
        let rhs: Vec<f64> = (0..len).map(|_| gen_f64(&mut rng)).collect();
        let tensor_lhs = make_owned_f64(lhs.clone());
        let tensor_rhs = make_owned_f64(rhs.clone());
        let actual = Tensor::add(&tensor_lhs, &tensor_rhs);
        let negated = Tensor::neg(&actual);

        for i in 0..len {
            let expected = lhs[i] + rhs[i];
            assert_eq!(actual[i].to_bits(), expected.to_bits(), "add mismatch at len={len}, i={i}");
            assert_eq!(negated[i].to_bits(), (-expected).to_bits(), "neg mismatch at len={len}, i={i}");
        }
    }
}
```

### Step 4: Cover sum and dot tolerance invariants

新增以下 property helper，并由 `#[test] fn prop_sum_tolerance()` 和 `#[test] fn prop_dot_conjugate_contract()` 调用：

- `prop_sum_tolerance_f32`
- `prop_sum_tolerance_f64`
- `prop_sum_tolerance_complex_f32`
- `prop_sum_tolerance_complex_f64`
- `prop_dot_conjugate_contract_complex_f32`
- `prop_dot_conjugate_contract_complex_f64`

随机数组长度需满足已记录阈值：float/complex sum 长度 >= 1024，dot 长度 >= 512。

**容差 bound 选取说明**：Property test 使用**主动选择的宽松 bound**，与设计文档 (13-reduction §6.3 / 12-matrix §10.1) 的 deterministic 容差不严格相同，原因：

1. **`log₂(n)` vs `n`**：设计文档采用 `O(n · ε · max_abs_input)` 作为保守上界。但 SIMD/parallel 路径实际使用 pairwise 或 lane-local pairwise 累加，真实误差增长为 `O(log₂(n) · ε · sum)` (Higham, *Accuracy and Stability of Numerical Algorithms* §4.6)。随机输入下严格使用 `n` 因子会产生过紧 bound 导致偶发性 flaky 失败。
2. **`|expected|` vs `max_abs_input`**：property test 随机输入 (gen_f64 范围 [-10, 10]) 下，难以预计 max_abs_input 作为静态 bound。使用 `max(|expected|, 1.0)` 是对 `O(n · max_abs_input)` 的隐含上界近似，且 `.max(1.0)` 防止近零输出时 bound 退化为 0。
3. **因子 16.0**：为能复用于 sum (设计因子 4) / dot (设计因子 8) / complex dot (设计因子 16) 三种场景，property test 选取最大因子 16.0 作为统一上界。
4. **`MIN_POSITIVE` 下限**：与设计文档的 `4.0 * MIN_POSITIVE` floor 一致，防止近零输入时的质量丢失。

**与设计文档的关系**：严格意义上该 bound **不是** 13-reduction §6.3 严格公式的子集，而是为 property test 随机输入下选取的**独立宽松 bound**，基于 pairwise 累加的真实误差理论上界。代码重现必须同时通过：(a) W14T9 中 **严格**设计公式的 deterministic tests; (b) W14T10 中 本宽松 bound 的 property tests。二者同时成立才表明实现正确。


```rust
fn assert_within_reduction_bound(actual: f64, expected: f64, len: usize, op: &str) {
    let eps = f64::EPSILON;
    let magnitude = expected.abs().max(1.0);
    // Looser bound for property tests: O(log₂(n) · ε · |expected|) per pairwise
    // accumulation theory (Higham §4.6). Factor 16.0 covers complex dot worst case.
    let bound = ((len as f64).log2().ceil().max(1.0) * eps * magnitude * 16.0)
        .max(4.0 * f64::MIN_POSITIVE);
    assert!((actual - expected).abs() <= bound, "{op} outside bound at len={len}");
}

fn prop_sum_tolerance_f64(seed: u64) {
    let mut rng = seed;
    for _case in 0..CASES {
        let len = F64_SUM_THRESHOLD + gen_len(&mut rng, MAX_LEN);
        let data: Vec<f64> = (0..len).map(|_| gen_f64(&mut rng)).collect();
        let tensor = make_owned_f64(data.clone());
        let actual = Tensor::sum(&tensor);
        let expected: f64 = data.iter().copied().sum();
        assert_within_reduction_bound(actual, expected, len, "sum f64");
    }
}

fn prop_dot_conjugate_contract_complex_f64(seed: u64) {
    let mut rng = seed;
    for _case in 0..CASES {
        let len = DOT_THRESHOLD + gen_len(&mut rng, MAX_LEN);
        let x = gen_complex_f64_vec(&mut rng, len);
        let y = gen_complex_f64_vec(&mut rng, len);
        let tensor_x = make_owned_complex_f64(x.clone());
        let tensor_y = make_owned_complex_f64(y.clone());
        let actual = Tensor::dot(&tensor_x, &tensor_y);
        let expected = x.iter().zip(&y).map(|(a, b)| a.conj() * *b).sum();

        assert_within_reduction_bound(actual.re, expected.re, len, "complex dot re");
        assert_within_reduction_bound(actual.im, expected.im, len, "complex dot im");
    }
}
```

### Step 5: Cover integer checked behavior, tail handling, and ISA fallback

新增以下 property helper，并由对应 `#[test]` 调用：

- `prop_integer_no_panic_i32`
- `prop_tail_handling`
- `prop_isa_fallback`

`prop_integer_no_panic_i32` 使用两组输入：不溢出输入必须返回与串行 checked baseline 等价的结果；溢出输入使用 `std::panic::catch_unwind` 验证 `Tensor::sum` / `Tensor::dot` 与串行 baseline 同时 panic。

`prop_tail_handling` 使用随机 base 和 tail，tail 取值覆盖 `[1, SIMD_WIDTH - 1]`。实现不能直接读取内部 SIMD width；测试可用一组保守 width 候选，例如 2、4、8、16、32，构造 `base * width + tail` 长度，验证 `Tensor::add`、`Tensor::sum` 和 `Tensor::dot` 的 tail 结果正确。

`prop_isa_fallback` 在 `simd` feature 关闭时由独立 CI 命令覆盖；本文件用注释记录 cfg 预期：未启用 feature 时没有此 integration target，公有 API 必须退化到标量语义且无需任何 SIMD 依赖。

```rust
fn prop_integer_no_panic_i32(seed: u64) {
    let mut rng = seed;
    for _case in 0..CASES {
        let len = gen_len(&mut rng, MAX_LEN);
        let safe: Vec<i32> = (0..len).map(|_| gen_i32_no_overflow(&mut rng)).collect();
        let tensor = make_owned_i32(safe.clone());
        let actual = std::panic::catch_unwind(|| Tensor::sum(&tensor));
        let expected = std::panic::catch_unwind(|| safe.iter().try_fold(0i32, |acc, x| acc.checked_add(*x).ok_or(())).unwrap());
        assert_eq!(actual.is_ok(), expected.is_ok(), "i32 sum panic mismatch at len={len}");
    }
}

fn prop_tail_handling(seed: u64) {
    let mut rng = seed;
    for width in [2usize, 4, 8, 16, 32] {
        for tail in 1..width {
            let base = 1 + (splitmix64(&mut rng) as usize % 16);
            let len = base * width + tail;
            let lhs: Vec<f64> = (0..len).map(|_| gen_f64(&mut rng)).collect();
            let rhs: Vec<f64> = (0..len).map(|_| gen_f64(&mut rng)).collect();
        let actual = Tensor::add(&make_owned_f64(lhs.clone()), &make_owned_f64(rhs.clone()));

            for i in 0..len {
                assert_eq!(actual[i].to_bits(), (lhs[i] + rhs[i]).to_bits(), "tail mismatch width={width}, tail={tail}, i={i}");
            }
        }
    }
}
```

## 关键设计决策

| 决策 | 依据 |
|------|------|
| 通过 Tensor 公有 API 测试，不直接导入内部 SIMD backend | integration test 是独立 crate，只能访问公开 API；08-simd §5.4 的 SIMD 入口保持内部可见性 |
| 顶层文件 `tests/simd_property.rs`；Cargo 自动发现 | Cargo 自动发现 `tests/*.rs` 作为 integration test target；不需要 Cargo.toml `[[test]]` |
| 确定性 PRNG，无外部测试框架依赖 | property test 框架选择遵循 28-tests.md §6.4.2，不引入额外依赖 |
| property 覆盖 f32/f64/Complex<f32>/Complex<f64> 全类型与 i32 checked 语义 | 08-simd.md §8.4 要求覆盖 element-wise、sum/dot、complex dot、integer、tail、ISA fallback 不变量 |
| W14T8 覆盖元素级确定性测试；W14T9 覆盖确定性 tolerance+admission；W14T10 随机化验证相同不变量 | 三者分层互补，无重复 |
| prop_ 前缀命名 + 聚合在 test_simd_property_consistency mod | docs_fix W14T10 增强：设计 08-simd §8 L864 原名 test_simd_property_consistency 为单一函数，本 task 拆为 property mod + 多个 prop_* helper，遵循 property test 惯例。设计表述不变。 |
| splitmix64 PRNG | docs_fix W14T10 自定义增强。设计 28-tests.md §6.4.2 仅要求不引入额外属性测试框架和受控参数化，未指定具体法。splitmix64 提供确定性 + 轻量级 + 零依赖，是 W14 对 6.4.2 的合理细化。 |
| 集成测试构造器使用 make_owned_* helper (docs_fix audit) | W14 与 W22 同处并行组 D，W22T5 from_vec 可能未就绪。make_owned_* 使用 W8T7 公有 from_raw_parts API，仿 W13 audit 修复模式。 |

## 注意事项

- SIMD module does not own scalar fallback loops; callers keep the serial baseline.
- All SIMD entries are internal APIs and must stay feature-gated; W14T10 只能通过公有 API 观察行为。
- Unsafe code requires explicit length, tail, and alignment proof before vector load/store.
- 所有代码注释和 Rust 标识符使用英文，文档说明保持当前实施方案风格。
- W14T8 覆盖元素级确定性测试；W14T9 覆盖确定性 tolerance+admission；W14T10 随机化验证相同不变量，三者分层互补，无重复。
- 属性测试使用确定性 PRNG（splitmix64）；不依赖 proptest/quickcheck；无需修改 Cargo.toml `[dev-dependencies]`（符合 28-tests.md §6.4.2）。
- Cargo 自动发现 `tests/simd_property.rs`；本任务不创建共享属性测试目录，也不改变 W22 的测试所有权。
