## 实施步骤

### Step 1: 建立目标文件骨架

按 27-benchmark §5.1 和 §5.8 的 `harness = false` 模式创建或更新目标文件，保留 `--quick` 与名称 filter 入口，确保单个 bench 可独立运行。

```rust
use std::hint::black_box;

use xenon::prelude::*;

mod utils;
use utils::{generators, run_timed, SIZES_1D};

fn bench_dot_1d_f64(quick: bool) {
    for &size in SIZES_1D {
        let lhs = generators::sequential_1d(size);
        let rhs = generators::sequential_1d(size);
        let median = run_timed(quick, || {
            // 12-matrix.md §5: dot(&self, other) -> Result<A, XenonError>
            let _result = black_box(lhs.dot(&rhs).expect("same-length 1D dot must succeed"));
        });
        println!("dot_1d_f64/{size}: {median} ns");
    }
}

fn bench_dot_1d_complex(quick: bool) {
    for &size in SIZES_1D {
        let lhs = generators::complex_1d(size);
        let rhs = generators::complex_1d(size);
        let median = run_timed(quick, || {
            // 12-matrix.md §5: dot(&self, other) -> Result<A, XenonError>
            let _result = black_box(lhs.dot(&rhs).expect("same-length 1D dot must succeed"));
        });
        println!("dot_1d_complex/{size}: {median} ns");
    }
}

fn should_run(filter: Option<&str>, name: &str) -> bool {
    filter.map_or(true, |needle| name.contains(needle))
}

fn main() {
    let args = std::env::args().skip(1).collect::<Vec<_>>();
    let quick = args.iter().any(|arg| arg == "--quick");
    let filter = args.iter().find(|arg| !arg.starts_with("--")).map(String::as_str);

    if should_run(filter, "dot_1d_f64") { bench_dot_1d_f64(quick); }
    if should_run(filter, "dot_1d_complex") { bench_dot_1d_complex(quick); }
}
```

### Step 2: 覆盖 benchmark 参数矩阵

Step 1 的 `bench_dot_1d_f64` 与 `bench_dot_1d_complex` 均遍历 `SIZES_1D`（对齐 27-benchmark §5.4.1 Small/Medium/Large 与 §5.5 `dot_1d_f64` / `dot_1d_complex` 行），在 hot loop 内用 `std::hint::black_box` 包裹被测操作。`run_timed(quick, ...)` 的 `quick` 参数对应 27-benchmark §5.6 / §8.1 的 quick smoke 口径。

## 关键设计决策

| 决策 | 依据 |
|------|------|
| 使用仓库本地 `harness = false` runner，而非 Criterion 等第三方框架 | 27-benchmark §11 决策 1 要求不引入额外 benchmark 框架 |
| quick 模式保留 filter 与最小输入规模 | 27-benchmark §5.6 和 §8.1 要求 CI smoke 可快速验证 benchmark 入口 |
| benchmark 只记录性能趋势，不定义功能正确性合约 | 27-benchmark §1.1 将功能正确性边界交给 28-tests |
| dot bench 仅 2 个条目（dot_1d_f64 与 dot_1d_complex 用 Complex\<f64\>），不展开 f32 / Complex\<f32\> | 27-benchmark §5.5 dot 行只列两条；Complex\<f64\> 覆盖 12-matrix §5.1 BLAS xdotc 共轭乘法路径。**f32 dot 性能由 simd_dot_compare 提供 SIMD-on vs SIMD-off 对比**（W28T10 simd_dot_compare 覆盖 f32/f64 两档），W28T5 范围内不再独立列 dot_1d_f32 基准（避免与对比 bench 重复测量）；**Complex\<f64\> dot 另由 W28T11 par_dot_compare 提供 parallel-on/off 对比**（W28T11 par_dot_compare 覆盖 f64 + Complex\<f64\>）；**Complex\<f32\> dot 在 W28 范围内全不覆盖**（设计 §5.5 simd_dot_compare 仅列 f32/f64，par_dot_compare 仅列 f64+Complex\<f64\>），需扩展 §5.5 才能补充 Complex\<f32\> dot 覆盖 |

## 验证方式

1. 编译检查: `cargo check --benches`
2. Lint 检查: `cargo clippy --benches -- -D warnings`
3. 测试验证: `cargo bench --bench dot -- dot_1d_f64 --quick`
4. 手动验证: 运行对应 bench 的 `--quick` filter，确认输出包含本任务的 benchmark 名称和 median ns 数值。

## 注意事项

- `black_box` 必须包裹被测结果，避免编译器消除热路径。
- benchmark 输入生成应固定、可重复，避免随机噪声污染趋势判断。
- SIMD/并行对比只在对应 feature 组合下解释性能差异，不得改变默认 API 行为。
