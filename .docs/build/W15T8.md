## 目标

收口 Wave 15 整体的 feature gate：

1. 验证默认构建（无 `--features parallel`）不引入 `rayon` 依赖。
2. 通过 `ParallelExecStrategy::max_workers: Some(1)` 验证单 worker 与多 worker 路径产生相同结果。
3. 通过 doctest `compile_fail` 块验证：未启用 `parallel` feature 时，对 `par_*` 函数的引用必须编译失败。
4. 不引入越权依赖（不依赖 W18 reduction 的 `tensor.sum()`、不 import `pub(crate)` 符号到外部集成测试）。

> **范围说明（与 09-parallel.md §7 T8 的差异）**：09-parallel.md §7 T8 中原本同时列出 `tests/test_parallel.rs` 作为目标文件。本 task 修订为：
> - **不创建** `tests/test_parallel.rs` 外部集成测试文件。原因：外部测试 crate 无法 import `pub(crate)` 的 `par_*` / `ParallelExecStrategy` / `ParallelGuard`（30-dispatch §5.3、09-parallel §5.2），唯一可调用的入口是公开 API（`tensor.sum()` / `tensor + tensor` 等），但这些公开 API 由 W16/W17/W18 实现，在 Wave 15 阶段尚未就绪。
> - feature gate + config matrix 测试改为 `src/parallel/mod.rs` 内联 `#[cfg(test)]`，可直接访问 `pub(crate)` 入口。
> - W19+ 的某个 wave（建议 W29 documentation/integration tests）可再补 `tests/test_parallel.rs` 端到端测试。

### Step 3: 编译期测试 — `compile_fail` doctest 块

按项目惯例（Wave 5 审计修复总结："任何引入新 dev-dependency 的方案优先用 doctest `compile_fail` 替代；trybuild 仅在 doctest 无法覆盖时引入"），使用 doctest `compile_fail` 块。本 task **不引入 `trybuild`** dev-dependency。

在 `src/parallel/mod.rs` 添加模块级 doc comment 块：

```rust
//! Parallel backend module. Only compiled with `--features parallel`.
//!
//! # Compile-fail test: parallel APIs require the `parallel` feature
//!
//! Without `--features parallel`, the `parallel` module is excluded from
//! compilation (see 09-parallel.md §5.1). Any reference to `par_map`,
//! `par_sum`, `par_dot`, `par_zip_map`, `ParIter`, etc. must fail to
//! compile. The following doctest asserts that contract.
//!
//! ```compile_fail
//! // This doctest is run by `cargo test --doc` WITHOUT --features parallel.
//! // It must fail to compile because the `parallel` module is gated out.
//! use xenon::parallel::map::par_map;
//! fn main() {}
//! ```
//!
//! # Compile-fail test: bool does not implement Numeric (par_sum / par_dot)
//!
//! 03-element §5.2 line 707-721: `bool` implements `Element` only, NOT
//! `Numeric`. W15T4 `par_sum` and W15T5 `par_dot` require `A: Numeric`,
//! so any attempt to call them on a `bool` tensor must fail to compile.
//! This satisfies 09-parallel.md §8.7 (“类型边界 / 编译期测试”).
//!
//! ```compile_fail
//! # #[cfg(feature = "parallel")] {
//! use xenon::tensor::Tensor;
//! use xenon::dimension::Ix1;
//! use xenon::dispatch::{select_exec_path, ParallelExecStrategy};
//! use xenon::parallel::reduce::par_sum;
//! let t: Tensor<bool, Ix1> = Tensor::from_shape_vec(
//!     Ix1(2), vec![true, false],
//! ).unwrap();
//! let (_p, g) = select_exec_path(
//!     t.len(), t.is_f_contiguous(), t.is_aligned(),
//! );
//! let _ = par_sum(&t, &ParallelExecStrategy::auto(), g.unwrap());
//! // ^^^^^^^ trait bound `bool: Numeric` is not satisfied
//! # }
//! ```
//!
//! When `--features parallel` IS enabled, the positive doctest in the
//! first block compiles; the negative doctest above continues to fail
//! because the trait bound itself is independent of the feature gate.
```

> **运行机制**: `cargo test --doc` 默认不启用 `parallel` feature；doctest `compile_fail` 块期望编译失败（找不到 `parallel` 模块），从而验证 feature gate 正确。这是 std 库标准做法，不引入额外 dev-dep（Wave 5 审计修复模式）。

### Step 4: 单/多 worker 配置矩阵测试

09-parallel §8.6 line 632-640：feature 矩阵测试要验证"启用 `parallel`，结果与串行路径一致"。在 `src/parallel/mod.rs` 内联 `#[cfg(test)] mod tests` 中通过 `ParallelExecStrategy::new(None, Some(1))` 和 `ParallelExecStrategy::auto()` 分别测试单 worker 与默认多 worker 路径，结果必须一致。

> **不使用 `RAYON_NUM_THREADS` 环境变量**: 该方案要求 shell 配合执行，无法在 `cargo test` 一条命令内验证；改用程序化设置 `max_workers: Some(1)` 同样能强制单 worker 路径，且独立于 rayon 全局池配置。

### Step 5: 单元测试

> **强制要求**:
> - 本步骤必须包含一个或者多个单元测试。
> - 测试函数名称和测试内容必须参考对应设计文档的 **「测试计划」** 一节。
> - 编译检查与Lint检查不等同于单元测试。
> - 如果测试没有通过需要修复直至测试通过。
> - **无测试 = 任务未完成。**

测试依据：09-parallel §8.6 line 632-640（feature 矩阵）+ §8.7 line 644 (`bool` 不参与 `par_sum` / `par_dot` 由 03-element §5.2 trait bound 在编译期保证；本 task 无需运行时测试，仅作为 §9 关键设计决策记录）。

```rust
// In src/parallel/mod.rs
#[cfg(all(test, feature = "parallel"))]
mod feature_matrix_tests {
    // Cross-wave test convention (PLAN.md §W13 line 423-429 pattern):
    // W15 and W22 share PLAN.md group D; W22T5 `Tensor::from_shape_vec`
    // is unavailable. Tests construct via W8T7 `TensorView::from_raw_parts`.
    use super::*;
    use crate::dispatch::{
        select_exec_path, ExecPath, ParallelExecStrategy,
        set_parallel_threshold, reset_parallel_threshold, ParallelGuard,
    };
    use crate::parallel::map::par_map;
    use crate::parallel::reduce::par_sum;
    use crate::dimension::{Dimension, Ix1};
    use crate::storage::Storage;
    use crate::element::Element;
    use crate::layout::Strides;
    use crate::tensor::{TensorBase, TensorView};

    fn acquire_parallel_guard<S, D, A>(t: &TensorBase<S, D>) -> ParallelGuard
    where
        S: Storage<Elem = A>,
        D: Dimension,
        A: Element,
    {
        let (path, g) = select_exec_path(t.len(), t.is_f_contiguous(), t.is_aligned());
        assert_eq!(path, ExecPath::Parallel);
        g.expect("Parallel implies Some(guard)")
    }

    unsafe fn view_1d_f64<'a>(data: &'a [f64]) -> TensorView<'a, f64, Ix1> {
        TensorView::<f64, Ix1>::from_raw_parts(
            data.as_ptr(),
            data.len(),
            Ix1(data.len()),
            Strides::from_slice(&[1_usize]).unwrap(),
            0,
        )
        .expect("valid F-order 1-D f64 view")
    }

    #[test]
    fn test_parallel_feature_matrix_single_worker() {
        // max_workers: Some(1) — programmatically force single-worker path.
        set_parallel_threshold(1);
        let data = vec![1.0f64, 2.0, 3.0, 4.0];
        let tensor = unsafe { view_1d_f64(&data) };
        let strategy = ParallelExecStrategy::new(None, Some(1)).unwrap();
        let guard = acquire_parallel_guard(&tensor);
        let result = par_map(&tensor, &strategy, guard, |v| v * 2.0);
        assert_eq!(result.as_slice().unwrap(), &[2.0, 4.0, 6.0, 8.0]);
        reset_parallel_threshold();
    }

    #[test]
    fn test_parallel_feature_matrix_default_workers() {
        // auto() — use rayon default thread pool size.
        set_parallel_threshold(1);
        let data = vec![1.0f64, 2.0, 3.0, 4.0];
        let tensor = unsafe { view_1d_f64(&data) };
        let strategy = ParallelExecStrategy::auto();
        let guard = acquire_parallel_guard(&tensor);
        let result = par_map(&tensor, &strategy, guard, |v| v * 2.0);
        assert_eq!(result.as_slice().unwrap(), &[2.0, 4.0, 6.0, 8.0]);
        reset_parallel_threshold();
    }

    #[test]
    fn test_parallel_single_and_multi_worker_results_agree() {
        // Compute par_sum on the same input with single-worker and
        // default-worker strategies; results must match within tolerance.
        set_parallel_threshold(1);
        let data: Vec<f64> = (0..2048).map(|i| i as f64).collect();
        let tensor = unsafe { view_1d_f64(&data) };

        let strategy_single = ParallelExecStrategy::new(None, Some(1)).unwrap();
        let guard_single = acquire_parallel_guard(&tensor);
        let sum_single = par_sum(&tensor, &strategy_single, guard_single);

        let strategy_multi = ParallelExecStrategy::auto();
        let guard_multi = acquire_parallel_guard(&tensor);
        let sum_multi = par_sum(&tensor, &strategy_multi, guard_multi);

        // Same dispatch path + identical chunking → same result for f64 sum.
        // Tolerance accounts for any chunk merge reordering across workers
        // (09-parallel §10.2; 需求说明书 §28.3 为权威基准).
        let serial: f64 = data.iter().sum();
        assert!((sum_single - serial).abs() < 1e-10 * serial.abs().max(1.0));
        assert!((sum_multi - serial).abs() < 1e-10 * serial.abs().max(1.0));
        reset_parallel_threshold();
    }
}
```

## 关键设计决策

| 决策 | 依据 |
|------|------|
| 只实现本 task 对应切片 | SUMMARY.md 将 W14-W16 拆成单文件粒度任务 |
| 不创建 `tests/test_parallel.rs` 外部集成测试（暂缓到 W29） | 外部 test crate 无法 import `pub(crate)` 的 `par_*` / `ParallelExecStrategy`；W15 阶段公开 API（W16 math / W18 reduction）尚未就绪 |
| 使用 doctest `compile_fail` 验证 feature gate，不引入 `trybuild` | Wave 5 审计修复总结的项目惯例 |
| 单/多 worker 通过 `ParallelExecStrategy::new(None, Some(1))` 程序化切换，不用 `RAYON_NUM_THREADS` | 可在单条 `cargo test` 内验证；独立于 rayon 全局池配置 |
| `bool` 不参与 `par_sum` / `par_dot` 由 trait bound 在编译期保证 | 03-element §5.2 line 707-721：`bool` 仅实现 `Element`，不实现 `Numeric`；W15T4/T5 的 `A: Numeric` bound 自动排除 bool |
| feature 矩阵测试用真实的 `dispatch::select_exec_path` 获取 guard | 30-dispatch §5.7 line 553：唯一合法 guard 入口 |

## 验证方式

1. 编译检查（默认）: `cargo check`（rayon 不应在依赖图中）
2. 编译检查（启用）: `cargo check --features parallel`
3. 默认构建依赖验证: `cargo tree --no-default-features | grep -i rayon` —— 应无输出
4. doctest compile_fail: `cargo test --doc` —— 应通过（compile_fail 块按预期失败编译）
5. feature 矩阵测试: `cargo test --features parallel feature_matrix_tests`
6. 完整回归: `cargo test && cargo test --features parallel`

## 注意事项

- 并行函数假定 dispatch 已选中并行路径。
- Outer `ParallelGuard` 留在调用线程栈帧。
- Worker 闭包必须包裹 `dispatch::with_parallel_worker_context`。
- 默认构建不引入 rayon；启用 `parallel` feature 后才有 rayon 依赖（09-parallel §5.1 line 102-107）。
- 外部集成测试（`tests/test_parallel.rs`）暂缓到 W29，在 W16/W18 公开 API 就绪后通过 `tensor.sum()` / `tensor + tensor` 等公开入口验证 dispatch → parallel 端到端路径。
- 所有代码注释和 Rust 标识符使用英文。
- 不添加新的第三方依赖。
