## 实施步骤

### Step 1: 提取设计约束

从 29-documentation §5.4.1、§5.4.2、§5.6 和 §5.11 提取本任务必须体现的 crate-level 文档结构、doctest 和文档门禁规则。

### Step 2: 修改目标文件

在 `src/lib.rs` 中写入任务范围内的文档内容，保持英文用户文档，避免引入未实现功能或平台承诺。按 29-documentation §5.4.1 (line 230-284) 模板写入 **6 个结构段落**（H1 项目名 + 5 个 H2 小节）：

结构内容 (§5.4.1 模板)：
1. **`# Xenon` (H1)**：crate 介绍句 + Quick Start 代码块
2. **`## Runtime Environment` (H2)**：声明 `Xenon supports only the std environment；no std feature toggle`
3. **`## Optional Features` (H2)**：`parallel` / `simd` 表（只拏 execution 与语义区别，不各 nightly）
4. **`## Supported Element Types` (H2)**：Base / Numeric / Real / Complex 表
5. **`## Memory Layout` (H2)**：F-order 默认 + BLAS/LAPACK 兼容说明
6. **`## Documentation` (H2)** 或 `## License` (H2)：项目外部链接与许可证表说明（以§5.4.1 模板为准）

约束条款（独立于结构，并行生效）：
- 不得声称 nightly-only feature；不得写入 `#![cfg_attr(docsrs, feature(doc_cfg))]` 或任何 `doc(cfg(...))` 属性（MSRV 1.95 stable）。
- 不得越界于§5.4.1 未列出的段落，避免与 README (§5.8) 反复。

```rust
//! ```rust
//! # use xenon::prelude::*;
//! # fn demo() -> xenon::Result<()> {
//! let a = Tensor::<f64, _>::zeros([2, 3])?;
//! let b = Tensor::<f64, _>::ones([2, 3])?;
//! let c = (&a + &b)?;
//! assert_eq!(c.shape(), &[2, 3]);
//! assert_eq!(c.sum(), 6.0);
//! # Ok(())
//! # }
//! ```
```

实际 Quick Start 应至少覆盖：构造、加法（同形状 `(&a + &b)?`）、reduction（`sum()`），与 §5.4.1 模板对齐。

### Step 3: 协同审查示例代码

按 29-documentation §5.4.2 检查示例：索引用 fallible API，构造错误语义正确，运算符示例体现 `Result`，feature 描述不使用 nightly-only `doc_cfg`。

### Step 4: 检查链接与元数据

验证 lib.rs intra-doc links 可解析，且不出现 broken intra-doc links。

### Step 5: 单元测试

> **强制要求**: 本 task 目标为 Rust 源码（`src/lib.rs`），按 TEMPLATE.md L79-99「等效验证条款」，doctest 与 `cargo doc -D warnings` 作为等效验证脚本（失败时非零退出，可入 CI）。所有 Rust doc examples 必须通过 `cargo test --doc` 验证；编译/lint 检查不替代 doctest 验证。

```bash
cargo test --doc --all-features
RUSTDOCFLAGS="-D warnings" cargo doc --all-features --no-deps
cargo clippy --all-features -- -D clippy::missing_errors_doc -D clippy::missing_panics_doc -D clippy::missing_safety_doc
```

验收点：新增或修改的 Rust doc examples 可编译运行；所有 `Result` 示例使用 `?` 并包含断言；文档显式声明仅支持 std。

## 关键设计决策

- 文档内容跟随源码签名和设计文档，不通过文档引入新 API 或新依赖。
- 所有 Rust doc comment、README 和 examples 使用英文，实施方案说明保持中文以匹配现有 build 文档。
- 示例优先写成可运行 doctest 或 `main() -> xenon::Result<()>`，并使用 `?` 与断言满足 29-documentation §5.6。

## 验证方式

1. 编译检查: `RUSTFLAGS="-D warnings" cargo check --all-features`
2. Lint 检查: `cargo clippy --all-features -- -D warnings`
3. 文档构建: `RUSTDOCFLAGS="-D warnings" cargo doc --all-features --no-deps`
4. Doctest 验证: `cargo test --doc --all-features`
5. 示例验证: `cargo build --examples --all-features`
6. 手动验证: 打开生成的 rustdoc 或目标 Markdown，确认章节非空、链接有效、示例与任务目标一致。

## 注意事项

- 不要把编译检查当作 doctest；文档示例必须由 `cargo test --doc` 覆盖。
- 不要展示方括号索引语法；索引示例使用 `try_at`、`try_at_mut`、`get` 或 `get_mut`。
- 不要新增依赖、教程站点、notebook 或自定义 rustdoc 主题。
