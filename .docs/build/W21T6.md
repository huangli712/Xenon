## 目标

在 `TensorBase<S, D>` 上实现 `slice<I>(&self, info: SliceInfo<I, D>) -> Result<TensorView<'_, A, I>>`：基于 W21T4 构造的 `SliceInfo` 完成 shape-aware 边界校验、checked 偏移累加、layout flags 重算与只读 `TensorView` 构造，**绝对不复制数据**。本任务严格对齐 `17-indexing §6.3 / §6.4` 的语义约束。

## 实施步骤

### Step 1: 确认实现边界与契约

依据 `17-indexing §6.3 line 336–425`，`TensorBase::slice(info)` 的 6 步流程：
1. **Debug-assert** `info.input_dim().ndim() == self.ndim()`（D 类型已编译期保证，运行期 debug 兜底）。
2. **Per-axis 校验 + slice_delta 累加**：
   - `Index(idx)`：`idx < shape[axis]` 否则 `IndexOutOfBounds`；折叠该轴，`slice_delta += idx * src_strides[axis]`（checked）。
   - `Range { start, end }`：`end <= shape[axis]` 否则 `InvalidArgument { kind: RangeOutOfBounds }`（`start <= end` 已在 W21T4 保证）；保留该轴，`slice_delta += start * src_strides[axis]`（checked），`out_shape.push(end - start)`，`out_strides.push(src_strides[axis])`。
3. **绝对 offset 计算**：`new_offset = self.offset().checked_add(slice_delta)` 失败 → `InvalidLayout { reason: AccessRangeExceedsStorage }`（line 401 明确要求）。
4. **构造输出 dim / strides**：`I::try_from_slice(&out_shape)` 与 `Strides::<I>::from_slice(&out_strides)`。
5. **logical_ptr 分支构造 + layout flags 重算**：line 405–423 明确要求空切片走 `NonNull::<A>::dangling()`，非空切片走 `self.as_ptr().add(slice_delta)`（**不是 new_offset**，避免双重偏移）。
6. **`derived_from_view_mut` 传播**：line 386 明确 3 条规则（见 Step 2 实现），通过 `new_unchecked` 写入新视图。
7. 用 `ViewRepr::from_ref(self.storage())` 包裹只读存储，返回 `TensorView<'_, A, I>`。

本 task **不**实现可写切片（设计文档 line 384 明确"切片产出始终是只读视图"）；**不**改变 W21T4 已写入的 `SliceInfo*` 定义。

### Step 2: 实现任务目标

```rust
use crate::dimension::Dimension;
use crate::error::{InvalidArgumentKind, InvalidLayoutReason, Result, XenonError};
use crate::layout::{compute_layout_flags, Strides};
use crate::storage::{Storage, StorageKind, ViewRepr};
use crate::tensor::{TensorBase, TensorView};

impl<S, D, A> TensorBase<S, D>
where
    S: Storage<Elem = A>,
    D: Dimension,
{
    /// Creates a read-only sliced view of the tensor.
    ///
    /// Implements `17-indexing §6.3`. All bounds checks happen on the safe
    /// path; the only `unsafe` is the pointer add used by
    /// `compute_layout_flags` for non-empty results — and only after
    /// shape-aware bounds + checked offset arithmetic have proved the
    /// element offset valid.
    ///
    /// # Errors
    ///
    /// - `Index(idx)` with `idx >= shape[axis]` → `XenonError::IndexOutOfBounds`.
    /// - `Range { start, end }` with `end > shape[axis]` →
    ///   `XenonError::InvalidArgument { kind: RangeOutOfBounds { .. } }`.
    /// - Any offset arithmetic overflow →
    ///   `XenonError::InvalidLayout { reason: AccessRangeExceedsStorage, .. }`.
    ///
    /// # Returns
    ///
    /// A read-only `TensorView<'_, A, I>` that shares the source's storage.
    /// Always `ViewRepr<'_, A>` regardless of source storage kind (per
    /// 17-indexing §6.3 line 385 — uniform demotion rule).
    pub fn slice<I>(&self, info: SliceInfo<I, D>) -> Result<TensorView<'_, A, I>>
    where
        I: Dimension,
    {
        // Step 1: debug-assert input rank matches.
        debug_assert_eq!(info.input_dim().ndim(), self.ndim());

        // Step 2: per-axis validation + slice_delta accumulation.
        let shape = self.dim().slice();
        let strides = self.strides().slice();
        let mut out_shape = Vec::with_capacity(info.output_dim().ndim());
        let mut out_strides = Vec::with_capacity(info.output_dim().ndim());
        let mut slice_delta = 0usize;

        // Helper closure: build the canonical InvalidLayout for offset overflow.
        //
        // Field semantics (26-error §5 line 637 + 648):
        // - `offset` field: per 26-error, this is meant to convey "the offset
        //   value involved in the failure". For per-axis overflow during
        //   slice_delta accumulation, we pass the **partial slice_delta at
        //   the failure point** rather than `self.offset()`. This mirrors how
        //   `NdIndex::index_checked` reports its in-progress offset (W21T2)
        //   and gives downstream diagnostics the actual value that overflowed.
        //   For the final `new_offset` overflow at Step 3, we pass
        //   `slice_delta` itself (the value that, when added to self.offset(),
        //   overflowed).
        // - `storage_kind` / `storage_len`: placeholders pending W7's actual
        //   tag-retrieval API (see 前置准备 第 5 条). StorageKind::tag_of::<S>()
        //   is one possible form; if W7 exposes `S::KIND` instead, swap accordingly.
        let overflow_err = |partial_offset: usize| XenonError::InvalidLayout {
            operation: "TensorBase::slice".into(),
            storage_kind: StorageKind::tag_of::<S>(), // placeholder; W7-dependent
            shape: shape.to_vec(),
            strides: strides.to_vec(),
            offset: partial_offset, // partial slice_delta at failure (see above)
            storage_len: 0, // placeholder; W7-dependent
            reason: InvalidLayoutReason::AccessRangeExceedsStorage,
        };

        for (axis, elem) in info.indices().iter().enumerate() {
            match elem {
                SliceInfoElem::Index(idx) => {
                    if idx >= shape[axis] {
                        return Err(XenonError::IndexOutOfBounds {
                            operation: "TensorBase::slice".into(),
                            attempted_index: vec![idx],
                            axis,
                            shape: shape.to_vec(),
                        });
                    }
                    let term = idx
                        .checked_mul(strides[axis])
                        .ok_or_else(|| overflow_err(slice_delta))?;
                    slice_delta = slice_delta
                        .checked_add(term)
                        .ok_or_else(|| overflow_err(slice_delta))?;
                    // axis folded — not pushed to output.
                }
                SliceInfoElem::Range { start, end } => {
                    // start <= end is guaranteed by SliceInfo::new (W21T4).
                    // Per 17-indexing §6.3: shape-aware bound check `end <= shape[axis]`.
                    if end > shape[axis] {
                        return Err(XenonError::InvalidArgument {
                            operation: "TensorBase::slice".into(),
                            kind: InvalidArgumentKind::RangeOutOfBounds {
                                axis,
                                axis_len: shape[axis],
                                start,
                                end,
                            },
                        });
                    }
                    let term = start
                        .checked_mul(strides[axis])
                        .ok_or_else(|| overflow_err(slice_delta))?;
                    slice_delta = slice_delta
                        .checked_add(term)
                        .ok_or_else(|| overflow_err(slice_delta))?;
                    out_shape.push(end - start);
                    out_strides.push(strides[axis]);
                }
            }
        }

        // Step 3: absolute new offset (checked).
        let new_offset = self
            .offset()
            .checked_add(slice_delta)
            .ok_or_else(|| overflow_err(slice_delta))?;

        // Step 4: construct output dim + strides.
        // `I::try_from_slice` is the canonical Dimension constructor from
        // a runtime-length slice (02-dimension §5.4). Rank mismatch (which
        // cannot happen here because we built out_shape ourselves with the
        // exact count of Range elements, and SliceInfo::new already enforced
        // that count == out_dim.ndim()) would still surface as DimensionMismatch.
        let new_dim = I::try_from_slice(&out_shape)?;
        let new_strides = Strides::<I>::from_slice(&out_strides)?;

        // Step 5: logical_ptr branching per 17-indexing §6.3 line 405–423.
        //
        // - Empty result (product(out_shape) == 0): use NonNull::dangling.
        //   The source's storage base might itself be dangling (07-tensor
        //   §6.2 empty-tensor rule); `self.as_ptr().add(slice_delta)` on a
        //   dangling pointer with non-zero delta is UB even with checked
        //   delta.
        // - Non-empty result: self.as_ptr() already includes self.offset
        //   (07-tensor §5.4), so we add the RELATIVE slice_delta — adding
        //   new_offset here would double-apply self.offset.
        let logical_ptr: *const A = if new_dim.product() == 0 {
            core::ptr::NonNull::<A>::dangling().as_ptr()
        } else {
            // SAFETY: slice_delta was validated above via per-axis bounds and
            // checked-offset arithmetic; the resulting offset lies within the
            // source's reachable storage range, and self.as_ptr() already
            // includes self.offset (we add ONLY the relative delta).
            unsafe { self.as_ptr().add(slice_delta) }
        };
        let new_flags =
            compute_layout_flags::<A, I>(new_dim.slice(), new_strides.slice(), logical_ptr);

        // Step 6: derived_from_view_mut propagation per 17-indexing §6.3 line 386
        // (full 3-rule table in 07-tensor §5.1).
        //
        // Rule 1: source is ViewMut (storage_kind == ViewMut) → new view inherits
        //         the mark as true (the original exclusive mutable borrow has
        //         been transferred and any future write-access must be re-proven).
        // Rule 2: source is ViewRepr already carrying derived_from_view_mut == true
        //         → propagate the mark as true.
        // Rule 3: any other case (Owned, ArcRepr, plain ViewRepr without the mark)
        //         → mark stays false.
        let derived_from_view_mut = match self.storage_kind() {
            StorageKind::ViewMut => true,
            StorageKind::View => self.derived_from_view_mut(),
            // Owned / Shared (ArcRepr) → no mark to inherit.
            _ => false,
        };

        // Step 7: construct read-only TensorView via ViewRepr demotion.
        // Per 17-indexing §6.3 line 385: slice output is ALWAYS ViewRepr,
        // regardless of source kind (uniform demotion rule).
        let view_storage: ViewRepr<'_, A> = ViewRepr::from_ref(self.storage());
        // SAFETY: all metadata fields were validated above:
        //   - new_dim built from out_shape that itself came from validated Ranges;
        //   - new_strides reuses source strides (already valid);
        //   - new_offset = self.offset() + slice_delta both checked;
        //   - new_flags recomputed against logical_ptr;
        //   - derived_from_view_mut follows the 3-rule table.
        // The remaining safety burden (storage pointer aliasing / lifetime) is
        // discharged by ViewRepr::from_ref borrowing self.storage() for '_.
        let view = unsafe {
            TensorBase::new_unchecked(
                view_storage,
                new_dim,
                new_offset,
                new_strides,
                new_flags,
                derived_from_view_mut,
            )
        };
        Ok(view)
    }
}
```

```rust
#[cfg(test)]
mod slice_tests {
    use super::*;
    use crate::dimension::{Ix1, Ix2, IxDyn};
    use crate::tensor::Tensor;

    /// 17-indexing §8.2 priority "高": shape/stride/layout-flags reconstructed.
    ///
    /// F-order tensor `[4, 5]` filled with `0..20` in column-major order:
    /// element at logical (row=r, col=c) sits at storage index `r + 4*c`.
    /// Slicing Range{1,4} on axis 0 + Index(2) on axis 1 yields
    /// `slice_delta = 1*1 + 2*4 = 9`, out shape `[3]`, stride `[1]`,
    /// elements `[9, 10, 11]`.
    #[test]
    fn test_slice_layout_recomputed() {
        let tensor = Tensor::from_shape_vec([4usize, 5], (0i32..20).collect()).unwrap();
        let info = SliceInfo::new(
            SliceInfoIndices::from_vec(vec![
                SliceInfoElem::Range { start: 1, end: 4 },
                SliceInfoElem::Index(2),
            ]),
            Ix2(4, 5),
            Ix1(3),
        )
        .unwrap();
        let view = tensor.slice(info).unwrap();
        assert_eq!(view.shape(), &[3]);
        assert_eq!(view.as_slice(), Some(&[9, 10, 11][..]));
    }

    /// 17-indexing §8.2 priority "中": view-of-view shares data.
    #[test]
    fn test_slice_chain() {
        let tensor = Tensor::from_shape_vec([3usize, 4], (0i32..12).collect()).unwrap();
        let info1 = SliceInfo::new(
            SliceInfoIndices::from_vec(vec![
                SliceInfoElem::Range { start: 0, end: 2 },
                SliceInfoElem::Range { start: 1, end: 3 },
            ]),
            Ix2(3, 4),
            Ix2(2, 2),
        )
        .unwrap();
        let view1 = tensor.slice(info1).unwrap();
        let info2 = SliceInfo::new(
            SliceInfoIndices::from_vec(vec![
                SliceInfoElem::Index(1),
                SliceInfoElem::Range { start: 0, end: 2 },
            ]),
            Ix2(2, 2),
            Ix1(2),
        )
        .unwrap();
        let view2 = view1.slice(info2).unwrap();
        assert_eq!(view2.shape(), &[2]);
    }

    /// 17-indexing §8.2 priority "中": IxDyn high rank slicing works.
    #[test]
    fn test_slice_high_rank_ixdyn() {
        // 7-rank tensor with each axis length 2 → falls into Dynamic indices path.
        let dyn_shape = IxDyn::from_slice(&[2, 2, 2, 2, 2, 2, 2]);
        let total: usize = dyn_shape.slice().iter().product();
        let tensor = Tensor::from_shape_vec(dyn_shape.clone(), (0i32..total as i32).collect())
            .unwrap();
        // Slice: Index(0) on every axis → result is rank 0 (Ix0).
        let elems: Vec<SliceInfoElem> = (0..7).map(|_| SliceInfoElem::Index(0)).collect();
        let info = SliceInfo::new(
            SliceInfoIndices::from_vec(elems),
            dyn_shape,
            IxDyn::from_slice(&[]),
        )
        .unwrap();
        let view = tensor.slice(info).unwrap();
        assert_eq!(view.ndim(), 0);
    }

    /// 17-indexing §8.2 priority "中": extreme stride/shape returns error
    /// rather than panicking on offset overflow.
    ///
    /// **⚠️ PARTIAL COVERAGE**: The real overflow path requires a poisoned
    /// stride (e.g. `stride == usize::MAX / 2`) which the public `from_shape_vec`
    /// constructor rejects at layout validation. Triggering the actual
    /// `checked_mul` / `checked_add` failure branch requires either:
    ///   (a) a test-only constructor in W7/W8 that bypasses layout validation
    ///       (e.g. `TensorBase::from_raw_parts_for_test` with poisoned strides),
    ///   (b) a property test in W29 (integration tests) that explores
    ///       adversarial metadata via FFI-imported tensors, or
    ///   (c) directly exercising the closed-form `checked_mul`/`checked_add`
    ///       in a `#[cfg(test)]` helper.
    ///
    /// This unit test currently only asserts the **happy path** (sanity check
    /// that normal slices still succeed). Full overflow verification is
    /// deferred to W29 per 17-indexing §8.4 (property tests).
    #[test]
    fn test_slice_extreme_offset_checked() {
        let tensor = Tensor::from_shape_vec([2usize, 2], vec![0i32, 1, 2, 3]).unwrap();
        // Sanity: normal slice still succeeds.
        let info_ok = SliceInfo::new(
            SliceInfoIndices::from_vec(vec![
                SliceInfoElem::Index(1),
                SliceInfoElem::Range { start: 0, end: 2 },
            ]),
            Ix2(2, 2),
            Ix1(2),
        )
        .unwrap();
        assert!(tensor.slice(info_ok).is_ok());
        // FULL overflow verification: W29 property tests (17-indexing §8.4).
        // Per 17-indexing §6.3 line 401, the canonical guards are:
        //   - per-axis `checked_mul(idx, stride[axis])`
        //   - per-axis `checked_add` into slice_delta
        //   - final `self.offset().checked_add(slice_delta)` → new_offset
        // All three return `InvalidLayout { reason: AccessRangeExceedsStorage }`.
    }

    /// 17-indexing §8.2 priority "高": 10^7-element tensor end-element index
    /// and adversarial offset combination.
    ///
    /// Shape `[3162, 3162]` has ~10^7 elements. F-order stride is `[1, 3162]`.
    /// End element at logical `(3161, 3161)` has offset `3161 * 1 + 3161 * 3162
    /// = 9_996_643` (well within `usize`). Verify both: (a) legal end-element
    /// slice returns Ok; (b) constructing a slice that would push the absolute
    /// offset toward `usize::MAX` returns `InvalidLayout`.
    #[test]
    fn test_index_large_tensor_offset_boundary() {
        const N: usize = 3162;
        let data: Vec<i32> = (0..(N * N) as i32).collect();
        let tensor = Tensor::from_shape_vec([N, N], data).unwrap();

        // (a) legal: take the very last row's last column as a scalar (Ix0) slice.
        // Output dim for two Index() folds is rank-0 (Ix0).
        let info_end = SliceInfo::<crate::dimension::Ix0, Ix2>::new(
            SliceInfoIndices::from_vec(vec![
                SliceInfoElem::Index(N - 1),
                SliceInfoElem::Index(N - 1),
            ]),
            Ix2(N, N),
            crate::dimension::Ix0,
        )
        .unwrap();
        let view = tensor.slice(info_end).unwrap();
        assert_eq!(view.ndim(), 0);

        // (b) overflow scenario: not directly constructible via public API
        // because `from_shape_vec` validates that `product(shape) * size_of::<A>()`
        // fits in usize. The overflow guard at slice_delta / new_offset is
        // therefore protective against pathological FFI-imported tensors;
        // a property test (see §8.4) is the canonical place to cover that.
        // Here we at least assert the path returns Ok on the legitimate end-element.
    }
}
```

> 测试注记：
> - `test_index_large_tensor_offset_boundary` 中的 `Ix0` 构造使用显式 turbofish `SliceInfo::<Ix0, Ix2>::new(..)` 直接产出 rank-0 输出；该写法不依赖 `IxDyn → Ix0` 的 `TryFrom` 实现（W3 未明确暴露该转换），是 02-dimension §5 中最稳定的构造路径。
> - `test_slice_extreme_offset_checked` 的真正溢出路径需要 poisoned stride，公开 API 难以构造；当前测试**仅覆盖正常路径**（PARTIAL COVERAGE），完整溢出验证下放到 W29 集成测试 / §8.4 属性测试（见测试函数文档注释）。

## 关键设计决策

1. 依据 `17-indexing §6.3 line 353–358 / line 401`，所有 offset 算术溢出（`checked_mul` / `checked_add` 的失败、最终 `new_offset` 的 `checked_add`）一律映射到 `XenonError::InvalidLayout { reason: InvalidLayoutReason::AccessRangeExceedsStorage, .. }`，**不是** `XenonError::overflow`（后者在 26-error §5 中根本不存在）。
2. 依据 `17-indexing §6.3 line 386` + `07-tensor §5.1`，`derived_from_view_mut` 必须按 3 条规则传播：
   - 来源 `ViewMutRepr` → 新视图 `true`；
   - 来源带标记的 `ViewRepr` → 新视图 `true`；
   - 其他（Owned / ArcRepr / 不带标记的 ViewRepr）→ 新视图 `false`。
   实现通过 `match self.storage_kind()` 显式分支处理。
3. 依据 `17-indexing §6.3 line 348–349`，`Range.end > shape[axis]` 失败用结构化 `InvalidArgumentKind::RangeOutOfBounds { axis, axis_len, start, end }`（**不是**字符串）。
4. 依据 `17-indexing §6.3 line 385`，切片输出**永远**是 `ViewRepr<'_, A>`（uniform demotion），与源存储类型（Owned / ArcRepr / ViewRepr / ViewMutRepr）无关；这是 05-storage §5.11.1 的统一规则。
5. 依据 `17-indexing §6.3 line 405–423`，logical_ptr 必须按 `product(out_shape) == 0` 分支：空切片走 `NonNull::dangling()`（避免对 dangling storage base 做 `.add()` 触发 UB），非空切片走 `self.as_ptr().add(slice_delta)`（**不是 `new_offset`**，因为 `self.as_ptr()` 已经叠加过 `self.offset`，再加 `new_offset` 会双重偏移）。
6. 依据 `17-indexing §8.2`，本 task 落地 5 个测试覆盖：layout 重算、view-of-view 共享、IxDyn 高 rank、极端 stride 偏移检查（**PARTIAL COVERAGE**：仅正常路径；溢出路径需 poisoned stride，下放 W29 / §8.4）、`10^7` 元素张量末元素索引。
7. 依据 Wave 21 依赖层级，本 task 不新增第三方依赖，不改变 W2 / W3 / W6 / W7 / W8 的 public contract；但**依赖 W7/W8 暴露**以下 API（见前置准备第 5 条）：`TensorBase::storage_kind()`、`TensorBase::derived_from_view_mut()`、`StorageKind::tag_of::<S>()`（或等价 `S::KIND`）、`ViewRepr::from_ref(..)`。任一缺失需 W7/W8 补齐或本 task 在实施阶段调整调用形式。
8. **`overflow_err` 闭包的 `offset` 字段语义**（B7）：依据 26-error §5 line 637/648，`InvalidLayout.offset` 是"涉及失败的 offset 值"。本 task 在累加阶段失败时传入 `partial slice_delta`（**不是** `self.offset()`），因为 partial delta 才是实际溢出的值；与 W21T2 `NdIndex::index_checked` 报告 in-progress offset 的语义一致。Step 2 的 `overflow_err` 闭包 doc-comment 详细记录了这一约定。

## 验证方式

1. 编译检查: `cargo check`
2. Lint 检查: `cargo clippy --all-targets -- -D warnings`
3. 测试验证: `cargo test --lib index::slice::slice_tests`（5 个 `#[test]` 全通过）。
4. 手动验证: 构造 F-order `Tensor::from_shape_vec([4, 5], (0..20).collect())`，对 `(Range{1,4}, Index(2))` 切片后逐元素打印，必须得到 `[9, 10, 11]`（与设计文档 §6.3 示例一致）。
5. 错误路径手动验证:
   - 构造 `Range { start: 0, end: 100 }` on a `shape[0] = 4` 张量 → 必须返回 `InvalidArgument { kind: RangeOutOfBounds { axis: 0, axis_len: 4, start: 0, end: 100 } }`（**结构化** kind，不是字符串）。
   - 构造 `Index(99)` on `shape[0] = 4` → `IndexOutOfBounds { axis: 0, .. }`。
6. `derived_from_view_mut` 传播验证: 用 `tensor.view_mut()` 拿到 `ViewMutRepr` 张量，对其调用 `.slice(..)` 得到只读 view；再检查该 view 的 `access_semantics()`（07-tensor §5.3）必须返回 `SharedReadOnly`（因为 `derived_from_view_mut == true`），**不是** `ReadOnly`。

## 注意事项

- `usize` 只作为索引和 shape 元数据，不扩展负索引或高级索引（`17-indexing §1.2`）。
- unsafe 接口只跳过检查，不改变 offset 语义；本 task 唯一的 `unsafe` 是 `self.as_ptr().add(slice_delta)`（仅非空切片）与 `TensorBase::new_unchecked`，前者的安全前提由 Step 2 完整的 bounds + checked 算术保证（§6.4），后者由本方法构造的全部元数据已校验保证。
- 切片必须更新 offset、shape、stride 和布局状态，不复制数据；输出始终是 `ViewRepr`（无论来源是 Owned 还是 ArcRepr，都按 05-storage §5.11.1 的 uniform demotion 规则降级）。
- F-order 测试断言依赖 `Tensor::from_shape_vec` 按 F-order 填充数据，这是 W3 / W8 的契约（02-dimension §5 与 07-tensor §5.4 已确认）；若 W8 实际填充顺序不同，需要在 W21 开始前与 W8 对齐修订断言值。
- `test_slice_extreme_offset_checked` 的真正溢出路径需 poisoned stride，公开 API 无法直接构造；本 task 只能 sanity-check 正常路径，溢出语义验证留给 §8.4 属性测试（W29）。
