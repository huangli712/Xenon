## 目标

Complex element-wise SIMD: Add/Sub/Mul/Div/Neg kernels for Complex\<f32\>/Complex\<f64\>，对齐 `08-simd.md §5.6` 操作覆盖表对 Complex element-wise 「已实现」的声明。

> **docs_fix 缘起**（W14T2 audit FIND-1 修复）：原 W14T2 仅实现 f32/f64 element-wise，遗漏 Complex 部分（设计文档 5.6 明示已实现 + 5.8 明示阈值=128）。本独立 task 承担 Complex element-wise 实现，依赖 W14T2（f32/f64 element-wise 基础）+ W14T5（Complex AoS deinterleave 基础设施），避免直接扩充 W14T2 导致拓扑循环（W14T2→W14T5→W14T3→W14T2）。

1. 实现 5 个 Complex 二元/一元 kernel（`ComplexAddKernel<T>`、`ComplexSubKernel<T>`、`ComplexMulKernel<T>`、`ComplexDivKernel<T>`、`ComplexNegKernel<T>`，T ∈ {f32, f64}）。
2. 扩展 `dispatch_vector_binary_op` 和 `dispatch_vector_unary_op` 的 Complex\<f32\>/Complex\<f64\> 分支。
3. Complex element-wise SIMD 最小长度阈值 = **128**（08-simd.md 5.8 L451）。
4. 复用 W14T5 提供的 AoS→SoA deinterleave 路径作为输入 lane 拆分基础。

## 实施步骤

### Step 1: Implement Complex element-wise binary kernels (Add/Sub/Mul/Div)

为 Complex\<f32\> 和 Complex\<f64\> 各实现四个二元 kernel 结构体：`ComplexAddKernel<T>`、`ComplexSubKernel<T>`、`ComplexMulKernel<T>`、`ComplexDivKernel<T>`。每个 kernel 持有 `lhs: &[Complex<T>]`、`rhs: &[Complex<T>]`、`dst: &mut [Complex<T>]`，通过 `get_arch().dispatch(...)` 进入 `pulp::WithSimd`。

**AoS 重排路径**（复用 W14T5 deinterleave 基础设施）：

1. **输入 deinterleave**：`&[Complex<T>]` 重解释为实/虚交织的 `&[T]`，使用 W14T5 同型 deinterleave helper 拆为 `(real_lane, imag_lane)` 两个 SoA 片段。

2. **对运算逐类实现 vector body**：
   - **`Add`/`Sub`**：实部与虚部独立 lane-wise op，与 W14T2 f32/f64 路径同构（`simd.f32s_add(re_lhs, re_rhs)` + `simd.f32s_add(im_lhs, im_rhs)`，f64 同理）。
   - **`Mul`**：`(a+bi)*(c+di) = (ac-bd) + (ad+bc)i`。使用独立 lane-wise mul/sub/add 表达，**禁用 FMA**（与 W14T2 同样受 08-simd 6.6 FMA 禁令约束）：
     ```
     re_out = re_lhs * re_rhs - im_lhs * im_rhs
     im_out = re_lhs * im_rhs + im_lhs * re_rhs
     ```
   - **`Div`**：`(a+bi)/(c+di) = ((ac+bd) + (bc-ad)i) / (c² + d²)`。依赖独立实数除法：
     ```
     denom = re_rhs * re_rhs + im_rhs * im_rhs
     re_out = (re_lhs * re_rhs + im_lhs * im_rhs) / denom
     im_out = (im_lhs * re_rhs - re_lhs * im_rhs) / denom
     ```
     除零语义与标量路径一致（`f32::INFINITY / NaN`）。

3. **输出 reinterleave**：合并 `(real_result, imag_result)` 为交织的 `&mut [T]`，重解释为 `&mut [Complex<T>]` 写回 `dst`。同一 unsafe `reinterpret` 模式与 W14T5 保持一致。

4. **Tail 处理**：Complex element-wise 亦可能遇到非 SIMD-width 整数倍长度。使用标量尾部逐 `Complex` 元素表达式计算，与主体 lane 路径逻辑一致。

> **参见 08-simd §6.6 "精度优先约束"**：Complex element-wise 主循环的乘加运算 **必须** 按标量表达式顺序分开执行，**不得使用** `simd.f32s_mul_add` / `f64s_mul_add` 等 lane FMA 操作，保持与标量路径逐位一致。

### Step 2: Implement Complex Neg unary kernel

实现 `ComplexNegKernel<f32>` 和 `ComplexNegKernel<f64>`。Neg 对 Complex 实部和虚部同时取反：

```
out.re = -in.re
out.im = -in.im
```

**实现简化**：由于实部和虚部独立取反，**不需要 deinterleave**——直接把 `&[Complex<T>]` 重解释为 `&[T]`（长度翻倍），调用 W14T2 已有的 `NegKernel` 路径处理。或直接用 `simd.f32s_neg(re_im_lane)` lane op 一遍处理（实/虚交织无所谓，因为它们对称）。

### Step 3: Wire Complex branches into facade

在 `dispatch_vector_binary_op` 中扩展 Complex\<f32\> 和 Complex\<f64\> 分支：
- `BinaryOp::Add` → `ComplexAddKernel<T>`
- `BinaryOp::Sub` → `ComplexSubKernel<T>`
- `BinaryOp::Mul` → `ComplexMulKernel<T>`
- `BinaryOp::Div` → `ComplexDivKernel<T>`

在 `dispatch_vector_unary_op` 中扩展：
- `UnaryOp::Neg` → `ComplexNegKernel<T>`

**阈值准入**：Complex element-wise 最小长度 = **128**（08-simd.md §5.8 L451）。低于阈值时 facade 拒绝（返回 `false`），不进入 kernel。类型 gate 由 Complex\<f32\>/Complex\<f64\> 单态分支和 trait 系统表达。

### Step 4: Per-kernel internal admission

每个 Complex kernel 实现内部 admission：
- 长度为零提前 return（不进入 SIMD body）
- 长度小于 SIMD width 二倍直接走标量尾部（不进入 deinterleave）
- 三个切片长度（`lhs.len() == rhs.len() == dst.len()`）由 `SimdKernel` 契约 panic 保护
- 当前 Arch 必须存在 lane width > 1 的可用 ISA

`simd/` 模块不实现标量 fallback loop。所有拒绝条件只通过 facade 返回 `false` 表达。

### Step 5: 单元测试

> **强制要求**:
> - 本步骤必须包含一个或者多个单元测试。
> - 测试函数名称和测试内容必须参考对应设计文档的 **「测试计划」** 一节。
> - 编译检查与 Lint 检查不等同于单元测试。
> - 如果测试没有通过需要修复直至测试通过。
> - **无测试 = 任务未完成。**

```rust
#[cfg(all(test, feature = "simd"))]
mod complex_elementwise_tests {
    use super::*;
    use crate::complex::Complex;

    /// Helper: 标量逐元素 add baseline for Complex<f32>
    fn assert_complex_add_f32(
        lhs: &[Complex<f32>],
        rhs: &[Complex<f32>],
        actual: &[Complex<f32>],
    ) {
        let expected: Vec<Complex<f32>> = lhs.iter().zip(rhs).map(|(&l, &r)| l + r).collect();
        assert_eq!(actual, expected.as_slice());
    }

    #[test]
    fn test_vector_add_complex_f32() {
        let lhs: Vec<Complex<f32>> = (0..256)
            .map(|i| Complex::new(i as f32, (i as f32) * 0.5))
            .collect();
        let rhs: Vec<Complex<f32>> = (0..256)
            .map(|i| Complex::new(-(i as f32) * 0.25, i as f32 * 0.75))
            .collect();
        let mut dst = vec![Complex::new(0.0_f32, 0.0_f32); lhs.len()];
        let handled = dispatch_vector_binary_op(BinaryOp::Add, &lhs, &rhs, &mut dst);
        // len=256 > Complex element-wise threshold 128 (08-simd §5.8 L451)
        assert!(handled, "Complex<f32> len=256 above threshold 128 must admit SIMD");
        assert_complex_add_f32(&lhs, &rhs, &dst);
    }

    #[test]
    fn test_vector_add_complex_f64() {
        let lhs: Vec<Complex<f64>> = (0..256)
            .map(|i| Complex::new(i as f64, (i as f64) * 0.5))
            .collect();
        let rhs: Vec<Complex<f64>> = (0..256)
            .map(|i| Complex::new(-(i as f64) * 0.25, i as f64 * 0.75))
            .collect();
        let mut dst = vec![Complex::new(0.0_f64, 0.0_f64); lhs.len()];
        let handled = dispatch_vector_binary_op(BinaryOp::Add, &lhs, &rhs, &mut dst);
        assert!(handled, "Complex<f64> len=256 above threshold 128 must admit SIMD");
        for (i, (a, e)) in dst.iter().zip(lhs.iter().zip(&rhs).map(|(l, r)| l + r)).enumerate() {
            // 元素级一致（与 f64 add 同样逐位一致 per Tier 1）
            assert_eq!(*a, e, "Complex<f64> add mismatch at {}", i);
        }
    }

    #[test]
    fn test_vector_mul_complex_f32() {
        let lhs: Vec<Complex<f32>> = (0..256)
            .map(|i| Complex::new(i as f32 * 0.125, (i as f32) * 0.0625))
            .collect();
        let rhs: Vec<Complex<f32>> = (0..256)
            .map(|i| Complex::new((i as f32) * 0.25, -(i as f32) * 0.5))
            .collect();
        let mut dst = vec![Complex::new(0.0_f32, 0.0_f32); lhs.len()];
        let handled = dispatch_vector_binary_op(BinaryOp::Mul, &lhs, &rhs, &mut dst);
        assert!(handled, "Complex<f32> mul len=256 must admit SIMD");
        // Component-wise tolerance (per W14 audit fix decision 12; not .norm())
        for (i, (a, (l, r))) in dst.iter().zip(lhs.iter().zip(&rhs)).enumerate() {
            let expected = *l * *r;
            // element-wise mul tolerance: 4·ε·max_abs (per-element scope, not reduction)
            let tol = 4.0 * f32::EPSILON
                * (l.re.abs() + l.im.abs()).max(r.re.abs() + r.im.abs())
                * 2.0;
            assert!((a.re - expected.re).abs() <= tol.max(4.0 * f32::MIN_POSITIVE),
                "Complex<f32> mul real mismatch at {}: a={}, e={}", i, a.re, expected.re);
            assert!((a.im - expected.im).abs() <= tol.max(4.0 * f32::MIN_POSITIVE),
                "Complex<f32> mul imag mismatch at {}: a={}, e={}", i, a.im, expected.im);
        }
    }

    #[test]
    fn test_vector_neg_complex_f32() {
        let src: Vec<Complex<f32>> = (0..256)
            .map(|i| Complex::new(i as f32 - 128.0, (i as f32) * 0.25))
            .collect();
        let mut dst = vec![Complex::new(0.0_f32, 0.0_f32); src.len()];
        let handled = dispatch_vector_unary_op(UnaryOp::Neg, &src, &mut dst);
        assert!(handled, "Complex<f32> Neg len=256 above threshold 128 must admit SIMD");
        for (i, (a, e)) in dst.iter().zip(src.iter().map(|c| -*c)).enumerate() {
            assert_eq!(*a, e, "Complex<f32> neg mismatch at {}", i);
        }
    }

    #[test]
    fn test_complex_elementwise_below_threshold_rejects() {
        let lhs: Vec<Complex<f32>> = (0..64).map(|i| Complex::new(i as f32, 0.0)).collect();
        let rhs: Vec<Complex<f32>> = (0..64).map(|i| Complex::new(i as f32, 0.0)).collect();
        let mut dst = vec![Complex::new(0.0_f32, 0.0_f32); lhs.len()];
        let handled = dispatch_vector_binary_op(BinaryOp::Add, &lhs, &rhs, &mut dst);
        // len=64 < Complex element-wise threshold 128
        assert!(!handled, "Complex<f32> len=64 below threshold 128 must reject SIMD");
        // dst should remain unchanged when SIMD rejects
        for value in dst.iter() {
            assert_eq!(*value, Complex::new(0.0_f32, 0.0_f32),
                "SIMD reject must not mutate dst");
        }
    }

    // Repeat Sub/Div for Complex<f32>/Complex<f64> + Mul/Neg for Complex<f64> following the same pattern.
}
```

## 关键设计决策

| 决策 | 依据 |
|------|------|
| Complex element-wise 独立 task (W14T2b)，不嵌入 W14T2 | docs_fix W14T2 audit FIND-1 修复；嵌入 W14T2 会产生拓扑循环 W14T2→W14T5→W14T3→W14T2 |
| 拓扑位置：批次 6（W14T5 之后，与 W14T6 同批可并行） | 依赖 W14T5 deinterleave；与 W14T6 同样基于 W14T5 实现，可并行 |
| 复用 W14T5 AoS deinterleave 而非重新实现 | 避免重复 unsafe reinterpret 代码；W14T5 已通过 spike 验证 deinterleave 路径 |
| Complex element-wise 最小长度 = **128**（高于 f32/f64 的 64） | 08-simd §5.8 L451；AoS 重排额外开销需要更长输入才能获益 |
| Complex Mul / Div 同样禁用 FMA | 08-simd §6.6 FMA 约束在 element-wise 的推广；Mul 公式 `(a+bi)*(c+di) = (ac-bd) + (ad+bc)i` 需独立 lane mul/sub/add；Div 依赖实数除法于 `c²+d²` |
| Complex Neg 简化路径：实/虚对称，可直接 reinterpret 为 `&[T]` 后调用 W14T2 NegKernel | Neg 对实/虚独立取反，不需要 deinterleave；这是 Complex 唯一可直接复用 W14T2 路径的运算 |
| Complex 测试断言使用 **分量级比较**（real/imag 分别断言），不用 `.norm()` | W14 修复决策 12；08-simd §6.6；`.norm()` 会掩盖分量级误差 |
| 测试覆盖至少 Add/Mul/Neg 三个代表运算 + 一个 below-threshold 拒绝路径 | 08-simd §8.2 单元测试清单；Mul 是非 commutative 的代表，Add 是 commutative 代表，Neg 是 unary 代表 |

## 注意事项

- Complex element-wise SIMD 仅适用 Complex\<f32\> 和 Complex\<f64\>。其他 Complex\<T\> 类型由 trait 系统编译期排除。
- AoS 重解释为 `&[T]` 的 unsafe 前提与 W14T5 完全相同：①`Complex<T>` 是 `#[repr(C)]` 且 alignment 与 `T` 相同；②重解释切片长度 = `slice.len() * 2`；③`(&[Complex<T>], &mut [Complex<T>])` 互不重叠、生命期完整。这些不变量已由 W14T5 通过 spike 与单元测试验证。
- **FMA 使用规则**（08-simd §1.2/§6.6）：Complex element-wise mul/add/sub/div 主循环禁用 FMA（保持与标量逐位一致）；仅 horizontal reduction merge 阶段可在记录容差且 FMA capability bit 独立检测确认后使用（不适用于本 task）。
- 所有 SIMD entries 是 internal `pub(crate)` APIs and must stay feature-gated。
- Complex Neg 测试使用 `assert_eq!` 而非容差比较：Neg 是位级取反，不涉及累加误差，可保持精确比较。
- Complex Mul / Div 测试使用分量级容差比较，禁用 `.norm()`：参见 W14 audit FIND-3 修复要求（08-simd §6.6 复数比较）。
- W14T8 / W14T10 后续修订需要扩展 Complex element-wise 一致性测试 / property 测试（W14T2b 单元测试只是 minimal 覆盖）。
