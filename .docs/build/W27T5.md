## 实施步骤

### Step 1: Audit chunk partition helper

Canonical 分块入口是 `compute_safe_chunks(total: usize, num_workers: usize) -> usize`，定义于 `src/parallel/mod.rs`，**返回每个 chunk 的元素数**（chunk_size 标量）。权威算法定义见 `docs/design/09-parallel.md §6.3`（行 338-358 给出完整 pseudocode）；其在 `parallel` feature 下作为公开 API 内部并行执行路径分块入口的角色由 `docs/design/25-safety.md §9.3` 描述。

本 task 审计 `src/parallel/iter.rs` 中并行迭代器对该入口的使用，验证以下契约：

1. **`compute_safe_chunks` 自身边界契约**（直接断言函数行为，对应 `25-safety §8.4` 的"分块覆盖全部元素且互不重叠"不变量在分块尺度上的前置条件）：
   - `total == 0` → 返回 `1`（dummy；不会调度任何工作）
   - `total <= num_workers` → 返回 `1`（每个 worker 至多一个元素）
   - 一般情形 → 返回 `max(ceil_div(total, num_workers * 4), MIN_CHUNK)`，且结果 ≥ `MIN_CHUNK = 1024`
2. **覆盖完整 + 不重叠**：调用方使用 rayon `IndexedParallelIterator`/`.par_chunks(chunk_size)` 等标准 API 按 `compute_safe_chunks` 输出切分时，覆盖与非重叠由 rayon 的索引切片语义保证（参见 `25-safety §6.2`）。本 task 在 Step 2 通过审计调用点确认这一调用契约成立。
3. **边界鲁棒**：上述边界情形（`total = 0` / `total = 1` / `total < num_workers`）均由 `compute_safe_chunks` 的早返回分支处理，下游 rayon 切分等价于「单 chunk 串行执行」或「每 worker 一元素」。

本 step 不在 `src/parallel/iter.rs` 中引入新的模块级 chunking helper（与下方「关键设计决策」中的"不在此 task 引入新的 mutable chunk API"一致）。

### Step 2: Audit existing parallel chunk dispatch path

Review the existing parallel iterator code in `src/parallel/iter.rs` to verify:

1. The chunking helper already enforces non-overlapping partitions before creating mutable sub-views
2. Layout validation (contiguity / stride check) is performed before splitting, rejecting layouts that would alias
3. Conservative rejection (fallback to serial) is used when non-overlap cannot be proven at compile time

No new public API should be introduced in this step. The audit confirms existing guards are sufficient or identifies gaps for follow-up.

### Step 3: 单元测试

参考 `docs/design/25-safety.md` 的「测试计划」增加 chunk 完整性、不重叠和边界测试。

> **强制要求**:
> - 本步骤必须包含一个或者多个单元测试。
> - 测试函数名称和测试内容必须参考对应设计文档的 **「测试计划」** 一节。
> - 编译检查与Lint检查不等同于单元测试。
> - 如果测试没有通过需要修复直至测试通过。
> - **无测试 = 任务未完成。**

```rust
#[cfg(test)]
mod tests {
    use crate::parallel::compute_safe_chunks;

    // Must match the constant defined in `src/parallel/mod.rs`
    // (authoritative source: `docs/design/09-parallel.md §6.3` line 344-345).
    const MIN_CHUNK: usize = 1024;

    #[test]
    fn test_chunks_cover_all() {
        // Authoritative `09-parallel §6.3` line 349-350: `total == 0` → 1.
        // Downstream rayon `.par_chunks(1)` over an empty slice produces
        // zero chunks, trivially covering the empty range [0, 0).
        assert_eq!(compute_safe_chunks(0, 4), 1);

        // General case: chunk_size * num_chunks_generated_by_rayon
        // must cover `total` exactly once. Here we verify the scalar
        // contract on which downstream coverage depends: chunk_size ≥ 1
        // and, for non-trivial inputs, ≥ MIN_CHUNK.
        let size = compute_safe_chunks(100_000, 4);
        assert!(size >= MIN_CHUNK, "chunk_size must be ≥ MIN_CHUNK for non-trivial inputs, got {}", size);
    }

    #[test]
    fn test_chunks_no_overlap() {
        // `09-parallel §6.3` line 351-353: `total <= num_workers` → 1.
        // A chunk_size of 1 combined with rayon's index-based chunking
        // gives one element per chunk, which is trivially non-overlapping.
        assert_eq!(compute_safe_chunks(3, 8), 1);
        assert_eq!(compute_safe_chunks(1, 4), 1);

        // For larger inputs, chunk_size stays ≥ 1 (a pure scalar
        // positivity invariant); non-overlap is guaranteed by rayon's
        // `.par_chunks(chunk_size)` semantics, which partitions
        // `0..total` into consecutive [i*size, (i+1)*size) ranges
        // (last chunk may be shorter). This is validated by audit in
        // Step 2 rather than by duplicating rayon's contract here.
        assert!(compute_safe_chunks(17, 4) >= 1);
    }

    #[test]
    fn test_chunks_boundary() {
        // Boundary matrix enumerated in Step 1:
        // total = 0            → 1     (dummy; no work scheduled)
        // total = 1            → 1     (≤ num_workers branch)
        // total < num_workers  → 1     (≤ num_workers branch)
        // total > num_workers  → max(ceil_div(total, workers*4), MIN_CHUNK)
        assert_eq!(compute_safe_chunks(0, 4), 1);
        assert_eq!(compute_safe_chunks(1, 4), 1);
        assert_eq!(compute_safe_chunks(3, 8), 1);

        // total = workers * 4 * 2 = 64 elements/worker-slot,
        // ceil_div = 2; raised to MIN_CHUNK by the `raw.max(MIN_CHUNK)` clamp.
        assert_eq!(compute_safe_chunks(64, 8), MIN_CHUNK);

        // Large uneven case: total = 10_000, workers = 3 →
        // target_chunks = 12, raw = ceil_div(10_000, 12) = 834,
        // clamped to MIN_CHUNK = 1024.
        assert_eq!(compute_safe_chunks(10_000, 3), MIN_CHUNK);

        // Large case above MIN_CHUNK threshold: total = 1_000_000, workers = 4 →
        // target_chunks = 16, raw = ceil_div(1_000_000, 16) = 62_500,
        // which exceeds MIN_CHUNK so raw wins.
        assert_eq!(compute_safe_chunks(1_000_000, 4), 62_500);
    }
}
```

## 关键设计决策

| 决策 | 依据 |
|------|------|
| 测试直接断言 `compute_safe_chunks` 的标量行为契约 | `09-parallel §6.3` 定义 `compute_safe_chunks(total, num_workers) -> usize` 返回 chunk_size 标量。测试验证其边界条件（`total=0→1`, `total≤workers→1`, 一般情形 `≥MIN_CHUNK`）。覆盖/不重叠由调用方使用 rayon `.par_chunks(size)` 的标准语义保证，在 Step 2 审计调用点确认 |
| 不在此 task 引入新的 mutable chunk API | W27T5 是审计任务，属于 Wave 27 的"Safety Audit"。新 API 应在对应的设计文档（如 09-parallel.md）中定义 |
| MIN_CHUNK 常数在测试中硬编码为 1024 | 与 `09-parallel §6.3` 行 344-345 和 W15T1 实现一致。若未来该常数变更，测试需同步更新 |
| 选用 `09-parallel §6.3` (chunk_size 标量返回) 而非 `25-safety §9.3` (intervals `&[(usize, usize)]`) | `25-safety §9.3` 行 706-712 描述与 `09-parallel §6.3` 行 338-358 不一致。本 task 以 `09-parallel §6.3` 为权威实现（更具体的设计文档），原因：W15T1 已按该文档落地为标量返回形式，调用方通过 rayon `.par_chunks(chunk_size)` 获得覆盖 + 不重叠语义。`25-safety §9.3` 是顶层安全描述，未反映实现细节 |

## 验证方式

1. 编译检查: `cargo check --features parallel`
2. Lint 检查: `cargo clippy --all-targets --features parallel`
3. 测试验证: `cargo test --features parallel test_chunks`
4. 手动验证: 用 len=0、1、prime len 和 chunks > len 的输入打印 chunk ranges，确认覆盖完整且无重叠。

## 注意事项

- 不要用 unsafe 指针拆分替代现有非重叠 validator。
- chunk 边界计算必须避免遗漏尾部元素。
- 嵌套并行回退串行路径不应改变结果。
