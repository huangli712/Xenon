## 目标

Overload tests: Add/Sub/Mul/Div traits, broadcast dispatch, Result ownership, scalar operators。

本任务实现 W29 集成测试体系中的一个交付物，覆盖 28-tests §5 的测试文件职责、§6 的数值精度与并行/SIMD 规则、§7 的分层执行安排以及 §8 的测试矩阵。核心测试或 fixture 包括：`test_add_same_shape_overload`, `test_add_broadcast`, `test_add_ref_ref`, `test_add_scalar`, `test_native_scalar_add_tensor_f64`, `test_broadcast_incompatible`。

## 前置准备

- 确认 `tests/common` 基础设施或前置测试文件已按依赖完成。
- 使用 28-tests §6.2 定义的精确比较和文档化容差，不随意放宽浮点断言。
- 测试仅验证既有公共 API 和错误语义，不通过测试引入新的产品能力。

## 实施步骤

### Step 1: 创建测试文件与导入

创建或更新目标文件，使用 `xenon::prelude::*` 和 `tests/common` helper。每个测试名称必须描述可观察行为，并保持单文件可独立运行。

```rust
use xenon::prelude::*;
```

所有 `#[test]` 函数统一放入 Step 3 的 `mod tests` 块中，保持单一测试块的工程惯例，避免顶层裸 `#[test]` 与 `mod tests` 同名冲突。

### Step 2: 实现正常路径、边界路径和错误路径

按 28-tests §5 的清单补齐正常路径、边界输入、错误返回或编译失败 fixture；涉及浮点、复数、SIMD、并行时按 §6.2 和 §6.3 选择对应比较层级。

直接复用 `tests/common::assertions` 中的精确比较 helper（§6.2.1 Tier 1）。具体使用规则：
- 整数张量与"从整数构造的 f64 常量"运算结果可精确表示，逐元素比较使用裸 `assert_eq!`（与 W29T1 `real_bits_eq` 在精确可表示值上等价，但更易读）。
- 错误路径必须 `assert!(matches!(err, XenonError::<Variant> { .. }))` 到具体变体（28-tests §6.2 / 26-error.md §5.3）。
- 复数运算结果使用 `Complex::new(re, im)` 字面构造再 `assert_eq!`（同执行路径的 Tier 1 精确比较）。

本任务不需要额外 wrapper：上述断言模式直接在 Step 3 内表达即可。

### Step 3: 单元测试

> **强制要求**:
> - 本步骤必须包含一个或者多个单元测试。
> - 测试函数名称和测试内容必须参考对应设计文档的 **「测试计划」** 一节。
> - 编译检查与Lint检查不等同于单元测试。
> - 如果测试没有通过需要修复直至测试通过。
> - **无测试 = 任务未完成。**

```rust
#[cfg(test)]
mod tests {
    use super::*;
    use xenon::Complex;
    use xenon::overload::Scalar;  // Scalar 不在 prelude (19-overload §5.3); 需显式 import。

    // ---- High-priority §5.24 tests (L709-728) ----

    #[test]
    fn test_add_same_shape_overload() {
        // [2,3] + [2,3] 返回 Ok(...)，逐元素验证（运算符 trait 重载路径）。
        let a = Tensor1::from_shape_vec([3], vec![1.0_f64, 2.0, 3.0]).unwrap();
        let b = Tensor1::from_shape_vec([3], vec![4.0_f64, 5.0, 6.0]).unwrap();
        let r = (&a + &b).expect("same-shape add must succeed");
        assert_eq!(r.shape(), &[3]);
        assert_eq!(r.iter().copied().collect::<Vec<_>>(), vec![5.0, 7.0, 9.0]);
    }

    #[test]
    fn test_add_scalar() {
        // tensor + 5.0 返回 Ok(...)，逐元素验证（§5.24 L716）。
        let a = Tensor1::from_shape_vec([2], vec![1.0_f64, 2.0]).unwrap();
        let r = (&a + 10.0_f64).unwrap();
        assert_eq!(r.iter().copied().collect::<Vec<_>>(), vec![11.0, 12.0]);
    }

    #[test]
    fn test_add_ref_ref() {
        // &a + &b 返回 Ok(...)，且 a/b 所有权保留。
        let a = Tensor1::from_shape_vec([3], vec![1.0_f64, 2.0, 3.0]).unwrap();
        let b = Tensor1::from_shape_vec([3], vec![4.0_f64, 5.0, 6.0]).unwrap();
        let r = (&a + &b).unwrap();
        // 验证所有权保留：a/b 仍可访问。
        assert_eq!(a.shape(), &[3]);
        assert_eq!(b.shape(), &[3]);
        assert_eq!(r.iter().copied().collect::<Vec<_>>(), vec![5.0, 7.0, 9.0]);
    }

    #[test]
    fn test_add_owned_ref() {
        // a + &b 返回 Ok(...)，a 被消费。
        let a = Tensor1::from_shape_vec([2], vec![1.0_f64, 2.0]).unwrap();
        let b = Tensor1::from_shape_vec([2], vec![3.0_f64, 4.0]).unwrap();
        let r = (a + &b).unwrap();
        assert_eq!(r.iter().copied().collect::<Vec<_>>(), vec![4.0, 6.0]);
        // b 仍可访问。
        assert_eq!(b.shape(), &[2]);
    }

    #[test]
    fn test_add_ref_owned() {
        // &a + b 返回 Ok(...)，b 被消费。
        let a = Tensor1::from_shape_vec([2], vec![1.0_f64, 2.0]).unwrap();
        let b = Tensor1::from_shape_vec([2], vec![3.0_f64, 4.0]).unwrap();
        let r = (&a + b).unwrap();
        assert_eq!(r.iter().copied().collect::<Vec<_>>(), vec![4.0, 6.0]);
        assert_eq!(a.shape(), &[2]);
    }

    #[test]
    fn test_scalar_wrapper_add_tensor() {
        // 泛型场景：Scalar(5.0) + tensor。
        let a = Tensor1::from_shape_vec([2], vec![1.0_f64, 2.0]).unwrap();
        let r = (Scalar(5.0_f64) + &a).unwrap();
        assert_eq!(r.iter().copied().collect::<Vec<_>>(), vec![6.0, 7.0]);
    }

    #[test]
    fn test_native_scalar_add_tensor_i32() {
        // 原生 i32 + Tensor<i32>。
        let a = Tensor1::from_shape_vec([2], vec![1_i32, 2]).unwrap();
        let r = (10_i32 + &a).unwrap();
        assert_eq!(r.iter().copied().collect::<Vec<_>>(), vec![11_i32, 12]);
    }

    #[test]
    fn test_sub_basic() {
        let a = Tensor1::from_shape_vec([2], vec![10.0_f64, 8.0]).unwrap();
        let b = Tensor1::from_shape_vec([2], vec![3.0_f64, 5.0]).unwrap();
        let r = (&a - &b).unwrap();
        assert_eq!(r.iter().copied().collect::<Vec<_>>(), vec![7.0, 3.0]);
    }

    #[test]
    fn test_mul_basic() {
        let a = Tensor1::from_shape_vec([2], vec![2.0_f64, 3.0]).unwrap();
        let b = Tensor1::from_shape_vec([2], vec![4.0_f64, 5.0]).unwrap();
        let r = (&a * &b).unwrap();
        assert_eq!(r.iter().copied().collect::<Vec<_>>(), vec![8.0, 15.0]);
    }

    #[test]
    fn test_div_basic() {
        let a = Tensor1::from_shape_vec([2], vec![10.0_f64, 12.0]).unwrap();
        let b = Tensor1::from_shape_vec([2], vec![2.0_f64, 4.0]).unwrap();
        let r = (&a / &b).unwrap();
        assert_eq!(r.iter().copied().collect::<Vec<_>>(), vec![5.0, 3.0]);
    }

    #[test]
    fn test_result_ownership() {
        // Ok 中的结果张量与输入不共享 storage（§5.24 L725）。
        let a = Tensor1::from_shape_vec([2], vec![1.0_f64, 2.0]).unwrap();
        let b = Tensor1::from_shape_vec([2], vec![3.0_f64, 4.0]).unwrap();
        let a_ptr = a.as_ptr();
        let b_ptr = b.as_ptr();
        let r = (&a + &b).unwrap();
        let r_ptr = r.as_ptr();
        assert_ne!(r_ptr, a_ptr, "result must not alias input a's storage");
        assert_ne!(r_ptr, b_ptr, "result must not alias input b's storage");
    }

    // ---- Existing high-priority tests preserved (no *_then wrappers) ----

    #[test]
    fn test_add_broadcast() {
        // 28-tests §5.24 L712 明示指定形状 [2,1,3] + [3] 广播：
        // 1D [3] 需先左被pad 为 [1,1,3] 再广播到 [2,1,3]。
        let a = Tensor3::from_shape_vec(
            [2, 1, 3],
            (1..=6).map(|i| i as f64).collect(),
        )
        .unwrap();
        let b = Tensor1::from_shape_vec([3], vec![10.0_f64, 20.0, 30.0]).unwrap();
        let r = (&a + &b).unwrap();
        assert_eq!(r.shape(), &[2, 1, 3]);
        // F-order [2,1,3] strides=[1,2,2]，数据 [1..6] 映射：
        //   (0,0,0)=data[0]=1, (1,0,0)=data[1]=2, (0,0,1)=data[2]=3,
        //   (1,0,1)=data[3]=4, (0,0,2)=data[4]=5, (1,0,2)=data[5]=6
        // Broadcast: result[i,j,k] = a[i,j,k] + b[k]
        assert_eq!(*r.try_at(&[0, 0, 0]).unwrap(), 11.0);  // 1 + 10
        assert_eq!(*r.try_at(&[0, 0, 1]).unwrap(), 23.0);  // 3 + 20 (F-order: a[0,0,1]=data[2]=3)
        assert_eq!(*r.try_at(&[0, 0, 2]).unwrap(), 35.0);  // 5 + 30 (F-order: a[0,0,2]=data[4]=5)
        assert_eq!(*r.try_at(&[1, 0, 0]).unwrap(), 12.0);  // 2 + 10 (F-order: a[1,0,0]=data[1]=2)
    }

    #[test]
    fn test_native_scalar_add_tensor_f64() {
        // 实证 17-indexing.md §10：Xenon 不实现 Index<usize>；元素访问走 try_at。
        // 使用解引用 + assert_eq! 是最简洁的正确写法。
        let a = Tensor1::from_shape_vec([2], vec![1.0_f64, 2.0]).unwrap();
        let r = (10.0_f64 + &a).unwrap();
        assert_eq!(*r.try_at(&[0]).unwrap(), 11.0);
    }

    #[test]
    fn test_broadcast_incompatible() {
        // §6.2 / 26-error.md §5.3：错误断言到具体变体，不使用宽泛的 is_err()。
        let a = Tensor1::from_shape_vec([3], vec![1.0_f64, 1.0, 1.0]).unwrap();
        let b = Tensor1::from_shape_vec([5], vec![2.0_f64, 2.0, 2.0, 2.0, 2.0]).unwrap();
        let err = (&a + &b).unwrap_err();
        assert!(
            matches!(err, XenonError::BroadcastError { .. }),
            "expected BroadcastError, got {err:?}"
        );
    }

    // ---- §5.24 Medium-priority coverage ----

    #[test]
    fn test_i32_tensor() {
        let a = Tensor1::from_shape_vec([2], vec![1_i32, 2]).unwrap();
        let b = Tensor1::from_shape_vec([2], vec![3_i32, 4]).unwrap();
        let r = (&a + &b).unwrap();
        assert_eq!(r.iter().copied().collect::<Vec<_>>(), vec![4_i32, 6]);
    }

    #[test]
    fn test_complex_tensor() {
        let a = Tensor1::from_shape_vec([2], vec![
            Complex::new(1.0_f64, 2.0), Complex::new(3.0, 4.0)
        ]).unwrap();
        let b = Tensor1::from_shape_vec([2], vec![
            Complex::new(5.0_f64, 6.0), Complex::new(7.0, 8.0)
        ]).unwrap();
        let r = (&a + &b).unwrap();
    // 实证 17-indexing.md §10 L593 + 26-error.md L596：Xenon 不实现 std::ops::Index，
    // 元素访问仅能走 try_at()。
    assert_eq!(*r.try_at(&[0]).unwrap(), Complex::new(6.0_f64, 8.0));
    assert_eq!(*r.try_at(&[1]).unwrap(), Complex::new(10.0_f64, 12.0));    }
}
```

## 关键设计决策

| 决策 | 依据 |
|------|------|
| 集成测试通过公开 API 验证跨模块协作 | 28-tests §1.1 和 §5 将跨模块行为定义为本 wave 职责 |
| Tier 1 浮点路径默认使用 bitwise/ULP==0 精确比较 | 28-tests §6.2.1 禁止将基础路径自动放宽为容差比较 |
| compile-fail 与运行时错误测试互补 | 28-tests §8.4 要求非法类型边界通过仓库本地 harness 验证 |
| `ui_blanket_scalar_add_rejected` compile-fail fixture 交由 W29T25 交付 | 28-tests §5.24 L720 / §5.25 L734 将 orphan-rule 护栏作为独立 fixture；本任务仅负责运行时重载测试，fixture 集中置于 tests/compile_fail 目录由 W29T25 提交 |

## 验证方式

1. 编译检查: `cargo check --tests`
2. Lint 检查: `cargo clippy --tests -- -D warnings`
3. 测试验证: `cargo test --test test_overload`
4. 手动验证: 人工审阅失败断言信息，确认 shape、索引、feature 或错误类型上下文足以定位失败原因。
