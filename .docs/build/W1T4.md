## 目标

Prelude module skeleton and initial public export surface placeholder.

创建 `src/prelude.rs`，提供占位结构和导出入口。按 `01-architecture.md §7` 的导出清单预配置 re-export 占位符。

## 前置准备

- W1T3 完成：`src/lib.rs` 中已声明 `pub mod prelude`
- `src/prelude.rs` 在 W1T3 Step 4 中已创建占位文件（仅包含一行模块级文档注释）

## 实施步骤

### Step 1: 覆盖写入 prelude 模块文档和骨架

> **覆盖语义明示**：本步骤会**完整覆盖**（overwrite）W1T3 Step 4 创建的 `src/prelude.rs`
> 占位内容。这是 W1T3 与 W1T4 协调的预期行为：W1T3 仅负责让 `pub mod prelude;`
> 不导致编译失败，W1T4 负责填充正式骨架。覆盖写入对 W1T3 单元测试无影响——
> W1T3 的 `test_prelude_module_file_exists` 只检查文件存在性，与文件内容无关。

```rust
//! Xenon prelude module.
//!
//! Provides a convenient way to import the most commonly used types and traits
//! from the Xenon crate.
//!
//! # Usage
//!
//! ```
//! use xenon::prelude::*;
//! ```

// --- Core types (added incrementally as modules are implemented) ---
// Order strictly follows 01-architecture.md §7 prelude export list (lines 542-576).

// Tensor types — available after W8
// pub use crate::tensor::{TensorBase,
//                          Tensor, TensorView, TensorViewMut, ArcTensor};

// Dimension types — available after W3
// pub use crate::dimension::{Dimension, IntoDimension,
//                            Ix0, Ix1, Ix2, Ix3, Ix4, Ix5, Ix6,
//                            IxDyn, Axis};

// Element traits — available after W4
// pub use crate::element::{Element, Numeric, RealScalar, ComplexScalar};

// Complex type — available after W5
// pub use crate::complex::Complex;

// Error types — available after W2
// pub use crate::error::{XenonError, Result};

// Construction convenience helpers — available after W22
// pub use crate::construct::{zeros, ones, eye, from_shape_vec};
```

### Step 2: 等效验证脚本

> **目标文件类型说明**：`src/prelude.rs` 在本 task 阶段只包含文档注释 + re-export 注释占位符，
> 不构成可被 `#[test]` 直接覆盖的 Rust 逻辑。按 `TEMPLATE.md` 「等效验证条款」，本 task
> 采用脚本验证 + W1T3 文件存在性测试的组合履行测试义务，且脚本必须在任意检查失败时
> 以非零退出码返回。

```bash
set -euo pipefail

# 1) 模块级文档注释存在
grep -q "^//! Xenon prelude module\." src/prelude.rs

# 2) Usage 文档存在
grep -q "use xenon::prelude::\*" src/prelude.rs

# 3) 与 01-architecture.md §7 导出清单的关键占位符逐项对照
required_placeholders=(
    "pub use crate::tensor"
    "pub use crate::dimension"
    "pub use crate::element"
    "pub use crate::complex::Complex"
    "pub use crate::error"
    "pub use crate::construct"
)
for placeholder in "${required_placeholders[@]}"; do
    grep -q "$placeholder" src/prelude.rs || {
        echo "FAIL: missing placeholder: $placeholder" >&2
        exit 1
    }
done

# 4) 占位符必须仍为注释状态（避免误激活引用未实现模块）
if grep -E "^[[:space:]]*pub use crate::" src/prelude.rs; then
    echo "FAIL: re-export must remain commented at this stage" >&2
    exit 1
fi

echo "OK: W1T4 prelude skeleton validated"
```

## 关键设计决策

| 决策 | 依据 |
|------|------|
| 使用注释占位符 | 各模块类型在后续 Wave 中实现，完成后取消注释对应的 `pub use` |
| 保持 prelude 精简 | `01-architecture.md §7` 仅列出核心类型 |
| 不在 prelude 中导出内部类型 | `IsOwned`, `IsView` 等标记 trait 不暴露 |
| re-export 注释顺序严格对齐 §7 | tensor → dimension → element → complex → error → construct，与 `01-architecture.md §7` 第 542-576 行逐行对应 |
| 单元测试 + 等效验证脚本组合 | 本 task 目标文件 `src/prelude.rs` 阶段性只包含静态文本，无可执行 Rust 逻辑。`src/prelude.rs` 的存在性由 W1T3 的 `test_prelude_module_file_exists` 验证；内容骨架由 Step 2 的等效验证脚本保证（脚本失败必非零退出）。符合 `TEMPLATE.md` 「等效验证条款」 |
| 覆盖写入 W1T3 占位文件 | W1T3 Step 4 与 W1T4 Step 1 均明示该覆盖行为，避免实施歧义 |

## 验证方式

> 所有命令在失败时必须以非零退出码返回。

1. **编译**: `cargo check`（依赖 W1T3 创建的 lib.rs 与 prelude 模块）
2. **文档**: `RUSTDOCFLAGS="-D warnings" cargo doc --no-deps -p xenon` 确认 prelude 文档零警告
3. **等效验证脚本**: 执行 Step 2 的 bash 脚本（`set -euo pipefail` 启动），任何检查失败必非零退出
4. **W1T3 测试回归**: `cargo test --lib -- test_prelude_module_file_exists` 必须仍然通过

## 注意事项

- 当前阶段所有 re-export 均为注释状态——W1T4 只需骨架
- 后续 task 实现对应模块后，负责取消注释对应行的 `pub use`
- prelude 不导出 `std` 标准库类型（如 `Arc`），用户自行导入
- 不要把占位符验证测试写入 `src/prelude.rs`；该文件当前应只保留文档和 re-export 占位符
- **W1T4 覆盖 W1T3 占位文件是预期行为**：W1T3 Step 4 已声明该交接关系，本 task Step 1 再次明示，下游 task 不得回退此覆盖
- **等效验证脚本工具链前提**：`bash` 4.0+ 与 `grep`（POSIX）；不需要 Python；若 CI 镜像无 bash 4.0+（如 Alpine 默认 ash），需在 CI 内安装 bash 后再执行
