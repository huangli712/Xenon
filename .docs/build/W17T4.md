## 目标

将 dispatch 接入 `dot()`：在 W17T3 校验 + 标量内积之上插入 `let (path, guard) = select_exec_path(len, is_contiguous, alignment_ok)`，按 `ExecPath::{Serial, Simd, Parallel}` 三路 match。本 task **三路全部回退到 `scalar_dot`**——SIMD 真正接入由 W17T5、Parallel 真正接入由 W17T6 增量替换；W17T4 只完成 wiring 与契约对齐。

同时引入 12-matrix §6.4 line 370 引用但 W17T1-T3 尚未实现的 `alignment_ok(a, b)` 私有 helper——它聚合两侧张量的对齐状态生成 dispatch 第三参数（bool）。

## 实施步骤

### Step 1: 引入 dispatch 模块依赖与 `alignment_ok` helper

`alignment_ok(a, b)` 聚合两侧 `is_aligned()` 为单一 bool，与 12-matrix §6.4 line 370 的调用形式一致；它是 dispatch 第三参数的 helper，与 30-dispatch §5.5 line 365 "Caller asserts that input data pointers satisfy alignment fast-path" 的契约一致——即调用方对"是否对齐"作出**断言**，传给 dispatch 作为路径推荐的依据。

```rust
use crate::dispatch::{select_exec_path, ExecPath, ParallelGuard};

/// Combine the two-input alignment hints into the single `alignment_ok`
/// boolean that `dispatch::select_exec_path` consumes (30-dispatch §5.5
/// line 365). Per 30-dispatch §5.5 the value is a capability hint, not
/// a hard gate — the simd backend re-checks actual pointer alignment
/// at admission time.
#[inline]
fn alignment_ok<S1, S2, A, D1, D2>(
    a: &TensorBase<S1, D1>,
    b: &TensorBase<S2, D2>,
) -> bool
where
    S1: Storage<Elem = A>,
    S2: Storage<Elem = A>,
    D1: Dimension,
    D2: Dimension,
{
    a.is_aligned() && b.is_aligned()
}
```

> `ParallelGuard` import 在本 task 添加；W17T6 真正消费它。`#[allow(unused_imports)]` 在该 import 暂未使用时不需要——本 task 的 `dot()` match arm 会绑定 `guard` 变量，即触发使用。

### Step 2: 引入 `dot_serial` 私有 helper

为 W17T5 / W17T6 提供同一个 fallback 入口名，避免它们各自重新引用 `scalar_dot`。

```rust
/// Serial scalar fallback used by every dispatch path until W17T5 /
/// W17T6 specialize Simd / Parallel. Thin wrapper over `scalar_dot`
/// keeps subsequent tasks' diffs surgical — they only swap their match
/// arm, not the fallback target.
#[inline]
pub(crate) fn dot_serial<S1, S2, A, D1, D2>(
    a: &TensorBase<S1, D1>,
    b: &TensorBase<S2, D2>,
) -> A
where
    S1: Storage<Elem = A>,
    S2: Storage<Elem = A>,
    A: Numeric + DotAccumulate,
    D1: Dimension,
    D2: Dimension,
{
    scalar_dot(a, b)
}
```

### Step 3: 重写 `dot()` 接入 dispatch

按 12-matrix §6.1 line 233-247 与 §6.4 line 367-381：

1. 先做 `validate_dot_inputs(a, b)?` —— 与 W17T2 / W17T3 完全一致；
2. 调用 `select_exec_path(a.len(), is_contig, alignment_ok(a, b))`，**用 `let (path, guard) = ...` tuple destructure**（30-dispatch §5.5 line 166 原子绑定不变量）；
3. match 三个 arm，本 task 全部走 `dot_serial(a, b)`；
4. `Parallel` arm 在本 task 还不消费 guard，但**必须按 §6.1 line 240-242 的 invariant 含义校验**、以 `let _guard = match guard { Some(g) => g, None => unreachable!(...) }` 形式锁定 guard 与其所有权生命，避免 W17T6 反向修改本 task 的 match 体（设计 12-matrix §6.1 line 240-242 伪代码示例 `let-else` 与本 task 采用的 `match` 语义等价，本实施选择 `match` 以统一 W17T6 的 invariant 校验模板，不侵入设计补丁）。

```rust
pub fn dot<S1, S2, A, D1, D2>(
    a: &TensorBase<S1, D1>,
    b: &TensorBase<S2, D2>,
) -> Result<A, XenonError>
where
    S1: Storage<Elem = A>,
    S2: Storage<Elem = A>,
    A: Numeric + DotAccumulate,
    D1: Dimension,
    D2: Dimension,
{
    validate_dot_inputs(a, b)?;

    let is_contig = a.is_f_contiguous() && b.is_f_contiguous();
    let (path, guard) = select_exec_path(a.len(), is_contig, alignment_ok(a, b));

    match path {
        ExecPath::Serial => Ok(dot_serial(a, b)),
        ExecPath::Simd => {
            // W17T4 boundary: SIMD dispatch falls back to scalar; W17T5
            // replaces this arm with `simd::try_dot_*` admission.
            let _ = guard; // dispatch invariant: guard is None on Simd.
            Ok(dot_serial(a, b))
        }
        ExecPath::Parallel => {
            // Dispatch invariant (30-dispatch §5.5 line 166): when
            // ExecPath::Parallel is returned, guard MUST be Some.
            // W17T4 holds the guard alive but does not yet enter the
            // parallel backend; W17T6 swaps the body for par_dot.
            let _guard = match guard {
                Some(g) => g,
                None => unreachable!(
                    "dispatch returned (ExecPath::Parallel, None) — \
                     invariant violated, see 30-dispatch §5.5 line 166"
                ),
            };
            Ok(dot_serial(a, b))
        }
    }
}
```

### Step 4: 单元测试

针对 W17T4 的 wiring 行为补加单元测试。除了 §8.2 line 466-467 的 `test_dot_empty` / `test_dot_single_element`（验证数值），新增一个**dispatch wire-up smoke test**——构造长度跨越 SIMD / parallel 阈值的输入，断言公开行为（结果正确）。这覆盖 W17T4 的核心增量"wire dispatch decision into dot"。

**实施提示**：本 task 不创建新的 `mod tests_w17tN` 声明。以下 4 个测试函数追加到 W17T1/W17T2/W17T3 共享的 `#[cfg(test)] mod tests { ... }` 块内（use 列表不需变更，`Ix1` 与 `Tensor1` 已由 W17T1/W17T2 引入）：

```rust
// 追加到 mod tests 块末尾（在 W17T3 的 test_dot_real_conjugate_is_identity 之后）：

#[test]
fn test_dot_empty() {
    let a = Tensor1::<i32>::from_shape_vec(Ix1(0), vec![]).unwrap();
    let b = Tensor1::<i32>::from_shape_vec(Ix1(0), vec![]).unwrap();
    // 12-matrix §8.3: empty vectors return additive identity.
    assert_eq!(dot(&a, &b).unwrap(), 0_i32);
}

#[test]
fn test_dot_single_element() {
    let a = Tensor1::from_shape_vec(Ix1(1), vec![7_i32]).unwrap();
    let b = Tensor1::from_shape_vec(Ix1(1), vec![6_i32]).unwrap();
    assert_eq!(dot(&a, &b).unwrap(), 42_i32);
}

#[test]
fn test_dot_wire_dispatch_small_input_serial() {
    // Below any SIMD / parallel threshold: dispatch picks Serial.
    // W17T4's match wires all paths back to dot_serial, so the
    // observable result must equal the direct scalar baseline.
    let a = Tensor1::from_shape_vec(Ix1(4), vec![1.0_f64, 2.0, 3.0, 4.0]).unwrap();
    let b = Tensor1::from_shape_vec(Ix1(4), vec![5.0_f64, 6.0, 7.0, 8.0]).unwrap();
    assert_eq!(dot(&a, &b).unwrap(), 1.0 * 5.0 + 2.0 * 6.0 + 3.0 * 7.0 + 4.0 * 8.0);
}

#[test]
fn test_dot_wire_dispatch_large_input_falls_back_to_scalar() {
    // Above any threshold; with default features (no simd, no
    // parallel) dispatch still returns Serial and all match arms
    // route to dot_serial. The result must be deterministic and
    // equal to the explicit scalar fold.
    let n: usize = 4096;
    let xs: Vec<f64> = (0..n).map(|i| (i as f64) * 0.5).collect();
    let ys: Vec<f64> = (0..n).map(|i| (i as f64) * 0.25 + 1.0).collect();
    let a = Tensor1::from_shape_vec(Ix1(n), xs.clone()).unwrap();
    let b = Tensor1::from_shape_vec(Ix1(n), ys.clone()).unwrap();
    let expected: f64 = xs.iter().zip(ys.iter()).map(|(x, y)| x * y).sum();
    // Same accumulation order as dot_serial (sequential fold), so
    // equality is bit-stable in the default-feature configuration.
    assert_eq!(dot(&a, &b).unwrap(), expected);
}
```

## 关键设计决策

- **`(path, guard)` tuple destructure 锁定 dispatch invariant**：与 30-dispatch §5.5 line 166 "选中并行路径与进入并行临界区原子绑定" 完全一致；同一组绑定贯穿 W17T4 → W17T6，避免 W17T6 反向重命名 `_guard` → `guard`。
- **`alignment_ok(a, b)` 私有 helper 与 §6.4 line 370 一一对照**：返回 bool 而非 `Alignment::compatible_with` 这种不存在的 API；helper 内联到 dispatch 调用点。
- **`Parallel` arm 已固化 invariant 校验**：本 task 即便不消费 guard，也用 `let _guard = match guard { Some(g) => g, None => unreachable!(...) }`，让 W17T6 只需把 `let _guard = ...` 改为 `let guard = ...` 然后 `parallel::par_dot(..., guard)`，无需触碰 invariant 校验代码。
- **三个 arm 全部回退到 `dot_serial`**：W17T4 范围严格限定为 "wire"，不引入任何 SIMD / parallel 行为变化；后续 task 只替换单个 arm，diffs 最小。
- **`Simd` arm 显式 `let _ = guard;`**：dispatch §5.5 保证 Simd path 时 guard 为 None，但写出来让 rustc 不报"unused binding"且让人看到 guard 在 Simd 上是 noop。

## 验证方式

1. 执行 ``cargo check``——必须通过且 `src/matrix/dot.rs` 无新增 warning。
2. 执行 ``cargo test matrix::dot``——W17T1 / W17T2 / W17T3 / W17T4 全部测试通过（W17T4 新增 4 个）。
3. 执行 ``cargo test --features simd matrix::dot``——`feature = "simd"` 启用时 dispatch 可能返回 `ExecPath::Simd`，对应 arm 仍回退到 `dot_serial`，结果与默认特性一致；测试无 flaky。
4. 执行 ``cargo test --features parallel matrix::dot``——`feature = "parallel"` 启用时 dispatch 可能返回 `ExecPath::Parallel` + `Some(guard)`，invariant 校验不触发 `unreachable!`；结果仍与 `dot_serial` 一致。
5. 手动验证：打开 `src/matrix/dot.rs`，确认 `let (path, guard) = select_exec_path(...)` 形式 + `unreachable!` 文案与 30-dispatch §5.5 line 166 完全一致；`alignment_ok` 取代了任何形式的 `compatible_with` / `Alignment::...` 调用。

## 注意事项

- `let (path, guard) = ...` 绑定一旦在 W17T4 落地，**不允许在 W17T5 / W17T6 中再次重命名**；W17T6 只需在 `Parallel` arm 内把 `let _guard = ...` 改为 `let guard = ...` + 调用 par_dot。
- `dot_serial` 必须保持 `pub(crate)` 可见——W17T5 / W17T6 / 集成测试都会引用它。
- 不要在本 task 接入 `simd::try_dot_*` 或 `parallel::par_dot`——它们超出 W17T4 范围。
- `alignment_ok` 必须保持私有，不要 `pub(crate)`——这是 dot 内部用于聚合 dispatch 第三参数的极简 helper，外暴露毫无价值。
- 不要在本 task 添加 `Send + Sync` 边界——它属于 W17T6 接入 parallel 时的边界扩张。
