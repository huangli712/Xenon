# pulp API 能力勘察报告

> **W14T0 spike** — W14 SIMD Backend 前置调研
>
> pulp 版本: **0.22**（以 `Cargo.toml` 为准）
>
> 勘察日期: 2026-05-21

## 1. i32->i64 widening

### 调查目标

检查 pulp 是否提供 `i32s_widen_to_i64s` 或等价方法，用于 i32 整数 sum/dot 的 SIMD 中间累加（W14T4）。

### pulp 0.22 实际 API

pulp 0.22 的 `Simd` trait **未提供通用 i32→i64 宽化转换**。唯一相关的 widening 操作是：

```rust
// Simd trait method (lib.rs:1509)
fn widening_mul_u32s(self, a: Self::u32s, b: Self::u32s) -> (Self::u32s, Self::u32s);
```

`widening_mul_u32s` 执行 u32×u32→u64 的宽化乘法，返回 (low_half, high_half) 两个 u32s 向量。这可用于获取乘法的高 32 位，但**不是**通用的符号扩展宽化转换。

以下方法**不存在**于 pulp 0.22：
- `i32s_widen_to_i64s` / `cast_i32s_to_i64s`
- `simd.widening_add_i32s`
- 任何形式的 `{i32s,u32s} → {i64s,u64s}` 直接类型提升

### 结论

| 属性 | 值 |
|------|-----|
| 可用性 | **unavailable** |
| 备注 | pulp 0.22 未暴露通用 i32→i64 宽化转换；仅有 `widening_mul_u32s` 用于乘法场景。 |
| fallback 路径 | W14T4 仅保留 admission facade + `None` 返回；调用侧走标量 `checked_add`/`checked_mul` 路径。不得引入未审计的 `unsafe` intrinsic 临时替代。 |

### 对下游 task 的影响

- **W14T4**：不得实现 i32 SIMD sum/dot。admission 接口返回 `None`，由调用方走标量路径。
- **W14T9**：i32 admission 测试仅验证 facade 返回 `None`，不做数值对比。

## 2. Complex AoS deinterleave/shuffle

### 调查目标

检查 pulp 是否提供 shuffle/deinterleave API，用于 `Complex<f32>`/`Complex<f64>` 的 AoS 输入在寄存器内拆分实部/虚部（W14T5/W14T6/W14T11）。

### pulp 0.22 实际 API

pulp 0.22 的 `Simd` trait 提供了以下 deinterleave/interleave 方法：

```rust
// Default impls on Simd trait (lib.rs:720-837)
fn deinterleave_shfl_f32s<T: Interleave>(self, values: T) -> T;
fn deinterleave_shfl_f64s<T: Interleave>(self, values: T) -> T;
fn interleave_shfl_f32s<T: Interleave>(self, values: T) -> T;
fn interleave_shfl_f64s<T: Interleave>(self, values: T) -> T;
fn swap_re_im_c32s(self, a: Self::c32s) -> Self::c32s;
fn swap_re_im_c64s(self, a: Self::c64s) -> Self::c64s;

// Lane rotation (lib.rs:1294-1347)
fn rotate_left_f32s(self, a: Self::f32s, amount: usize) -> Self::f32s;
fn rotate_right_f32s(self, a: Self::f32s, amount: usize) -> Self::f32s;
```

**重要限制**：上述 `deinterleave_shfl_*` 和 `interleave_shfl_*` 方法的默认实现使用 **内存回退**（`deinterleave_fallback` / `interleave_fallback`，通过 `core::ptr::read`/`write` 逐元素重排）。它们**不是** ISA 特定的硬件 shuffle 指令（如 x86 `_mm_shuffle_ps`、`_mm256_permute_ps`、NEON `vtrn`）。

`swap_re_im_c32s`/`swap_re_im_c64s` 直接操作 complex SIMD 向量交换实部/虚部,在平台特定实现中可能使用硬件指令。

### 结论

| 属性 | 值 |
|------|-----|
| 可用性 | **partially available** |
| 备注 | API 方法存在但默认实现为内存回退；具体 ISA 后端（x86 V3/V4、NEON）可能覆盖为硬件 shuffle 指令，需分别验证。 |
| fallback 路径 | 对于 W14T5/W14T6/W14T11，优先使用 `deinterleave_shfl_f32s`/`deinterleave_shfl_f64s`。若性能不足，可考虑 x86 `_mm_shuffle_ps` / `_mm256_permute_ps` 或 NEON `vtrn` intrinsic，但需经架构审计。 |

### 对下游 task 的影响

- **W14T5**（Complex sum）：可用 `deinterleave_shfl_*` 进行 AoS→SoA 拆分。Complex sum 阈值 = 1024 无需调整（当前 API 可满足需求）。
- **W14T6**（Complex dot）：同 W14T5，复用其 deinterleave 路径。Complex dot 阈值 = 512 无需调整。
- **W14T11**（Complex element-wise）：API 可直接用于 AoS deinterleave。

## 3. FMA capability

### 调查目标

确认 pulp 是否将 FMA 作为独立能力位检测，而不是仅通过 AVX2 capability 间接推断。需确认 `Arch` 是否暴露独立查询 API。

### pulp 0.22 实际 API

**CPU 特征检测层面**：FMA 作为独立 CPU 特征进行检测。

- 在 `core_arch/raw_cpuid_detect.rs:54` 中，`"fma"` 作为独立条目通过 `cpuid.has_fma()` 检测。
- 在 `x86/v3.rs:25` 中，V3 结构体包含独立的 `pub fma: f!("fma")` 字段，与 `avx`/`avx2` 字段并列。
- 在 `x86/v4.rs:24` 中，同 V3。
- NEON 架构中 FMA 指令（`vfmaq_f32`/`vfmaq_f64`）在 NEON 可用时始终可用，无需独立检测。

**公有 API 层面**：pulp **未暴露**公开的 FMA 能力查询方法。

```rust
// Arch enum — NO has_fma() or similar capability query
pub enum Arch {
    Scalar,
    #[cfg(feature = "x86-v3")]
    V3(V3),
    #[cfg(feature = "x86-v4")]
    V4(V4),
}
// Only: fn new() -> Self, fn dispatch<Op: WithSimd>(self, op: Op)
```

`Simd` trait 提供 `mul_add_f32s` / `mul_add_f64s` 方法，它们在所有 `S: Simd` 实现上均可用（包括 `Scalar`），在 ISA 后端自动使用 FMA 指令（如果可用）。调用方**无需**显式查询 FMA 能力 — 透明使用即可。

### 结论

| 属性 | 值 |
|------|-----|
| 可用性 | **available, but not publicly queryable** |
| 备注 | FMA detection is independent from AVX2（在 CPU 特征检测层面是独立的，不与 AVX2 绑定）；但 `Arch` 不暴露 `has_fma()` 公有查询方法。`mul_add_f32s`/`mul_add_f64s` 在所有 SIMD 后端均可用（含 Scalar 回退），因此 Xenon SIMD 内核无需显式分支 FMA 可用性。 |
| fallback 路径 | 不使用独立 FMA 查询。`mul_add_*` 方法在 `Scalar` 后端自动回退到标量 `fma_f32`/`fma_f64`。W14T3/T5/T6 中仅 horizontal reduction merge 阶段可调用 `mul_add_*`，需在注释中注明容差边界。 |

### 对下游 task 的影响

- **W14T2/T11**（element-wise）：禁止在 per-element 主循环使用 `mul_add_*`（保持与标量逐位一致）。无影响。
- **W14T3**（float sum）：horizontal reduction merge 阶段可使用 `mul_add_f32s`/`mul_add_f64s`。
- **W14T5/T6**（complex sum/dot）：同上。

## 4. unaligned load/store

### 调查目标

确认 pulp 是否提供 unaligned load/store API，或其 slice conversion helper 是否允许安全处理非对齐输入（W14T2 等 element-wise SIMD）。

### pulp 0.22 实际 API

pulp 0.22 提供完整的 slice split helpers，**自动处理非对齐场景**：

```rust
// Simd trait — associated functions (generated by split_slice! macro)
// 命名约定: as_{mut_}simd_{type}s(slice) → (body, tail)
fn as_simd_f32s(slice: &[f32]) -> (&[Self::f32s], &[f32]);
fn as_mut_simd_f32s(slice: &mut [f32]) -> (&mut [Self::f32s], &mut [f32]);
fn as_simd_f64s(slice: &[f64]) -> (&[Self::f64s], &[f64]);
fn as_mut_simd_f64s(slice: &mut [f64]) -> (&mut [Self::f64s], &mut [f64]);

// 反向 split（scalar head + aligned body）
fn as_rsimd_f32s(slice: &[f32]) -> (&[f32], &[Self::f32s]);
fn as_mut_rsimd_f32s(slice: &mut [f32]) -> (&mut [f32], &mut [Self::f32s]);

// Partial load/store（处理小于完整向量的尾部）
fn partial_load_f32s(self, slice: &[f32]) -> Self::f32s;
fn partial_store_f32s(self, slice: &mut [f32], values: Self::f32s);

// Masked load/store（按位掩码控制加载/存储）
unsafe fn mask_load_ptr_f32s(self, mask: MemMask<Self::m32s>, ptr: *const f32) -> Self::f32s;
unsafe fn mask_store_ptr_f32s(self, mask: MemMask<Self::m32s>, ptr: *mut f32, values: Self::f32s);
```

**核心机制**：`as_simd_f32s` 内部通过 `unsafe { split_slice(slice) }` 实现，使用指针算术将输入切片的前缀部分对齐到 SIMD 向量自然对齐边界，返回 `(aligned_body, scalar_tail)`。**不需要**用户预先确保对齐 — 输入可以是任意 `&[f32]`。

### 结论

| 属性 | 值 |
|------|-----|
| 可用性 | **available** |
| 备注 | `as_simd_*`/`as_mut_simd_*` 自动处理非对齐输入；`as_rsimd_*` 提供反向 split 变体；`partial_load_*`/`partial_store_*` 处理尾部；刍入无需额外 unsafe intrinsic。 |
| fallback 路径 | 无极。本 API 即 Xenon SIMD 内核的唯一 unaligned 输入入口。 |

### 对下游 task 的影响

- **W14T2**：直接使用 `S::as_simd_f32s(lhs)` / `S::as_simd_f64s(lhs)` 替代设计文档中 pulp 0.18 风格的 `simd.f32s_as_simd()`。
- **所有 SimdKernel 实现**：使用新的命名约定 `as_simd_{type}s`（关联函数形式），而非 `{type}s_as_simd`（实例方法形式）。

## 5. lane width runtime query

### 调查目标

确认 `f32s_as_simd`、`f64s_as_simd` 或等价 API 是否暴露运行时 lane width，或是否需要通过返回的 SIMD chunk 长度间接推导。报告必须说明 `SimdKernel::width()` 的实现依据。

### pulp 0.22 实际 API

pulp 0.22 的 `Simd` trait 提供了**编译时常量**作为 lane count：

```rust
// Simd trait compile-time constants (lib.rs:597-618)
const F32_LANES: usize = core::mem::size_of::<Self::f32s>() / core::mem::size_of::<f32>();
const F64_LANES: usize = core::mem::size_of::<Self::f64s>() / core::mem::size_of::<f64>();
const I32_LANES: usize = core::mem::size_of::<Self::i32s>() / core::mem::size_of::<i32>();
const I64_LANES: usize = core::mem::size_of::<Self::i64s>() / core::mem::size_of::<i64>();
// ... 以及其他类型
```

这些常量在 `with_simd<S: Simd>()` 内可直接使用 `S::F32_LANES`。不同平台的值：

| 平台 | `S::F32_LANES` | `S::F64_LANES` |
|------|---------------|---------------|
| Scalar | 1 | 1 |
| SSE4.1 | 4 | 2 |
| AVX2 (V3) | 8 | 4 |
| AVX-512 (V4) | 16 | 8 |
| NEON | 4 | 2 |

**间接推导方式**：通过 `S::as_simd_f32s(slice)` 返回的 body 切片 `&[S::f32s]` 中每个 `S::f32s` 的 `size_of` 除以 `size_of::<f32>()` 得到 lanes 数量。但推荐直接使用 `S::F32_LANES` 常量。

### 结论

| 属性 | 值 |
|------|-----|
| 可用性 | **available** |
| 备注 | `S::F32_LANES` / `S::F64_LANES` 等编译时常量，在 `with_simd<S: Simd>()` 内直接使用。不是运行时查询而是编译时确定 — 因为 `S` 类型已在 dispatch 时选定。 |
| fallback 路径 | 无极。该常量是 `SimdKernel::width()` 的直接实现依据。 |

### 对下游 task 的影响

- **SimdKernel::width()**：在 `with_simd<S: Simd>()` 内使用 `S::F32_LANES` / `S::F64_LANES` 返回值。不是泛型函数在编译期确定的，而是由 `Arch::dispatch` 路由到正确的 `S` 实现后在 `with_simd` 内取得。
- **W14T1**：`SimdKernel` trait 的 `width()` 方法签名需要返回 `usize` 但无法在 trait 层面泛型化为类型常量；实际应在 `WithSimd` 内核内通过 `S::F32_LANES` 获取。`SimdKernel` 须考虑这一约束。

## 6. pulp 0.18 → 0.22 API 命名变更

设计文档 `08-simd.md` §6.1 基于 pulp 0.18 API 编写。pulp 0.22 的命名约定已全面变更。下表记录关键差异，所有 W14 task 实现必须按 pulp 0.22 命名：

| 用途 | pulp 0.18 (设计文档) | pulp 0.22 (实际) |
|------|---------------------|------------------|
| 不可变 slice split | `simd.f32s_as_simd(slice)` | `S::as_simd_f32s(slice)` |
| 可变 slice split | `simd.f32s_as_mut_simd(slice)` | `S::as_mut_simd_f32s(slice)` |
| Splat | `simd.f32s_splat(x)` | `simd.splat_f32s(x)` |
| 加法 | `simd.f32s_add(a, b)` | `simd.add_f32s(a, b)` |
| 减法 | `simd.f32s_sub(a, b)` | `simd.sub_f32s(a, b)` |
| 乘法 | `simd.f32s_mul(a, b)` | `simd.mul_f32s(a, b)` |
| 除法 | `simd.f32s_div(a, b)` | `simd.div_f32s(a, b)` |
| 取负 | `simd.f32s_neg(a)` | `simd.neg_f32s(a)` |
| FMA | 不存在 | `simd.mul_add_f32s(a, b, c)` |

**结构变化总结**：
- Split helpers 从 `simd.` 实例方法变为 `S::` 关联函数。
- 算术操作从 `{type}s_{verb}` 变为 `{verb}_{type}s`（动词前置）。
- 新增 `as_rsimd_*` 反向 split 变体（scalar head + aligned body）、`partial_load_*`/`partial_store_*`、`mul_add_*` FMA 操作。

## Conclusions for W14T2-T7

### API 可用性总览

| API 能力 | 可用性 | W14T2 | W14T3 | W14T4 | W14T5 | W14T6 | W14T7 | W14T11 |
|----------|--------|-------|-------|-------|-------|-------|-------|--------|
| i32→i64 widening | **unavailable** | — | — | ❌ 仅 facade | — | — | — | — |
| Complex AoS deinterleave | **partially available** | — | — | — | ⚠️ fallback | ⚠️ fallback | — | ⚠️ fallback |
| FMA capability | **available (internal)** | 禁用 | ✅ merge | — | ✅ merge | ✅ merge | — | 禁用 |
| Unaligned load/store | **available** | ✅ | ✅ | — | ✅ | ✅ | — | ✅ |
| Lane width query | **available** | ✅ | ✅ | ✅ | ✅ | ✅ | ✅ | ✅ |

图例: ✅ 可直接使用 | ⚠️ 可用但需关注性能 | ❌ 不可用，走标量回退 | — 本 task 不涉及

### 关键决策

1. **pulp 0.22 API 命名变更**：所有 W14 task 实现中必须使用 pulp 0.22 的新命名约定（`S::as_simd_f32s`、`simd.add_f32s` 等），不得沿用设计文档中记录的 pulp 0.18 命名。

2. **W14T4 (i32 sum/dot)**: i32→i64 通用宽化不可用。W14T4 仅实现 admission facade（返回 `None`），由调用方走标量 `checked_add`/`checked_mul`。i64 本身无 SIMD facade 承诺。

3. **W14T5/W14T6 (Complex sum/dot)**: `deinterleave_shfl_*` 存在但为内存回退实现。当前阈值（sum=1024，dot=512）保留，不因本 spike 上调。若后续 benchmark 显示 deinterleave 开销过高，可进一步审计 ISA-specific intrinsic。

4. **FMA 使用规则确认**: FMA 在 pulp 内部透明可用。Xenon 规则不变：element-wise 主循环禁用 FMA；仅 horizontal reduction merge 阶段可在注明容差边界后使用 `mul_add_*`。

5. **Unaligned 输入**: `as_simd_*` 系列自动处理非对齐的任意 `&[f32]`/`&[f64]` 切片，无需 Xenon SIMD 内核实现任何对齐预检查和 unsafe intrinsic。
